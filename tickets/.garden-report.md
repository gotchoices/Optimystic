## What this pass changed

### Merges (survivor ← absorbed)

- **`1-bug-cluster-size-resolution-single-source`** ← `bug-key-network-cluster-size-default-diverges`
  + `feat-warn-when-repair-floor-is-unsatisfiable`.
  One class: the node's size yardsticks are resolved in more than one place and the resolution is
  invisible. Arm A — the key network bypasses the resolution and defaults to 16 while everything else
  defaults to 10. Arm B — an embedder shipped a two-machine product whose nodes could never repair
  each other, because the resolved corroboration floor is never announced. Deliverable is the
  invariant: one resolved policy object, a construction-time coupling assertion, and a startup warning
  when the resolution is self-defeating.
- **`6-bug-docs-out-of-date-with-code`** ← `bug-docs-quote-superseded-super-majority-default`
  + `debt-docs-stale-transaction-naming`.
  One class: docs restate a value or a name owned by the source instead of citing the symbol, so they
  drift silently. Both site tables preserved verbatim.
- **`debt-mesh-harness-arms-real-gates`** ← `debt-mesh-harness-reconcile-double-bypasses-quorum`
  + `debt-mesh-level-partition-admission-regression` + `debt-mesh-client-signature-enforcement`.
  One file (`src/testing/mesh-harness.ts`), one weakness: for each safety gate the harness either
  substitutes a permissive stand-in, sets the escape hatch that disables it, or never threads the
  option that arms it. The three findings are the same bug seen three times.
- **`debt-session-mode-bridge-coverage`** ← `debt-bridge-partial-commit-branch-test`
  + `debt-session-mode-bridge-statement-recording-test`.
  Both are untestable for the same reason: no plugin-level harness stands the bridge up in session
  mode. Build the harness once; both gaps close against it.
- **`debt-competing-writer-test-transactor`** ← `debt-coordinator-retry-real-competing-committer-test`
  + `debt-e2e-stale-cache-hit-read-rejected`.
  Both need the same missing thing: a test transactor that can *durably land a competing commit
  mid-flight*. `FlakyCommitTransactor` only "stops refusing"; it never advances a log tail. Harness
  first, then the two assertions.
- **`feat-dispute-subsystem-live-activation`** ← `feat-authorize-dispute-protocol-streams` (extended,
  premise corrected). The absorbed ticket claimed any peer can already make a node vote on a dispute.
  **That is not true today** — verified: `libp2p-node-base.ts` (~643, ~1217) carries
  `[dispute-subsystem-dormant]` notes and the dispute handler is deliberately absent from the services
  map, so no peer can open the stream at all. The authorization gap becomes real *at the moment the
  activation ticket registers the handler*, which is where the decision now lives.

## Decisions waiting on you

These four are **not promotable as written** — each asks a human to choose, which the ticket rules put
in `blocked/`, not `backlog/`. A gardening pass without feedback may not move them, so they are flagged
here instead. Each is one question:

1. **`debt-optimystic-key-format-migration`** — *Does any Optimystic data written before the
   injective-key-encoding change need to survive an in-place upgrade?* If no, close it (and consider
   stamping a format version so the next breaking change is detectable). If yes, it needs a real
   reindex capability. **This one gates two other tickets**: `debt-optimystic-true-key-ordering` and,
   behind that, `debt-optimystic-pk-range-seek`. Answering it unblocks the whole optimystic
   performance chain.
2. **`debt-mixed-version-identify-incompatibility`** — *Nodes built before and after commit `849fd94`
   can no longer complete their introduction handshake, so a staged upgrade silently splits the
   network in half.* Choose: write it down and upgrade everything at once; ship a transition release
   that speaks both strings; or (independently) make the silent skip legible in the logs.
3. **`feat-phantom-read-protection`** — *Should a transaction that reads a block which does not exist
   be invalidated if someone later creates it?* The system used to do this by accident; a recent fix
   stopped. If the answer is "no", the ticket closes having recorded that the removal was deliberate.
4. **`feat-dispute-subsystem-live-activation`** — *Should being asked to vote on a dispute require the
   same permission check as reading and writing the database?* Now embedded in the activation ticket
   (see "Who may make this node vote?"), because the gap only becomes real when the handler is
   registered. Settle it before that code is written, not after.

Two further things worth knowing:

- **One missing capability gates four backlog items.** `feat-dispute-subsystem-live-activation`,
  `feat-cluster-membership-threshold-cert-anchoring`, `debt-read-repair-commit-cert-verification`, and
  (indirectly) `debt-read-repair-penalty-provable-only` are all waiting on the same thing: the ability
  for a node to independently verify who is legitimately in a cohort, rather than re-deriving it or
  trusting first contact. That work sits in `backlog/hardening/` — chiefly
  `invalidation-live-wiring-requires-arbitrator-set-anchoring` and
  `cohort-topic-trust-anchor-txlog-committed-binding`. Promoting one of those unlocks the most
  downstream value of anything in the queue.
- **`feat-cross-collection-atomic-commit`'s real prerequisite is not ticketed.** Cross-collection
  invalidation does not exist as a ticket anywhere on the board. Whoever promotes that item must file
  it first or absorb it.
