# Review: lock the namespace tree shut, and finish the reference table

Step 3 of 3 of `debt-service-logs-split-across-two-logger-factories`. Steps 1 and 2 fixed the
individual call sites; this step closes the door behind them and makes `docs/debugging.md` match
what the code actually emits.

## What landed

### 1. Lint rule — `eslint.config.js`

Two `no-restricted-syntax` selectors, applied to `packages/*/src/**/*.ts` (all packages, not just
db-p2p, so a future package that embeds libp2p inherits the guard):

| Selector | Why |
|---|---|
| `CallExpression[callee.property.name='forComponent']` | libp2p's `components.logger.forComponent('x')` yields the bare namespace `x`, which `DEBUG=optimystic:db-p2p:*` never matches |
| `ImportDeclaration[source.value='debug']` | bypasses the package's `src/logger.ts`, which is what prepends `optimystic:<package>:` |

The selectors are hoisted to named consts at the top of the file so the exemption block can reuse
one of them.

**Deviation from the ticket, deliberate:** the ticket said to express the exemptions as a later
block that sets the rule to `'off'`. Setting it off would also drop the `forComponent` ban in those
files, because flat config replaces a rule's whole config rather than merging selectors. The
exemption block instead re-declares the rule with **only** `NO_LIBP2P_COMPONENT_LOGGER`, so
`packages/*/src/logger.ts` and `packages/reference-peer/src/cli.ts` may import `debug` (they are
the chokepoint and an executable entry point respectively) but still may not reach for libp2p's
component logger. Confirmed by probe — see *How each guard was proven* below.

`reference-peer/src/cli.ts` was re-checked and does still import `debug`, so the exemption is live,
not dead.

The file's SCOPE comment now says the config enforces two rules, both about logging, instead of
"the only enforced rule is `no-console`".

### 2. Structural guard tests — `packages/db-p2p/test/logger.spec.ts`

New `describe('db-p2p log-namespace guards')` with four `it`s. Source directory resolved as
`fileURLToPath(new URL('../src/', import.meta.url))` — never `process.cwd()`, never a walk rooted
at the package directory (`dist/` holds compiled copies of the very strings being asserted absent).

- **`finds source files to scan at all`** — guards the guards. Asserts >20 files found and that
  `logger.ts` is among them, so a bad path cannot make the other three vacuously pass. (Currently
  142 files.)
- **`never calls libp2p's components.logger.forComponent()`** — zero files contain `.forComponent(`.
- **`imports \`debug\` only in src/logger.ts`** — zero other files match an `import … from 'debug'`.
- **`documents every sub-namespace the package emits in docs/debugging.md`** — extracts every
  `createLogger` string literal (**both** quote styles; the tree has double-quoted call sites in
  `src/cohort-topic/host.ts` and the whole reactivity directory) and asserts each appears as a
  backticked cell inside the `### db-p2p sub-namespaces` section.

All three failure messages name the offending files/namespaces rather than printing a bare count.

Two design points worth a reviewer's attention:

- **Comments are stripped before scanning.** `src/libp2p-node-base.ts:1110` legitimately explains
  in a comment which `forComponent` reach-through it replaced, and `src/logger.ts`'s JSDoc contains
  a `createLogger('parent:child')` example that is not a real channel. Rather than exempting those
  two files by name (which would blind the guard to a real call in them), the scan blanks
  `/* … */` and `// …` first. This is a lexer's-eye approximation, not a parser — documented as a
  `NOTE:` at the helper. **Verify this is the right call**; the alternative is per-file allowances.
- **First string literal inside the call, not first argument.** `createLogger(init.logPrefix ??
  'repo-service')` and the same shape in `cluster/service.ts` are real call sites; a
  `createLogger\('([^']+)'\)`-style regex would miss both. The regex is
  `/createLogger\(\s*[^)'"]*['"]([^'"]+)['"]/g`.

### 3. `src/logger.ts` — one `NOTE:`

Records that the docs-completeness guard sees **string literals only**: a namespace built from a
variable would be invisible to it and could go undocumented silently. No such call site exists
today.

### 4. `docs/debugging.md` — table rewritten

**10 rows → 45**, split into seven `####` sub-tables by subsystem (transactions/consensus, storage
and block movement, networking and routing, node startup wiring, reactivity, disputes,
cohort-topic integration) because 45 rows in one block is unreadable. Each row's description was
written from the actual `log(...)` format strings in the file that constructs the logger — tag
names, what the fields are — not "logging for X".

Because the section now contains `####` headings, the guard splits on `'\n### '` **with the
trailing space**; a bare `'\n###'` would stop at the first sub-heading and silently check one
seventh of the table.

Other edits in the same pass:

- **Address-learning prose** — the "two places" claim was re-verified against the code and is still
  correct: `merge` lines come only from `ClusterService`'s sink (`peer-address-book`) and
  `Libp2pKeyPeerNetwork.recordPeerAddresses` (`libp2p-key-network`, whose private `addressLog`
  forwards into `this.log`). Added one parenthetical: `ClusterClient` also walks fetched records,
  but only emits the record-level `peer-address-book:record-capped` tag, under `cluster-client`.
- **"Cluster consensus" recipe** — annotated to say `cluster` is an exact match for
  `ClusterCoordinator` alone and does not pull in `cluster-client`/`cluster-policy`/
  `cluster-service`.
- **"Full transaction lifecycle" recipe** — changed to `optimystic:db-p2p:cluster*` (dropping the
  now-redundant explicit `cluster-member`) and added `coordinator-repo*`. Rationale in a comment
  above it: a stalled transaction is as likely to be a sizing or protocol-handler problem as a
  consensus one. **This is a judgement call — worth a second opinion.**
- **"Adding new loggers"** — now opens with the rule the lint rule enforces, naming both banned
  constructs and why `test/` is exempt.

The *cohort-topic sub-namespaces* section higher in the file was left untouched, as the ticket
directed (it is wrong in a different way, filed as
`bug-cohort-topic-debug-namespaces-are-documented-but-not-emitted`). Note the resulting near-miss
for a reader: `optimystic:db-p2p:cohort-topic` (the host wired into a db-p2p node, newly documented
here) is a **different** namespace from that section's `optimystic:cohort-topic:*`. The new row
says so explicitly.

## Known gaps — treat these as the floor, not the finish line

- **The 45 descriptions were written from grepped format strings, not from reading each file's
  control flow.** They are accurate about *which tags a channel emits and what their fields mean*;
  they do not claim to describe every branch that reaches those tags. Spot-checking a handful
  against their source files is the highest-value thing a reviewer can do here.
- **The docs guard checks presence, not quality.** A row reading `` | `foo` | logging for foo | ``
  satisfies it. Nothing prevents the table from decaying back toward uselessness one lazy row at a
  time, and nothing checks a row landed in the *right* sub-table.
- **`cluster-client`'s row is inferred, not observed.** That logger emits no `log(...)` call of its
  own; it is passed into `mergeRecordPeerAddresses`, so its lines are that helper's
  `peer-address-book:record-capped` and unparseable-peer-id tags. Traced by reading
  `src/peer-address-book.ts:332-360`, not by running it.
- **Comment stripping could over-strip.** A string literal containing `/*` or a non-URL `//` would
  blank the rest of that line or comment. No such literal exists in this package; the symptom if
  one appears is a guard that goes quiet, not one that false-positives.
- **The structural tests are db-p2p-local by design.** The other six packages get only the lint
  rule, which does not run under `yarn test`. Generalizing the scans across the workspace was
  explicitly out of scope for this pass.
- **`packages/db-p2p/src/protocol-client.ts` may appear as `M` in `git status`.** Its content is
  byte-identical to HEAD (`git hash-object` matches `git rev-parse HEAD:<path>`, and `git diff` is
  empty) — a stale stat-cache entry from a probe that was written and restored. Nothing to commit
  there.
