# Cohort-topic: a topic can place its root at a routing key — review handoff

First of three tickets for the accepted decision in `docs/reactivity.md` § Origination point. This one is the transport-free half in db-core. Nothing produces the new fields yet (the host honors them in `cohort-topic-host-serves-a-root-at-a-storage-group`; reactivity uses them in `reactivity-notifications-need-the-tail-cohort-to-be-the-topic-cohort`), so every change is behind an optional field or argument and the existing behavior is unchanged when none is set.

## What was built

**Addressing** (`addressing.ts`). `TierAddressing.rootCoord(rootKey)` = `H(rootKey)` — the key hashed once with no tier byte, so it equals the key network's position for the same routing key. `coord(d, P, topicId, rootKey?)` dispatches to it at `d = 0`; `d ≥ 1` ignores the key. `rootCoord` throws `RangeError` on an empty key.

**Wire** (`wire/types.ts`, `wire/validate.ts`, `wire/primitives.ts`, `wire/payloads.ts`, `sig/payloads.ts`).
- `RegisterV1.rootKey?` and `ChildLinkV1.rootKey?`: base64url, validated to 1..`MAX_ROOT_KEY_BYTES` (256) decoded bytes by a new `b64urlBoundedLen` primitive. The 256 is a chosen policy value: a generated block id is 43 bytes, a named header block is the collection name.
- `SignRequestV1.rootPlaced?` and `CohortGossipV1.rootPlaced?`: must be literally `true` when present (new `optTrue` primitive).
- Signing coverage, all **only when present**: `registerSigningPayload` appends `rootKey` as a 15th element; `childLinkSigningPayload` inserts `rootKey` before the trailing `cohortEpoch` (the `/sign` endorser's positional epoch read is preserved; `ChildLinkSignable` gains `rootKey`); `cohortGossipSigningPayload` appends `rootPlaced` after `timestamp`. A frame without the field signs byte-for-byte what it signed before. `SignRequestV1` is not a signed frame, so its flag is unsigned (the type comment explains why forging it gains nothing).

**Ports** (`ports.ts`). `ITopicRouter.routeToRoot?(rootKey, activity)` (optional). `RootPlacement { quorumRatio }` and `MembershipLookupOptions { rootPlaced?: true }`. `IMembershipSource.current/fetch(coord, opts?)` and `IMembershipTrustAnchor.directAnchor(cert, tier, placement?)` take the new optional argument; `noAuthorityTrustAnchor` updated. All optional, so every db-p2p implementer and test double compiled unchanged.

**Threshold rule** (`sig/threshold.ts`). `createRootPlacement(ratio)` throws `RangeError` outside `(0, 1]`. `rootPlacedMinSigs(memberCount, placement)` = `max(1, ceil(memberCount × quorumRatio))` — same expression as `captureCommitCert`; the floor of 1 only differs at zero members, where it stops an empty member list from counting as a quorum.

**Walk and service** (`walk.ts`, `service.ts`). `WalkEngine.register(…, opts: WalkOptions { probe?, rootKey? })`; the factory's `build` gets `rootKey` and the service's factory stamps it on the frame before signing, at every tier. New private `routeToTier`: `d = 0` with a root key goes through `router.routeToRoot` when present, else `routeAndAct(coord(d, self, topicId, rootKey), …)` with the usual `wantK`/`minSigs`. `RegisterRequest.rootKey?`, `lookup(topicId, tier, rootKey?)`; both reject an empty or over-long key with `RangeError` at the call (`assertRootKey`). The renewal transport's `relookup` passes the request's root key, so the all-backups-failed re-walk re-registers at the same root. `CohortHint.rootKey?` is set (only when present) on lookup results and registration handles, so a caller verifying a notice from that root knows the placement rule applies — this field is beyond the ticket's text; it is the "handle remembers the root key" requirement made visible.

**Verifier** (`membership/verifier.ts`, `membership/source.ts` doc only). `verifyMessage(…, opts?: VerifyMessageOptions)` where `VerifyMessageOptions extends RefetchBound { placement?: RootPlacement }`. With a placement, `minSigsFor(cert, placement)` replaces the constructor `minSigs` in all three `verifyThreshold` calls: the cert's self-consistency, the rotation chain (counted over the predecessor cert's members, since the predecessor signs the rotation), and the message. The placement is passed to `source.current/fetch` as `{ rootPlaced: true }` and to `anchor.directAnchor`. Cache: each `CachedCert` records the `quorumRatio` it was validated under (`undefined` = default rule); `heldUnder(coordKey, placement)` is the one read path and returns the entry only under the same rule, for message verification, the chain predecessor and the trust lock alike. `cache(cert, placement?)` (public) records the rule a self-published cert was published under — also beyond the ticket text, needed so a root-placed engine's own cert is usable under its rule. One extra guard: `lockedUnderAnotherRule` — a cert accepted under rule B is used for the current message but **not cached** when the coord holds a *trusted* entry under rule A, so a call under the wrong rule cannot erase a trust lock; a `NOTE:` at the method records that two rules at one coord is an anomaly and names the remedy if it ever costs.

**Docs** (`docs/cohort-topic.md`). New § Root placement at a routing key under § Tier addressing (the two overrides, the field table, the router seam, the implementation pointers, and the fact that a root key is not bound to its topic id); threshold wording in § Membership fetch and a verifier paragraph in its implementation note; the three wire-format blocks and their notes gain the new fields. `yarn lint:docs` passes.

## Tests added

- `wire.spec.ts` › root key signing coverage › *registerSigningPayload keeps its image without a rootKey, and binds one that is present* — pins the exact 14-element pre-existing image for a frame with no key; a keyed frame's image differs from the stripped and from a swapped key; the image re-derived from the decoded frame equals the signed one.
- `wire.spec.ts` › *childLinkSigningPayload keeps its image without a rootKey, and binds one that is present before the epoch* — exact 8-element image without a key; with one, the key is covered, `cohortEpoch` is still last, a swapped key differs, decode round-trips.
- `membership.spec.ts` › root-placed coords › *uses ceil(members × quorumRatio) under a placement, and the default minSigs without one* — a 3-member cert signed by 3 verifies a 3-signer message under `0.75`; 2 signers do not; the same cert and signers are untrusted under the default 14; a 3-member cert only 2 of whom signed is untrusted under the ratio.
- `membership.spec.ts` › *re-validates a cert cached under one rule instead of reusing it under the other* — both directions: a placement-validated entry is not reused by a default call (which goes to the source, fails, and leaves the entry intact), and a trusted default entry is not reused by a placement call (which goes to the source, finds nothing, and leaves the default entry intact).
- `walk.spec.ts` › *a root-placed topic reaches its root through routeToRoot, and at H(rootKey) on a router without it* — tier 1 keeps `coord_1(self, topic)` via `routeAndAct`; the root step hands `routeToRoot` the raw key; both frames carry the key; a router without `routeToRoot` gets the root step at `sha256(rootKey)`.

## Known gaps for the reviewer

- **Untested branches, by the ticket's test list:** the validator rejections (`rootKey` empty / over 256 bytes / not base64url, `rootPlaced` not literally `true`); `cohortGossipSigningPayload` covering `rootPlaced`; the service-level threading (`RegisterRequest.rootKey` → frame, `lookup`'s third argument, the renewal re-walk keeping the key, `CohortHint.rootKey`); `assertRootKey`; `rootCoord`'s empty-key throw; `createRootPlacement`'s range check. All are straight-line or single-branch and were read, not run.
- **`lockedUnderAnotherRule` is not exercised.** The cache test's second half gives the placement call an empty source, so `loadFrom` never reaches the guard. A test would need a source returning a cert that passes under the placement while a trusted default entry is held, then assert the default entry still answers and the placement call re-reads the source each time.
- **Chain-check threshold choice.** The ticket says `ceil(cert.members.length × quorumRatio)` for all three checks; for the rotation attestation I count over the **predecessor** cert's members (the cert handed to `verifyThreshold` there, whose members the signers must belong to). Same thing when the group size is unchanged across the rotation; differs when the group grew or shrank. I believe the predecessor count is the right one; worth a second opinion.
- **`rootPlacedMinSigs` floors at 1**, so a zero-member cert cannot verify. `captureCommitCert` has no such floor (a cohort always has at least the coordinator). Documented at the function.
- **The walk's root fallback** passes the default `wantK`/`minSigs` to `routeAndAct` at `H(rootKey)`. Fine for mocks and for a ring-routed delivery, but a FRET binding that reads them as the cohort's size and threshold would get the wrong numbers there; the real binding is expected to have `routeToRoot`, so the fallback is for routers that don't.
- **`CohortHint.rootKey`** is added with a conditional spread so `deep.equal` assertions on hints elsewhere stay valid; a reviewer may prefer it always present as `undefined`.
- **Membership source test doubles** (`MockSource` etc.) ignore the new `opts`; nothing asserts the verifier passes `{ rootPlaced: true }` to the source. That is port wiring the host ticket's live-tier spec will exercise end to end.

## Review findings so far (from implementing)

- **Pre-existing bug found and filed**: `tickets/fix/membership-verifier-accepts-a-certificate-for-another-coordinate`. `loadFrom` never checks that a fetched cert's `cohortCoord` is the coord being verified, so one dishonest cohort member can answer a membership fetch with a self-signed cert for an unrelated coordinate and have a forged message accepted — bypassing the direct anchor and the trust lock, both of which key on the cert's own coord. Reproduced with a throwaway spec (`"verified"` where `"untrusted"` was expected); the spec was not kept. Not fixed here: outside this ticket's "no behavior change" bar, and the fix should decide what `FretMembershipSource` does with unchecked reply bytes too.
- **Two arms appended to `cohort-topic-host-serves-a-root-at-a-storage-group`** (its *Edge cases* list): a root key is not bound to its topic id, so `0x00 ‖ topicId` is a valid root key landing on a default-addressed topic's `coord_0` — the host must fix the rule per engine and refuse a frame claiming the other rule for that coord; and a root-placed engine's `onCertPublished` must call `verifier.cache(cert, placement)` or its own cert is never used under the placement rule. The first is also stated as a requirement in the new doc subsection.
- Tripwire recorded as a `NOTE:` at `lockedUnderAnotherRule` in `membership/verifier.ts`: two threshold rules meeting at one coord costs a source read per call under the second rule; key the cache by `(coord, rule)` if that is ever paid in practice.
