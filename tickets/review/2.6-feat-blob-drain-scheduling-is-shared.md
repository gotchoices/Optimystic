# The drain's scheduling is shared

## What changed

`DrainScheduler<TEntry, TTally>` in `packages/db-p2p/src/repo/drain-scheduler.ts` holds everything that used to sit around the per-entry work in `UnderReplicationDrain`: the triggers (`start`, `connection:open`, `peer:identify`, the re-check timer, `checkNow`, and a new `wake()`), the debounce and minimum-interval throttle with its one-timer-pulled-earlier rule, pass serialization, partition suppression, the eligible-peer set (connected, deduplicated, membership gate, optional peer-store protocol check), the rotating per-pass budget, the per-(entry, peer) give-up rule with reconnect reset, and the pass log lines (`started`, `stopped`, `start pass error`, `pass error`, `throttled`, `pass:skip`, `pass:done`, `peer:abandoned`) written through the logger the owner hands in.

The owner supplies two seams: a `DrainEntrySource` (`list`, `size`, `keyOf`) and a `DrainEntryStep` that receives a `DrainEntryContext` (`reachable`, `noteFailure`, `noteSuccess`, `forgetEntry`, `tally`). `onPeerReturned` is an optional callback fired from the connection handler, after the peer's give-up state is forgotten, under the "only connection" test; the block drain does not pass it.

`UnderReplicationDrain` keeps its public surface: constructor, `UnderReplicationDrainDeps`, `UnderReplicationDrainConfig` (with `blockBudget`, mapped to `entryBudget`), `DEFAULT_UNDER_REPLICATION_DRAIN_CONFIG`, `DrainPassResult`, `checkNow`, `getDiagnostics`, `start`, `stop`, and re-exports of `BlockDurabilitySink`, `DrainTrigger` and `DrainLibp2p` (the last two now defined in the scheduler module). Its `drainEntry` is today's body rewritten over the context. `checkNow` maps the scheduler's `DrainPassReport` to `DrainPassResult` (`toPassResult`), turning `skipped: 'no-eligible-peer'` into `'no-pushable-peer'`.

The `pass:done` format is built from the tally list in order, so with `['solo', 'waiting', 'pushed', 'cleared', 'dropped']` the substituted text equals today's line. `peer:abandoned` is now formatted `peer:abandoned %s=%s …` with the entry label (`block`), so the raw template differs but the printed line is the same.

## Decisions worth a second look

- **Deps read lazily.** The existing spec reassigns `deps.partitionDetector` and `deps.emit` after the drain is constructed and started. So `UnderReplicationDrain` hands the scheduler a partition detector and an entry source that read through `this.deps` on every pass (comment at the construction site). `libp2p`, `membership` and the protocol id are captured at construction, as the listeners always were.
- **`UnderReplicationDrain.pushablePeers` survives as a one-line method** over `context.reachable(owed.peerIds)`. It exists to keep the block-specific `NOTE:` (a named peer the gate has since refused, or one rebuilt as a client, keeps its entry from settling) at the site three doc citations name (`docs/internals.md` twice, `packages/db-p2p/docs/repo.md` once). The generic half of the old comment (what "eligible" means) moved to `DrainScheduler.eligiblePeers`. A reviewer may prefer to inline it and retarget the citations at `drainEntry`.
- **Protocol rule unchanged.** A `protocolPrefix` of `''` still means "check `buildBlockTransferProtocol('')`", because the protocol id is set whenever the prefix is not `undefined`, not when it is truthy.
- **`wake()` is untested here.** It is `schedule('manual')`: debounced, then throttled like a connection event, and it forgets no peer state. The blob drain ticket (`feat-blob-owed-copies-are-drained`) is its first caller and should exercise it there.
- `DrainPassReport.tallies` is built with a cast (`Object.fromEntries(...) as Record<TTally, number>`), since the type system cannot see that mapping a `readonly TTally[]` covers every key.
