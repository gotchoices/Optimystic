# React Native reads decode UTF-8 in native code

GitHub #51. Second of two tickets; the first (`storage-drivers-can-carry-values-as-text`, complete) made the shared storage layer generic in how a value is held (`RawStoreDriver<V>`, `ValueCodec<V>`, `textValueCodec`). This one puts the React Native LevelDB backend on text.

## What changed

- **Driver surface** (`leveldb-like.ts`): `LevelDBLike` gains `getText(key)` and `textIterator(options)` (options are an iterator's less `keys`, as `LevelDBTextIteratorOptions`); `LevelDBIteratorLike<V = Uint8Array>` and `drain<V>` are generic.
- **`rn-leveldb` adapter** (`rn-opener.ts`): `RNLevelDBNative.getStr` and `RNLevelDBIteratorNative.valueStr` declared; `getText` is `getStr(...) ?? undefined`; one `RNLevelDBIteratorAdapter<V>` carries the positioning and bounds walk for both value kinds, parameterized by a `ReadValue<V>` (`bytesValue`, `textValue`, `noValue` for `keys: true`).
- **Test and upgrade-check adapters** (`test/classic-level-driver.ts`, `packages/upgrade-check/writer/classic-level.mjs`): text reads use `classic-level`'s per-operation `valueEncoding: 'utf8'`, which classic-level decodes in C++ (`napi_create_string_utf8` in its `binding.cc`), the same shape as rn-leveldb's JSI `createFromUtf8`. Both iterator paths share `rangeOf` and `adaptIterator` helpers. `spyBatchWrites` forwards both new reads.
- **`LevelDBJournalStore implements JournalStore<string>`**: `get` uses `getText`, `rangeRevisions` drains `textIterator`. Writes, journal, listings, byte estimate unchanged (bytes).
- **`LevelDBRawStorage extends KvRawStorage<string>`**: `KvRawStorage<string>(CachedStoreDriver<string>(WriteGroupDriver<string>(JournalBatchBackend<string>(LevelDBJournalStore(db)), options, textValueCodec), readCachePool, readCacheLabel ?? 'leveldb', textValueCodec), textValueCodec)`. `LevelDBRawStorageOptions` is now an interface extending the write-group and journal options, plus `readCachePool?` and `readCacheLabel?`. `readCached: true` re-declared with `declare`. Constructor signature unchanged.
- **`LevelDBKVStore`**: overlay is `WriteGroup<string, string>` (`storedBytes: textValueCodec.storedBytes`), `get` reads with `getText`, `commit` encodes with `TextEncoder`. Its module-level `TextDecoder` is gone. `set` holds `asStoredText(value)` so an overlay hit and a cold read agree on a lone surrogate (before, the overlay held `TextEncoder` bytes, so a hit already came back normalized).
- **`asStoredText`** (`raw-store-codec.ts`): the codec's private `asStored` renamed and exported, for the KV store above; `textValueCodec.encodeActionId` uses it as before.
- **`keys.ts`**: tripwire `NOTE:` at `actionIdFromKey` (listings still decode key suffixes with `TextDecoder`; ASCII fast path if it shows in a profile).
- **Docs**: `storage.md` (*Shared KV Kernel*: new paragraph "The React Native backend is the one text composition"; *Wiring*: new bullet "A backend may build its cache in"; the intro's "only speaks bytes" corrected); `db-p2p/readme.md` `TextDecoder` polyfill row; `db-p2p-storage-rn/README.md` (new "Reads decode text in native code" section with the BOM note, the read-cache options and why the polyfill stays required; one-storage-per-handle rule; close-order comment; the usage example now actually passes `storage` and `kvStore` to `createLibp2pNode`, which it never did). One stale comment in `repro-issue8.mjs`.

Close ordering checked by inspection: `CachedStoreDriver.close` clears and unregisters from the pool synchronously, then awaits the write-group driver's `close` (flush, then backend close). A latched storage's `close` still releases the pool claim before throwing `StoreFailedError`, and a second `close` does not strip a successor's claim (`unregisterStore` checks the claim is its own).

Pass-through checked by inspection: `resolveStorage` (node) and `CollectionFactory.createLocalTransactor` (Quereus) both go through `withReadCache`, which returns a `readCached` storage unchanged with no lease.

## Tests

Added, in `test/leveldb-storage.spec.ts` under `describe('LevelDB text reads')`, sharing one fixture set with BMP non-ASCII (`é`, `中`) and an astral character (`😀`) in every value kind:

- **"values an earlier build wrote, non-ASCII included, read back unchanged"** — writes the bytes the old path stored (`TextEncoder` of `JSON.stringify(v)`, and of the action id) straight into the handle for metadata, a revision, a pending and a committed transform, a proof and a materialized block; reads each back through a fresh `LevelDBRawStorage` (`getMetadata`, `getRevision`, `listRevisions`, `getPendingTransaction`, `getTransaction`, `getBlockProof`, `getMaterializedBlock`). Pins the codec plumbing over `classic-level`.
- **"no stored value read calls a TextDecoder, from LevelDB or from the read cache"** — saves every kind, `close()`s, opens a second storage, wraps `TextDecoder.prototype.decode` with a counter, reads every kind twice (cold, then cache hits), asserts zero calls, restores the prototype in `finally`. Negative-controlled during implementation: routing `LevelDBJournalStore.get` through a `TextDecoder` made it fail; reverted.

Changed: **"a batch write that fails leaves the database untouched and latches the storage"** now closes the latched storage (expecting `StoreFailedError`) before opening its reader, since the read cache's pool claim refuses a second storage over an open one's handle.

No KV-store test added: the existing `leveldb-kv-store.spec.ts` cases already read from a store with an empty overlay (`getText` path).

## Known gaps and things for the reviewer to weigh

- **`rn-leveldb`'s `getStr`/`valueStr` were not checked against an installed copy.** The package is not in this repo's `node_modules`; the declared signatures (`getStr(key): string | null`, `valueStr(): string`) follow the plan's reading of rn-leveldb 3.11.1's sources. `check:rn` never touches native modules. A wrong signature would fail only on a device.
- **Behaviour change for hosts: a second `LevelDBRawStorage` over an open handle now throws.** This includes a host that hands the node a factory (`storage: () => new LevelDBRawStorage(db)`) and restarts the node over the same handle without closing the previous storage: the node never closes a storage it was handed, so the second construction is refused. Before, the node's shared cache deduped by handle identity and the pattern "worked" while two write groups ran over one store. The README now says to close the first; worth checking downstream (sereus) for this pattern before release.
- **Pool statistics label**: the RN storage now shows in `pool.stats()` as `'leveldb'` (or `readCacheLabel`), not `node:<networkName>`, since the node no longer wraps it.
- **KV-store pacing**: `maxUnsyncedBytes` for the KV store now counts UTF-16 length (`textValueCodec.storedBytes`), an undercount by up to 3× for non-ASCII; it only paces size-forced flushes.
- **`asStoredText` widens db-p2p's public surface** by one function, and costs the KV store one regex pass per `set`. The alternative was duplicating the regex in the RN package.
- **Hermes's own UTF-8 decoder is not tested here.** Everything rests on the JSI contract plus every stored value being valid UTF-8.
