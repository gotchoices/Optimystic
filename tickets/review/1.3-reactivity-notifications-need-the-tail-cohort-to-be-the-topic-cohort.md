# Reactivity: root the announcement tree at the tail block's storage group — review handoff

Third of three tickets for the maintainer's decision of 2026-10-02 (the accepted text is now the first two paragraphs of `docs/reactivity.md` § Origination point). The first two tickets added root placement to the cohort-topic substrate and taught the db-p2p host to serve a root whose group is a block's storage group; this one switches reactivity onto it and binds the host's root group to the key network. The deleted FRET membership gate (`reactivity-membership-gate.ts`) is gone from the tree and from every doc.

## What changed, by site

- **Key network** (`packages/db-p2p/src/libp2p-key-network.ts`). `assembleServingCohort(key)` is now `hashKey(key)` followed by a coordinate-taking `assembleServingCohortAt(coord)`; `findCluster` and `findCoordinator` still go through the former, so storage placement and root placement share one assembly. New public `servingCohortAt(coord)` returns the cohort's peer-id strings in proximity order.
- **Node base** (`createLibp2pNodeBase` in `packages/db-p2p/src/libp2p-node-base.ts`). One `rootGroupAt` binding over `keyNetwork.servingCohortAt` feeds the host option `rootGroup = { membersAt, quorumRatio: consensusConfig.superMajorityThreshold }`, the push-state gossip authenticity gate, and the recover transport's target read. `cohortTopic.host` can no longer carry `rootGroup` (removed from the option type). The forwarder's `verifierFor`, the watch service and every subscription manager use `consensusConfig.superMajorityThreshold`. `resolveChildPrimary` stays on FRET. The matchmaking query handler keeps its own `coord0` addressing. The `wantK` option comment now says what it governs: every cohort that is not a root-placed root.
- **Origination gate** (`selfAppliedTail` in `packages/db-p2p/src/cohort-topic/change-bridge.ts`). A change event originates iff it names a tail and that tail is among `blockIds`. The bridge applies the rule itself; the injectable `selfIsCohortMember` dependency is gone. The retained-cert check is unchanged.
- **Verifier** (`createNotificationVerifier` in `packages/db-core/src/reactivity/verify.ts`). `expectedCoord = reactivityRootCoord(b64urlToBytes(n.tailId))`, verified under a `RootPlacement` built from the new required `quorumRatio` dependency. The unused `fanout` dependency is dropped. `reactivityRootCoord(tailBytes, hash)` lives beside `reactivityTopicId` in `packages/db-core/src/reactivity/topic-anchor.ts` and delegates to the addressing's `rootCoord`.
- **Subscriber walk** (`ReactivitySubscriptionManager.register`). Passes `rootKey: tailIdAtAttach`, so the walk's root step goes through the host router's `routeToRoot`. `ReactivitySubscriptionManagerOptions.quorumRatio` and `ReactivityCollectionWatchOptions.quorumRatio` are new required fields.
- **Forwarder-side reads.** Push-state gossip's `cohortCoord` is `reactivityRootCoord(tailIdAtJoin)`; its `isCohortMember` gate is async (the driver's `deliver` is now `Promise<void>`, a throwing or rejecting gate drops the frame), keys on the push state's `tailIdAtJoin`, and lets a frame for a topic this node serves no push state for through (the resolve step drops it as unserved). The recover transport's `resolveCohort` takes the tail bytes and returns a promise; `backfillTransport` and `resumeTransport` take the tail bytes instead of the topic id.
- **Mock harness.** `setupRootPlacedTopic` in `packages/db-p2p/src/testing/cohort-topic-mesh-harness.ts` instantiates a root-placed engine on every root-group member through the cold-sibling gossip path (the pattern `live-tier.spec.ts` case 12 uses) and waits for a willing quorum. The reactivity harness models a tail's storage group as the `wantK` members nearest its root coordinate (so `clusterSize` equals `wantK` there), binds that as every mock host's `rootGroup`, caches tail certs under the placement, verifies with a `quorumRatio` option (default 0.75), and builds commit certs with `rootPlacedMinSigs`. Its `minSigs` option now governs only non-root cohorts.
- **Docs.** `docs/reactivity.md`: the addressing block, § Subscription (`rootKey`), the origination implementation note, the wire comment, § Origination point (the two accepted paragraphs plus implementation, coordinator-only announcing, two-views-of-the-group, reversibility and cost), § Propagation, § Delivery, § Authentication and integrity, the mock-tier and real-libp2p coverage notes. `docs/internals.md` § Cohort-Topic Origination Bridge diagram and wiring bullet. `docs/cohort-topic.md` § Application policies. `docs/architecture.md` milestone sentences. `yarn lint:docs` passes.

## Known gaps and judgment calls for the reviewer

- **The wide-mesh case reproduces the threshold arm, not the disjoint-group arm.** With the cohort-topic defaults (`wantK` 16 on six machines) the old gate would have passed on every node; the old build failed because `minSigs` 14 exceeds a three-member group's signatures. A second run with `wantK` below the machine count would also exercise the disjoint announcing group. I did not add that variant, to keep the env-gated suite's wall time down.
- **The gossip gate reads the key network per inbound frame** (one serving-cohort assembly per collection per group member per gossip round). A `NOTE:` at the gate in `libp2p-node-base.ts` names the memoization if it ever shows in profiles. The host's own root-group snapshot cache is not exposed on `CohortTopicHost`, which is why the node binds the key network directly.
- **A cert cached under the default rule is invisible under the placement rule** (`heldUnder` in the membership verifier). Every hand-cached cert in the specs now passes the placement; a future spec that caches without it will see `untrusted` with no other symptom.
- **Groups of three or fewer still announce from the coordinator only** (the `NOTE:` at `captureCommitCert`), and a group of one never announces. Both are documented in § Origination point and unchanged by this ticket; the Quereus plugin's `clusterSize: 1` node watches but does not wake others.
- **Mixed versions break**, as the decision accepted: an old-build subscriber registers and verifies at `coord_0(topicId)`. Documented under reversibility.
- **"Tail cohort" wording** survives in parts of `docs/reactivity.md` outside the rewritten sections (replay, rotation, worked scenarios). The term now means the tail's storage group, which the rewritten sections define; a reviewer may prefer a sweep.
- **Distant subscribers trust the root's published membership on first use**, tracked by `feat-reactivity-root-membership-anchored-by-the-commit-log` (plan), out of scope here.
