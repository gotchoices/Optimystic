# Review: all `forComponent` call sites moved onto `createLogger`

Step 2 of 3. Step 1 (`logger-factory-error-and-formatters`) widened `createLogger` with an
`.error`/`.trace` sub-channel and a port of libp2p's `%p`/`%e`/`%b`/… format specifiers. This step
replaced every remaining use of libp2p's `components.logger.forComponent(name)` in
`packages/db-p2p`. Step 3 (`lock-and-document-db-p2p-log-namespaces`) still owes the lint rule,
the structural guard tests, and the `docs/debugging.md` namespace table — **those are not in this
diff and their absence is not a finding here.**

## What changed

`grep -rn forComponent packages/db-p2p/src` now returns exactly one hit: a comment.

| File | Was | Now |
|---|---|---|
| `src/cluster/service.ts` | `forComponent('db-p2p:cluster')` | `createLogger(init.logPrefix ?? 'cluster-service')` |
| `src/repo/service.ts` | `forComponent('db-p2p:repo-service')` | `createLogger(init.logPrefix ?? 'repo-service')` |
| `src/sync/service.ts` | `forComponent('db-p2p:sync-service')` | `createLogger('sync-service')` |
| `src/dispute/service.ts` | `forComponent('db-p2p:dispute')` | `createLogger('dispute-protocol')` |
| `src/network/network-manager-service.ts` | `forComponent('db-p2p:network-manager')` | `createLogger('network-manager')` |
| `src/cluster/block-transfer-service.ts` | optional `components.logger` + ternary | component field deleted; the file's own `log.error` |
| `src/libp2p-node-base.ts` ×3 | `(node as any).logger?.forComponent?.(…)?.(…)` | the file's existing `wiringLog` |

Renames were forced by collisions with namespaces that already belonged to a *different* class:
`cluster` is `ClusterCoordinator` (`src/repo/cluster-coordinator.ts`), `dispute` is `DisputeService`
(`src/dispute/dispute-service.ts`). Both keep their names, so `docs/debugging.md`'s existing
"Cluster consensus" recipe still means what it says. Verified no `createLogger` namespace in the
package is now claimed by two unrelated classes — the only repeats are the pre-existing, deliberate
`peer-address-book` (×3) and `cluster-member` (×2).

`src/repo/service.ts` also had a module-level `debugLog = createLogger('repo-service')` used on the
redirect path — the same class and the same concern as `this.log`, split across two factories inside
one file. Merged into `this.log`; the namespace string is unchanged, so the docs' existing
"Routing and redirect decisions" recipe now shows the whole picture instead of half of it.

## Interface changes reviewers should check

Five components interfaces lost their `logger` field, and `BlockTransferServiceComponents` lost its
optional one entirely. `Logger` is now imported from `../logger.js`, not `@libp2p/interface`. This is
a **breaking change for any external embedder** that registers these services directly with a
`logger` in the components object — TypeScript's excess-property check will flag it, but a JS
embedder gets silence. Nothing inside this repo does so (checked every construction site).

`logPrefix` on the cluster and repo services was reinterpreted: it used to accept a full libp2p
namespace (a second way for an embedder to escape the documented tree) and now names a
sub-namespace under `optimystic:db-p2p:`. Both doc comments say so. Nothing in the repo sets either.

## Behavior changes that are intentional but observable

- **`libp2p-node-base.ts`'s three wiring sites are now unconditional.** They were
  `(node as any).logger?.forComponent?.(…)?.(…)` — a chain that silently logged nothing when the node
  exposed no logger, on exactly the lines that explain a half-started node. Control flow is unchanged:
  `wiringLog` returns `void`, and the `.catch(err => { wiringLog(…); })` arm still swallows.
- **`BlockTransferService` denial lines moved channel.** They used to fall back to the main
  `log(...)`; they now always go to `log.error(...)`. So
  `DEBUG=optimystic:db-p2p:block-transfer-service` alone no longer shows them —
  `…:block-transfer-service:*` does. `captureLog` enables both, so specs are unaffected by
  construction.
- **The arachnode logger is a tagged wrapper, not its own namespace.** `libp2p-node-base.ts:1106`
  now builds `log` as a closure that prefixes `arachnode: ` onto `wiringLog`. Its ~8 call sites lost
  their `?.` since the function is always defined. Parked as a `NOTE:` tripwire at that site: if ring
  and rebalance logging ever gets voluminous enough to drown the wiring lines, it should be promoted
  to `createLogger('arachnode')`.

## Test changes — what to poke at

**`test/inbound-stream-authorization.spec.ts` was rewritten, not merely de-stubbed.** Its old
`makeLogger()` returned an `errors: string[]` that three assertions read through; that array is dead
once the services log through `debug`. The two logging cases now wrap `driven.drive(...)` in
`captureLog(svc.namespace, …)` and assert with `hasLine` (not `hasTag` — these lines carry
peer/protocol/reason as `%s` arguments `debug` leaves for downstream `util.format`, so the literal
template still reads `peer=%s`). `ServiceCase` gained a `namespace` field, and the throw case asserts
the denial text lands on `optimystic:db-p2p:<namespace>:error` specifically. **That namespace
assertion is the load-bearing one** — a sink-was-called assertion passes just as happily when a line
is stranded outside the documented tree, which is the whole regression this ticket closes. Worth
confirming it actually fails when a service is pointed at the wrong namespace.

**`test/cluster-error-propagation.spec.ts` gained a `%p`/`%e` case** (the ticket asked for one on at
least one of the three lines that use them). It drives `handleIncomingStream` with a throwing
cluster and asserts the captured line contains the peer id and the error text, and that no literal
`%p`/`%e` survives. The negative assertions alone would pass on an empty capture — the two positive
ones are what make it real.

Dead `logger:` stubs deleted from `cluster-service-redirect`, `redirect`,
`repo-service-remote-get-consult`, `cluster-error-propagation` (in `makeComponents`), and
`inbound-message-caps` (whose `makeLogger()` helper went with them, 9 call sites).

## Known gaps — please treat these as the starting point

- **`yarn test:integration` was NOT run.** It stands up real TCP meshes and exceeds the ~10-minute
  agent budget. The migrated namespaces are exercised by unit specs only; a reviewer or CI with time
  should confirm a real multi-node run still logs what an operator expects under
  `DEBUG=optimystic:db-p2p:*`.
- **No structural guard exists yet** that a *new* service cannot reintroduce `forComponent`, and no
  test pins the namespace table. That is step 3's scope by design, but until it lands the only thing
  holding these nine sites in place is this diff.
- **The `libp2p-node-base.ts` wiring lines have no test coverage at all**, before or after. They fire
  only on init failure paths (FRET unavailable, storage seed rejection). The change from
  "conditionally logged" to "always logged" is argued from reading, not from a run.
- **`docs/debugging.md` still lists no entry for `cluster-service`, `dispute-protocol`, or
  `block-transfer-service`'s `:error` child.** Step 3 owns the table; a reader consulting the docs
  today will not find the two renamed namespaces.
- The arachnode `log` wrapper interpolates its tag into the format string
  (`` wiringLog(`arachnode: ${msg}`, …) ``). Every current call site passes a string literal, so no
  stray `%` can reach the formatter — but nothing enforces that.
