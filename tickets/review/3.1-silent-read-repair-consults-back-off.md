# Silent read-repair consults back off — review handoff

Third of the three retries in Sereus `../sereus/tickets/blocked/optimystic-retries-do-not-back-off.md` (gotchoices/sereus#48). Sereus measured one block re-asked about every 8.2 s, 224 times in 180 s, every time finding the other member silent: a read-repair consult that a silent cohort peer leaves without arming the lazy window used to be re-sent by the next read as soon as the previous one ended.

## What landed

- **`SilentConsultHolds`** (`packages/db-p2p/src/repo/silent-consult-holds.ts`). Per block `{ consecutive, heldUntil, since, silent }`; per peer the last time it answered. `noteSilentConsult` places a hold of `min(capMs, baseMs × 2^(consecutive − 1))`, restarting at 1 when the prior hold was released. `holds` is false with no entry, once `now >= heldUntil`, or once any peer silent in that consult has answered at or after `since` (a released entry is deleted, so the count resets). `clear` forgets a hold. Base not above 0 disables everything (stores nothing). Both maps are `LruMap(1000)`.
- **Config.** `CoordinatorRepoConfig.retryBackoffBaseMs` (default 0). `createLibp2pNodeBase` fills it from `linkDeadlines.retryBackoffBaseMs` (the declared `linkRoundTripMs`, 0 when undeclared). Cap is the repo's `reconcilePassTimeoutMs`. Clock is the repo's `now` seam.
- **Fed by** `fetchBlockFromCluster`: `noteAnswered` for each peer in the consult's `answered` (asker stand-in included); a new return field `heldBySilence` set only at the `!corroborated` exit when silence is non-empty and the window was not armed (`cohort-too-small` returns before it). `noteConsultOutcome` (both consult paths for a held block) places or clears; a thrown consult does neither. `noteVotersAnswered` after `executeClusterTransaction` in `pendThroughCluster` and `commitThroughCluster`: every non-self peer with a promise or commit signature.
- **Read by** `shouldReadRepair`'s `'lazy'` arm, first (so the sample-rate arm is gated too). Missing blocks, floor-demanded consults, `'paranoid'` and `'off'` are untouched. A held read takes the existing not-stale branch, so `unconfirmedAheadRev` is stamped exactly as before. Missing-block tripwire `NOTE:` is on `shouldReadRepair`.
- **Log.** `cluster-fetch:consult-held { blockId, holdMs, consecutive, silent }`, once per hold.

## Deviations from the ticket's literal TODO (each deliberate — check you agree)

- **A missing block's consult neither places nor clears a hold** (`if (!isMissing)` in `readRepairBlock`). The hold gates only window-demanded consults of a held block, and a missing block consults on every read, so placing one there would log `consult-held` on every read for a hold that holds nothing, and grow `consecutive` so that a block which later arrives (a push, a commit) would start at a long hold. Its `answered` peers are still noted, so its consults still release other blocks' holds.
- **Holds are disabled outside `'lazy'`** (`baseMs` passed as 0). Only the `'lazy'` arm reads them; in `'paranoid'` every read consults, and placing holds there would log `consult-held` on every read for nothing.
- **`noteSilentConsult` returns the placed hold instead of logging**, and `CoordinatorRepo.noteConsultOutcome` logs it through the repo's peer-suffixed logger — the same split as `StuckReservationTracker`. One log site for both consult paths.

## Tests (one new spec, three tests)

`packages/db-p2p/test/coordinator-repo-silent-consult-backoff.spec.ts`, built like `coordinator-repo-held-block-background-consult.spec.ts` (silent peer = callback rejects; `awaitWindowConsults = true`; `now` seam):

- *a base of 0 re-asks on the next read, as before* — two reads, two consults, no `consult-held` line. Pins that undeclared nodes and direct constructors are unchanged.
- *holds for one base, doubling … up to the reconcile pass bound, and the held read keeps its doubt* — cohort of three (A claims rev 5, uncorroborated; B silent), base 1000, cap 5000 (default per-peer budget). Each round: a read at the hold's end consults; a read 1 ms before the next hold ends consults nobody and carries `unconfirmedAheadRev: 5`. `holdMs` sequence `[1000, 2000, 4000, 5000, 5000]`.
- *a silent peer answering a consult of another block releases the hold and restarts its doubling* — X held; the partner answers a consult of Y; the next read of X, still inside X's hold, consults; its new hold is one base, not two.

Verified the two hold tests fail with the gate in `shouldReadRepair` disabled (the zero-base test passes either way, by design).

By inspection only, not tested: release by a pend/commit vote (`noteVotersAnswered`); a clean consult clearing a hold; a corroborated consult with a silent third member staying unheld (`heldBySilence` unset on armed exits); last-writer-wins when a floored blocking consult and a background one for the same block both note outcomes; LRU eviction.

## Known gaps / things to look at

- **No non-zero base has run on a real mesh, and nothing has re-measured Sereus's link.** Every mesh and integration spec runs at base 0. The 22 → 7 consults-in-180 s figure is Sereus's estimate, quoted as such in the docs. Whether the traffic drops is unverified until Sereus measures again.
- **`yarn test:integration` was not run.**
- **Release window of `since`.** An answer counts only at or after the consult that placed the hold *ended*. A silent peer that answered a concurrent consult of another block a moment before this consult ended does not release it. Matches the ticket's rule; harmless in the measured shape, but it is a rule a reviewer could argue either way.
- **A vote is counted from the returned record only.** A pend/commit that throws (`ValidatorRejectionError`, `ConflictRaceLostError`, `BlocksHeldError`) carries signed votes too, and those members did answer, but they do not release holds. The ticket asked for the returned record; widening it means threading the error's record through.
- **Signatures merged into a record count as answers even if relayed.** A promise/commit signature verifies as the member's own, so the member was alive recently; it is not proof it answered *this* node directly. Accepted per the ticket's "a vote is an answer".
- **`coordinator-repo.ts` grew to 3761 lines** (`wc -l`, from 3684). Measurement appended to `tickets/backlog/debt-freshness-state-scattered-across-coordinator-repo.md`, not filed separately.
