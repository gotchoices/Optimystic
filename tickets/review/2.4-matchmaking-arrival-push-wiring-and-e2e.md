# Matchmaking arrival push — node wiring, end-to-end proof, docs (review)

Last of five tickets in the arrival-push chain. The prereqs built the selection, the cohort-side `ArrivalPushDriver`, the seeker loop and the seeker-side `ArrivalPushReceiver`; this ticket connects them in production nodes and proves the whole path.

## What was built

**libp2p delivery (`arrival-push-send.ts`).** `createArrivalPushSend({ node, receiver, protocol, maxBytes?, streamOpen?, log? })` returns the driver's `send(contactHint, frame)`. It reads the hint with `contactHintTarget`: a bare peer-id string, or a multiaddr whose **last** component is `/p2p/<id>`. Anything else (including a circuit address that stops at `/p2p-circuit`, which names only the relay) is logged and the push dropped. A hint naming this node is delivered in process via `receiver.receive(frame, selfPeerId)`. A multiaddr hint is merged with `mergePeerAddresses` before the dial (the one peerStore writer; libp2p's peerStore takes a per-peer write lock synchronously, so the dial's read waits for the merge). Then `requestResponse(...)` under the node's `linkDeadlines`; a rejection is logged and resolves `undefined`. Deviation from the ticket's sketch: no `selfPeerId` parameter — it is read from `node.peerId`, so the two cannot disagree.

**Node wiring (`libp2p-node-base.ts`, cohortTopic block, after the query handler).** One `ArrivalPushReceiver`, registered with `registerArrivalPushHandler` and attached as `node.matchmakingArrivalPush` (typed in `OptimysticNodeAttachments`, no cast). One `ArrivalPushDriver` (slot rule `createSlotAssigner(createRingHash())`, signing with the node key — now one `signWithNodeKey` closure shared with the query handler — and the send above), subscribed via `host.onRecordAdded`. Teardown is in the existing up-front stop wrapper, as undefined-guarded bindings (the established rollback pattern): unsubscribe, then `driver.stop()`, before the matchmaking protocols are unhandled. The fire-and-forget handler NOTE now counts five helpers.

**Receiver timer seam.** `ArrivalPushReceiverOptions.setTimer` (default the new shared `armUnrefTimer` in `unref-timer.ts`, which the driver now uses too in place of its private copy). Needed so a walk's push wait can run on the mesh harness's virtual time.

**Mesh harness.** Every member gets a real driver (subscribed to its real host) and receiver, both on one shared virtual time. The driver's `send` is in process: it resolves the hint with the production `contactHintTarget` and calls the target member's `receiver.receive`, recording each delivery in `pushSends`. `seek()` is unchanged (its own instant clock). New `startSeek(..., { pushOnArrival? })` runs a walk on the shared virtual time and returns `{ done, parked() }`; `advance(ms)` fires due virtual timers in order (driver coalescing, push waits, poll sleeps), giving each fired timer 10 ms of real time to settle. `MatchResult` gained `queries`. The harness `renew` stays a no-op.

## Tests added

- `mesh-push.spec.ts` "fresh arrival pushes to the waiting seeker …" — one provider present, a push-path and a poll-path seeker (`wantCount` 2) hanging out at the root; a second provider registers, gossip runs, one coalescing window passes. The push seeker returns it with `queries === 1`, exactly one push from one member, and the poll seeker is never pushed; after one requery interval the poll seeker finds it with `queries > 1`. (Doc bullet: fresh arrival pushes to longest waiters.)
- `mesh-push.spec.ts` "each selected seeker is pushed by exactly one cohort member — its slot primary" — three push seekers (`wantCount` 1), one provider with budget 3; `pushSends` equals exactly one `{from: slot primary, to: seeker}` per seeker. (Doc: §Fairness, who computes the set and who sends.)
- `arrival-push-send.spec.ts` — `contactHintTarget` on a bare peer id, a direct multiaddr, a circuit address with the seeker after `/p2p-circuit`, a circuit address naming only the relay, a multiaddr with no peer, and garbage. Pins the relay-mis-target rule, which nothing else exercises.
- `substrate-real-libp2p.integration.spec.ts` case 5d — a remote seeker builds the transport with its node's `matchmakingArrivalPush` and `selfServe.renew` bound to `resolveRenew(seeker.host.registry, r, Date.now())`; the walk is observed parked on pushes with one query; the seeker record is gossiped to every member; a provider registers at the routed primary; the walk returns it with `queries === 1` (no safety or final poll). Patience 30 s (past one 10 s TTL). The seeker is chosen so its slot primary is another node whenever one qualifies, so the push crosses a real socket.

Mutation checks run: making every member push fails both mesh tests; making the remote dial a no-op fails case 5d (the 5 s safety poll found the provider instead, `queries` 2). Both reverted.

## Known gaps — reviewer, please weigh

- **Applications cannot bind `selfServe.renew` without a cast.** A seeker whose slot primary is its own node (common in small meshes, where every node is in every cohort) needs `selfServe.renew` bound to the host's `resolveRenew`, or every renew/withdraw addressed to itself is skipped and the record lapses after one TTL. The test reaches the host through `(node as unknown as { cohortTopicHost }).cohortTopicHost`; a production application would have to do the same, because `cohortTopicHost` is not on `OptimysticNodeAttachments` and the node offers no ready-made `selfServe`. Same pre-existing gap for `selfServe.register` / `query` on a self-routed primary. Candidate fix: the node exposes a ready `MatchmakingSelfServe` beside `matchmakingArrivalPush`, or `createLibp2pMatchmakingSeekerSession` builds one from the node. Related backlog: `debt-node-attachment-reads-bypass-typed-surface`. Not done here (outside the ticket's file list and a public-surface decision).
- **Case 5d uses `createLibp2pMatchmakingTransport` + `SeekerWalkClient`, not `createLibp2pMatchmakingSeekerSession`** as the ticket wrote. The session hides its transport, so the test could not see the walk park on pushes or count its queries, which are the only evidence the provider came by push. The session is a thin wrapper whose deps extend the transport deps, so `arrivalPush` passes through by type.
- **Branches of `createArrivalPushSend` that run in no test:** the self-delivery branch (case 5d steers away from it; the mesh harness has its own in-process send), and the merge-before-dial branch for a multiaddr hint over real sockets (the libp2p seeker transport advertises a peer-id hint). Inspection only.
- **Real renew over real sockets is not asserted.** Case 5d finishes in ~0.3 s, so no renew is needed; patience is sized so a slow run would depend on it.
- **Case 5d falls back to in-process delivery** when every candidate seeker is its own slot primary (about 1.6% of runs at N = 4); it still passes then, but covers the receiver's self path rather than the dial.
- **Harness settle time.** `advance` gives each fired timer 10 ms of real time; the push specs additionally `waitFor` the push before awaiting the walk, so a slow machine waits rather than fails, but a walk continuation that needed more than 10 ms before arming its next virtual timer could be skipped past within one `advance` call. Not seen in any run.
- No new tripwire `NOTE:`s were added; the driver's existing ones stand.
