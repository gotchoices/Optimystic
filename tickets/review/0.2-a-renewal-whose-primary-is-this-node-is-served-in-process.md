# A renewal whose primary is this node is served in process

## What changed

- `FretTopicRouter.dialMember` (`packages/db-p2p/src/cohort-topic/topic-router.ts`) now checks, before dialing, whether `bytesToPeerId(member.id).toString()` equals `selfPeerId`; when it does and `handleLocally` was given, it returns `handleLocally(activity)` and opens no stream. A throw from the local handler propagates (renewal counts it as a failed ping). Without the two options the router dials as before.
- `createCohortTopicHost` (`packages/db-p2p/src/cohort-topic/host.ts`) now always passes `selfPeerId: selfPeerStr` and `handleLocally` (→ `handleRegisterFrame`) to the router; only `rootGroupMembers` stays conditional on root placement. Root-group dialing (`dialRootGroup`) is unchanged.
- Option docs for `selfPeerId` / `handleLocally` and the class/method comments updated (also dropped a stale doc line-number reference "L457-460").
- `docs/cohort-topic.md` §TTL and renewal: one sentence that a self-primary renewal is answered in process with no network request.

## Consequences to check (by inspection, untested)

- The walk's direct member dial (`dialMember` in `packages/db-core/src/cohort-topic/walk.ts`) now gets the same in-process route for a self-addressed `unwilling_member` retry / re-attach — intended.
- A self-primary registration's withdraw tombstone now reaches its own engine and evicts locally (gossiped), where it previously failed silently and waited out the TTL.
- A self-primary registration no longer migrates to `backups[0]` after three failed pings each cohort epoch.
- Reentrancy: `handleRegisterFrame` is declared later in `createCohortTopicHost` than the router; it is only called at dial time (the root-group branch already relied on this).

## Tests

- `topic-router.spec.ts` → "serves a dial addressed to this node in process, opening no stream": router with `selfPeerId` + recording `handleLocally`, `dialMember` to its own id returns the handler's bytes, the handler saw the activity verbatim, and `MockNode.dialProtocol` (overridden to count and reject) was never called.

## Validation

- `yarn build` (root), `yarn test` in `packages/db-p2p` (3557 passing, 74 pending), `yarn lint:docs`, eslint on the three touched files — all clean.
- Not run: `yarn test:integration`. No end-to-end two-node test reproduces the original self-dial failure (repro was static); a reviewer wanting confirmation could register from a node whose `assignSlots` names itself on a two-node in-process mesh and call `renew`.
