# The piece store interface, the memory store and the conformance suite — review handoff

A blob is kept on a node as immutable pieces of at most 1 MiB, each named by its `PieceId`. This ticket added the storage interface for those pieces and everything a backend needs to be tested against it. Nothing uses a piece store yet: the filesystem store is `feat-blob-file-piece-store`, the blob service that writes pieces is `feat-a-node-stores-blob-pieces`, and the node does not yet pass a piece store to `StorageMonitor`.

## What was built

- **`IPieceStore`** (`packages/db-p2p/src/blob/piece-store.ts`): `has`, `get`, `put`, `delete`, `list`, `bytesUsed`, `flush`, `durability`, optional `storeIdentity` and `close`. The contract from the plan is written verbatim into the doc comments (store never hashes; second put of a present id writes nothing; caller's buffers are never the store's; flush keeps rules 1, 2 and 4 of the `RawStoreDriver.flush` contract but not the prefix rule; `storeIdentity` equal to a block store's means the block store already measures the pieces).
- **`MemoryPieceStore`** (`packages/db-p2p/src/blob/memory-piece-store.ts`): a `Map`, copying with `slice()` on `put` and `get`; `list` snapshots the keys before the first yield; `durability: 'none'`; no `storeIdentity`, no `close`.
- **`PowerLossPieceStore`** (`packages/db-p2p/src/testing/power-loss-piece-store.ts`, exported from `@optimystic/db-p2p/testing`): writes go to an overlay (`null` = delete) served to every read; `flush` applies it to the shared `durable` map; `powerLoss()` makes every method throw `StoreLostPowerError` (reused from `power-loss-kv-store.ts`, whose doc comment now names both stores); `reopen()` throws unless `powerLoss()` ran. Never flushes on its own; no `close`.
- **`runPieceStoreConformance`**, **`conformancePieceId`**, `PieceStoreHarness`, `PieceStoreConformanceOptions` (`packages/db-p2p/src/testing/piece-store-conformance.ts`). Ids are built as CIDv1 raw sha2-256 through `pieceIdOfCid`; bytes compared element-wise (`sameBytes`) so a `Buffer` passes. Uses `RAW_CODEC` from `@optimystic/db-core` rather than importing `multiformats/codecs/raw` as the plan suggested — same value, one fewer import. `conformancePieceId` is exported so a backend's own tests (a torn file, say) can name pieces the same way.
- **Published entry**: `src/testing/conformance/index.ts` barrel re-exports both suites; `./testing/conformance` in `packages/db-p2p/package.json` now points at it. The `NOTE:` in `src/testing/index.ts` was replaced by one sentence saying the barrel is where a further dev-only helper goes. `test/testing-entry-runtime-deps.spec.ts` unchanged (already lists the subpath as dev-only).
- **Package entries**: both blob modules exported from `src/index.ts` and from `src/rn.ts` (the RN entry must re-export the same module set; `test/entry-parity.spec.ts` enforces it and passes).
- **`StorageMonitor`** (`packages/db-p2p/src/storage/storage-monitor.ts`): optional third constructor parameter `pieces?: IPieceStore`; exported `blockStoreCountsPieces(storage, pieces)` — false when the block store has no `getApproximateBytesUsed`, else true only when both identities are present and equal. Decided once in the constructor (both identities are fixed at construction by contract). `estimateUsedSpace` sums the block figure and the uncounted piece figure inside the one memoized, single-flight scan, so a rejected `bytesUsed` rejects the scan uncached, as a block scan error does. The `NOTE:` about two spellings of one directory being counted twice is at the function.
- **Docs**: `docs/blobs.md` status line and §The local store (names the three new symbols, the flush difference, and `blockStoreCountsPieces`); `docs/repository.md` §Capacity estimation and staleness (one sentence); `packages/db-p2p/docs/storage.md` §1 (pieces are the exception to "every write goes through `IRawStorage`").

## Deviation from the plan

- **One conformance case beyond the plan's list**: "two concurrent puts of one id both resolve, with the piece stored once" (`Promise.all` of two puts, then `get` equal and `list` yields the id once). The contract states it, and it is the case a filesystem store (temp-file rename race) or an IndexedDB store (`add` vs `put` constraint error) can plausibly fail. Cut it if the reviewer judges it not worth its run time across every backend.

## Tests added

- `packages/db-p2p/test/memory-piece-store.spec.ts`:
  - `runPieceStoreConformance('MemoryPieceStore', …)` — the 11 contract cases against memory.
  - `runPieceStoreConformance('PowerLossPieceStore', …, { persistent: true })` — the same cases plus flush-then-reopen; the harness's `reopen` calls `powerLoss()` then `reopen()`.
  - "loses a put no flush reached, and keeps one a flush did" — pins what the double exists for.
- `packages/db-p2p/test/storage-monitor.spec.ts`, describe "piece bytes":
  - sum when the piece store's identity is absent (`MemoryPieceStore`) or differs (`file:/elsewhere`);
  - block figure alone when identities are equal.

## Not run / known gaps

- `yarn check:rn` (Metro + Hermes bundle of the RN entry) was not run. `src/rn.ts` gained two plain re-exports of modules with no runtime imports beyond types, so a failure there is unlikely, but it is unverified.
- The other three storage packages (`db-p2p-storage-ns`, `-rn`, `-web`) import the conformance subpath too and were not re-run; only the fs one was.
- Inspection-only edge cases (no test, per the plan): a `StorageMonitor` built without a piece store behaves as before; a block store without `getApproximateBytesUsed` beside an equal-identity piece store still adds the piece bytes; a rejected `bytesUsed` rejects the scan uncached; every `PowerLossPieceStore` method throws after `powerLoss()` (the `list` throw happens at the first `next()`, since it is an async generator).
- `MemoryPieceStore.delete` and `PowerLossPieceStore.delete` of an absent id: the double records a `null` in its overlay, harmless (flush deletes nothing).
