# Client-only node: `NodeOptions.servesBlocks: false` — review handoff

Requested by Sereus (sereus#63). The design is the plan ticket's, unchanged; docs/internals.md §Client nodes is the reference (subsystem table, ignored options, type, the `isNetworkMember` relationship and mixed versions, the settled questions, cost, limits).

## What was built

- **The option.** `NodeOptions.servesBlocks` (default true). `createLibp2pNodeBase` reads it once as `servesBlocks`; on a client it logs one `node-wiring` line naming the serving-only options it was given (`logIgnoredServingOptions`, the one literal list).
- **Pre-start split.** The serving storage half — durability policy, raw storage and its lease, under-replication ledger, `StorageRepo`, the cluster/repo proxies, the block-holders sink — is one function, `prepareServingStore`, returning a `ServingStore` whose late-bound seams (`late.restore`, `late.cluster`, `late.coordinatedRepo`, `late.blockHolders`) replace the old `let`s. The four storage protocol service factories are `storageProtocolServices`, spread into the services map only when serving. `wired.repo.setLibp2p` runs only when serving (`WiredServices.repo` is now optional). Prepared streams: `repo` only on a client.
- **Post-start split.** The whole serving span (from `fetchArchiveFromPeer` through the owned-block seed and the dispute service) moved verbatim into `wireServingRole`, dedented one tab. A whitespace-insensitive diff of the moved span against the original shows only the intended substitutions: `clusterImpl` → `member` (no more `import(...)` casts), `coordinatedRepo =`/`restoreCallback =`/`blockHoldersTarget =` → `serving.late.*`, and the remote half of the cohort consult extracted to `remoteClusterLatest`. `assertClusterSizeCoupling` moved ahead of the span so a client runs it too. Every stop wrapper inside still sits right after its resource.
- **Client cohort-topic.** The commit-log trust anchor asks through `served.clusterLatestCallback` on a serving node and `clientClusterLatest` (remote only; a self ask answers "holds nothing") on a client. The cert store, origination manager and change bridge are built only when serving; the watch service gets `localChanges` only when serving. Everything else in the block runs on a client.
- **Types.** `OptimysticNodeAttachmentsBase` holds the shared handles; `OptimysticNodeAttachments` (`servesBlocks: true`, plus the repo/store/notifier/dispute/`reportBlockHeld`) and `OptimysticClientNodeAttachments` (`servesBlocks: false`) extend it; `OptimysticClientNode` added. `createLibp2pNode` in both entries has three overloads (`ClientNodeOptions` → client, `ServingNodeOptions` → serving, `NodeOptions` → union); the base returns the union. Exported through the existing `export *`.
- **CollectionFactory.** `FactoryNode` accepts a client; `libp2pNodes`' `coordinatedRepo` is optional; `getRepo` throws a named error if this node is ever picked without a coordinated repo; `localPeerId` is passed only when a coordinated repo exists (nothing is co-located on a client); `registerLibp2pNode`'s `coordinatedRepo` defaults to `node.coordinatedRepo`, so a host registers a client with two arguments. The plugin's own builder still builds a serving node. reference-peer compiles unchanged (its literal options select the serving overload).
- **NOTEs/docs.** `selfServes` doc (false branch now supported), `membershipOverfetch` NOTE (clients occupy over-fetch slots), `pushablePeers` NOTE (a member rebuilt as a client is never pushable, its entry never settles). docs/internals.md §Client nodes is new; §Reactive Watch Bridge points at it; docs/optimystic.md renames "Client-only" to "Dial-only" and adds the client bullet and example; docs/architecture.md gains a short §Machines that store nothing; both READMEs gain a short client paragraph.

## Known gaps and judgment calls for the reviewer

- **Pre-existing flake, filed.** `collection watch over real libp2p (a mesh wider than one storage group)` failed 2 of 10 full-file runs here and 1 of 8 with the original factory swapped back in — written up in `tickets/.pre-existing-error.md`. A serving node's cohort-topic wiring is unchanged by this ticket.
- **`responsibilityK` added to the ignored list** beyond the plan's list: it configures only the `repo` and `cluster` services' redirect checks, which a client does not register. Drop it if the reviewer disagrees.
- **Measured client write cost differs from the plan's "one request each".** A client's reads go out as one request per coordinator the read's blocks fall on (`createBatchesForPayload` resolves a coordinator per block; only the pend uses the covering grouping), so the refresh is two requests whenever the collection header and the log tail fall on different servers — seen in some runs on the two-server fixture. Steady write: 3 or 4 requests; first write on a fresh handle: one more (the leaf). Documented in §Client nodes; no code change. If client request counts matter, grouping a read's blocks onto one covering coordinator as the pend does is the lever (db-core `NetworkTransactor.get`); not filed — reviewer's call whether it is worth a ticket or a `NOTE:`.
- **Watch wakes before replication.** A client watch's registration reaches the announcing server one cohort gossip round (~5 s here) after it lands on another root-group member; a commit inside that window wakes the client only through the watch service's tick (up to 30 s). Same for any watcher outside the root group; documented in §Client nodes.
- **`wireServingRole` is ~800 lines.** Extracted as one unit per the plan; decomposing it is backlog `debt-node-factory-wiring-steps-own-their-teardown`. Storage is now acquired after the HLC clock starts (it used to be before); nothing between them holds a resource, so a failure there still leaves nothing to release.
- **The test transactor's request recorder** is a `Proxy` over `RepoClient` counting method calls; a `get` that `RepoClient` itself re-asks for left-out blocks would count once. Not an issue at these block sizes.
