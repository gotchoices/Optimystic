## What landed

- **`TransactionCoordinator.commitEntry(entry: EntryCommit, options?: SyncOptions): Promise<TransactionDurability | undefined>`** in `packages/db-core/src/transaction/coordinator.ts`. The per-entry slice commit: one `HeadCommitHandle` per collection the entry wrote, opened in sorted collection-id order and closed in reverse; an opening refresh round through the handles; per attempt `stage()` on every remaining participant, `entry.recordAttempt` with every participant's `InFlightAttempt` (awaited under every latch), `release()` every handle, the coordinator's own gather/pend/commit/cancel phases over the staged attempts, `retake()` every handle in sorted order inside a `finally`, then the outcome under the retaken latches — `fold` on every committed participant in one await-free pass then `replay` on each; `refused()` on every refused one, every one visited before the first recorded refusal is thrown. A partial landing on returned refusals records the committed participants as saved, closes their handles and throws `CoordinatorStaleLossError` so the shared retry loop re-drives the rest; a partial landing on a hard failure throws `CoordinatorPartialCommitError`. Once anything is saved, every later failure goes through `reportSaved`, as `commit`'s does. Requires `pendValidation: 'none'` (throws before touching anything otherwise). Answers `undefined` only when the opening refresh found every participant saved by the status read and nothing was sent.
- **`packages/db-core/src/transaction/entry-commit.ts`** (new): `WriteContext` and `writeContextOf(transaction)`; the public `EntryCommit` type (exported from the transaction index); `RefreshParticipant`; and `EntryParticipants`, the lock-step over the handles (open sorted with duplicate, empty and unregistered ids refused as defects before anything is opened and partial opens closed on a throw; `refreshers()`, `stage()`, `retainedAttempts()`, `release()`, `retake()` visiting every handle, `landed()` fold-all-then-replay-each-then-close, `refused()` visiting every handle, `close()` in reverse).
- **The phase refactor.** `applyActionsToCollection`, `coordinateTransaction`, `pendPhase`, `pendTogether`, `pendCollection` and `pendRequestFor` take a `WriteContext` (action id, timestamp, reads, clamped priority) in place of a `Transaction`; `commitOnceLatched` and `execute` derive one per attempt with `writeContextOf`. The phases from the gather on (`coordinateAttempts`, new; `pendPhase`, `commitPhase`, `commitTogether`, `commitEach`, `commitCollection`, `commitRequestFor`) take a per-collection `CollectionAttempt` (transforms, tail id, revision, base revisions, block digests) in place of three parallel maps plus a declared-digests map. `declareTouchedBlocks` now builds those attempts from the live trackers (digests and `stagedBaseRevs` read in the same step, where `pendRequestFor` used to re-read the bases at pend time under the same latch); `coordinateTransaction` is declare-then-`coordinateAttempts`, and `commitEntry` calls `coordinateAttempts` directly with attempts read off the `StagedAttempt`s, since `stageAttempt` has already described and size-checked them against the head tracker.
- **The retry loop shared.** `commitAttempts` now runs over an `AttemptDriver` (attempt, refresh round, nothing-left, opens-with-refresh) with its budget in a `RetryBudget` class; `refreshRounds` is the inner "back off, refresh, keep refreshing while finishing is refused" loop; `refreshBetweenAttempts` takes a list of `RefreshParticipant`s (`registeredRefreshers()` for `commit`, `EntryParticipants.refreshers()` for the slice). `reportSaved` takes an action id and no longer releases the stamp; `commit` releases it on every successful return and when `reportSaved` hands back a partial error. `cleanFailureError` is the one place a nothing-committed failure becomes its error.
- **Docs**: `docs/internals.md` §Staged actions are segments gained the slice's bullet; `docs/transactions.md` names `commitEntry` beside `commit` under the coordinator-centric principle and in the key-files list; `docs/offline-sync.md` §One entry, one network transaction names it. The backlog ticket `debt-multi-collection-retry-cannot-see-the-taken-revision` carries the slice as an arm, and `debt-collection-write-retry-logic-outgrew-its-file` the re-measured line counts.

## Deviations from the ticket, each deliberate

- **The slice does not call `declareTouchedBlocks`.** The ticket listed it among the phases to run. It reads the LIVE tracker, which under segments holds every sealed segment's effects plus the open segment's, so its digests would declare content the head attempt does not send and every checking member would reject the commit as `content-digest-mismatch`. The head commit's `stageAttempt` already describes and size-checks the attempt tracker, so the slice carries `StagedAttempt.blockDigests` and `.baseRevs` into the phases unchanged. A reviewer should confirm there is no third place the live tracker is read on the slice's path: I found none (`pendRequestFor` used to, and no longer does).
- **The committed set is recorded in `cycle.saved` BEFORE the local treatment on both partial branches** (`commitEntryOnce`), where `commitOnceLatched` records it only on the stale-loss branch and after its fold. A replay that throws inside `landed()` would otherwise escape bare over a durable commit. Harmless on the hard-failure branch: `reportSaved` merges the same entries it already carries.
- **The retry loop was generalised rather than copied.** The ticket asked for the refresh-round loop to be reused; the whole `commitAttempts` loop is, so `commit`'s behaviour depends on the same `RetryBudget` arithmetic as before. The one behavioural difference for `commit`: the stamp on the all-saved exit is released in `commit` after the loop returns rather than inside it — same tick, no await between.
- **A missing collection at the declare step is a thrown defect** rather than the per-collection pend failure it used to produce. It is unreachable: `commitOnceLatched` takes its participants from the registry and `execute` refuses an unregistered collection at `applyActionsToCollection`. The phase-level case `returns a failure (no throw) when a collection is missing from the map` in `coordinator.spec.ts` pinned that dead path and was removed; the sibling cases there still pin cancel-on-failure.

## Tests

`packages/db-core/test/coordinator-entry-commit.spec.ts`, five cases over two `Tree`s on one `TestTransactor` (`alpha`, `beta`, seeded through a handle of their own so the trees under test open over committed collections):

- **A refusal at one participant's pend leaves nothing durable.** `CompetingWriterTransactor` runs a rival on B's key after the opening refresh and before B's pend delegates (keyed on B's log tail among the pend's blocks, so it does not depend on fan-out order). Verifies: B's pend refused as stale, A's cancelled, no commit sent; the refresh adopts the rival and the replay refuses B's head; `stage()` throws the recorded `TreeKeyTakenError` on the next attempt; both segments still sealed; A's log holds nothing under the action; two pends in all.
- **Both participants commit as one action.** Verifies each log holds exactly one entry under the action id at revision 2 carrying the entry's timestamp (read through `Log.select` over a fresh handle on the unwrapped transactor); A's segment behind the head is re-staged over the committed state, A's open segment survives, B is clean; the collection ids were passed unsorted.
- **The latches are released during the round trip.** `GatedCommitTransactor` parks the first commit after it lands; `treeA.stage` resolves within 2 s while parked; after the gate the staged action is in A's open segment, not committed.
- **A partial landing on a hard failure, then a re-drive.** A local double throws on every commit of B's tail (nothing delegated); verifies `CoordinatorPartialCommitError` with A committed and B failed after three transient retries of B, A's head consumed, B's still sealed and first and unrefused; then `commitEntry` over `[B]` alone under the same action id on the same coordinator lands B, and each log holds the entry once.
- **A recorded attempt resumes a torn participant.** A local double tears A (tail only, the `TailLandsButReportsStale` shape, keyed on A's tail) and cleanly loses B in one attempt under `maxAttempts: 1`; verifies the first drive throws `CoordinatorStaleLossError` with both attempts recorded by the hook; the control re-drive without `resume` is refused `transforms-not-held` with nothing re-sent; the re-drive with `resume` finishes A on the opening refresh (its data block lands), commits B by one attempt recorded over B alone, and answers a durability with both holders known.

`packages/db-core/test/coordinator.spec.ts` had its phase-level helpers moved to the new signatures (`attemptsFor`, a `WriteContext` constant, `declaredFor` returning attempts); one dead-path case removed (above). No other test changed.

Not tested, by inspection: `reportSaved` after a refresh saved a participant (reused unchanged); a head refused while the round trip is in flight (the one-collection case in `collection-segments.spec.ts` pins the re-check order, and `refused()` here runs through the same handle); the sorted open order against a concurrent `commit` (asserted at the seam by `compareCollectionIds` in `entry-commit.ts`, spelled the same way as `commitOnce`'s and `execute`'s comparators, with a comment naming all three); the `pendValidation` guard (a one-line throw).

## Known gaps and tripwires for the reviewer

- **`stage()` on a resumed cycle rebuilds the attempt** (fix ticket `offline-sync-resumed-head-commit-rebuilds-the-attempt`, in `tickets/fix/`). The resume test here passes because B's attempt is byte-identical when rebuilt (no roll-over, no fresh node ids); the fix lands in `stage()`, which this driver calls, so nothing here changes when it does.
- **No `tailFloor` reaches the slice's refresh rounds** — the `NOTE:` on `refreshBetweenAttempts` names `debt-multi-collection-retry-cannot-see-the-taken-revision`, which now carries the slice as an arm.
- **`RetryBudget` is a second copy of the retry accounting**, beside `AttemptCycle` in `write-attempts.ts`. Deliberately not unified: the shapes differ (no stall check, no `staleAt`, the loss is a `CoordinatorStaleLossError`), and `debt-collection-write-retry-logic-outgrew-its-file` already tracks the unification; re-measured there.
- **`holdersUnknown`** turns an all-unknown answer into `undefined`, per the ticket's API ("`undefined` when the opening refresh found every participant already saved … and sent nothing"). `commit` answers the map with unknown classes in the same situation. The queue ticket wraps `commitHead`'s `undefined` with `transactionDurability`; if it would rather have the map for `commitEntry` too, drop the three-line helper and the one call.
- **`landed()` on the success path closes every handle itself**; the outer `finally`'s `close()` then does nothing. A reviewer may prefer the symmetry of closing only in the `finally`; the current shape keeps "the set is what is left to commit" true at every point.
- **`coordinator.ts` is now 2474 lines** (`wc -l`), 280 more than before; `entry-commit.ts` is 263. Recorded on the file-size debt ticket with what a split should move next.
- **Not re-tested**: db-p2p and the plugin's own suites. Nothing in either names the changed signatures (the phases are private; `EntryCommit` is new); the plugin typecheck against the rebuilt db-core `dist` is clean.
