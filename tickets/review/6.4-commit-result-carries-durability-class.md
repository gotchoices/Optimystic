# What was built

Every successful pend and commit result now carries a required `durability: WriteDurability` field. Its `quorum` is one of four classes, ordered `unrouted < local < majority < full`:

- `full` — every member of the resolved cohort confirmed it holds the write.
- `majority` — a strict majority confirmed (the existing acknowledgement bar), at least one member did not, and `unconfirmed` names who.
- `local` — the cohort resolved to this node alone. A correct, complete one-machine write.
- `unrouted` — the cohort never resolved: the lookup threw, named nobody, or named a single peer that is not this node. The write sits on this node's storage and the network was never consulted. This is the GitHub #19 case, which used to be indistinguishable from a healthy commit.

The scalar fields (`quorum`, `confirmed`, `cohort`, `unconfirmed`, `cohortPeerIds`) always describe the WEAKEST cohort an action ran on; `otherCohorts` carries the rest; `torn` names blocks a torn multi-block commit abandoned and cancelled. `isFullyDurable` is the one "completely saved" test, and it is false for a torn action even when the tail's cohort reported `full`.

**Policy is unchanged.** The durability gate (`isDurableMajority`) still uses exactly `confirmed > cohort / 2`; the solo short-circuit still accepts what it accepted; a refusal is still a `StaleFailure` with no durability field. The class is derived from the same sets the gate was measured on, so the two cannot disagree.

## Where each class is produced

- `StorageRepo.pend`/`commit` and the member-side verdict in `cluster-repo.ts` answer `localDurability()` — one machine speaking for its own storage. These never leak out as the coordinator's answer: every exit of `CoordinatorRepo.pend` and `commit` replaces them.
- `ClusterCoordinator.resolveCohort` is the new lookup primitive (`{ resolved: true, peerIds } | { resolved: false, reason }`), with `getClusterPeerIds`/`getClusterSize` derived from it. `resolveCohort` was added to `ICoordinatorClusterSeam`, which broke the five spec doubles at compile time as intended; all are updated.
- `CoordinatorRepo.commitSolo` / `pendSolo` classify via `soloCohortDurability`. The `commit:solo-cohort` log line now carries `quorum` (and `reason` when unresolved) from the same classification.
- Cluster path: `cohortWriteDurability` derives `full`/`majority` from `CohortDurability`, which now carries peer-id sets instead of counts. Self contributes per arm exactly as the gate counts it: local verdict success (local-executed arm), cohort membership (fallback arm), never (tolerated divergence).
- `pendCohortDurability`: `confirmed` counts approving promise votes on the record, adding self when its member applied successfully, removing self when its member applied and faulted, and leaving the vote alone when no verdict was retained.
- `NetworkTransactor.commit` merges the tail's answer with every confirmed sweep batch's answer, then `withTornBlocks` clamps `full` down to `majority` when the sweep abandoned anything, naming the blocks. `cancelAbandonedSweepBlocks` returns the abandoned set so `torn` is the same set that was cancelled, by construction.

# Use cases to validate

1. **GitHub #19 shape.** A node whose cohort lookup throws for every block: commit still succeeds (policy unchanged), `durability.quorum === 'unrouted'`, `cohort === 0`, `confirmed === 1`, `isFullyDurable` false. Spec: `coordinator-repo-write-durability.spec.ts`, which also asserts the complementary two-member `full` case and that the two classes differ.
2. **Genuine solo node.** Cohort resolves to exactly self: `local`, `cohortPeerIds: [self]`, `unconfirmed: []`; the one-machine proof is minted exactly as before (`coordinator-repo-solo-commit-proof.spec.ts` now also asserts `quorum` on the log line).
3. **Cohort of one that is not self.** `unrouted`, cohort 0. Reachable only when the responsibility check's own lookup failed and fell open; the spec wires the key network to throw for that reason.
4. **Four-member cohort, three confirm** → `majority`, 3 of 4, `unconfirmed` names the refuser. **All four** → `full` with `unconfirmed` present and empty.
5. **Tolerated local divergence** on a confirming remote majority → success, `majority`, self absent from the count and listed as unconfirmed.
6. **Absent local verdict** (restart / TTL) → not counted, so `majority` with self unconfirmed: reads lower than reality, never higher.
7. **Gate refusal** → `StaleFailure`, `conflict: true`, no `durability` property.
8. **Torn commit on a real mesh** (`torn-commit-cancels-abandoned-blocks.spec.ts`): the seed commit reads `full` with no `torn`; the torn one reads `torn: ['S']` and `isFullyDurable` false, while still acknowledged.
9. **Two coordinators** (`network-transactor.spec.ts` with `RoutedKeyNetwork`): tail `full` on a 2-cohort plus non-tail `local` merges to `local` with the full report in `otherCohorts`.
10. **Merge rule** (`durability.spec.ts`): weakest wins in every ordering, `torn` unions across inputs, nested merges flatten, empty input throws.

# Known gaps and decisions for the reviewer

- **A cohort of one without an identity.** With `localPeerId` undefined (direct constructors, test wiring) a resolved cohort of exactly one peer reads `local`, not `unrouted`, matching `isResponsibleForBlock`'s "no identity means responsible" posture. Production always has an identity. Documented at `soloCohortDurability`; reconsider if a direct-constructor deployment ever runs multi-node.
- **A pend's `full` can overstate on a remote bare fault.** The pend arm of `ClusterRecord.applyOutcomes` reports only conflict-shaped refusals, so a remote member that promised and then faulted at apply keeps its approve vote in the count. Conflict-shaped refusals still downgrade the whole pend to a retryable conflict, so no success is affected by them. The field's doc already says a pend's `confirmed` is not storage durability; this is one more reason. Not filed: the fix is to widen the member's report, which is the `under-replication-ledger-records-missing-holders` ticket's territory.
- **Torn clamp leaves `unconfirmed` empty.** `withTornBlocks` lowers `quorum` from `full` to `majority` but does not add anyone to `unconfirmed` (the cohort did confirm every block it was asked for). A consumer that reads `unconfirmed` to decide who to repair must also read `torn`; `isFullyDurable` covers both.
- **A zero-block pend now throws** at `NetworkTransactor.pend` (`mergeDurability` refuses an empty input). No caller produces one; a `NOTE:` at the site says what to do if one appears.
- **`otherCohorts` has unit coverage only.** As the ticket predicted, the in-process mesh collapses every pend onto one coordinator (`debt-no-mesh-fixture-forces-two-coordinator-batches`), so the multi-cohort merge is pinned by `durability.spec.ts` and the `RoutedKeyNetwork` transactor cases, not by a mesh.
- **`refuseCommitNotDurable` log fields changed shape**: `remoteHolders` and `remoteRefusals` are now peer-id arrays rather than counts. No spec asserted on the counts; `docs/debugging.md` does not list those fields.
- **`docs/correctness.md`** gained one sentence at the end of "Commit durability reporting" saying the rule is unchanged and now reported. `plan/6.5-docs-one-durability-bar-one-size-floor` was pointed at it so the authoritative statement keeps that sentence rather than restating the bar.
