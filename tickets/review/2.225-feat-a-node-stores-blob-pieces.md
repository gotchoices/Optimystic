# A node stores blob pieces — review handoff

## What was built

`createLibp2pNodeBase` now builds a `LocalBlobService` for every node and attaches it as `node.blobs`.

- **Options.** `NodeOptions.pieceStorage?: PieceStoreProvider` (`IPieceStore | (() => IPieceStore)`), resolved by `resolvePieceStore` right after `resolveKvStore`: the instance, the factory's result, or a `MemoryPieceStore` with the `node-wiring` warning the plan specified. `NodeOptions.blobs?: { digest?: BlobDigest }` is passed to the service as given (no `checkBlobDigest` call; the host's job, as documented on the option).
- **Both roles.** The service is built over the resolved piece store and the resolved key-value store, before the HLC clock, for serving and client nodes. `pieceStorage` and `blobs` are not in `logIgnoredServingOptions`, so a client uses them and does not log them as ignored.
- **Attachment.** `blobs: BlobService` (db-core's type) is on `OptimysticNodeAttachmentsBase`, so it is on both `OptimysticNode` and `OptimysticClientNode`. It is written through the typed `shared` literal, so a missing assignment is a compile error.
- **Lifecycle.** `blobs.start()` (arms the start-up sweep timer, unref'd) runs right after `Object.assign(node, attachments)`, and the stop wrapper (`try { await blobs.stop() } finally { await previousStop() }`) is installed immediately after it, so the startup rollback stops it. On `stop()` it runs after the cohort-topic wrappers (installed later) and before the serving role's wrappers and libp2p. A failure before `Object.assign` never started it, so there is nothing to stop.
- **Storage monitor.** `ServingRoleContext` carries `pieceStore`; the Arachnode `StorageMonitor` gets it as its third argument, so piece bytes count once (`blockStoreCountsPieces`).
- **Key-value store warnings and docs** now mention the blob records, which a client also persists now (the `resolveKvStore` client warning no longer says the HLC mark is "the one thing a client keeps").

## Things for the reviewer to look at

- **Every node now logs the `pieceStorage` warning** when no piece store is supplied, including every test node and the reference peer. That is the plan's choice (mirrors `kvStore`), but it adds a line to every node start-up log; the Quereus plugin's own node builder and `packages/reference-peer` were not changed to pass a piece store.
- **Every node now arms a start-up sweep timer** (5 s, unref'd). It is cancelled by `stop()`. A node that is never stopped keeps no process alive, but a sweep may run against a host's store after the host thinks it is done with it, as with any un-stopped node.
- **A factory `kvStore` leaks if the `pieceStorage` factory throws**: the key-value store is resolved first and nothing closes it on a construction failure. Same shape as the existing `storage` factory resolved after `kvStore`; not addressed here.
- **No host wiring yet.** The Quereus plugin, the reference peer and the other storage packages (ns, rn, web) do not pass a piece store; the other storage packages have no piece store yet (separate tickets per docs/blobs.md status line).
