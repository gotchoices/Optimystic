Part 4, the last, of stage 6 of [docs/offline-sync.md §Implementation stages](../../docs/offline-sync.md#implementation-stages). The node's gate (`KeyNetworkCohortReachability`, `node.cohortReachability`), the queue's solo refusal and the typed unanswered read came from the three prereqs; this ticket connects them to the Quereus plugin.

## What was built

**One stand-in gate per transactor key.** `CollectionFactory.getCohortReachability` now hands out a `LateBoundCohortReachability` (new file `late-bound-reachability.ts`) per `${transactor}:${keyNetwork}` key. `reachable` asks whatever gate is bound now (always-open until one is); `onChange` keeps its own listener set and, while it has listeners, is subscribed to the bound gate's `onChange`; `bind` moves that subscription. `registerCohortReachability(key, gate)` binds. The old two-map arrangement (`cohortReachabilities` + `cohortGates`) is gone.

**The factory registers the node's gate.** `createNetworkTransactor` calls `registerNodeCohortReachability`, which binds `node.cohortReachability` only when the node carries one and nothing is bound for the key yet — an explicit registration (test or host) wins whichever order the two happen in.

**The controller routes the wake.** `OfflineMode.setTablePolicy` subscribes once per distinct gate (`gateWakes` map, `subscribeToGate`). `onGateChange`: ignored after dispose; if `restorer.hasDeferred()`, `whenTransactionIdle().then(() => restorer.run())`, failures logged `offline:restore-pass-failed from=wake`; then `queue.wake()`. Not passed as `OfflineQueueOptions.wakeOn`. `dispose` releases the subscriptions first (`releaseGateWakes`, sets `wakesReleased`). `withdrawTablePolicy` leaves the subscription.

**`offline.allowSoloCommit`.** `parseOfflineConfig` accepts it (boolean only; anything else refused by name as `must be true or false`); `OfflineMode` passes it to `OfflineQueue`.

**One change beyond the ticket's design — please weigh it.** `OptimysticVirtualTable.doInitialize` now calls `publishOfflinePolicy()` at the *start* of every full (non-provisional) initialization instead of after `registerCollections()`. Reason: a table whose initialization fails because its cohort cannot be reached — exactly the table a journaled record is deferred on after a restart — never published its gate, so when it was the only table (or the only one on its transactor) the controller was subscribed to nothing and the wake could not retry the restore. Neither the policy (a tag) nor the gate (a factory object) needs a network read. A refused CREATE still withdraws (the `create` catch already calls `withdrawOfflinePolicy`). Verified by probe: with the old placement the new restore-on-wake case times out.

## Tests added

- `test/offline-mode-two-machine.spec.ts` (new), on the in-process two-node mesh with node A's **real** `KeyNetworkCohortReachability` over `mesh.nodes[0].keyNetwork`, events from an `EventTarget`, `wakeDebounceMs: 10`, registered under `shared:test` before tables exist. "B away" = `partitionSides` + `failingPeers` + a `wrapRepo` that throws for B and counts every pend/commit any transactor sends.
  - *queued, sent nowhere, read locally, drained on the wake*: the entry reaches `waitingFor: 'cohort'`, zero sends during the cut, A's live read serves both rows with `readsServedLocally`, then healing + dispatching `peer:identify` drains it within 10 s although `recheck` is 60 s (jitter floor 30 s); statuses collapse to `queued → submitting → committed`, one `submitting`; B reads the row. Probe: without the dispatch it times out.
  - *`expireAfterMs` while away*: `failed` with reason `expired`, `changedTables: ['main.Notes']`, never `submitting`, zero sends, row gone from A's view, B never got it.
- `test/offline-restore.spec.ts`: *a deferred record with nothing else queued is put back by the gate's wake*. The spec's stub `Gate` gained `onChange` and a hand-called `wake()`. The deferred table's initialization fails, the queue is empty, no read of the table happens — only the wake can retry. Probe: without `gate.wake()` it times out; also pins the early-publication change above.
- `test/offline-mode.spec.ts`: the registration-refusal case now checks an unknown key (`soloCommit`) and a non-boolean `allowSoloCommit` instead of refusing `allowSoloCommit` itself.

## Not tested, by inspection only

- Gate registered *after* a table took the stand-in: the subscription moves (`LateBoundCohortReachability.bind`). The two-machine spec registers before tables exist.
- Wake after `dispose`: ignored (`wakesReleased` checked first in `onGateChange`; subscriptions released at the top of `dispose`).
- Injected node without `cohortReachability`: nothing bound, always-open, no wake.
- `allowSoloCommit: true` reaching the queue: one line in the constructor; the refusal itself is pinned in `packages/db-p2p/test/offline-queue-mesh.spec.ts`.
- `createNetworkTransactor` registering the node's gate on a real `createLibp2pNode` node — no spec builds a real `network` transactor through the factory with offline mode; the mesh specs register explicitly.

## Known gaps / things to look at

- `onGateChange` starts one restore pass per wake while anything is deferred (passes requested while one runs join the pending one). Tripwire `NOTE:` left at the site.
- A wake landing during dispose can log one `restore-pass-failed from=wake` with `QueueDisposedError` if it got past the flag before `releaseGateWakes` — same noise `tableReadable` already has.
- `LateBoundCohortReachability` uses `addListener`, so the same listener function subscribed twice counts once (the controller subscribes each gate once, so not reachable today).
- `docs/offline-sync.md` §When to submit was rewritten to describe the gate as built (the `identifying` arm, `no-cohort`/`lookup-failed`, the restart and FRET-grace cases that read reachable and end in a shortfall wait, the 500 ms debounce, the controller route); §Registration, §Restore after a restart, stage 6 marked implemented "in four tickets", and §Test plan updated. `docs/internals.md` *The offline queue* paragraph and the README offline section updated ("Not yet in this stage" reachability bullet removed; a "When a queued transaction is sent" paragraph added).
