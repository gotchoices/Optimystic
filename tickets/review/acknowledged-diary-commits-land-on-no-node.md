# Acknowledged Diary commits land on no node — implemented

## What changed, in one paragraph

A commit's approve votes were never evidence of storage: every cohort member can sign a commit and then refuse it at apply (it never saw the pend, or it holds no base for the block and the fork guard drops the pending record), each member tolerates its own divergence so the stream is not reset, and `CoordinatorRepo.commit` used to count the votes and tell the writer the append had landed. Now every member retains **one post-reconcile durable verdict** per applied commit (does local storage record the commit's revision under its action, for every block, after the apply and any reconcile it triggered) and reports it on the record it answers with; the coordinator counts the successes plus its own member's verdict against the size of `record.peers` and acknowledges only a strict majority, otherwise answering the retryable refusal `commit-not-durable: …`. Separately, the coordinator now delivers the merged consensus record to its own member first and awaits it before fanning out to the remote members, so a behind member's reconcile finds the coordinator's proof-carrying copy and can adopt it as a single holder. Together: the bad geometry heals (four behind members restore from the coordinator), and any shape that cannot heal fails loudly instead of silently.

## The invariant (as implemented)

A commit is acknowledged to the writer only when more than half of the cohort the commit ran on (`Object.keys(record.peers).length`) reports durably holding the committed revision under this action, each member measured after its own reconcile. `clusterReachedCommitConsensus` (votes) and `commitQuorumRulesOutRivals` (freshness arming) are untouched and still keyed to the vote count; the two quorums are not conflated.

## Where each piece lives

**Member side (`ClusterMember`).** The commit branch of `applyConsensusOperation` is now: `applied = await applyCommitToStorage(record, commit, proof)` (storage's result; a thrown missing pend becomes `{ success: false, reason }` after the reconcile; missing-base refusals reconcile too; ahead refusals return as-is; genuine faults still throw so `handleConsensus` rolls back), then `executedCommitResults.set(messageHash, await durableCommitVerdict(commit, applied))`. `durableCommitVerdict` trusts a clean success without re-reading; for a refusal it checks every block with `holdsCommittedRevision` (the `IRevisionActionReader.getRevisionAction` capability when present — so an ahead member whose index names this action counts — else `latest`), returning `{ success: true }` if all hold or the original refusal otherwise, so the coordinating node can still classify its own member's ahead-shaped refusal against a rival. `withOwnApplyOutcome` stamps `{ pend?, commit? }`: the pend arm keeps its refusal-only rule, the commit arm is always stamped.

**Coordinator side (`ClusterCoordinator`).** `executeClusterTransaction` extracts `cohortCommitOutcomes` (self excluded, shape re-checked to `success === true` or an object with `success === false`) beside `cohortPendRefusals`. `broadcastMergedRecord` delivers local-first, awaited, then remote in parallel; the commit round in `commitTransaction` stays parallel (no member can reach consensus there).

**Gate (`CoordinatorRepo.commit`).** `cohortDurability(record, cohortCommitOutcomes)` gives `{ cohortSize, remoteHolders, remoteRefusals }`.
- *Local-executed arm:* the existing `confirmCommitRivalAgainstLocal` conversion runs first (a confirmed rival still returns the conflict). Then `localDurable = localCommitResult.success === true`, or `true` when the confirmation came back `'own-durable'`; an absent verdict is not counted. Refuse unless `remoteHolders + local > cohortSize / 2`.
- *Fallback arm (member did not execute):* `selfInCohort = localPeerId in record.peers`. Refuse **before** the local commit unless `remoteHolders + (selfInCohort ? 1 : 0)` is a majority — a failing gate skips the local commit so a refused commit never seeds a lone off-cohort holder. If the local commit succeeds, acknowledge (the gate already admitted this shape). If it diverges (thrown missing pend or `missing-base-revision`) and votes reached consensus, `tolerateLocalCommitDivergence` now acknowledges only if `remoteHolders` alone is a majority, else refuses. Any other `success:false` still returns as-is (a genuine stale loss).
- The refusal is `{ success: false, conflict: true, reason: 'commit-not-durable: N of M cohort member(s) report holding rev R of action A (<arm>)' }`, logged as `coordinator-repo:commit-not-durable` with the counts; `isCommitNotDurableFailure` matches the prefix. The read-repair window is not armed on refusal.
- The `<arm>` suffix is one of `local-executed`, `fallback-skipped`, `fallback-diverged: <detail>` — operator-facing only.

## Known gaps and judgement calls (please look at these)

- **The fallback arm counts a coordinator inside `record.peers`.** The ticket's rule was "evaluate before the fallback commit, skip when it fails". I implemented the slightly richer version: the pre-check counts self only when `localPeerId ∈ record.peers` (the member-did-not-execute-but-is-in-cohort case: a rolled-back apply, or the local delivery failed in the commit round), and after a local *divergence* only the remote holders count. When `localPeerId` is undefined (direct-constructor wiring without a local peer) self never counts. Pinned in `coordinator-repo-commit-divergence.spec.ts` ("a coordinator inside the cohort …", three cases).
- **A clean storage success is trusted without a re-read.** `durableCommitVerdict` returns `applied` as-is when `applied.success`; only refusals trigger the per-block revision-index check. This keeps the hot path at zero extra reads; the argument is that `StorageRepo.commit` answers success only when every block committed or was already committed under this action.
- **The verdict reads the revision index, not the materialization.** `holdsCommittedRevision` asks `getRevisionAction(blockId, rev) === actionId`. A Crash-D3-shaped block (revision saved, `setLatest` lost) would count as held; that is the same trust `confirmCommitRivalAgainstLocal` already places in the index.
- **Three unit specs' doubles were changed to report durability.** `coordinator-repo-commit-divergence`, `coordinator-repo-commit-conflict`, `coordinator-repo-commit-freshness`: their seam doubles never reported holders, so every consensus-path commit was refused after the gate landed. I gave them reports (freshness: every record peer durable by default; conflict: a 3-peer record with a `remoteHolders` knob, default 2; divergence: `durableReports(record, n)`), renamed the "keeps the fabricated success" cases to say what is now true, and added gate cases. The reviewer should check those defaults encode the intended semantics rather than just making the old assertions pass — in particular the conflict spec's "own-durable counts as a holder" case.
- **Pre-upgrade members.** A member that never stamps the commit arm is counted as not holding, so a mixed-version cohort would refuse commits its coordinator did not execute locally. Consistent with "don't worry about backwards compatibility yet"; noted for completeness.
- **The scheduled-retry residual is real and documented, not fixed.** A member reached only by `scheduleCommitRetry` applies after `executeClusterTransaction` resolved, so its report never counts; the gate refuses honestly and the writer re-drives with the same action id (`isOwnRevision` / `inFlightActionId` converge it). Stated in `docs/correctness.md`.
- **A coordinator outside the cohort still writes a local copy when the gate passes** (the routing spec's "direct write" arm prints `holdersOutsideCohort: 1`). By design: the ticket asked only that a *refused* commit not create one. The off-cohort residual belongs to the blocked routing ticket.
- **Not run:** `reference-peer` suite (its distributed-diary concurrent test is separately tracked as intermittent in the ledger), `yarn test:integration`, `yarn check`.
- **Tripwire parked as a `NOTE:`** in `StorageRepo.pend` pass 1: an update-only pend for a block this node holds no revision of is accepted and can never be promoted here without a reconcile; if pend-time refusals ever become worth their cost, refuse at `ClusterMember.validatePendOperations` instead.
- **Logs:** the fix stage's `tickets/.logs/acknowledged-diary-{full3,exp14,run8}.log` were deleted as the ticket asked; this run's suite log is `tickets/.logs/acknowledged-diary-commits-land-on-no-node.test.log`. No other artifacts were written outside `tickets/.logs/` and the session scratchpad.
