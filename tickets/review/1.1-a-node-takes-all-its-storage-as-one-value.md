# Review: a node takes all its storage as one value

## What landed

`NodeOptions.storage` is now one value — a `NodeStorage` with a `blocks`, a `kv` and a `pieces` — in place of the three independent options `storage`, `kvStore` and `pieceStorage`, each of which used to default to its own in-memory store. The three provider types (`RawStorageProvider`, `KVStoreProvider`, `PieceStoreProvider`) and the instance-or-factory shape are gone with them, as are their re-exports from both node entries.

### New module: `packages/db-p2p/src/storage/node-storage.ts`

- `NodeStorage` — `blocks: IRawStorage`, `kv: IKVStore`, `pieces: IPieceStore`. The read-cache ownership prose that used to live on `RawStorageProvider` moved onto `NodeStorage.blocks` verbatim (who leases, who releases, which two cache constructions are accepted).
- `OpenNodeStorage` — `NodeStorage` plus `close()`. What a platform factory will return; the host closes it after `stop()`, since the node closes nothing it was handed.
- `memoryNodeStorage(): OpenNodeStorage` — a **fresh** set of memory stores per call, `close` a no-op.
- Exported from `src/index.ts` and `src/rn.ts` as the last line of each (`entry-parity.spec.ts` compares the two).

### One warning instead of two

`resolveKvStore` and `resolvePieceStore` are gone, and with them their two `WARN:` lines. `resolveNodeStorage(options.storage, servesBlocks)` returns what the host supplied, or `memoryNodeStorage()` plus one role-aware `node-wiring` `WARN:` line naming every store it is keeping in memory and what is lost with each — serving: blocks, under-replication ledger, in-flight agreement state, HLC high-water mark, blob records and owed-blob ledger, blob pieces; client: everything but the first two. Both lines end with the way out (supply `NodeOptions.storage`, or `memoryNodeStorage()` to say it was meant).

**The test is the presence of the option, not the durability of the stores.** That is the behaviour change worth a reviewer's attention: `memoryNodeStorage()` now gets you zero warnings where three separate memory stores used to get you two.

`resolveStorage` keeps its one job — `withReadCache` in front of the block store — and now takes an `IRawStorage` rather than a provider. The memory default reaches it as a `MemoryRawStorage`, which `withReadCache` already returns unwrapped with no lease, so the old "deliberately not routed through the helper" special case was deleted rather than preserved: same outcome, one branch fewer. Worth confirming that reading.

`prepareServingStore` now takes the whole `NodeStorage` instead of a bare `kvStore`, and reads `storage.blocks` and `storage.kv` from it. `logStorageDurability` is untouched.

`storage` came **off** `logIgnoredServingOptions` (and off the `servesBlocks` doc comment, and off the "Options a client ignores" paragraph in `docs/internals.md`), because a client uses two of its three parts. The line's wording also changed from "builds no storage" to "stores no blocks" for the same reason.

## Use cases to test / validate

- **A serving node with no `storage`.** One `node-wiring` `WARN:` line, naming blocks + five key-value namespaces + transaction state + pieces. Previously two lines and a silence about the block store.
- **A client (`servesBlocks: false`) with no `storage`.** One `WARN:` line, naming only what a client keeps. It must NOT say it is ignoring `storage`.
- **A client WITH `storage`.** No "ignores: storage" line; its `kv` and `pieces` are used, its `blocks` never read. Pinned by `client-only-node.integration.spec.ts` (6 passing) plus inspection: `prepareServingStore` is the only reader of `blocks` and a client skips it.
- **`memoryNodeStorage()` passed explicitly.** No warning at all. `reference-peer --storage memory` now takes this path.
- **Two nodes in one process over memory.** Each `memoryNodeStorage()` call returns its own stores; nothing is shared by accident. The blob specs spawn 2–3 nodes each and pass.
- **A restart over one storage.** `real-libp2p.integration.spec.ts` "cold-restart over real transport with shared storage" and `plugin-first-launch-libp2p.integration.spec.ts` "cold-restart over shared storage preserves rows" now share one `memoryNodeStorage()` across both sessions, which also shares the key-value store where before only the block store carried over. Both pass; worth a reviewer's eye on whether the wider sharing weakens either assertion.
- **A hand-built mixed value** (file blocks beside a memory key-value store) still works and is now **silent**. `packages/upgrade-check` is exactly that for `fs`, by design (two directories per the fixture manifests), and its 341 tests pass.
- **One store identity per location.** `blockStoreCountsPieces` is untouched; a value whose stores sit over different locations still counts piece bytes separately, erring toward reporting the node fuller. Unchanged by this ticket.

## Call sites

Memory now returns `memoryNodeStorage()`.

- The four blob specs take `{ ...memoryNodeStorage(), pieces: theirStore }` (blob-copy's writer takes a full literal, since it names all three across a restart).
- **Four call sites the ticket did not list**, found by the compiler: `packages/db-p2p/test/real-libp2p.integration.spec.ts`, `packages/reference-peer/test/{distributed-diary,offline-storage,quick-test}`, and `packages/quereus-plugin-optimystic/test/{plugin-first-launch-libp2p.integration,distributed-transaction-validation}`. ## Tests

## Known gaps for the reviewer

- **`write-scenario.mjs` is unexecuted** (above). Both branches are read-only until `yarn write-fixture` runs.
- **The mixed-durability case is now silent.** Recorded as a `NOTE:` tripwire at `resolveNodeStorage`; a reviewer may judge that too quiet.
- **`memoryNodeStorage()` as the explicit opt-out is an unpinned contract.** The only thing distinguishing "meant memory" from "forgot the option" is `!== undefined`, which means a host that passes `{ ...someStorage }` built from memory parts gets no warning either. Deliberate; see the type's doc.
- `OpenNodeStorage` has no implementor in this repository yet beyond `memoryNodeStorage()` and the two hand-built ones (`reference-peer`, `upgrade-check`). The per-platform factories are `each-storage-package-opens-a-whole-nodes-storage`.
