# Committed rows register the blobs they reference — review handoff

Built in `packages/db-core`, no SQL, as the implement ticket designed it. Downstream users: `feat-blob-reference-trees-follow-sql-rows` (stages through `BlobReferenceTree` / `BlobScopeRegistry`, uses the `tree` accessor and `decodeBlobReferenceKey`), `feat-a-referenced-blob-is-copied-to-its-cohort`, `feat-unreferenced-blobs-are-reclaimed` (reads with `BlobScopeRegistry.enumerate` and `BlobReferenceTree.listed`, branching on `certain` and `exists`).

## What exists now

- **Key framing** (`reference-key.ts`): key = `ref + '\u0000' + referrer`. `blobReferenceKey` throws `BlobRefError` for a non-reference (via `isBlobRef`); `decodeBlobReferenceKey` splits at the first separator and validates the prefix; `blobReferenceBounds` / `blobReferenceRange` give `[ref\u0000, ref\u0001)` and do not validate.
- **Reference tree** (`reference-tree.ts`): `BlobReferenceEntry = [key, ref]`. `blobReferenceAction(changes)` — pure, validates every change before building any element (map over all keys first), add = unguarded upsert `[key, [key, ref]]`, remove = unguarded delete `[key, undefined]`. `BlobReferenceTree` wraps a `Tree<string, BlobReferenceEntry>` (public `tree`), `createOrOpen` (staging path), `stage` / `stageAdd` / `stageRemove` (one `Tree.stage`, never syncs, empty list stages nothing), static `listed(transactor, id, refs)`.
- **Scope registry** (`scope-registry.ts`): `BLOB_SCOPE_REGISTRY_ID = 'optimystic/blob-scope-registry'`, `BlobScopeEntry = [scope, scope]`, `blobScopeAction` (RangeError on empty scope; unguarded — the deliberate departure from the backlog's `absentOrEqual`, reasoned in the doc comment and docs), `BlobScopeRegistry` with `createOrOpen`, `stageRegister` / `stageUnregister`, static `register` / `unregister` (open + `Tree.replace`; the action is built, so validated, before opening), static `enumerate`.
- **Readers** (`committed-read.ts`): `readCommittedTree(transactor, id, pass)` opens a fresh read-only handle with `Tree.open` per call. Absent header → `{ exists: false, certain: true }`. `BlockUnavailableError` / `BlockPossiblyStaleError` from the open or the pass → logged `blob:read-uncertain`, `certain: false` (open failure leaves `exists: true`); any other error rethrows. After the pass, `tree.getCollection().belowFloorAnswerCount() > 0` → `certain: false`. `listed` dedups and sorts refs (default `.sort()`, UTF-16 code units) and merge-joins with one cursor (`find`, then `moveNext` on a miss — `BTree.findFirst`'s shape); empty refs returns without opening. `enumerate` walks `first()` / `moveNext`.
- **Below-floor count**: `BlockFloors.belowFloorAnswers` (private counter, incremented in `answeredBelowFloor`'s reporting branch, not reset by `clear`), `Collection.belowFloorAnswerCount()`.
- `pairEntryKey` (the `entry[0]` extractor) lives in `committed-read.ts` and is shared by both trees; it is not re-exported from the package. `readCommittedTree` and `CommittedTreeRead` are exported by name; the three other modules by `export *`.

## Tests (all in `packages/db-core/test/blob-reference-tree.spec.ts`)

- *frames keys so a longer reference never falls in a shorter one's range* — pins the separator framing with cast references `'bafkab'` / `'bafkabc'` and referrers `''`, `'a'`, `'\u0000'`.
- *stages, commits and reads back which references are listed* — absent tree reads empty and certain and stays absent; one `stage` with adds (R1,a), (R1,b), (R2,a), add+remove (R3,a), remove of never-added (R4,a); `listed([R4,R2,R1,R3,R1])` = {R1,R2}, certain; removing (R1,a) keeps R1 via b; removing (R1,b) unlists it.
- *commits both of two racing first registrations of one scope as one entry* — `enumerate` before: `{scopes: [], certain: true, exists: false}`; two handles opened before any commit (INVENTED) `stageRegister` + `tree.sync()` in `Promise.all`, both resolve, one entry; two sequential `unregister` both succeed, then `scopes: []`, `exists: true`.
- *answers uncertain, without throwing, when a tree node may be stale* — `DoubtingTransactor` stamps `unconfirmedAheadRev` on tree-node answers. Verified by log that the cause is `possibly-stale`.
- *answers uncertain when a tree node is answered older than the log says it is* — `LaggingTreeTransactor` (local copy of the `LaggingDataTransactor` shape) answers pinned tree-node reads as of the revision after the first commit. Verified by log that the cause is `below-floor` (one `collection:block-below-floor` line, floorRev 2, servedRev 1).

Not tested, with reason (as the plan said): concurrent reference adds (pinned by `two-handle-collection-fork.spec.ts`); `BlockUnavailableError` (same catch arm as the stale case); the `BlockFloors` counter on its own (exercised end to end); `decodeBlobReferenceKey` (a one-line split; the SQL ticket's oracle exercises it).

## Things a reviewer should look at

- `readCommittedTree` reads the below-floor count only when the pass completed; when the pass throws one of the two errors the answer is already uncertain, so the count is not consulted. Intended.
- The `listed` cursor is a `Path` held across descents on a handle nothing else touches; a version bump on it would only come from a refresh/replay, which never runs on this handle. If a later ticket ever passes a shared handle into these readers, the cursor would throw "Path is invalid" rather than answer wrongly.
- A remove staged into a reference tree that was never written brings the empty tree into existence when committed (the staging path uses `createOrOpen`). Harmless, per the plan; no code avoids it.
- `BlobScopeRegistry.register`/`unregister` open a fresh handle per call (two requests for the open plus the write). Fine for table create/drop, the only expected callers.
- Docs: §Registering references in docs/blobs.md now describes what exists (keys, staging and the three commit routes, no guards and why, readers and the certainty rule, the below-floor detection limit); the existing "Under transaction validation" paragraph is kept verbatim. One sentence there says the SQL plugin "is to use" the helper, since that is the next ticket.
