# Cohort gossip is verified once, off the synchronous path — review

GitHub [#49](https://github.com/gotchoices/Optimystic/issues/49). Third of three tickets from the plan `feat-idle-cohort-gossip-costs-a-phone-little`.

## What changed

**Port (db-core).** `ICohortGossipTransport.onMessage(handler(from, bytes))` is gone; `onGossip(coord, handler(g: CohortGossipV1))` subscribes to decoded frames naming one coord. `broadcast` is unchanged. `TransportCohortGossipBus` subscribes under its own coord, no longer decodes, keeps `isOurCoord` as a defensive guard, and its `verifyInbound` is documented as the bus's own gate (membership in db-p2p's binding); the signature is the transport's job.

**Transport (db-p2p).** `FretCohortGossipTransport` keeps subscribers in a `bytesKey(coord)` map. `deliver(g)` hands a decoded frame to that coord's subscribers only. `hasSubscriber(coord)` is a plain map lookup (touches no engine). `subscriberCount` is still the total over all coords.

**Host handler** (`handleGossipFrame` in `host.ts`), in order:
1. Decode once; a malformed frame is logged and dropped (it used to throw inside the bus and get logged by the frame handler).
2. Drop unless some bus subscribes to `g.coord`, or the frame could wake a cold sibling (live-signer mode and `treeTier === 0`). This replaces the pre-verify `registry.findByCoord` probe, so the old `NOTE:` about bumping LRU recency before the gate is retired.
3. Live-signer mode: `gossipSignatureVerifies(g)` — non-empty signature, both `fromMember` and `signature` b64url-decodable (logged on failure), then `await verifyPeerSigAsync(...)`. Key-less mode skips it.
4. If no subscriber now (looked up after the await), `maybeInstantiateColdSibling(g, coord)` — same membership / root-group checks as before, minus its own decode and signature check.
5. `gossipTransport.deliver(g)`.

**Gates.** `verifyGossipSig` is gone. `verifyGossip` is renamed `gossipFromMember` (on `CoordEngineContext` too) and is membership only; it is still defined only in live-signer mode. The participant bus and each engine bus keep their `rootPlaced` rule checks in front of it.

**Primitive.** `verifyPeerSigAsync(signer, payload, sig): Promise<boolean>` in `peer-sig.ts` uses `peerIdFromString(...).publicKey.verify`. It is total like `verifyPeerSig`. Its doc covers the platform behaviour (Node native; browser/RN WebCrypto when the module-load probe finds Ed25519, else noble), the polyfill-before-first-import requirement, and the strict RFC 8032 vs ZIP215 acceptance difference. `verifyPeerSig` stays for the synchronous ports. The module comment no longer says verification is synchronous.

**Threshold collection.** `FretCohortThresholdCrypto.collectFrom` now awaits `verifyPeerSigAsync`. The synchronous `verify` port (`verifyCollectedMultisig`) stays on noble. An RFC 8032-verified chunk is also ZIP215-valid, so what collection accepts, the later noble check accepts.

**Docs.** `docs/cohort-topic.md` §Cohort gossip "Per-coord routing" now describes decode-once, coord-only routing, the pre-verify drop, the one platform-verifier check, the bus membership gate, and why out-of-order verification is harmless. The §Cold-start instantiation implementation note says when the handler calls `maybeInstantiateColdSibling`. `docs/internals.md` §Cohort-Topic Port Boundary never mentioned `onMessage` and still reads correctly, so it is unchanged.

## Things a reviewer should look at

- **An engine evicted while its frame was verifying.** The ticket's edge-case list says the frame is simply dropped. Step 4 as written ("no subscriber → cold-sibling path") means a *tier-0* frame from a verified co-member instead re-creates the engine, which then merges the frame. That is what the old code did for any later frame (the cold path ran before every delivery), so it is not new behaviour, only a different frame doing it. A tier-d > 0 frame is dropped.
- **Malformed frames.** Before, a malformed frame threw inside the bus, so the frame handler aborted the stream and logged it. Now it is logged and dropped, and the stream closes normally. The sender is fire-and-forget either way.
- **`gossipFromMember` stays live-signer only.** In key-less mode no membership gate runs, as before. Without a verified signature, `fromMember` proves nothing.
- **The phone gain depends on a polyfill.** Without WebCrypto Ed25519 installed before `@libp2p/crypto` is first imported, `@libp2p/crypto`'s browser entry uses noble, so the per-verify cost on that phone is unchanged. The saving there is the single decode and the fewer frames from the prerequisite ticket. Nothing here checks the import order; that is the app's job (sereus#33). Nothing measured the on-device saving.
- **A handler that throws inside `deliver`** still stops later subscribers of the same coord from receiving that frame, as the old fan-out loop did. Unchanged; with coord routing that now affects at most the participant bus plus one engine bus.
