First of four tickets for stage 3 of [docs/offline-sync.md §Implementation stages](../../docs/offline-sync.md#implementation-stages). `Collection.commitHead` keeps its behaviour and is now `openHeadCommit` followed by `driveHeadCommit` over a `HeadCommitHandle`; the two hooks the queue and the journal need, `recordAttempt` and `resume`, are on `HeadCommitOptions`. The next ticket (`offline-sync-coordinator-entry-commit`) drives the handle for several collections at once.

## What landed

- **`packages/db-core/src/collection/head-commit.ts`** (new): the `HeadCommitHandle` interface (`refresh`, `nextRev`, `heldRev`, `stage`, `send`, `release`, `retake`, `fold`, `replay`, `refused`, `close`, plus `collectionId`, `instanceTag`, `entryId`) and `driveHeadCommit(handle, options)`, the one-collection loop with the `AttemptCycle` accounting unchanged. Its doc carries the step order a driver keeps and the sorted-open-order rule against a concurrent coordinator commit.
- **`Collection.openHeadCommit(entryId, identity, resume?)`**: asserts the resume's action id before taking the latch, takes the latch, runs the three `assertHeadCommittable` preconditions (releasing the latch on a throw), marks the action in flight, sets `headCommitEntry`, seeds the retained attempt from `resume`, and returns the handle. The handle is built by the private `Collection.headCommitHandle` as closures over private state; the head tracker lives in the closure so it is reused across one cycle's attempts exactly as before. `headCommitAttempts`, `sendUnlatched` and the `LatchHandle` type are gone; `committableHead`, `headSegment`, `headTrackerFor`, `buildHeadTracker`, `buildAttempt`, `send` and `foldOwnCommit` stay private and are reached through the handle. The quadratic-replay `NOTE:` now sits at the handle's `replay`; the `buildHeadTracker` `NOTE:` is unmoved.
- **`HeadCommitOptions.recordAttempt`** is awaited by the driver after `stage()` and before `release()`, under the latch; **`HeadCommitOptions.resume`** is the attempt a caller hands back.
- **`InFlightAttempt` gained `actionId`** (see *Deviations*). `retainInFlightAttempt(attempt)` now takes the attempt alone and gates on `attempt.actionId`; `retainedAttempt(staged, actionId)` sets it; the coordinator's hand-built attempt names `transaction.id`. `Collection.send` takes a `priority` number instead of the cycle.
- The new module is exported through the collection barrel. Docs: `docs/internals.md` §Staged actions are segments names the handle, the driver and both hooks and replaces the `sendUnlatched` citation; `docs/offline-sync.md` §Identity across attempts names `recordAttempt` and `resume`; the backlog debt ticket on `collection.ts`'s size carries the new line counts.

## Deviations from the ticket, each deliberate

- **`InFlightAttempt.actionId`.** The ticket listed the fields as `transforms`, `rev`, `tailId`, `blockDigests?`, `baseRevs?` and also asked that `openHeadCommit` assert a `resume` under another action id. The assertion is impossible without the id in the record, so the record now carries the action id it was sent under. It is still plain data (a string); I read the ticket's "nothing with identity" as object identity. If the reviewer reads it as "no action identity", the alternative is to drop the assertion and keep the type-level note only.
- **The handle is not generic and carries `instanceTag`.** Nothing in the interface is action-typed, so `HeadCommitHandle<TAction>` had an unused parameter; `instanceTag` is what `AttemptCycle` logs under and the handle is the driver's only view of the collection.
- **`driveHeadCommit(handle, options)`**, not `(handle, identity, options)`: the identity is the handle's (it went into `openHeadCommit`), and the action id the driver needs for `retainedAttempt` is `options.actionId`.
- **Order of the pre-attempt checks and the refusal re-check.** The in-line loop re-checked the head's recorded refusal before `AttemptCycle.beforeAttempt`; the driver runs `beforeAttempt` first and the re-check happens inside `stage()`. Only which error wins when a cycle is both aborted (or past its deadline) and refused changes; documented on `driveHeadCommit`.
- **Latch-state assertions.** Every handle step that touches instance state throws a defect when called with the latch released, after `close()`, or (`retake`) while already held, and `send` throws when called with the latch held. Beyond the ticket; cheap, and the next ticket's lock-step driver is exactly the kind of caller that gets this wrong.
- **`collection.ts` grew** from 2777 to 2838 lines rather than shrinking: the handle's twelve closures and the moved prose outweigh the thirty-line loop that left. Recorded on the debt ticket.

## Tests

All in `packages/db-core/test/collection-segments.spec.ts`, in a new `describe` block; every existing `commitHead` case passes unmodified.

- **A `recordAttempt` hook that throws aborts before anything is sent.** Verifies: the hook's own error escapes `commitHead` unchanged, the double counted zero pends, both segments stay sealed, the log is unchanged, the hook saw an attempt with the action id and the next revision, and the second `commitHead` (which would hang if the latch leaked) lands the head once with the hook called again.
- **A recorded attempt finishes a torn head on a later cycle.** Over `TailLandsButReportsStale` with `maxAttempts: 1`: the first cycle ends in `SyncRetryExhaustedError` with its tail landed; the control re-drive without `resume` throws `TornActionError` with reason `transforms-not-held`, builds no attempt and sends nothing; the re-drive with `resume` finishes the write on its opening refresh (one more pend, the re-send; one landed commit), answers a defined durability, consumes the head, leaves the segment behind it re-staged, and a fresh handle over the unwrapped transactor reads the row, so the data block landed and not only the tail.
- **A recorded attempt under another action id is refused before the latch is taken.** Verifies the assertion in `openHeadCommit` names both ids and leaves the segment and the latch untouched. Beyond the two tests the ticket named; one guard with real branching. Cut it if the reviewer judges it does not pay for itself.

The spec-local `CountsPends` double extends `TailLandsButReportsStale` with a pend counter, so one class serves both the tearing and the non-tearing cases.

## For the reviewer

- **`recordAttempt` receives the same transforms object the collection retains on a refusal**, uncopied (`retainedAttempt`'s contract). Nothing downstream mutates it (a fold clones inserts and applies updates to the cache's own blocks), but a hook that mutated its argument would corrupt the retry's re-send. If that is too sharp an edge for the queue and the journal, copy at the hook call.
- **`close()` with the latch released** clears `headCommitEntry`, `headInFlight` and the in-flight mark latch-free rather than retaking (the ticket's "release only if held"). A driver that throws between `release()` and `retake()` without retaking is a defect; `driveHeadCommit` retakes in a `finally`, and the next ticket's driver must too. The hazard if one does not: a reader's refresh mid-flight could treat the commit's entry as a stranger's and re-stage the head over it.
- **`nextRev` and `heldRev` do not assert latch state** (pure reads); every other step does.
- The `resume` revision check is the one `completeOwnEntry` already made (`attempt.rev !== rev` refuses as `transforms-not-held`); by inspection, no test.
- `review:` is not set: the handle shape is the seam the next three tickets build on, so a review pass is wanted.
