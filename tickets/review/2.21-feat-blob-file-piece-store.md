# The filesystem piece store — review handoff

`FilePieceStore` (`packages/db-p2p-storage-fs/src/file-piece-store.ts`, exported from the package index with `PIECE_DIRECTORY = 'optimystic-pieces'`) implements `IPieceStore` (`packages/db-p2p/src/blob/piece-store.ts`) on files: one file per piece at `<basePath>/optimystic-pieces/<xx>/<piece id>`, `<xx>` = `id.slice(-3, -1)`, holding exactly the piece's bytes. No write-ahead log, write group or lock.

## What was built

- **Id guard.** `pieceLocation` tests every id against `/^b[a-z2-7]{50,}$/` and throws `RangeError` before any path is built or any directory created (every method calls it before `open()`).
- **Open** (lazy, memoized, memo cleared on rejection): `mkdir` the piece root, mark dirty the piece root and every directory above it up to the parent of the first directory `mkdir` created (or up to the base path when it created nothing), `mkdir` `incoming/`, delete every file in it (`incoming:cleared count=N`).
- **put**: present → write nothing; else `mkdir` the fan directory (marking the root dirty when created), write `incoming/<16 hex>.tmp` with `'wx'`, `writeFile`, `sync`, close, `rename` into place. A rename failing with `EEXIST`/`EPERM`/`EACCES` while the final file exists is a lost race (`rename:raced`), any other failure rethrows; the temp is discarded best-effort either way (`temp:unlink-failed` logged, the next open clears it). The fan directory is marked dirty in every arm.
- **get**: `readFileIfExists`, returned as a plain `Uint8Array` view over the buffer the read allocated (not the `Buffer` itself).
- **has**: `fs.access`, `ENOENT` → false. **delete**: unlink, `ENOENT` ignored, fan directory marked dirty.
- **list**: readdir the root, keep directories matching `/^[a-z2-7]{2}$/` (excludes `incoming`), readdir each fully before yielding, yield files whose name passes the id test AND whose fan is the directory they sit in.
- **bytesUsed**: sum of `stat().size` over what `list` yields; `ENOENT` counts 0.
- **flush**: take and clear the dirty set, `fsyncDir` each, deepest first, one at a time. **close** = flush. `durability: 'power-loss'`; `storeIdentity()` = `fileStoreIdentity(basePath)`.
- `PIECE_DIRECTORY` added to `ROOT_NON_BLOCK_DIRS` in `file-batch-backend.ts`, with the same accepted-limit `NOTE:` `COMMIT_PROOFS_DIR` carries; `FileKVStore.keyToPath`'s `NOTE:` names `optimystic-pieces`.
- Logger namespace `optimystic:db-p2p-storage-fs:pieces:file`.

## Deviations from the plan (judge these)

- **Open marks the piece root and the base path dirty every time, not only when it created them.** The plan marked only directories `open` created. A piece written by an earlier process that crashed (not the machine) before flushing is still in the page cache, its directory entries not durable; a put in this process that finds it present resolves, the caller flushes and writes a record naming it, and a later power cut could lose the piece under the record. Marking the root and base path once per open costs two directory syncs on the first flush and closes that.
- **put marks the fan directory dirty even when the piece was already present, and delete marks it even on `ENOENT`.** A concurrent put (or delete) of the same id may have renamed (unlinked) without yet running the line that marks the directory; the second call resolving and its caller flushing must still cover the entry. Dedup'd in a `Set`, so the cost is at most one sync per fan directory per flush.
- **list also requires a file's fan to match its directory**, so a file misfiled by hand is never yielded where `has`/`get` could not find it.
- Temp cleanup failures are logged and swallowed (not rethrown over the original error); the next open removes any temp left behind.

## Tests added

`packages/db-p2p-storage-fs/test/file-piece-store.spec.ts`:
- `runPieceStoreConformance('FilePieceStore', …, { persistent: true })` — the whole `IPieceStore` contract, each case in a fresh `fs.mkdtemp` directory, `reopen` a new store over it (12 cases).
- "a leftover temp is never served and is removed on open" — a file planted in `incoming/` is not listed by a fresh store and is gone after its open.
- "refuses an id that is not a lowercase base32 CID" — `get('../x')` and `put` of an uppercased id reject with `RangeError`, and the base directory is still empty.

`yarn test` in `packages/db-p2p-storage-fs`: 131 passing, 1 pending (pre-existing). `yarn build`, `yarn lint:docs`, `yarn lint:deps`, and eslint on the package pass.

## Covered by inspection only (no test)

- Crash after rename, before flush: file bytes are synced before the rename, so the name holds the whole piece or nothing.
- The rename race arm (Windows refusing to replace an open target); the conformance concurrent-put case passes on Windows but does not force the refusal.
- `open()` failing and being retried; the first put into a base path that did not exist marking the created chain dirty; the deepest-first flush order.
- No new block-listing test: the skip is one more name in an existing set.

## Known gaps / tripwires parked

- `NOTE:` at `FilePieceStore.flush` — directory syncs run one at a time; if a flush after a large blob's put shows up slow on POSIX, sync the fan directories concurrently first.
- `NOTE:` at `FilePieceStore.bytesUsed` — one stat per piece; keep a running total if it ever shows up slow on millions of pieces (a node whose block store shares the base path never calls it, `blockStoreCountsPieces`).
- `NOTE:` at the class — two stores over one directory are unsupported (the second's open deletes the first's temps); no lock is taken.
- **README usage example**: `NodeOptions` has no `pieceStorage` option yet (planned by `feat-a-node-stores-blob-pieces`), so the README shows the store constructed and closed after `stop()` and says it is passed to the node once that option lands. Whoever lands that option should update the README example to pass `pieceStorage`.
- Directory syncs are no-ops on win32 (`fsyncDir`'s own `NOTE:`), so on Windows a flushed piece's directory entry rests on NTFS's own journaling, same footing as the write-ahead log's checkpoint.
