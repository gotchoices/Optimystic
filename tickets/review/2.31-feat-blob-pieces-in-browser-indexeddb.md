# Blob pieces in the browser's IndexedDB database — review handoff

## What was built

`IndexedDBPieceStore` (`packages/db-p2p-storage-web/src/indexeddb-piece-store.ts`, exported through `index.ts`'s `export *`) implements `IPieceStore` (`packages/db-p2p/src/blob/piece-store.ts`) over a new `pieces` object store in the database `openOptimysticWebDb` opens, sharing the handle with `IndexedDBRawStorage`, `IndexedDBKVStore` and the identity helper. It is not a `RawStoreDriver` store and does not go through the journal.

- **Schema (`db.ts`).** `OptimysticWebDB.pieces: { key: PieceId; value: Uint8Array }`, a schema-comment bullet, an `objectStoreNames.contains('pieces')` guard in `upgrade`, `DEFAULT_DB_VERSION` 4 → 5 with its comment updated (including that a version 5 database refuses an open at 4 with `VersionError`). The opener's doc comment now names the piece store among the handle's users.
- **`put`**: one `readwrite` transaction per piece, `durability: transactionDurability(strict)`; `getKey` then `put` inside it, so a present id writes nothing; `Promise.all([write(), tx.done])` so a failed request (quota included) rejects the call rather than escaping unobserved. The piece is passed through a private `wholeBufferBytes` (a view into a larger buffer is sliced, since structured clone stores the whole buffer).
- **`has`** reads the key only (`getKey`); **`get`** is `db.get`; **`delete`** is `db.delete` at the browser's default durability (a lost delete leaves an orphan the sweep removes).
- **`list`** pages `getAllKeys('pieces', range, PIECE_LIST_PAGE)` (1000), the next range `IDBKeyRange.lowerBound(last, true)`, stopping on a short page. No cursor is held across yields.
- **`bytesUsed`** walks one readonly cursor summing `value.byteLength`, awaiting `tx.done` beside the walk; a failure logs under `storage:pieces` and answers 0. A `NOTE:` there records that it reads every byte and runs only when the piece store sits on a different handle from the block store, with the remedy if it ever shows in a profile.
- **`flush`** resolves at once: each strict put is already on the disk. **`durability`** is `'power-loss'` with strict transactions, else `'process-crash'`. **No `close`**: the handle is shared.
- **`storeIdentity`** is `identityForHandle(IDB_HANDLE_SCHEME, db)`. The scheme string `'idb-handle'` was a literal inside `IndexedDBJournalStore`; it is now the exported constant `IDB_HANDLE_SCHEME` in `indexeddb-storage.ts`, used by both, mirroring `SQLITE_HANDLE_SCHEME` in the NativeScript package. So over one handle the piece store and the block store report one identity and `blockStoreCountsPieces` never calls the cursor walk.
- `APPLY_STORES` (the journal's apply transaction) is unchanged and does not include `pieces`; `listBlockIds` reads `metadata` keys only, so pieces never appear as blocks.

## Tests (`packages/db-p2p-storage-web/test/indexeddb-piece-store.spec.ts`)

- `runPieceStoreConformance('IndexedDB pieces', …, { persistent: true })` — the whole `IPieceStore` contract (missing id, round-trip, second put writes nothing, concurrent puts, empty piece, delete, list, drain-before-yield, `bytesUsed` rise and fall, caller's buffers, 256 KiB and 1 MiB pieces, flush-then-reopen). Harness: fresh database name per case through `openOptimysticWebDb`, `{ strictDurability: true }`, reopen closes and reopens the same name, cleanup closes.
- "a piece handed as a view into a larger buffer is stored at its own length" — a 1 KiB view into a 1 MiB buffer reads back with `byteLength` 1024 over a 1024-byte buffer, with the same bytes, and `bytesUsed` is 1024. It pins `wholeBufferBytes`: with the slice removed it fails (`expected 1048576 to equal 1024`, checked during implementation).

No paging test, as the plan allowed: the loop is `getAllKeys` + exclusive `lowerBound`, and the exactly-one-full-page case ends on the following empty page.

`yarn build` and `yarn test` in `packages/db-p2p-storage-web` pass (77 passing); `yarn lint:docs`, `yarn lint:deps` and eslint over the package pass.

## Known gaps, for the reviewer

- **The upgrade from versions 1–4 is untested here**, and an open blocked by another tab's older connection still waits silently. Both belong to `debt-indexeddb-version-upgrade-is-untested-and-unhandled` (in `tickets/plan/`), which already carries a "version 5 (blob pieces)" arm. The upgrade's safety rests on the `objectStoreNames.contains` guards, by inspection.
- **No real browser was run.** `fake-indexeddb` keeps the durability a transaction asks for and does nothing with it, so "a resolved strict put is on the disk" rests on the browser, as it does for the block store. A browser ignoring `durability` makes every put relaxed; `durability` then reports `'process-crash'` and `flush` still resolves at once — by inspection.
- **Quota**: a put past the origin's quota should reject with `QuotaExceededError` through the `Promise.all`; not exercised (fake-indexeddb has no quota).
- **Two puts of one id at once** rely on IndexedDB serialising two `readwrite` transactions over one store; covered by the conformance suite's concurrent-put case under fake-indexeddb, not in a browser.
- `IDB_HANDLE_SCHEME` is now part of the package's public surface through `export *`. Harmless, but a reviewer who would rather keep it internal can switch `index.ts` to named exports.
