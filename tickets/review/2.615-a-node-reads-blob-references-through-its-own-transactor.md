# A node reads blob references through its own transactor

First of three parts of `feat-blob-announcements-are-answered` (docs/blobs.md §Who may fetch and who may store). This part builds the reader; the announce receiver that uses it is the third part (`feat-blob-announcements-are-answered`, in `implement/`).

## What was built

**`createNodeNetworkTransactor`** (`packages/db-p2p/src/node-network-transactor.ts`) — the plugin's `NetworkTransactor` construction moved into db-p2p verbatim: the `getRepo` closure (self → coordinated repo, throwing the "stores no blocks … a client is in no cohort" error when there is none; others → `RepoClient.create(...)` wrapped by `stateHoldingsOnReads` when a store exists), the deadline derivation (`resolveLinkDeadlines()` when none given), `localPeerId: coordinatedRepo ? peerId : undefined`, the clock, and both `NOTE:` comments. Init types: `peerId: PeerId` (libp2p), `keyNetwork: IKeyNetwork & IPeerNetwork`, `coordinatedRepo?: IRepo`, `storageRepo?: StorageRepo`, `protocolPrefix`, `linkDeadlines?`, `localChangeNotifier?`, `clock?`. Exported from both `src/index.ts` and `src/rn.ts` (the entry-parity spec requires both).

**The plugin** (`CollectionFactory.createNetworkTransactor`) now keeps node creation, `registerNodeCohortReachability`, `resolveKeyNetwork` and the prefix, and calls `createNodeNetworkTransactor` with exactly the values it used before. Imports `PeerId`, `RepoClient`, `stateHoldingsOnReads`, `resolveLinkDeadlines` dropped.

**The node** (`createLibp2pNodeBase`), on both roles, after `served` and `nodeBlobs` and before `Object.assign(node, attachments)`: builds `committedReader` with `coordinatedRepo: served?.coordinatedRepo`, `storageRepo: served?.storageRepo`, the node's `linkDeadlines` and `hlcClock`, and no change notifier; then `const blobReferences = new BlobReferenceCheck({ transactor: committedReader })`, left unused with a comment naming `feat-blob-announcements-are-answered`. Not attached to the node.

**`BlobReferenceCheck`** (`packages/db-p2p/src/blob/reference-check.ts`), exported from both entries:

- `inScope(ref, scope)`: `BlobScopeRegistry.enumerate` first; a scope not in the listing → `not-listed` (certain or not), with no read of that scope's tree; then `BlobReferenceTree.listed(transactor, scope, [ref])`. The listing containing `ref` → `listed` (even when not certain); not containing it and certain → `not-listed`; not certain → `uncertain` / `tree-uncertain`. Carries the `NOTE:` about enumerating the whole registry.
- `anywhere(ref)`: registry, then each scope ascending until one lists `ref`. An uncertain tree (or an uncertain registry, reason `registry-uncertain`) is remembered; nothing found → the first remembered `uncertain`, else `not-listed`.
- Any throw from either read → `uncertain` with the error's message as `reason`, logged `reference:read-failed scope=%s ref=%s err=%s` on `createLogger('blob:protocol')`. For a registry read the `scope=` field is the registry's id (`optimystic/blob-scope-registry`).

## Judgement calls the reviewer should look at

- **`anywhere` keeps walking after a scope whose read threw.** The ticket says a throw is `uncertain` and an uncertain tree is remembered; it does not say whether a throw ends the walk. I treated a throw like any uncertain tree: remembered, walk continues, so a later scope can still answer `listed`.
- **No stop wrapper for `committedReader`.** `NetworkTransactor.stop()` only stops the owed-cancel re-sends, which arise only from pend/cancel; this transactor only reads. Comment at the construction says so. If the third part ever writes through it, add the wrapper.
- **`storageRepo` is typed `StorageRepo`** as the ticket named it; `stateHoldingsOnReads` needs only `IHeldRevisionReader`, so narrowing it would also be reasonable.
- **The unused `blobReferences` local** shows as a TypeScript "declared but never read" hint in editors (not an error: `noUnusedLocals` is off). The third part consumes it.
- The node now holds two `NetworkTransactor`s when the plugin also builds one over it. Both are thin (no connection state of their own); noted, not acted on.

## Tests

`packages/db-p2p/test/blob-reference-check.spec.ts`, over db-core's `TestTransactor` wrapped to record every requested block id and, when set, to throw `BlockPossiblyStaleError` on one header:

- a registered scope whose tree lists the ref → `inScope` and `anywhere` both answer `listed` with that scope;
- an unregistered scope whose tree *does* list the ref → `not-listed`, and no request named that tree's header block (its collection id, which every open reads first);
- the reference tree's header read throws `BlockPossiblyStaleError` → `uncertain` (absorbed by `readCommittedTree` as `tree-uncertain`).

The transactor move has no test of its own beyond the plugin's suites, as the ticket specified.
