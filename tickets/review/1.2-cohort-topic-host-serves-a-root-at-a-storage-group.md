# Cohort-topic host: serve a root at a storage group — review handoff

Second of three tickets for the decision in `docs/reactivity.md` § Origination point. The prereq gave db-core root placement (`RegisterV1.rootKey`, `ChildLinkV1.rootKey`, the `rootPlaced` flags, `RootPlacement`, the optional `ITopicRouter.routeToRoot`). This ticket makes the db-p2p host honor it. Nothing produces root-placed frames until the third ticket (`reactivity-notifications-need-the-tail-cohort-to-be-the-topic-cohort`) binds the host option to the key network, so a running node is unchanged by this landing; the host is exercised by its own specs.

## What landed

**The option.** `CohortTopicHostOptions.rootGroup?: RootGroupOptions` (`host.ts`): `membersAt(coord)` is the root group at a coordinate (async, reads the peerStore) and `quorumRatio` the ratio of `rootPlacedMinSigs`. Without it the host refuses every root-placed frame (`unwilling_cohort`, reason "root placement not served"), the router has no `routeToRoot`, and nothing else changes.

**Snapshots.** `RootGroupSnapshots` (same file): a per-coord `LruMap` of `{ members, memberStrs, cohortEpoch = H(sorted members), readAt }`, capped at `coordEnginesMax` like the engine registry. `ensure` returns a held snapshot younger than `gossipIntervalMs` or reads afresh (concurrent reads of one coord share one `membersAt`), `refresh` always reads, `drop` runs on engine eviction. A root-placed engine captures the snapshot at creation and re-reads it at the start of every `gossipRound` (so the harness's gossip pumps refresh too). `cohortEpochOf` is now the one epoch derivation for both the FRET assembly and the snapshots.

**Placement per coordinate.** `EnginePlacement { rootPlaced, rootKey? }` is fixed when an engine is created; `CoordRegistry.forCoord` takes it and `reconcilePlacement` refuses a later frame claiming the other rule for the coord (`CoordPlacementMismatchError`), refuses a tier-`d ≥ 1` frame naming a different root key, and lets an engine created without a key (a gossip-instantiated cold sibling, a deeper child's link) adopt the first key it is shown. `CoordEngine` exposes `rootPlaced`, `placement`, `rootKey`.

**Site by site**, as the ticket listed them:

- Register dispatch: `prepareRootPlacedCoord` refuses a coord already served under the default rule before reading the group, reads the snapshot, and throws `RootPlacementRefusedError("not-member", group)` when self is outside it → `unwilling_member` with `candidateMembers` = the group. The engine is created root-placed; a tier-1 register's `parentCoord` is `H(rootKey)`. `crossCheckCohort` is skipped for root-placed coords. The unbound-root-key tradeoff is a `NOTE:` at that site.
- Child-link dispatch: `DispatchChildLinkDeps.coord` and `resolveParent` take the root key (the latter may be async now); a tier-1 link's parent is resolved root-placed after the same admission check; refusals map to `rejected` reasons. `registerForwarderWithParent` stamps the key on a tier-1 link and delivers it through `routeToRoot`.
- Engine: `cohort()` reads the snapshot; signers use `createDynamicThresholdSigner` (threshold read at each signing: `rootPlacedMinSigs(|group|)` or `minSigs`); the rotation attestation is counted over the predecessor's members under the ratio; the publisher goes through the same signer; `/sign` requests carry `rootPlaced: true` (new `CohortThresholdCryptoDeps.rootPlaced`); `selfEligible` is "self is in the group"; the willingness quorum is a majority of the group size; `onCertPublished` passes the placement so the verifier caches the cert under the rule it was published under.
- `/sign` endorsement: `signEndorse` picks the view per request (the served engine's root view, or an on-demand snapshot for a coord with no engine), refuses a request claiming the other rule for a served coord, and only then calls the unchanged `handleSignRequest`.
- Gossip: frames carry `rootPlaced` (new `GossipFrameInputs.rootPlaced`); the engine's inbound gate refuses a frame claiming the other rule and checks membership against the engine's own view; `verifyGossip` now takes the member list rather than a coord. `maybeInstantiateColdSibling` is async: signature first, then (for a root-placed frame) the group read, the self-membership check, and a root-placed engine. The cohort resolver behind gossip and notice broadcasts answers the root group for a root-placed coord (an engine decides; else a held snapshot). A demotion whose parent is a root group reads that group before fanning out.
- Membership fetch: `FretMembershipSource.fetch(coord, { rootPlaced: true })` asks the peers from a new `rootGroupPeers` option (the host binds it to `snapshots.ensure`); without the option such a fetch finds nobody.
- Trust anchor: `FretTrustAnchor.directAnchor(cert, tier, placement)` judges a root-placed cert against `rootGroupAt(coord)` (the host's snapshot/engine view) at any tier — the placement rule is the key network's, so the committed-tier deferral does not apply; "unknown" when no snapshot is held, when the group omits self, or when the group is self alone (a cold table's answer for every key — `NOTE:` at `rootGroupView`). Slack takes the form of partial overlap → "unknown", since a complete group has no neighbours to widen into.
- Notice verification: `NoticeApplyTarget.placement` (an engine's) is passed to `verifyMessage`.
- Router: `FretTopicRouter.routeToRoot` exists only when `rootGroupMembers` is given; it dials each member's `/register` in order, returns the first reply (an `unwilling_member` included), serves a member that is this node in process (`handleLocally`, bound to the host's `/register` body — libp2p refuses a self-dial, and a `clusterSize: 1` root group is this node alone), and answers `unwilling_cohort` when nobody answers. It never calls `routeAndAct`.
- The `/register` protocol body is now `handleRegisterFrame`, shared by the inbound handler and the router's local path; the stream handler's catch now logs the cause (it swallowed it before).

**Docs.** `docs/cohort-topic.md` § Root placement at a routing key gained the db-p2p host paragraph (root group = `membersAt`, threshold from `quorumRatio`, the two refusals, the snapshot cadence, the rule-per-coordinate refusal, `routeToRoot`). `docs/internals.md` § Service composition names the exception in one sentence.

## Tests added

- `live-tier.spec.ts` test 12: a 5-node mesh with a fake root group of 3 (ratio 0.75 → threshold 3; the mesh `minSigs` is 4). Seeds the group through `rootPlaced` willingness frames (so cold-sibling instantiation creates the three root-placed engines), registers from a participant whose stale `membersAt` names an outsider first (the walk's root step gets `unwilling_member`, its member retry dials a real member, the handle carries the group and the root key; the outsider never gets an engine), reads the outsider's reply directly over `/register`, publishes the root cert (members = the group, 3 signers) and verifies it from another group member: `verified` under `createRootPlacement(0.75)` (fetched from the group over `/membership`, anchored on the held group), `untrusted` under the default rule.
- `live-tier.spec.ts` test 13: a root group of one — the engine signs its own cert with one signer, `cohortMembers` is the single member; and a host built without `rootGroup` refuses a root-placed register (`unwilling_cohort` in the route trace, the walk backs off).
- `fret-trust-anchor.spec.ts`: a root-placed cert judged against the group whatever the FRET cohort around the coord is (anchored at tier 0; disjoint → rejected; a signer outside the group → unknown; the same cert without the placement → unknown); and the four "cannot judge" cases (no snapshot, self outside the group, a group of self alone, no reader).

Harness: `MeshOptions.rootGroup` (per member, so one node's view can differ), `SignedRegisterOptions.rootKey`, `signedWillingness(..., rootPlaced)`.

## Known gaps for the reviewer

- **Paths with no test:** a tier-1 child linking to a root group (`routeToRoot` carrying a `ChildLinkV1`, the root-placed parent resolution in `dispatchChildLink`); every `CoordPlacementMismatchError` refusal (register, child link, `/sign`, gossip); the demotion fan-out to a root-group parent; the on-demand snapshot fill in `signEndorse` for a coord with no engine (test 12's endorsers all had engines); the router's `handleLocally` self path (test 13's participant is not the solo member). All were traced by hand.
- **The membership protocol serves one node-wide cert** (`FretMembershipPublishSink.latest`). A node serving both a root-placed coord and default coords publishes them into one slot, so a `/membership` fetch can get the other coord's cert. Pre-existing; the open `tickets/fix/membership-verifier-accepts-a-certificate-for-another-coordinate` covers the verifier side. Root placement makes the shape more likely, and the third ticket's deployments will hit it on any node that serves more than one cohort.
- **Willingness quorum fixed at engine creation** from the group size: exact for a `clusterSize`-wide group, permissive for a group still filling on a small network (comment at the `createWillingnessCheck` call).
- **A root-placed engine the group rotated past keeps serving its records until evicted** — the same as a default engine under FRET churn; it stops signing as a member and answers later registers `unwilling_member` (`NOTE:` in `createCoordEngine`).
- **The anchor's group-of-one guard** trades rejection away for a genuine solo group (`NOTE:` at `rootGroupView`).
- `RootGroupOptions.membersAt` is read on every `/sign` request for a coord with no engine, bounded to one read per `gossipIntervalMs` per coord by `ensure`'s age check, and the snapshot store is an `LruMap`; a flood of `rootPlaced` sign requests at distinct coords costs one peerStore read per coord per interval.
