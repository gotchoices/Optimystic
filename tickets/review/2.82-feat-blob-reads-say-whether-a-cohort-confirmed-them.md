# Review: block reads say whether a cohort confirmed them

Before this change a reader could not tell three things apart: an answer the whole cohort confirmed, an answer from a node that merely cannot see its cohort, and an answer from a node that really is the only machine. All three arrived as the same unflagged `GetBlockResult`, because the existing markers (`unavailable`, `unconfirmedAheadRev`) are doubts — absent means "no reason to doubt", which an answer nobody was asked about also satisfies. This adds the positive fact, plus the one question the reachability gate could not answer, so `feat-unreferenced-blobs-are-reclaimed` can require both.

Nothing branches on the new marker and nothing sets the new request field, so no existing behaviour changes.

## What changed

**Two wire fields** (`packages/db-core/src/network/struct.ts`). `GetBlockResult.cohortConfirmed?: true`, set by the answering coordinator when a cohort member other than itself vouched for the answer; and `BlockGets.awaitConsult?: true`, which asks the answering coordinator to run a window-demanded consult *in front of* the answer rather than behind it. Both optional and additive: `RepoService` hands a `get` to `CoordinatorRepo.get` verbatim and `narrowBlockGets` spreads the fields it does not narrow, so no protocol change and no version gate (the same argument `floors` is recorded under). `downstreamGets` forwards `awaitConsult` with one more conditional spread, exactly as it forwards `skipWindowConsult`.

**The freshness stamp records whether it vouches** (`packages/db-p2p/src/repo/coordinator-repo.ts`). `FreshnessStamp.vouched?: true`. `markBlocksSeen` now takes one `basis: { vouched: boolean; floor?: number; quiet?: QuietCohort }` object instead of two positional optionals, so every one of its nine call sites states what it means rather than inheriting a default. Who passes what: the cluster commit path's three `armFreshness` sites pass `true` (consensus ran, so another member signed — documented once where `armFreshness` is computed, not three times); `noteCohortCommitApplied` passes `applied.cohortSize > 1`; `commitSolo` and the solo-self read exit pass `false`; the three consult exits pass their own verdict.

**One shared predicate, `consultVouches`**, module-level beside the verdict unions: `answered.length > 0 && silent.length === 0 && currency.kind === 'nothing-ahead' && absence !== 'claimed'`. `fetchBlockFromCluster` now returns `vouched: boolean` as a required field (same reason `currency` is required — an exit added later has to choose). The three exits that ask nobody return `false`; the `!corroborated` block computes it once for the two returns that share its `(absence, currency)` pair; the local-current and convergence exits each compute their own. The convergence exit's `currency` declaration moved above its `markBlocksSeen` call, since the stamp now needs the verdict.

**`markCohortConfirmed`**, called last on each `readRepairBlock` path, after the entry has been replaced by the refreshed read and every doubt flag applied. It refuses an entry carrying `unavailable` or `unconfirmedAheadRev`. The paths and what they pass: inside the window, the stamp's `vouched` gated on `readRepairMode !== 'off'`; under a quiet span, the stamp's `vouched`; after a blocking consult, that consult's verdict. The `skipWindowConsult` opt-out, a consult started behind the read, and a consult that threw do not call it at all — so those answers read as unconfirmed.

**`awaitConsult` is two lines**: it is subtracted from the `background` decision, and it overrides the `skipWindowConsult` early return. The blocking path already consults, logs its trigger, refreshes the entry and records the stamp.

**`KeyNetworkCohortReachability.aloneFor`** (`packages/db-p2p/src/network/cohort-reachability.ts`), over a private `judgeAlone` that shares `whyNotAlone` with `judgeCohort`. True only when every distinct block's cohort is this node alone *and* the self-only view passes the same test `reachable` applies to one. A false answer logs `reachability:not-alone reason=%s block=%s` once per call for the first failing block, leaves `reachable`'s one-line-per-change record alone and wakes no listeners. Exposed as a new `CohortAloneness` interface intersected into `NodeCohortReachability`, so `node.cohortReachability.aloneFor` is reachable; deliberately **not** on db-core's `ICohortReachability`, which would force an answer out of `alwaysReachable` for a question only a node with a real key network can answer.

## What to test, validate and use

**`packages/db-p2p/test/coordinator-repo-cohort-confirmed.spec.ts`** (new, 4 cases) — one `makeRepo` factory over a cohort of three, a deterministic clock and the `awaitWindowConsults` seam, parameterized by what this node holds and what each non-self member does when consulted (`'holds-local-rev' | 'holds-nothing' | 'silent'`):

- *marks an answer the whole cohort stood behind, and the reads inside the window it armed* — a missing block whose two members both answer "I hold nothing" is an authoritative absent **and** marked; a held block whose two members answer at the local revision is marked by the consult, and a second read 1 s later, inside the window that consult armed, is marked from the stamp (and consults nobody — the callback count stays at 3).
- *leaves an answer unmarked when one cohort member was silent* — window expired, `awaitConsult: true`, one member answers at the local revision and the other's callback rejects. The local copy is still served, with no `unavailable`, no `unconfirmedAheadRev` and no marker.
- *never marks a self-only view* — the case the marker exists for. A missing block is answered absent **unflagged** and unmarked, with the callback never invoked; a held block read twice (solo-self exit, then inside the window it armed) is unmarked both times.
- *`awaitConsult` puts the window consult in front of the answer* — two repos, each with a gate the non-self members' answers wait on. Without the field the read resolves while the gate is still shut (that it resolves at all is the proof it did not wait) and is unmarked. With it, `await consultStarted` then asserting the read has not settled proves it waits, and after the gate opens the answer is marked. No sleeps and no microtask counting in either half.

**`packages/db-p2p/test/cohort-reachability.spec.ts`** gained one `describe('aloneFor')` of three assertions over the key-network double already there: a cohort of `[SELF, PARTNER]` is `reachable` true and `aloneFor` false *in the same test*, which is the whole reason the second method exists; a genuine self-only cohort is true; a self-only cohort naming an absent member is false.

**No test for the wire fields or `downstreamGets`' forwarding** — a type and one conditional spread, exercised end to end by the specs above on the coordinator side.

**Worth a reviewer's attention:**

- The inside-window path reads `lastSeenCommitMs` directly rather than the local `stamp` variable, because that variable is only populated for an expired window. Two reads of the same map in one method.
- Stated-out-loud consequences, both fail-safe and both parked as comments rather than tickets: on a `readRepairMode: 'off'` node no held block is ever confirmed (its stamp can be arbitrarily old, so the mode gate is load-bearing), and for a **held** block vouching needs a corroborated revision, because the no-quorum path reports any claim at all as `absence === 'claimed'` — so an *undeclared* two-machine deployment (`clusterSize` left at the default while only two machines exist) never confirms a held block. Reclaiming there keeps every blob, which is no worse than before the marker existed; the fix is declaring `clusterSize`, which makes the sole partner a quorum.
- `tolerateLocalCommitDivergence` stamps `vouched: true` while this node holds *nothing* of the commit. That is right — the stamp covers blocks a durable majority of other members holds, and consensus ran — but it is the one vouching stamp written by a node that diverged.
- `NetworkTransactor.get`'s merge breaks an equal-rank tie on served revision alone, so a confirmed entry can lose to an unconfirmed entry at a newer revision and the merged answer then carries no marker. Verified by inspection (`rankOf`/`beats` read neither field, and whole entries are selected). The safe direction, and deliberately not given a rank of its own: the marker must not change which content a read returns.
- `judgeAlone` swallows a throwing lookup into `'lookup-failed'` without its own log line, unlike `judge`, so `aloneFor` emits exactly one line per false answer.
