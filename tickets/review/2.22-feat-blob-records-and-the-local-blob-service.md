# Review: blob records, the piece sweep, and the local blob service

Built as library code in `packages/db-p2p/src/blob/`, all exported from both `index.ts` and `rn.ts` (the entry-parity spec keeps them in step). Nothing is wired into the node yet; that is `feat-a-node-stores-blob-pieces` (already in `implement/`, which depends on this).

## What exists

- **`blob-record.ts`** — `BlobRecord` / `BlobHold` shapes, `BLOB_RECORD_KEY_PREFIX` (`optimystic-blobs/`), `DEFAULT_BLOB_OWNER`, `blobRecordKey`, `encodeBlobRecord` (JSON), `decodeBlobRecord` (throws `BlobRecordFormatError`). The decoder returns the parsed object after validating, so every unknown property — on the record and on each hold — is kept as found.
- **`blob-record-store.ts`** — `BlobRecordStore` over `IKVStore`: `get`, `listRefs` (skips and logs `record:bad-key` for a non-reference suffix), `update` (per-ref promise chain, not `Latches`; delete on no holds; no write when the encoding is unchanged; no delete when there was no record), `flush`.
- **`sweep-gate.ts`** — `SweepGate`, writer-preferring shared/exclusive. After an exclusive holder releases, the shared holders queued during it run before the next exclusive one.
- **`piece-sweeper.ts`** — `InProgressPieces` (reference-counted) and `PieceSweeper` (`noteRecordChange`, single-flight `run`, plus `idle()` for the service's `stop`). Steps follow the ticket exactly: exclusive start creating `changed`; drain `pieces.list()`; walk every record; exclusive re-walk of `changed`, add `inProgress`, delete the rest one at a time.
- **`local-piece-source.ts`** — `localPieceSource(pieces)`, the `{ get, has, verified: true }` source the sweeper and service share; the accepted-tradeoff `NOTE:` about unhashed local reads lives here.
- **`local-blob-service.ts`** — `LocalBlobService` (`start`, `stop`, `sweep`, and the `BlobService` methods), `DEFAULT_SWEEP_DELAY_MS`, `LAST_READ_RESOLUTION_MS`, `LocalBlobServiceInit`. Every record change goes through the private `changeRecord`.
- `BLOB_RECORD_KEY_PREFIX` added to `NODE_KV_NAMESPACES`; the namespace list in the `FileKVStore` path comment updated to match.
- Docs: docs/blobs.md (status line, §The local store's records paragraph, §Holds with the sweep and its three guards, §The node's blob service "What is built" with what waits on which ticket, and an "Open: replacing a corrupt piece" paragraph); docs/debugging.md gains the `blob:store` row and the db-p2p count goes 58 → 59.

## Where this departs from the ticket, or adds to it

Each is a judgement call worth checking:

- **New module `local-piece-source.ts`.** The ticket put the verified source inside the service, but the sweeper needs the same source and importing it from the service would make a cycle. The `verified` `NOTE:` is at that source.
- **A record the decoder would refuse is never written.** `BlobRecordStore.update` decodes its own encoding before `kv.set` and rejects the update otherwise, because one unreadable record stops every sweep. Costs one `JSON.parse` of a small record per write.
- **A ref that is not canonical is refused at the store** (`parseBlobRef` inside the key builder, so `get` and `update` reject with `BlobRefError`). A record under a non-reference key is one `listRefs` skips, so no sweep would see its holds.
- **The decoder also validates `lastReadAt`** (finite number when present). It does **not** reject duplicate holds (two pins by one owner): that would stop every sweep over a harmless duplicate; only the service's change functions keep the at-most-one rule.
- **One extra log tag, `record:correct-failed`.** A failed `whole` correction is logged and swallowed in both `stat` and `read`, so the read's own `BlobUnavailableError` (and a correct `stat` answer) is not replaced by a key-value fault. Documented in the debugging row.
- **`sweep:aborted` carries `error=`** with what made the record or tree unreadable, so the abort line is self-explaining; there is no separate per-cause line.
- **`unpin` with an empty owner is a no-op**, not a `RangeError` (the ticket specified the `RangeError` only for `put` and `pin`).
- **`read` checks the signal before starting** as well as between chunks.

## Tests (`packages/db-p2p/test/local-blob-service.spec.ts`, all from the ticket)

- *a put is stored, read whole and by range, and held under `default` until unpinned* — 600 KiB put; `stat` here with size; whole read and a range across a piece boundary; one `default` pin; unpin + sweep deletes all 4 pieces and `stat` goes `unknown`.
- *the empty blob* — size 0, `here`, zero bytes read, one stored piece.
- *a sweep while a put is in progress keeps its pieces* — two pieces stored, no record yet; sweep keeps both (`kept: 2`, `deleted: 0`), protected by `inProgress` alone.
- *a put that completes after the sweep read the records keeps its pieces* — a `HeldListKVStore` double holds `list` until the put has written its record and released `inProgress`; only the re-walk of `changed` keeps the pieces.
- *an aborted put leaves pieces the next sweep removes*.
- *two puts of the same content keep one set of pieces and both pins*.
- *a piece shared by two blobs survives unpinning one* — the shared piece stays, A's own piece and list piece go.
- *a missing piece fails a local read and corrects the record* — `not-here` with `from: 'here'`, `cohort-unreachable` without; `stat` `partial` with `heldBytes` one piece short; record `whole: false`.
- *records and pins survive a restart; pieces are checked, not assumed* — over `PowerLossPieceStore` / `PowerLossKVStore`; a memory piece store reports `unknown` and corrects the record; the reopened piece store reports `here`, corrects back, reads whole, and `unpin` deletes the record.
- *a malformed record stops the sweep* — `aborted` / `record-unreadable` / the ref, and the orphan stays.

Mutation check done during implementation: removing the step-4 re-walk of `changed` fails exactly one test, and removing the `inProgress` merge fails exactly one test, so the two race tests each pin their mechanism.

## Not tested (by inspection only)

- The timer path: tests inject a no-op `setTimer`, so `start()`'s start-up sweep, the schedule after a record deletion or a failed put, "a timer firing during a run sweeps again after it" (`runScheduledSweep` waits for `idle()` then runs), `stop()` waiting on a fired timer's run, and `sweep:failed` logging are unexercised. A reviewer might want one test that drives an injected timer.
- `SweepGate` alone, the `BlobRecordStore` no-write/no-delete rules, a throwing `change` callback leaving the chain usable, `listRefs` skipping a bad key, and each decoder rejection (the ticket declined these tests).
- `announce` rejecting and the listener stubs.
