# Every store reports its bytes and its free space

## What landed

Three things, all groundwork for the next ticket (`a-node-measures-its-use-against-one-allotment`), which is where the figures get a consumer.

### 1. A free-space capability, optional by presence

`approximateBytesFree?(): Promise<number>` on `RawStoreDriver` and `BatchBackend`, surfacing as `getApproximateBytesFree?(): Promise<number>` on `IRawStorage`. The contract, stated on both interfaces: it answers the bytes the store's **location** will still accept (not this store's share of it, so two stores over one location answer the same figure); it is advisory and may be stale, like `getApproximateBytesUsed`; **a failed read rejects and never answers 0**, because 0 means "full" and a transient failure read as full would make a node shed responsibility it did not need to shed; and presence is fixed for the store's life, so a backend that cannot ask its platform omits the method entirely rather than installing a stub.

The whole passthrough chain was wired, each conditional on the thing below having one: `KvRawStorage` (constructor, beside `getApproximateBytesUsed`), `WriteGroupDriver`, `JournalBatchBackend`, `CachedStoreDriver`, `RawStorageDriverAdapter` (and so `CachedRawStorage`, and so `withReadCache`'s result), and the test-only `TextReadsJournalStore`.

Which backends have one:

| Backend | Free space | How |
|---|---|---|
| `db-p2p-storage-fs` | yes | `fs.promises.statfs(basePath)`, `bavail * bsize`, in `FileBatchBackend` beside `approximateBytesUsed`. Opens first, so `statfs` never names a directory the store has not created. `FileRawStorage` re-declares it as always-present, as it does the other three fs optionals. |
| `db-p2p-storage-web` | yes, in a browser | `navigator.storage.estimate()`, `max(0, quota - usage)`, in `IndexedDBJournalStore`. Wired as an optional instance field in the constructor, so the method is **absent** where there is no `navigator.storage.estimate`; rejects when the estimate carries no `quota`. |
| `db-p2p-storage-ns` | no | handed an open `SqliteDb`, not a path; no free-space call reachable from a handle. `NOTE:` at the site, plus the README. |
| `db-p2p-storage-rn` | no | handed a `LevelDBLike` handle, same gap. `NOTE:` at the site, plus the README. |
| `MemoryStoreDriver` | no | no disk; a `Map`'s free space is the heap, which is not an allotment. `NOTE:` at the site. |

### 2. `IKVStore.storeIdentity?()`

Same one-directional contract wording `IPieceStore.storeIdentity` carries. Implemented by `FileKVStore` (`fileStoreIdentity(basePath)`), `SqliteKVStore`, `IndexedDBKVStore` and `LevelDBKVStore` (`identityForHandle` under each package's existing scheme constant). `MemoryKVStore` reports none, and its class doc now says why.

No `bytesUsed` was added, deliberately; the reason and the condition that would change it are a `NOTE:` beside `storeIdentity` in the interface.

### 3. One coverage assertion for all three of a node's stores

New module `packages/db-p2p/src/storage/store-coverage.ts`:

- `blockStoreCountsPieces(storage, pieces)` — moved from `storage-monitor.ts` unchanged, `NOTE:` included. `storage-monitor.ts` now imports it (the next ticket replaces that module, which is why the predicate moved out now).
- `assertOneMeasuredLocation(storage: NodeStorage, location: string)` — replaces `assertBlockStoreCountsPieces`. Throws unless the block store has a `getApproximateBytesUsed`, reports a `getStoreIdentity()`, and **both** `kv.storeIdentity?.()` and `pieces.storeIdentity?.()` equal it. The message names the location and which part disagreed.

The four `*NodeStorage` factories call it in place of the old helper, passing their location unchanged (`basePath`, `'this SQLite handle'` and friends). `memoryNodeStorage()` still asserts nothing. Both are exported from `packages/db-p2p/src/index.ts` and `rn.ts`; `assertBlockStoreCountsPieces` is gone.

### Docs

`packages/db-p2p/docs/storage.md` §7 gained a "How much room is left" paragraph with the backend table; §8's factory paragraph now says the assertion covers all three stores and names what each half would otherwise cost silently (pieces counted twice; key-value bytes counted not at all). The four package READMEs say whether their package reports free space, and for `ns`/`rn` why it cannot. `docs/blobs.md` and `docs/repository.md` had their `blockStoreCountsPieces` citations repointed to the new module.

## Use cases to check

- **A node on a Node host can learn its disk's free space.** `new FileRawStorage(dir).getApproximateBytesFree()` answers a positive number on win32 under this repository's Node (verified; see the test below). Confirm `bavail` is the right choice over `bfree` — the intent is "what an unprivileged process can still write", excluding the root-only reserve.
- **A node on NativeScript, React Native, or in memory learns nothing, and that reads as "unknown" rather than "full".** The method is absent, not a stub; `typeof storage.getApproximateBytesFree === 'function'` is the detection. Worth checking the `NOTE:` at each omission site actually says what it would take to add one.
- **A web store under Node reports no free space.** The package's specs run on `fake-indexeddb`, where there is no `navigator.storage`, so the constructor leaves the method off — the same answer `ns` and `rn` give. Verified by inspection, not by a test (see the gaps below).
- **A storage factory whose stores disagree fails at the first open, not silently.** All four factories assert. The fs factory asserts inside `openDirectory`, where the old helper was called, so it still fires once per directory rather than once per holder.
- **A read cache does not hide the capability.** `CachedRawStorage` over a `FileRawStorage` reports `getApproximateBytesFree`, because `RawStorageDriverAdapter` and `CachedStoreDriver` both pass it through conditionally. By inspection, beside the existing `getApproximateBytesUsed` passthroughs — no test was added, since the passthrough is wiring the compiler checks.
- **`packages/upgrade-check/test/current-build.ts` is untouched** and still hand-builds its stores over a two-directory `fs` layout, calling neither factory nor assertion. `yarn typecheck` in that package passes.

Nothing else was added, for the reasons the ticket gives: the three omissions are the *absence* of a method (a type and a `NOTE:`), each `storeIdentity` is one expression returning a value its sibling store already returns, and the passthroughs are wiring the type checker enforces.

## Known gaps — flag these honestly

- **The reject-don't-guess rule is not tested on either implementation.** Neither a failing `statfs` nor a quota-less `navigator.storage.estimate()` is provoked; both are by inspection. Provoking the fs one cheaply is not obvious (a path that does not exist is created by the `open()` first), and the web one has no way to stub `navigator.storage` in the `fake-indexeddb` harness today — which is the same reason the existing `getApproximateBytesUsed` case there asserts only "a number ≥ 0". If a reviewer sees a cheap way to pin either, it is worth having, since this is the rule the next ticket's consumer depends on.
- **`statfs` is verified on win32 only.** The test runs wherever the suite runs, so a POSIX CI run would cover it, but nothing here has executed it on Linux or macOS.
- **The web free-space method is unexecuted.** No spec reaches `estimateBytesFree` at all, because the harness never has `navigator.storage`. The `quota - usage` arithmetic and the no-quota rejection are read, not run.
- **`JournalBatchBackend.approximateBytesFree` passes through without an `open()` first**, unlike its `approximateBytesUsed`, with a comment saying why (free space is the location's and does not depend on whether the journal has been recovered). Worth a second opinion: it is a deliberate asymmetry.
- **The `ns`/`rn` free-space gap is asserted nowhere** — the absence of a method is a type fact, and `assertOneMeasuredLocation` does not check it. A backend author who added a stub returning 0 would break the contract with nothing failing. That is the shape of every other optional member here, so it is consistent rather than new, but it is real.
- **`assertOneMeasuredLocation`'s first two arms** (no `getApproximateBytesUsed`; no `getStoreIdentity`) have their own messages and no test. They are unreachable from any shipping factory, since all four block stores have both.
