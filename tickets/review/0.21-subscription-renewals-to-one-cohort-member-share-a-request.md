# Subscription renewals to one cohort member share a request

Found while planning `the-reactivity-backstop-check-costs-nothing-while-idle` (GitHub [#48](https://github.com/gotchoices/Optimystic/issues/48)). Before this, each watched collection's cohort-topic registration was renewed on every tick (TTL / 3: 30 s Core, 20 s Edge) with its own signed `RenewV1` dialed to its primary over `/register`: 18 tables on an Edge phone whose primary is the other machine of a two-member group ≈ 54 renew requests a minute. Now that is one request per tick (3 a minute), and none when the primary is this node (served in process since the prereq `a-renewal-whose-primary-is-this-node-is-served-in-process`).

## What landed

**Wire (db-core).** `RenewBatchV1 { v, renews: RenewV1[] }` and `RenewBatchReplyV1 { v, replies: RenewReplyV1[] }` in `wire/types.ts`; `MAX_RENEW_BATCH_ENTRIES = 64`, `validateRenewBatchV1` and `validateRenewBatchReplyV1` in `wire/validate.ts`; `decodeRenewBatchV1` / `decodeRenewBatchReplyV1` in `wire/codec.ts`; all exported. The request validator refuses an empty or oversized `renews`, and any entry where `reattach` or `withdraw` is *present* (even `false` — stricter than "set"; the sender never writes either field on a plain ping). The reply validator also refuses an empty or oversized `replies`; matching the request's length is the sender's check.

**Port (db-core).** Optional `ITopicRouter.dialMemberRenewBatch(member, frame)` and the `RenewBatchUnsupportedError` class, both in `ports.ts`.

**Participant (db-core `renewal.ts`).** `RenewalParticipant` gained `preparePing(): Promise<PreparedPing>` (signed plain ping + current primary) and `settlePing(reply | undefined)` (the old reply handling: reset / adopt `primary_moved` / strike → third strike fails over). `pingLoop` is now prepare → `transport.send` → settle, behaviour unchanged. Failover's re-attaches and re-walk still go singly through the transport.

**Service (db-core `service.ts`).** `CohortTopicService.renewMany(handles)`; `renew(handle)` is `renewMany([handle])`.
- Skips stale/withdrawn handles and any registration whose previous cycle is still running. The in-flight mark is `LiveRenewal.cycle` (the owning `RenewalCycle`), set in `beginCycles` and cleared by `endCycle` **in each cycle's own settle** — with an ownership check so the outer `finally` (which only matters for a throw before settling) can never clear a later call's mark.
- Prepares all pings in parallel (a signer failure → that registration settles with no answer, logged), groups by target (`groupByTarget`, keyed by `bytesKey`), chunks at 64, sends each chunk: one entry, no `dialMemberRenewBatch`, or a remembered-unsupported target → singles over `dialMember` in parallel; otherwise one batch. `RenewBatchUnsupportedError` → remember the target for `RENEW_BATCH_UNSUPPORTED_RECHECK_MS` (10 min) and re-send that chunk singly in the same call. Any other batch failure, a reply that fails validation, or a wrong-length reply (`CohortWireError`) → no answer for every entry of the chunk (logged).
- Settles only after every send has finished, in parallel, and only for a handle still live at that moment (`settleCycle`), so a registration displaced by a later `register` (a tail follow at the root) or withdrawn while its ping was out never fails over. Then `syncHandle`.
- Rejects after every settle has finished: with the one error itself when one cycle threw (so `renew`'s caller sees exactly what it saw before), an `AggregateError` when several did.
- `batchUnsupportedUntil` map carries the `NOTE:` tripwire (bounded by distinct primaries; cap it if that ever gets large).

**db-p2p.** `PROTOCOL_COHORT_RENEW_BATCH` / `renewBatch` in `protocols.ts` (both builders, `cohortTopicProtocolList`, header now says six). `FretTopicRouter.dialMemberRenewBatch`: self-addressed → `handleRenewBatchLocally`; a router given no such handler answers a self-addressed batch as unsupported so the pings fall back to `dialMember`'s own self path (a choice beyond the ticket). A remote negotiation refusal (`isUnsupportedProtocolError`, a new shared helper in `network/open-protocol-stream.ts`, which `identify-on-open.ts` now uses in place of its private constant) → `RenewBatchUnsupportedError` with the libp2p error as `cause`. Host: `handleRenewBatchFrame` beside `handleRegisterFrame` (decode, `resolveRenew` per entry with one `now`, encode), registered on `protocols.renewBatch` in `registerCohortTopicProtocols` and passed to the router as `handleRenewBatchLocally`.

**Watch service (`collection-watch.ts`).** `tick` marks the ticked subscriptions `tickQueued` and makes one un-awaited `service.renewMany(...)` over their registration handles (`renewAll`, rejection logged); the per-subscription `renew` step on the queue is gone. Module header's "Work on one subscription is serial" paragraph and the `armTick` cost `NOTE:` updated. `ReactivitySubscriptionManager.renew` is untouched.

**Docs.** `docs/cohort-topic.md` §TTL and renewal (new "Pings to one member share a request" paragraph), §Protocol IDs (`renew-batch`), new §Renew batch under §Wire formats; `docs/internals.md` §Protocol IDs (now lists all six, plus one paragraph on batching); `docs/reactivity.md` §The node's watch service (per-primary renewal cost replaces the "Renewals are not batched" sentence).

## Tests added

  - "a registration whose failover is still waiting on its re-walk is skipped by the next call, which still renews the others": **not in the ticket's list** — added because self-review found the in-flight mark was first released only when the whole call finished, so one registration's held re-walk kept every registration of that call out of later ticks. This test fails on that version.
  - "a member that does not speak the batch protocol is sent the same pings singly in the same call, and singly until the recheck interval passes": unsupported → singles in the same call, remembered, batch retried after `RENEW_BATCH_UNSUPPORTED_RECHECK_MS`.

## Known gaps and things to look at

- **No test runs the member side over a transport**: `handleRenewBatchFrame`, its registration on `/renew-batch`, and the router's in-process batch branch are verified by inspection only (they are wiring around `resolveRenew`). The cohort-topic mesh harness routes protocols generically, so a host-level test there is possible if wanted.
- **`AggregateError` on Hermes.** `throwFailures` constructs one (ES2021) when two or more cycles throw in one call; `packages/db-p2p/src/logger.ts` hedges that Hermes might not define it. Modern Hermes does, as far as I know; if not, the call rejects with a `ReferenceError` instead, which the watch logs the same way. `yarn check:rn` would not catch it (it never runs the bundle).
- **Tripwire, measured:** `openProtocolStream` treats a negotiation refusal like any failed path and forces a fresh dial before rejecting, so each refusal by an older member leaves one extra connection (1 → 2 on two local nodes). Bounded to one refusal per older member per 10 minutes; `NOTE:` at the catch in `FretTopicRouter.dialMemberRenewBatch`. Generic to every unsupported-protocol open in db-p2p, not new here.
- **Behaviour change for direct `renew` callers:** a second `renew(handle)` while the first is still running now resolves at once without pinging (the in-flight guard), where it used to run a second ping loop beside the first. `MatchmakingProviderSession` reaches this path; nothing in the repo relied on concurrent cycles (full suites green).
- **Renew racing a tail follow** now really happens (the renewal left the subscription queue). Covered by the live-handle check before settling; by inspection, as the ticket planned.
- **`RenewalParticipant` has two new required members**; no implementer outside `renewal.ts` exists in the repo.
- Out-of-ticket touch: `identify-on-open.ts` now imports `isUnsupportedProtocolError` instead of keeping its own copy of the error name (DRY; behaviour unchanged).
