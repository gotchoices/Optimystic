## What was built

### The port gained an optional wake

`ICohortReachability.onChange?(listener) => unsubscribe` in `packages/db-core/src/offline/reachability.ts`. A hint, not an answer: the listener asks `reachable` again. `alwaysReachable` has none. Optional, so the plugin's existing gates and wrappers compile unchanged.

### Identify progress for every peer

- `IdentifyProgress` in `packages/db-p2p/src/network/identify-progress.ts`: an `IdentifyObserver` counting identify exchanges in flight, per peer (bookkeeping only) and in total (`inFlight()`). A `settled` for a peer with nothing in flight is logged (`settled:unmatched`) and ignored, never driving the count negative.
- `combineIdentifyObservers(...observers)` beside `identifyOnConnectionOpen` in `identify-on-open.ts`: each observer call isolated, a throw logged (`observer:threw` on `:error`) and the others still told.
- `createLibp2pNodeBase` installs `identifyOnConnectionOpen(node, combineIdentifyObservers(bootstrapContact, identifyProgress))`, both built before `start()`. Not threaded into `Libp2pKeyPeerNetwork` (its ten-positional-parameter NOTE).

### The gate

`KeyNetworkCohortReachability` in `packages/db-p2p/src/network/cohort-reachability.ts`, deps `CohortReachabilityDeps` `{ keyNetwork (findCluster / absentCohortMembers / awaitingBootstrapContact), selfId, identifying?, events?, wakeDebounceMs? }`. Exported from both package entries (`index.ts` and `rn.ts`), with `NodeCohortReachability` (the port with `onChange` required), `NetworkChangeEvents` (structural `addEventListener`/`removeEventListener` for `'connection:open' | 'peer:identify'`, satisfied by a libp2p node or a plain `EventTarget`), `UnreachableReason`, and `DEFAULT_WAKE_DEBOUNCE_MS` (500).

`reachable(blockIds)` judges each distinct id concurrently (so a `findCluster` held by the bootstrap-contact wait is waited out once) and answers true only when every one is open:

1. `findCluster(routingKeyForBlock(id))`; any throw while judging → closed `lookup-failed` (never thrown out).
2. A member other than self → open.
3. Empty cohort → closed `no-cohort`.
4. Self-only → closed `absent-members`, else `awaiting-bootstrap`, else `identifying` (in that order of precedence for the logged reason); otherwise alone → open.

One log line per change of answer (`reachability:closed reason=… block=…` / `reachability:open`), not per call.

`onChange`: the first listener subscribes the two events; each event restarts one trailing debounce timer (`armUnrefTimer`); when it fires every listener is called, isolated. The returned unsubscribe is idempotent; the last one removes the event listeners and cancels the timer. `stop()` drops every listener, releases the events and timer, and makes later `onChange` calls return a no-op unsubscribe without subscribing. Departures do not wake.

### On the node

Built in `createLibp2pNodeBase` right after the key network, outside every optional-subsystem gate, over `keyNetwork`, `node.peerId.toString()`, `identifyProgress.inFlight`, and `node` as the event source; its stop wrapper is registered immediately (startup rollback releases it). Attached as `node.cohortReachability: NodeCohortReachability` on `OptimysticNodeAttachments`. `NodeOptions.cohortReachability?: { wakeDebounceMs?: number }`.

### Mesh harness

The per-node key network from `makeNodeKeyNetwork` in `packages/db-p2p/src/testing/mesh-harness.ts` now has `absentCohortMembers(key)`: under `failures.partitionSides`, the members of the unpartitioned cohort the side filter removed (never self), nearest first; `[]` with no partition. Consequence: a partitioned solo write now reports `local` with `unconfirmed` naming the far side, and records an under-replication entry. **No partition spec needed adjusting** — the full suite passed unchanged (see below); none asserted an empty `unconfirmed`.

### NOTEs added (tripwires)

- `membershipOf` in `libp2p-key-network.ts`: rewritten — the "second decision" has appeared and the gate covers the in-flight window; what remains is an identify that **fails** on a same-network peer whose list stayed partial (reads `foreign`, sits in the band, gate reads alone). Tripwire: if a fork is traced to an `identify:failed` line, treat a band member whose latest identify failed as not-alone.
- `reachable`: restart with persisted network state — a restored partner reads `serves`, so the gate answers reachable while the partner is offline until FRET drops it; harmless (shortfall, the queue waits; no lone commit since the cohort is not solo).
- The "member other than self" arm: FRET's `maxDeadGraceMs` grace keeps a departed long-lived peer live up to 5 min, so the gate reads reachable and the drain meets shortfalls with backoff. Tripwire: if drains spin on shortfalls through the grace, also require a live connection to that member.
- `onChange`: the trailing debounce restarts on every event, so a steady stream of events closer than `wakeDebounceMs` apart postpones the wake indefinitely (the queue's own re-check timer still runs). Tripwire: fire at most one interval after the first event of a burst. (This one is mine, not from the plan.)

## For the reviewer — things worth a second look

- **`identifying` counts exchanges with any peer**, foreign ones included (a relay, another network's node). A genuinely alone node that keeps connecting to foreign peers reads closed for the length of each such exchange (one round trip, or until the foreign refusal), then re-opens on the next ask. I judged that harmless; check you agree.
- **Precedence of reasons** only affects the logged reason, not the answer; check the order (absent → awaiting → identifying) reads sensibly in an operator's log.
- **The debounce test is timing-based** (20 ms / 80 ms on real timers). Deterministic in practice since both events are dispatched synchronously, but a heavily loaded CI box could in principle stretch the 80 ms; the gate has no injectable timer seam.
- **The harness change** shifts what partitioned solo writes report and records ledger entries on partitioned mesh nodes. Nothing asserted otherwise, but a reviewer may want to confirm no partition spec now passes for a different reason than intended.
- **Behaviour change visible to every node**: one more `connection:open`/`peer:identify` listener pair exists only while someone holds an `onChange` subscription (nobody does until `offline-sync-cohort-reachability` lands); the identify observer combinator now runs on every connection, costing a map update per exchange.
