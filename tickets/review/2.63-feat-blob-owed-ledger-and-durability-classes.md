## `KeyedSerialQueue` (`packages/db-p2p/src/keyed-serial-queue.ts`)

`run(key, operation)` chains `operation` behind every earlier operation for `key`, dropping the map entry when nothing waits. Extracted verbatim in semantics from `KvUnderReplicationLedger.serialized`, with `pending` added for observability. Three call sites use it now: the under-replication ledger (its private `serialized` and `queues` map deleted), `BlobRecordStore.update` (its `chains` map and `noop` helper deleted), and `OwedBlobLedger`.

The two pre-existing implementations differed only in *where* they dropped the map entry — the ledger in a `finally` after awaiting the run, the record store in a `void settled.then(…)`. Both check `queues.get(key) === tail` before deleting, so a waiter that has already re-pointed the entry is never orphaned; the extracted version keeps the ledger's `finally` shape. **This is the substitution worth a reviewer's eye**, since no new test pins it: the two existing suites are the check (both pass unedited).

## `OwedBlobLedger` (`packages/db-p2p/src/blob/owed-blob-ledger.ts`)

One JSON entry per announced blob under `owed-blobs/<ref>` (`OWED_BLOB_KEY_PREFIX`), carrying the scope, the **confirmed holders** (not the missing members) and `recordedAt`. `record` / `addHolders` / `get` / `list` / `size` / `delete`, shaped after `KvUnderReplicationLedger`: per-ref queue, one flush after the key is released, parse-and-check reads that log `read:malformed` and answer **absent** without deleting, a sequential full scan sorted oldest-first whose first run doubles as the size index's load, and no size cap (a `NOTE:` at the class names `feat-unreferenced-blobs-are-reclaimed` as what bounds it instead).

## `BlobRecord.durability` and the record door

`BlobRecord` gained an optional `durability: BlobDurability`, with a decoder rule beside the others in `recordProblem` and a local `DURABILITY_QUORUMS` set next to `HOLD_KINDS`. It is checked rather than kept-as-found, unlike the record's other additive fields, because `stat` hands it straight to a caller typed as a `BlobDurability`.

`BlobOwedRecords` is the narrow door the drain will use, declared on `LocalBlobService` (`implements BlobService, BlobOwedRecords`, so drift is a compile error): `holdOwed`, `releaseOwed`, `setDurability`, `durabilityOf`, `holdsWhole`, `emitDurability`. The three writers go through the existing `changeRecord`, so they take the sweep gate and the one per-ref queue. `LocalBlobService.stat` now carries the record's `durability` on all three return sites.

**One deviation from the implement ticket's letter, worth confirming:** the ticket's interface sketch did not say which reader `durabilityOf` and `holdsWhole` use, but its edge-case note says a malformed stored durability "reads the whole record as malformed, which `LocalBlobService.readableRecord` logs and treats as absent". Both therefore go through `readableRecord`, not `records.get` — so a record that does not decode does not reject a drain pass. For `holdsWhole` that under-counts this node, which keeps the blob (the safe direction).

## `classifyBlobDurability` (`packages/db-p2p/src/blob/blob-durability.ts`)

Pure, types-only imports. Five rules in the fixed order the ticket specifies, with `unconfirmed` as `accepting − holders` in `accepting` order on every class but `unrouted`.

# Known gaps and things to look at

- **No production caller yet.** `OwedBlobLedger`, `classifyBlobDurability` and `BlobOwedRecords` are exported and unused outside their specs until `feat-blob-owed-copies-are-drained` lands. Check the shapes against that ticket's `settleRef` and `cohortView` prose rather than against any current call.
- **A pre-existing shape I mirrored, not introduced.** `OwedBlobLedger.list`, like `KvUnderReplicationLedger.list`, assigns the index load from the same scan promise it returns to the caller (`this.indexLoad = this.indexFrom(scan); return scan;`). When the scan rejects, the caller sees the rejection and the stored chain — whose `catch` clears `indexLoad` and rethrows — can end up with no handler. Identical in both ledgers; the implement ticket told me to follow the existing one, so I did rather than diverging one of two copies. Worth a call on whether both should swallow instead of rethrow, but it is not this ticket's defect.
- **`durability:listener-threw` was not in the implement ticket's docs list.** `emitDurability` logs it on the `blob:store` channel, so I documented it in `docs/debugging.md` beside `read:malformed`. The ticket's docs section said the ledger's malformed read was the only new line; it had overlooked the emitter's.
- **`record:unreadable`** (pre-existing, `LocalBlobService.readableRecord`) is still undocumented in the `blob:store` row of `docs/debugging.md`. Outside this ticket's diff; left alone.
- **`packages/db-p2p-storage-fs/README.md`'s namespace list was already incomplete** — it named five prefixes and omitted `optimystic-blobs/`. I added both it and `owed-blobs/` while I was there, so the list now matches `NODE_KV_NAMESPACES`.
