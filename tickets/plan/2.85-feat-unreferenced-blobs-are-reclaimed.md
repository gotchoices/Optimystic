# Unreferenced blobs are reclaimed

A blob is kept on a machine while some hold names it (docs/blobs.md §Holds). After `feat-a-referenced-blob-is-copied-to-its-cohort`, a responsible machine takes a `responsible` hold on a blob once it finds committed state referencing it, and a writer keeps an `owed` hold and an owed entry until its cohort holds the blob; nothing releases either when the references go. This ticket adds the reference pass of docs/blobs.md §Lifetime: periodically, and on demand, each node reads every registered reference tree for the blobs it holds under `responsible` or owes, and releases a hold only for a blob that two counting passes at least a grace period apart (7 days by default) found listed nowhere. Releasing the last hold leaves the blob's pieces to the piece sweep. Cache eviction is `feat-blob-cached-copies-stay-within-a-budget`.

**This is the first code in the repository that deletes replicated data on a schedule.** Nothing reclaims block storage today (`gcEligibleBlocks` in `packages/db-p2p/src/libp2p-node-base.ts` is filled and never swept). Every rule below errs toward keeping: a wrong release deletes a file a committed row still names, on each holder independently, with nothing left to repair from.

## Design

### Where the pass reads from

The pass reads committed state through the node's own `NetworkTransactor` (built by `createNodeNetworkTransactor` in `feat-blob-announcements-are-answered`, the transactor `BlobReferenceCheck` reads with), wrapped for each pass in a `ConfirmationRecordingTransactor` (below). It reads with `BlobScopeRegistry.enumerate(transactor)` and `BlobReferenceTree.listed(transactor, scope, refs)` from `feat-committed-rows-register-the-blobs-they-reference`, which open a fresh read-only handle on every call, refresh it to the newest committed state, and report `certain: false` for a read that threw `BlockUnavailableError` or `BlockPossiblyStaleError` or received a below-floor answer.

### `ConfirmationRecordingTransactor` (`packages/db-p2p/src/blob/confirmation-recording-transactor.ts`)

```ts
/** A read-only ITransactor for one reclaim pass. Every read asks the answering coordinators to consult
 *  before answering (`BlockGets.awaitConsult`), and every block whose answer did not carry
 *  `GetBlockResult.cohortConfirmed` — including a block the result omits — is recorded. */
export class ConfirmationRecordingTransactor implements ITransactor {
	constructor(inner: ITransactor);
	/** Block ids whose answers no cohort member outside the answering node vouched for. */
	readonly unconfirmed: ReadonlySet<BlockId>;
	get clock(): HlcClock | undefined;			// inner's
	get(blockGets: BlockGets): Promise<GetBlockResults>;	// inner.get({ ...blockGets, awaitConsult: true }), then record
	getStatus(actionRefs: ActionBlocks[]): Promise<BlockActionStatus[]>;	// delegates
	pend(): Promise<PendResult>;				// throws ReclaimReadOnlyError
	cancel(): Promise<void>;				// throws ReclaimReadOnlyError
	commit(): Promise<CommitResult>;			// throws ReclaimReadOnlyError
}
export class ReclaimReadOnlyError extends Error {}
```

Read-only by construction: nothing in a pass writes, and a write through it would be a defect, so the write methods throw rather than delegate. The optional `ITransactor` methods are omitted. A `get` that throws records nothing and propagates; the reader turns it into `certain: false`.

### The predicate

One named, pure function holds every disqualifying condition from docs/blobs.md §Lifetime and the backlog ticket. A pass **counts** exactly when it returns an empty list.

```ts
export type ReclaimNotCountedReason =
	| 'partition'				// PartitionDetector.detectPartition() true at the start or the end of the pass
	| 'registry-threw'			// enumerate() threw
	| 'registry-uncertain'			// enumerate() answered certain: false
	| 'registry-absent'			// enumerate() answered exists: false while this node holds a responsible blob or an owed entry
	| 'tree-threw'				// some listed() threw
	| 'tree-uncertain'			// some listed() answered certain: false
	| 'unconfirmed-not-alone'		// some block answer was not cohortConfirmed and aloneFor(those blocks) was false
	| 'stopped';				// the pass was stopped before it applied anything

export interface ReclaimEvidence {
	readonly partitionAtStart: boolean;
	readonly partitionAtEnd: boolean;
	readonly registry: 'threw' | { readonly certain: boolean; readonly exists: boolean };
	readonly holdsAny: boolean;
	readonly trees: readonly { readonly scope: BlobScope; readonly outcome: 'threw' | 'certain' | 'uncertain' }[];
	readonly unconfirmedBlocks: number;
	/** `aloneFor` over the unconfirmed blocks; `undefined` when there were none. */
	readonly aloneForUnconfirmed: boolean | undefined;
	readonly stopped: boolean;
}

/** Every reason this pass does not count toward reclaiming; empty when it counts. */
export function whyPassDoesNotCount(evidence: ReclaimEvidence): ReclaimNotCountedReason[];
```

How each source rule maps:

- **A read that throws**, including `BlockUnavailableError` (any reason) and `BlockPossiblyStaleError`: the reader catches those two and answers `certain: false` (`tree-uncertain`, `registry-uncertain`); anything else it lets through, and the pass catches it (`tree-threw`, `registry-threw`).
- **A registry that cannot be read or opened**: `registry-threw` or `registry-uncertain`. **A registry that reads as absent while this node holds any responsible blob or owed entry**: `registry-absent`. An existing registry with no scopes counts (every reference tree was unregistered, so every blob is unreferenced there).
- **A below-floor answer**: the reader reports it as `certain: false`.
- **A pass during a detected partition**: `partition`, checked before the first read and after the last.
- **A read that rested on asking nobody, unless the node is alone**: every block whose answer lacked `cohortConfirmed` is collected by the recording transactor; when there are any, the pass calls `KeyNetworkCohortReachability.aloneFor` over them after its last read, and `false` gives `unconfirmed-not-alone`. An answer from another machine that lacked the marker (an older build, or a coordinator that itself asked nobody) makes `aloneFor` false, since that machine is in the cohort.
- **A reference tree the registry lists that reads as authoritatively absent**: the reader answers it empty and certain; the "after a consult" half is the confirmation rule above.

### Marks

A **mark** is the start time of the first counting pass that found a blob listed nowhere, persisted so it survives a restart:

- the blob record gains `unreferencedSince?: number` (milliseconds since the epoch), meaningful only while the record holds `responsible`;
- the owed entry gains `unlistedSince?: number`.

Only the reclaim pass sets either. Every write that adds, re-verifies or removes a `responsible` hold clears `unreferencedSince` in the same record write (the announce receiver's hold, reader repair, the cohort reaction's release), because each of those is either fresh evidence the blob is referenced or the end of the hold the mark was about; without this a mark left from before a hold was released and re-taken could release the new hold on one pass. Every write that creates or re-records an owed entry (an `announce` call for a reference already owed) clears `unlistedSince`, for the same reason.

```ts
export type MarkDecision = 'mark' | 'keep' | 'release';
/** For a blob a counting pass found listed nowhere. `mark` when there is none, or when it lies after
 *  `startedAt` (the wall clock went back: restart the grace period from now); `release` when
 *  `startedAt - mark >= graceMs`; otherwise `keep`. Pure. */
export function judgeMark(mark: number | undefined, startedAt: number, graceMs: number): MarkDecision;
```

### `BlobReclaimPass` (`packages/db-p2p/src/blob/reclaim-pass.ts`)

```ts
export const DEFAULT_RECLAIM_GRACE_MS = 7 * 24 * 60 * 60 * 1000;
/** Below this a pass could release on two passes too close to cover a reference being copied between rows. */
export const MIN_RECLAIM_GRACE_MS = 60 * 60 * 1000;
export const DEFAULT_RECLAIM_INTERVAL_MS = 6 * 60 * 60 * 1000;
export const DEFAULT_RECLAIM_FIRST_PASS_DELAY_MS = 5 * 60 * 1000;

export interface BlobReclaimDeps {
	records: BlobRecordStore;
	owed: OwedBlobLedger;
	/** The node's committed-state reader (`createNodeNetworkTransactor`). */
	transactor: ITransactor;
	cohort: Pick<KeyNetworkCohortReachability, 'aloneFor'>;
	partitionDetector: Pick<PartitionDetector, 'detectPartition'>;
	/** `LocalBlobService.sweep`. */
	sweep: () => Promise<void>;
	log: Logger;
}

export interface BlobReclaimOptions {
	graceMs?: number;			// default DEFAULT_RECLAIM_GRACE_MS; RangeError below MIN_RECLAIM_GRACE_MS or not finite
	intervalMs?: number;			// default DEFAULT_RECLAIM_INTERVAL_MS
	firstPassDelayMs?: number;		// default DEFAULT_RECLAIM_FIRST_PASS_DELAY_MS
	now?: () => number;			// default Date.now; tests inject a clock
}

export interface ReclaimPassReport {
	readonly startedAt: number;
	/** Set when the pass read nothing: nothing held, or stopped before it began. */
	readonly skipped?: 'nothing-held' | 'stopped';
	readonly counted: boolean;
	readonly notCounted: readonly ReclaimNotCountedReason[];
	readonly scopes: number;
	readonly treesRead: number;
	readonly responsibleChecked: number;
	readonly owedChecked: number;
	readonly listed: number;
	readonly newlyMarked: number;
	readonly cleared: number;
	readonly released: number;		// responsible holds
	readonly owedReleased: number;
	readonly unconfirmedBlocks: number;
}

export class BlobReclaimPass {
	constructor(deps: BlobReclaimDeps, options?: BlobReclaimOptions);
	/** Arm the first pass after `firstPassDelayMs`; each later pass `intervalMs` after the previous one ended. */
	start(): void;
	/** Run a pass now, or join the one running. Rejects after `stop`. */
	runNow(): Promise<ReclaimPassReport>;
	/** Clear the timer, mark stopped (a running pass applies nothing further) and wait for it. */
	stop(): Promise<void>;
}
```

**One pass**, in order:

1. `startedAt = now()`. Snapshot the work: every blob record holding `responsible` with its `unreferencedSince`, sorted ascending by code unit (references have one spelling and compare as strings); every owed entry with its scope and `unlistedSince`. If both are empty, return `skipped: 'nothing-held'` without reading.
2. `partitionAtStart = detectPartition()`. When true, read nothing: the pass does not count, and nothing is marked or cleared.
3. A fresh `ConfirmationRecordingTransactor` over `deps.transactor`.
4. `BlobScopeRegistry.enumerate(recorder)`. When it throws, answers `certain: false`, or answers `exists: false`, stop reading (step 8 still runs, so the report and log say why).
5. For each registered scope, ascending: the references to ask about are the snapshot's responsible references not yet found listed by an earlier tree, together with the owed references whose entry names this scope. When that set is empty, skip the tree. Otherwise `BlobReferenceTree.listed(recorder, scope, refs)` inside a `try`; a throw is recorded as `threw` and logged. Add what it lists to the responsible listed set and to this scope's listed set. Continue with the next tree whatever the outcome, so references other trees list still have their marks cleared. Check the stopped flag between trees.
6. An owed entry whose scope the registry does not list is unlisted (that tree was unregistered when its collection was dropped).
7. When the recorder holds unconfirmed blocks, `aloneFor([...recorder.unconfirmed])`.
8. `partitionAtEnd = detectPartition()`; `whyPassDoesNotCount(...)`.
9. **Apply**, unless stopped, one record or entry at a time, each write conditional on the record or entry as it is at that moment:
   - A responsible reference found listed by any tree (certain or not — a listing is evidence of a reference, and clearing only delays reclaiming): clear `unreferencedSince` if set.
   - An owed reference found listed by its own scope: clear `unlistedSince` if set.
   - Only when the pass counts, for each responsible reference listed nowhere, `judgeMark(snapshotMark, startedAt, graceMs)`:
     - `mark`: set `unreferencedSince = startedAt`, if the record still holds `responsible` and its mark still equals the snapshot's;
     - `release`: remove the `responsible` hold and its mark, under the same condition; a record left with no hold is deleted by the record store and its pieces are left for the sweep;
     - `keep`: nothing.
   - Only when the pass counts, for each owed entry unlisted in its scope, the same decision on `unlistedSince`; `release` deletes the owed entry first, if its `unlistedSince` still equals the snapshot's, then removes the record's `owed` hold. Once the entry is gone the drain no longer announces the blob.
   - A pin is never read or changed. A pinned blob that loses `responsible` or `owed` keeps its record and its pieces.
10. When any hold was released, `await deps.sweep()` once.
11. Log the pass line and return the report.

The conditional writes are what make a pass safe against everything that changes holds while it reads: an announcement that took a `responsible` hold mid-pass cleared the mark, so the snapshot's mark no longer matches and nothing is released. Use the record store's and the ledger's own update operations (read, decide on the current value, write); if either lacks one, add `update(ref, change: (current) => next | undefined)` there, serialized per reference with the writes those stores already make.

**Order of the owed release.** Entry first, hold second: a crash between leaves an `owed` hold with no entry, which keeps the blob (storage leaked, nothing lost). The reverse order would leave an entry whose drain announces a blob this node no longer holds. Record the leak as a `NOTE:` at the release: if orphaned `owed` holds are ever seen, release an `owed` hold with no entry on the next pass.

**Durability of marks.** The record store and the ledger write marks without forcing a flush. A mark lost to a crash only delays reclaiming; a release lost to a crash leaves the hold, which the next counting pass releases again (its mark is still old enough).

**Schedule.** `start()` arms `armUnrefTimer` for `firstPassDelayMs`; each pass, from the timer or `runNow`, re-arms the timer `intervalMs` after it ends, so passes never overlap and a pass that runs long delays the next rather than stacking. `runNow` while a pass runs returns that pass's promise. A pass that throws outside its reads (a record store failure) is logged `reclaim:pass-failed` and re-armed; `runNow` rejects with the error. Six hours bounds a release to between the grace period and the grace period plus six hours after the first counting pass, and costs four full reads of every registered reference tree a day on a node holding blobs; one hour would be 24. The first pass waits five minutes so a starting node has dialed its bootstrap peers and identified its cohort, although the confirmation rule already keeps a cold node's passes from counting.

### Node wiring

- `NodeOptions.blobs.reclaimGraceMs?: number`, default `DEFAULT_RECLAIM_GRACE_MS`. Below `MIN_RECLAIM_GRACE_MS` or not finite, `createLibp2pNodeBase` throws a `RangeError` naming the option before the node starts. Rejected: allowing small values for tests — tests inject a clock and keep the default.
- `createLibp2pNodeBase` builds one `BlobReclaimPass` beside the blob service (records, ledger, the node's committed-state transactor, the node's `cohortReachability`, the node's `partitionDetector`, the blob service's `sweep`, `createLogger('blob:reclaim', node.peerId.toString())`), calls `start()`, and installs a stop wrapper immediately after construction, in the pattern of the drain's, that awaits `stop()` before the previous stop.
- `OptimysticNodeAttachments.blobReclaim: { runNow(): Promise<ReclaimPassReport> }`, the on-demand entry, attached with `node.blobs`.

## Edge cases & interactions

- **Two passes too close together.** The second, inside the grace period, keeps the mark unchanged. Test.
- **Referenced in between.** Unreferenced, referenced, unreferenced: the grace period runs from the third pass. Test.
- **One failing tree among many.** The pass does not count for any blob; references other trees list still have their marks cleared. Test (the failing read is a `BlockPossiblyStaleError`, which also covers the stale-read case: both reach `certain: false` through the reader's one catch arm; `BlockUnavailableError` takes the same arm, by inspection of the reader).
- **A node that cannot see its cohort.** Self-only view with a remembered member missing: answers unconfirmed, `aloneFor` false, nothing marked or released over two passes a grace period apart. Test.
- **A deployment of one machine.** Alone by the gate's test, holding the registry and trees itself: passes count, and a blob unreferenced at two of them a grace period apart is released. Test.
- **Confirmed answers on a node that is not alone.** Count without consulting `aloneFor`. Test.
- **Partition.** Not counted; nothing read when detected at the start. Test (detected at the start; the end check is the same predicate, by inspection).
- **Absent registry while holding.** Not counted. Test. **An existing, empty registry** counts and releases after two passes: inspection of the predicate.
- **An owed blob whose row was deleted.** After two counting passes the owed entry and the `owed` hold are gone and the drain no longer lists it. Test.
- **An owed blob whose scope was unregistered.** Unlisted, released after two counting passes. Inspection (same branch as the deleted row once the scope is missing).
- **Pinned blob.** Released from `responsible`; record, pin and pieces stay. Test.
- **Restart between passes.** The first pass's mark survives on a persistent store; a new pass instance releases after the grace period. Test.
- **A hold re-taken after a stale mark.** A record marked long ago whose `responsible` hold is released and re-taken has no mark; one counting pass does not release it. Test (this is the conditional-write and clear-on-hold rule, the branch most likely to delete a live blob).
- **Shared pieces.** Two blobs share a piece; releasing one leaves the piece for the other after the sweep. Asserted once inside the one-machine test.
- **Hold changes during a pass.** Conditional writes on the mark; inspection.
- **Clock going back.** `judgeMark` restarts the grace period; inspection. **Clock jumping forward** shortens the real time between the two passes; record as an accepted-tradeoff `NOTE:` at `judgeMark` (wall-clock time is the only one that survives a restart; revisit if hosts with unreliable clocks are reported).
- **A reference that outlives its bytes** (an old revision of a row read from history) reads as `BlobUnavailableError` with the fetcher's reason, never a missing-block error: inspection of `feat-blob-pieces-move-between-machines`' fetch path; nothing here changes it.
- **Re-referencing.** No release on one pass, at startup or ever: every release needs a mark from an earlier counting pass at least `graceMs` (at least one hour) older. Inspection of `judgeMark` and the option check.
- **Large holdings.** One `listed` per registered tree, each one ordered walk over the tree with the references still unlisted; cost is bounded by the trees' sizes, not by blobs times trees. `awaitConsult` makes each expired-window block a blocking consult; record a `NOTE:` at the pass: if pass time shows up, read trees concurrently with a small bound.
- **Stop during a pass.** No write after the stopped flag is seen; inspection.

## Tests

`packages/db-p2p/test/blob-reclaim-pass.spec.ts`. Committed state lives in a db-core `TestTransactor`; registry and reference-tree entries are written through `BlobScopeRegistry.register` and `BlobReferenceTree` staging plus `sync`, references made with `buildBlob`. Blob records and the owed ledger sit on a `MemoryKVStore` (a `PowerLossKVStore`, `packages/db-p2p/src/testing/power-loss-kv-store.ts`, for the restart test); pieces in a `MemoryPieceStore` behind a real `LocalBlobService`, whose `sweep` the pass is given. `cohort` is a real `KeyNetworkCohortReachability` over a key-network double that returns a fixed cohort and absent-member list (the shape `packages/db-p2p/test/cohort-reachability.spec.ts` uses). `partitionDetector` is a real `PartitionDetector`, driven into partition with `recordFailure`. `TestTransactor` answers never carry `cohortConfirmed`, so the confirmed-answers test wraps it in a `DelegatingTransactor` subclass that adds the marker to every entry. The clock is injected; `G` is the default grace period.

- **One machine releases after two passes a grace period apart.** Alone. Blobs A and B share a piece; A's reference is in a registered tree, B's is not; both hold `responsible`. Pass at `t`: B marked, A not. Pass at `t + G`: B's `responsible` hold released, record gone, B's own pieces swept, the shared piece and A untouched.
- **Too close together.** Passes at `t` and `t + G - 1`: B's mark is still `t` and it still holds `responsible`.
- **Referenced in between.** Pass at `t` (unlisted), add B to a tree, pass at `t + 1` (listed: mark cleared), remove it, pass at `t + 2` (marked `t + 2`), pass at `t + G` (kept), pass at `t + 2 + G` (released).
- **One failing tree.** Alone, so the failing tree is the only reason. Eleven registered trees, ten clean, one read through a transactor that adds `unconfirmedAheadRev` to that tree's leaf blocks; a blob listed in one of the clean trees has a mark from an earlier pass. Two passes `G` apart: nothing marked or released, the listed blob's mark cleared, the report says `tree-uncertain`.
- **A node that cannot see its cohort.** Self-only cohort, absent-member list naming another peer: passes at `t` and `t + G` mark nothing, release nothing, report `unconfirmed-not-alone`.
- **Confirmed answers count without being alone.** Cohort naming this node and another, answers marked confirmed: passes at `t` and `t + G` release B.
- **Partition.** Partition detected: the pass reports `partition`, `treesRead: 0`, nothing marked.
- **Absent registry.** Nothing registered, B held `responsible`: `registry-absent`, nothing marked.
- **Owed blob whose row was deleted.** An owed entry for B naming a registered scope that no longer lists it: after passes at `t` and `t + G` the entry and the `owed` hold are gone.
- **Pinned blob.** B pinned and `responsible`: after two passes `G` apart the `responsible` hold is gone, the pin, record and pieces remain.
- **Restart.** Pass at `t` on a `PowerLossKVStore` after a flush; reopen the record store and ledger over the same store, build a new `BlobReclaimPass`; pass at `t + G` releases B.
- **A re-taken hold is not released on one pass.** Mark B at `t`; release and re-take its `responsible` hold through the record store's hold operations; pass at `t + G` marks it afresh instead of releasing.
