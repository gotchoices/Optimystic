# Blob announcements are answered

docs/blobs.md §Placement, copying and durability: a writer whose committed row references a blob *announces* it to the blob's cohort, and each member decides for itself whether to take it. §Who may fetch and who may store: "A node takes a blob on another's behalf only after reading committed state and finding the reference in the scope the announcement names, and only when that scope is in the registry and the node is in the blob's cohort. An announcement is a hint about where to look; it grants nothing."

`feat-blob-pieces-move-between-machines` defined the blob protocol's framing for all four requests and answers `announce` as a node that does not accept blobs. This ticket implements the receiving half of `announce` and both halves of `held`, the `blobs.hold` node option, the rule for peers that do not run the blob protocol, and readers keeping what they fetch. It does not track who still owes a copy, announce on its own, or report durability: that is `feat-blob-owed-copies-are-drained`.

## Wire shapes

The header envelope (version field, `kind` discriminator, length-prefixed JSON first frame, header size cap) is the one `feat-blob-pieces-move-between-machines` fixed; use its field names for the envelope. The bodies:

```ts
/** Request headers added to the blob protocol's request union. */
type BlobAnnounceRequest = { kind: 'announce'; ref: string; scope: string };
type BlobHeldRequest = { kind: 'held'; ref: string };

/** The receiver's answer to `announce`, in the order it decides them. */
export type BlobAnnounceAnswer = 'declined' | 'not-responsible' | 'unreferenced' | 'whole' | 'fetching';

type BlobAnnounceResponse = { kind: 'announce'; answer: BlobAnnounceAnswer };
/** `held` is acknowledged with an empty body; the sender ignores everything but the stream closing cleanly. */
type BlobHeldResponse = { kind: 'held' };
```

Validation (a failure is a malformed request, handled as the prereq handles any malformed header — the stream is reset and nothing is read or answered): `ref` must pass `parseBlobRef`; `scope` must be a non-empty string of at most `MAX_BLOB_SCOPE_CHARS` (1024, in `packages/db-p2p/src/protocol-limits.ts`). One request per stream, as for `stat`.

`BlobProtocolClient` gains `announce(peerId, ref, scope): Promise<BlobAnnounceAnswer>` and `held(peerId, ref): Promise<void>`, each bounded by one `responseTimeoutMs` of the node's `LinkDeadlines`, rejecting on a timeout or reset (the caller counts that as an unconfirmed round).

## The receiver's decision

`BlobAnnounceReceiver` in `packages/db-p2p/src/blob/announce-receiver.ts`; `BlobProtocolService` calls `decide` for each `announce` and writes its answer.

```ts
export interface BlobAnnounceReceiverDeps {
	selfId: string;
	hold: 'eager' | 'on-demand';
	keyNetwork: Pick<IKeyNetwork, 'findCluster'>;
	membership?: NetworkMembershipGate;
	limiter: AnnounceLimiter;
	references: Pick<BlobReferenceCheck, 'inScope'>;
	records: BlobRecordStore;
	/** Whether every piece of `ref` is here: `LocalBlobService.stat(ref)` reporting locality `here`. */
	isWhole: (ref: BlobRef) => Promise<boolean>;
	/** Start (or join) a background fetch of `ref`; `holder` is added to its candidate holders. Resolves when whole, rejects when it gave up. */
	fetchInBackground: (ref: BlobRef, holder: string | undefined) => Promise<void>;
	client: Pick<BlobProtocolClient, 'held'>;
	log: Logger;
}

export class BlobAnnounceReceiver {
	constructor(deps: BlobAnnounceReceiverDeps);
	decide(announcer: string, ref: BlobRef, scope: BlobScope): Promise<BlobAnnounceAnswer>;
	/** Resume, after a restart, the fetch of every blob holding a `responsible` hold that is not whole. */
	resume(): Promise<void>;
}
```

`decide`, in this order (docs/blobs.md and the backlog ticket give the first five; the two guards are this ticket's):

1. `hold === 'on-demand'` → `declined`.
2. **Guard: membership.** An announcer `admittedBy` refuses → `unreferenced`, logged `announce:refused-peer`, before any lookup. (The inbound stream gate, when configured, already refused non-members; this covers a node with only a membership predicate.)
3. `findCluster(routingKeyForBlob(ref))` does not include `selfId` → `not-responsible`. A lookup that throws → `not-responsible` too (responsibility undetermined; the announcer asks again), logged `announce:cohort-unresolved`.
4. **Guard: per-peer bound.** `limiter.admit(announcer)` false → `unreferenced`, logged `announce:limited`, with no committed-state read.
5. `references.inScope(ref, scope)`: anything but `listed` → `unreferenced`. Its order inside is registry first: a scope the registry does not list is answered with no reference-tree read.
6. `isWhole(ref)` → take the `responsible` hold (below) and answer `whole`.
7. Otherwise take the `responsible` hold, record `announcer` as awaiting `held` for `ref`, call `fetchInBackground(ref, announcer)` without awaiting it, and answer `fetching`.

The `responsible` hold is written and the key-value store flushed **before** the answer is sent, so a restart after `fetching` keeps the hold (and `resume` finishes the pull). The hold carries the scope it was verified under — change the record's `responsible` hold, as `feat-a-node-stores-blob-pieces` defined it, to `responsible?: { scope: BlobScope }` (absent when not held), since the cohort reaction re-announces with it. A second verification under another scope replaces the scope; either authorizes.

When a background fetch resolves, send `held` to every announcer recorded for that ref (in-memory `Map<BlobRef, Set<string>>`, cleared for the ref when its fetch settles), skipping any the membership gate now refuses; a send that fails is logged (`held:send-failed`) and not retried — the announcer's drain re-announces and is answered `whole`. A fetch that rejects is logged (`fetch:gave-up`), keeps the hold, and drops the awaiting set; the next announcement for the ref starts a fresh fetch. `resume` enumerates records with a `responsible` hold and calls `fetchInBackground(ref, undefined)` for each that is not whole; `NodeBlobService.start` calls it off the start path (`void … .catch(log)`).

`fetchInBackground` is `BlobFetcher`'s background (lowest-priority) fetch from the prereq; if that ticket's fetch takes no extra candidate holders, add an option `holders?: readonly string[]` that is unioned with the cohort and the `stat` respondents — the announcer may be a writer outside the cohort and the only holder. A fetch already in flight for the ref is joined (the fetcher's per-ref dedup), and the new holder is added to its candidates for the next piece request.

### The per-peer bound

`AnnounceLimiter` in `packages/db-p2p/src/blob/announce-limiter.ts`: a fixed one-minute window per peer id, at most `BLOB_ANNOUNCES_PER_PEER_PER_MINUTE` (600) admitted per window; plus a node-wide limit of `BLOB_ANNOUNCE_READS_IN_FLIGHT` (4) concurrent `inScope` calls, beyond which `decide` waits its turn rather than being refused. Both constants in `protocol-limits.ts`. The per-peer map drops a peer's entry once its window has passed (checked on access) and holds at most 4096 peers, evicting the oldest window first. 600 per minute is above what an honest announcer sends: its drain examines at most 64 entries per pass with at least 15 s between passes (256 a minute), and the cohort reaction at most 64 per check with at least 60 s between checks.

### Reading committed state

`BlobReferenceCheck` in `packages/db-p2p/src/blob/reference-check.ts`:

```ts
export type ReferenceVerdict =
	| { kind: 'listed'; scope: BlobScope }
	| { kind: 'not-listed' }
	| { kind: 'uncertain'; reason: string };

export class BlobReferenceCheck {
	constructor(deps: { transactor: ITransactor; log: Logger });
	/** Registry first: a scope it does not list is `not-listed` with no tree read. Then that one tree. */
	inScope(ref: BlobRef, scope: BlobScope): Promise<ReferenceVerdict>;
	/** Every registered scope, in the registry's order, until one lists `ref`. For a reader keeping what it fetched. */
	anywhere(ref: BlobRef): Promise<ReferenceVerdict>;
}
```

It reads through `BlobScopeRegistry.enumerate()` and `BlobReferenceTree.listed([ref])` from `feat-committed-rows-register-the-blobs-they-reference`, opened over the transactor with that ticket's read-path opener (never `createOrOpen`). `listed` only with `certain: true` and the ref in the set; a scope missing from the registry is `not-listed` whether or not the enumeration was certain (either way it is not a scope this node may act on); a tree answer that is not certain, or any throw — `BlockUnavailableError`, `BlockPossiblyStaleError` or anything else — is `uncertain`, logged with the error, never swallowed silently. The receiver treats `not-listed` and `uncertain` alike: `unreferenced`, and no pull.

The transactor is the node's own `NetworkTransactor`. Nothing in `createLibp2pNodeBase` builds one today; the Quereus plugin builds it in `CollectionFactory.createNetworkTransactor`. Move that construction into db-p2p as `createNodeNetworkTransactor` in `packages/db-p2p/src/node-network-transactor.ts`, exported, taking `{ peerId, keyNetwork, coordinatedRepo, storageRepo?, protocolPrefix, linkDeadlines, localChangeNotifier?, clock? }` and returning the `NetworkTransactor` exactly as the plugin configures it today (its `getRepo` with `RepoClient` and `stateHoldingsOnReads`, the deadlines and their `NOTE:` comments moved with it). The plugin calls it (behaviour unchanged); `createLibp2pNodeBase` builds one for blob reference reads after `coordinatedRepo` is set. Rejected: a host-supplied reader option, which would leave every node built without it unable to authorize anything, and a second hand-written transactor in node-base.

## The hold option and peers without the protocol

`NodeOptions.blobs.hold?: 'eager' | 'on-demand'`, default `'eager'`, added to the `blobs` option object the prereqs introduced, passed to the receiver and to `NodeBlobService`. An `'on-demand'` node answers every announcement `declined`, never takes a `responsible` hold, and still holds what it put, pinned or read.

`packages/db-p2p/src/blob/accepts-blobs.ts`:

```ts
/** What this node knows about whether `peerId` accepts blobs, from its peer-store protocol list. */
export type BlobAcceptance = 'accepts' | 'refuses' | 'unknown';
export function blobAcceptanceOf(peerStore: Pick<PeerStore, 'get'>, peerId: string, blobProtocol: string): Promise<BlobAcceptance>;
```

`accepts` when the protocol list includes the blob protocol; `refuses` when the peer is in the store with a list that lacks it (an older build: docs/blobs.md §Compatibility); `unknown` when it is not in the store or the read throws (not yet identified). `BlobProtocolClient.announce` and `held` refuse to dial a `refuses` peer (rejecting with `BlobPeerRefusesError`, a plain `Error` subclass in the same module) — dialing it would fail protocol negotiation anyway. The copy drain and durability count use the three values in the next ticket.

## Readers keep what they fetch

docs/blobs.md §Placement, copying and durability, "Readers repair". In `NodeBlobService`, when a `read` or `fetch` that fetched pieces from the network leaves the blob whole here, and `hold === 'eager'`, and `findCluster(routingKeyForBlob(ref))` includes this node, run `references.anywhere(ref)` in the background (after the read has yielded its bytes; never on the read path). On `listed`, add the `responsible` hold with the scope found and remove the `cached` hold; otherwise leave the `cached` hold. Log `read:kept-responsible`.

## Edge cases & interactions

- **Unregistered scope.** `unreferenced` with no reference-tree read (test).
- **Committed state unreadable.** A tree read throwing `BlockUnavailableError` or `BlockPossiblyStaleError`, or a non-certain answer: `unreferenced`, no fetch started, no hold taken (test for the stale case; inspection for the rest, which share the branch).
- **Announce before the receiver can see the commit.** `unreferenced`; the announcer asks again (covered end to end in the drain ticket).
- **On-demand.** Always `declined`, before any lookup (test).
- **Not in the cohort by this node's own view.** `not-responsible`, no reads (inspection: step 3 precedes all reads).
- **Hostile announcer.** Flooding real referenced blobs is bounded by the limiter; flooding unreferenced ones costs registry reads within the same bound and fetches nothing. Malformed refs or oversize scopes are refused before any work. Inspection.
- **Crash after `fetching`.** The hold was flushed before the answer; `resume` restarts the pull from missing pieces (the fetcher resumes by construction). Inspection plus the restart test in the drain ticket.
- **Two announcers, one fetch.** Both recorded; one fetch (fetcher dedup); both sent `held`. Inspection.
- **A `held` from a non-member.** The service drops it before calling the sink (inspection). In this ticket the sink only logs `held:received`; the drain ticket wires it.
- **The pin and cached holds are untouched** by announcements, except that reader repair converts `cached` to `responsible`. Inspection.
- **The plugin's transactor is unchanged** by the move into `createNodeNetworkTransactor`: the plugin's existing suites are the check.

## Tests

In `packages/db-p2p/test/blob-announce-receiver.spec.ts`, over a real `BlobRecordStore` on a `MemoryKVStore`, real `BlobScopeRegistry` and `BlobReferenceTree` over db-core's `TestTransactor` (wrapped to count reads of the reference tree's blocks), and a key network double returning a fixed cohort (the pattern the drain specs use):

- Each early answer in order: `on-demand` → `declined`; cohort without self → `not-responsible`; scope not registered → `unreferenced` with zero reference-tree reads. One table-driven case.
- A reference tree read that throws `BlockPossiblyStaleError` → `unreferenced`, no fetch started (`fetchInBackground` bound to a recorder), no hold written.
- A listed, not-whole blob → `fetching`, the `responsible` hold with its scope is in the store before `decide` resolves, and `held` is sent to the announcer when the bound fetch resolves.

One two-node test (in the harness `feat-blob-pieces-move-between-machines` used for its transfer tests): node B is responsible, the scope is registered and lists the ref; A puts the blob and calls `BlobProtocolClient.announce` to B; B answers `fetching`, pulls, and A's `held` sink sees B. This pins the wire round trip.

One test of reader repair: an eager node in the cohort reads a referenced blob it did not hold; afterwards its record has the `responsible` hold and no `cached` hold.
