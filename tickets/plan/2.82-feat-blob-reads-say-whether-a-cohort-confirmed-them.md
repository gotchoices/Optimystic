# Block reads say whether a cohort confirmed them

docs/blobs.md §Lifetime lets a machine release a blob only on "a certain answer", and excludes "a read that rested on asking nobody, unless the node is alone by the test the offline queue's reachability gate applies". The read path cannot say that today. A coordinator whose view of a block's cohort holds only itself answers an absent block as authoritatively absent, unflagged (`unasked` in `CoordinatorRepo`, docs/internals.md "A block read has three answers"), and serves a held block from its own copy for a whole read-repair window armed by that same self-only exit. A caller receives the same `GetBlockResult` it would have received after the whole cohort answered. So a node that merely cannot see its cohort, and a node that really is the only machine, are indistinguishable from the reader's side, and so are both from a node whose cohort confirmed the answer.

This ticket adds the smallest piece that lets `feat-unreferenced-blobs-are-reclaimed` tell the three apart: a positive per-answer marker set by the answering coordinator when a cohort member outside it vouched for the answer, a per-read request field that makes the answering coordinator run a window-demanded consult before answering instead of behind the answer, and a method on the reachability gate that says whether this node is alone for given blocks. No existing behaviour changes: nothing reads the marker except the reclaim pass, and the request field is set only by it.

## Design

### Wire fields (`packages/db-core/src/network/struct.ts`)

```ts
// On BlockGets:
/** The asker wants each block's answer to rest on a consult made for this read wherever the read
 *  path would otherwise answer from the coordinator's own copy and consult behind the answer: a held
 *  block whose lazy read-repair window has expired, or that `readRepairSampleRate` picked, is consulted
 *  BEFORE it is answered, as under `'paranoid'`. Reads inside the window are answered as before. Set
 *  only by the blob reclaim pass, whose reads must be confirmable (`GetBlockResult.cohortConfirmed`).
 *  Whole-read, forwarded on every batch like `skipWindowConsult`. A peer that predates the field ignores
 *  it and answers as before, without the marker, which the asker reads as unconfirmed. When both are
 *  set, `awaitConsult` wins. */
awaitConsult?: true;

// On GetBlockResult:
/** Set by the answering coordinator when at least one cohort member other than itself vouched for this
 *  answer: the consult made for this read, or the one that armed the read-repair window the answer was
 *  served under, heard from EVERY member of the coordinator's non-self cohort view, at least one such
 *  member exists, and nothing it heard is ahead of what is served; or the window was armed by a commit
 *  that another cohort member co-signed. POSITIVE on purpose: absent means "not known to be confirmed",
 *  so an answer from a repo that predates the field, a `TestTransactor`, a solo-self consult, a consult
 *  with a silent member, a background consult or a sync read all read as unconfirmed. Never set beside
 *  `unavailable` or `unconfirmedAheadRev`. Nothing but the blob reclaim pass reads it. */
cohortConfirmed?: true;
```

`downstreamGets` in `packages/db-core/src/transactor/network-transactor.ts` forwards `awaitConsult` exactly as it forwards `skipWindowConsult`. `narrowBlockGets` in `packages/db-p2p/src/repo/get-reply.ts` already spreads the remaining fields, so a later packing round carries it (inspection). `NetworkTransactor.get`'s merge keeps each chosen entry whole, so the marker travels with the entry it describes; it plays no part in ranking or in `isAuthoritative` (inspection).

### `CoordinatorRepo` (`packages/db-p2p/src/repo/coordinator-repo.ts`)

**The stamp records whether it vouches.** `FreshnessStamp` gains `vouched?: true`. `markBlocksSeen` changes to take one object so every caller states it:

```ts
private markBlocksSeen(blockIds: readonly BlockId[], basis: { vouched: boolean; floor?: number; quiet?: QuietCohort }): void;
```

Callers and the value each passes:

| Caller | `vouched` |
|---|---|
| `fetchBlockFromCluster`'s solo-self exit | `false` |
| `fetchBlockFromCluster`'s `cohort-too-small` arming, local-current exit and convergence exit | the consult's `vouched` (below) |
| `noteCohortCommitApplied` | `applied.cohortSize > 1` |
| the cluster commit path's three `armFreshness` sites | `true` (that path runs consensus with at least one other member) |
| `commitSolo` | `false` |

**`fetchBlockFromCluster` returns `vouched: boolean`**, a required field so an exit added later must state it:

```ts
/** Every member of the non-self cohort view answered, at least one exists, nothing heard is ahead of
 *  what this node serves, and no peer claimed the block exists when this node holds none. */
function consultVouches(answered: readonly string[], silent: readonly string[], currency: CurrencyVerdict, absence: AbsenceVerdict): boolean {
	return answered.length > 0 && silent.length === 0 && currency.kind === 'nothing-ahead' && absence !== 'claimed';
}
```

The no-callback, empty-cohort and solo-self exits return `false`; the three consult exits return `consultVouches(...)` with their own `absence` and `currency`. Partial silence does not vouch, although the read path serves it unflagged and arms the window on it: a silent member may hold a revision the others missed, and the one consumer of this marker deletes data.

**`readRepairBlock` sets the marker** through one helper, called last on each path after every flag has been applied:

```ts
/** Set `cohortConfirmed` on `results[blockId]` when `vouched` and the entry carries neither
 *  `unavailable` nor `unconfirmedAheadRev`. */
private markCohortConfirmed(results: GetBlockResults, blockId: BlockId, vouched: boolean): void;
```

| Path in `readRepairBlock` | `vouched` passed |
|---|---|
| inside the window (`!isMissing && !isStale`) | `readRepairMode !== 'off' && stamp?.vouched === true` |
| `skipWindowConsult` | not called |
| quiet span vouches | `stamp.vouched === true` |
| background consult | not reached when `awaitConsult` is set; otherwise not called |
| blocking consult | the `vouched` `fetchBlockFromCluster` returned |
| consult threw | not called |

`get` without `clusterLatestCallback`, and a `skipClusterFetch` read, never set it. Under `readRepairMode: 'off'` no held block is ever consulted, so no held block is confirmed; the reclaim pass on such a node counts only when the node is alone.

**`awaitConsult`.** In `readRepairBlock`, `const background = windowOnly && !this.awaitWindowConsults && !blockGets.awaitConsult;`, and the `skipWindowConsult` early return is skipped when `awaitConsult` is set. Nothing else changes: the blocking path already runs the consult, logs it, refreshes the entry and records the stamp.

### `KeyNetworkCohortReachability.aloneFor` (`packages/db-p2p/src/network/cohort-reachability.ts`)

```ts
/** True when, for every distinct block, `findCluster` assembles exactly this node and the self-only
 *  view passes the test `reachable` applies to one (`whyNotAlone`: no remembered serving member
 *  missing, no bootstrap peer awaited, no identify in flight). False when any cohort names another
 *  member — unlike `reachable`, which answers true then — is empty, or its lookup throws. Never throws. */
async aloneFor(blockIds: readonly BlockId[]): Promise<boolean>;
```

Implemented over a private `judgeAlone(blockId): Promise<UnreachableReason | 'other-members' | undefined>` sharing `whyNotAlone`; a false answer logs `reachability:not-alone reason=%s block=%s` once per call, for the first block that failed. It does not touch `lastAnswer` or the listeners.

Why a second method rather than `reachable`: an unconfirmed answer is acceptable only from a node that is alone. `reachable` is also true when the cohort names another member, which is exactly when an unconfirmed answer must not count (that member was not asked, or did not vouch).

## Edge cases & interactions

- **A node alone in its view with a remembered member missing.** Absent answers are `unasked` and unmarked, held blocks are served under a solo-self stamp and unmarked, and `aloneFor` is false (`absent-members`). Test (solo-self case) plus the `aloneFor` test.
- **A genuine one-machine deployment.** Answers are unmarked; `aloneFor` is true. The reclaim pass relies on that pair. Covered by the `aloneFor` test and the reclaim ticket's one-machine test.
- **A window armed by a full consult, then a read inside it.** Marked. Test.
- **A consult with one silent member.** Served unflagged as today, not marked. Test.
- **Window expired, lazy mode.** Without `awaitConsult`, unchanged (answered at once, consult behind, not marked). With it, consulted first and marked when the consult vouches. Test.
- **Floor-demanded consults and `'paranoid'`.** Already blocking; marked by the consult's verdict. Inspection.
- **A remote coordinator.** Its answer carries its own marker over the wire, set by the same code. A remote that predates the field sends none: unconfirmed, the safe reading. Inspection.
- **The marker never sits beside a doubt marker.** `markCohortConfirmed` checks both. Inspection.
- **Existing behaviour.** No caller other than the reclaim pass sets `awaitConsult`, and nothing branches on `cohortConfirmed`; the existing coordinator-repo suites pass unchanged except where they call `markBlocksSeen`'s old signature through a test seam (`setLastSeenForTest` keeps writing an unvouched stamp).
- **Cost.** `awaitConsult` makes an expired window's consult block the read; it is set only by a pass that runs every few hours. Inspection.

## Tests

`packages/db-p2p/test/coordinator-repo-cohort-confirmed.spec.ts`, constructing `CoordinatorRepo` over a real `StorageRepo` with a key-network double and a `clusterLatestCallback` the test controls, as `packages/db-p2p/test/coordinator-repo-solo-read-repair-window.spec.ts` does:

- **A whole cohort's answer is marked.** A missing block whose two other cohort members both answer "holds nothing": the absent answer carries `cohortConfirmed`. A held block read again inside the window that consult armed: marked.
- **A silent member leaves a present answer unmarked.** A held block, window expired, `awaitConsult`: one member answers at the same revision, the other's callback rejects. The answer has no `unavailable`, no `unconfirmedAheadRev` and no `cohortConfirmed`.
- **A self-only view is never marked.** Cohort view is this node alone: the absent answer for a missing block is unmarked; a held block read twice (the first read takes the solo-self exit and arms the window, the second is served inside it) is unmarked both times.
- **`awaitConsult` consults before answering.** Lazy mode, `awaitWindowConsults` false, a held block whose window has expired, a cohort whose callback answers at the same revision. Without the field the read returns before the callback is called and is unmarked; with it the callback has been called when the read returns and the answer is marked.

`packages/db-p2p/test/cohort-reachability.spec.ts`, one case: for a block whose cohort is this node and another, `reachable` is true and `aloneFor` false; for a self-only cohort with nothing absent and nothing awaited, both are true; with `absentCohortMembers` returning a peer, `aloneFor` is false.
