# The drain's scheduling is shared

docs/blobs.md §Placement, copying and durability requires a second drain — one that announces blobs to the members of their cohort — with "the same schedule, give-up rule and membership filter as `UnderReplicationDrain`", and requires the two to share that scheduling code rather than repeat it. Today all of it lives inside `UnderReplicationDrain` in `packages/db-p2p/src/repo/under-replication-drain.ts`, typed to block ids and to its ledger. This ticket extracts it into a generic class, `DrainScheduler`, and rebuilds `UnderReplicationDrain` on it with no change in behaviour. The blob drain (`feat-blob-owed-copies-are-drained`) is the second user.

The neighbouring backlog ticket `debt-three-sites-repeat-the-certified-push-loop` records that the block push loop is already shared (`pushBlockToPeers`). That loop is not part of this extraction: the blob drain does not push content, it announces, and the receiver pulls. What is shared here is everything *around* the per-entry work.

## What moves, and what stays

Moves into `DrainScheduler` (all of it is in `UnderReplicationDrain` today, and moves verbatim except for renamed identifiers):

- the triggers: `start` (one pass off the start path), a new `wake()` that schedules a pass exactly as a connection event does (the blob drain calls it when an entry is added; the block drain does not use it), `connection:open`, `peer:identify`, the self-arming re-check timer while the source reports anything outstanding, and `checkNow` (`manual`);
- the debounce (`debounceMs`), the minimum interval (`minIntervalMs`, a trigger inside it is deferred to its end, never dropped), the one-timer-pulled-earlier rule (`armTimer`), and pass serialization (`run`, `passInFlight`, `pendingTrigger`);
- partition suppression: a pass during `detectPartition()` does no work and returns `skipped: 'partition'`;
- the eligible-peer set: connected peers, deduplicated, admitted by the membership gate (`admittedBy`), and — when a protocol id is given — listing it in the peer store (today `pushablePeers` and `servesBlockTransfer`);
- the per-pass cap with the rotation cursor (`takeBudget`);
- the give-up rule: consecutive unconfirmed rounds per (entry, peer), abandoned at `maxAttempts` until the peer reconnects (`countFailure`, `forgetPeer`, `forgetDisconnected`, `forgetBlock`, `pruneState`), with the "fresh connection is the peer's only connection" rule and its `NOTE:` kept word for word;
- the pass log lines (`throttled`, `pass:skip`, `pass:done`, `peer:abandoned`), written through the logger the owner hands in so they stay under the owner's namespace.

Stays in `UnderReplicationDrain` (the block seam): resolving who an entry owes (`resolveOwedPeers`), the push (`BoundBlockPusher`), ledger writes (`noteAttempt`, `delete`, `takeConfirmedCopies`), the per-entry log lines (`push:ok`, `push:rejected`, `push:unreachable`, `entry:*`), and the mapping from the scheduler's report to the existing `DrainPassResult`.

## Design

New module `packages/db-p2p/src/repo/drain-scheduler.ts`, exported from `packages/db-p2p/src/index.ts`. Location: beside its first user; the blob drain imports it from there.

```ts
import type { Connection, Libp2p, Startable } from '@libp2p/interface';
import type { PartitionDetector } from '../cluster/partition-detector.js';
import type { NetworkMembershipGate } from '../network-membership-gate.js';
import type { Logger } from '../logger.js';

/** What woke a pass. Moved here from under-replication-drain.ts, which re-exports it. */
export type DrainTrigger = 'start' | 'connection' | 'identify' | 'recheck' | 'manual';

/** The slice of libp2p a drain uses. Moved here; under-replication-drain.ts re-exports it. */
export type DrainLibp2p = Pick<Libp2p, 'peerId' | 'addEventListener' | 'removeEventListener' | 'getConnections'> & {
	peerStore: Pick<Libp2p['peerStore'], 'get'>;
};

export interface DrainSchedulerConfig {
	debounceMs: number;
	minIntervalMs: number;
	/** `0` disables. */
	recheckIntervalMs: number;
	/** Entries examined per pass, rotating. */
	entryBudget: number;
	/** Consecutive unconfirmed rounds per (entry, peer) before the peer is abandoned for that entry. */
	maxAttempts: number;
}

/** Seam 1: what is owed. Read once per pass. */
export interface DrainEntrySource<TEntry> {
	/** Every outstanding entry, oldest first. */
	list(): Promise<readonly TEntry[]>;
	/** Outstanding count; must be cheap once warm — it decides whether the re-check timer re-arms. */
	size(): Promise<number>;
	/** A stable string key per entry; the give-up counters are keyed by it. */
	keyOf(entry: TEntry): string;
}

/** What the scheduler lends one entry's drain step. */
export interface DrainEntryContext<TTally extends string> {
	/** `candidates` filtered to this pass's eligible peers, minus those abandoned for this entry. */
	reachable(candidates: readonly string[]): string[];
	/** One unconfirmed round for `peerId` on this entry. Returns true when it abandoned the peer now. */
	noteFailure(peerId: string): boolean;
	/** `peerId` confirmed: its consecutive-failure count for this entry resets. */
	noteSuccess(peerId: string): void;
	/** The entry has left the source (settled, dropped): forget its counters now. */
	forgetEntry(): void;
	/** Count one outcome toward this pass's report. An entry may tally several. */
	tally(outcome: TTally): void;
}

/** Seam 2: the per-entry work. Never throws for an expected outcome; a throw is logged as a pass error. */
export type DrainEntryStep<TEntry, TTally extends string> = (entry: TEntry, context: DrainEntryContext<TTally>) => Promise<void>;

export interface DrainSchedulerDeps<TEntry, TTally extends string> {
	libp2p: DrainLibp2p;
	partitionDetector: Pick<PartitionDetector, 'detectPartition'>;
	/** Absent → no membership check. */
	membership?: NetworkMembershipGate;
	/** A peer counts as eligible only once its peer-store protocol list includes this id. Absent → every connected admitted peer. */
	protocol?: string;
	source: DrainEntrySource<TEntry>;
	drainEntry: DrainEntryStep<TEntry, TTally>;
	/** Every tally the step may report, in the order `pass:done` prints them. */
	tallies: readonly TTally[];
	/** The word `peer:abandoned` uses for an entry key (`block`, `blob`). */
	entryLabel: string;
	log: Logger;
	/** Called with a peer's id when its only connection opens (after its give-up state is forgotten). */
	onPeerReturned?: (peerId: string) => void;
}

export interface DrainPassReport<TTally extends string> {
	trigger: DrainTrigger;
	skipped?: 'partition' | 'no-eligible-peer';
	entries: number;
	examined: number;
	deferred: number;
	/** Peers newly abandoned for an entry this pass. */
	abandoned: number;
	tallies: Record<TTally, number>;
}

export class DrainScheduler<TEntry, TTally extends string> implements Startable {
	constructor(deps: DrainSchedulerDeps<TEntry, TTally>, config: DrainSchedulerConfig);
	start(): Promise<void>;
	stop(): Promise<void>;
	checkNow(): Promise<DrainPassReport<TTally>>;
	/** Ask for a pass through the debounce and the interval throttle (trigger `manual`), for an owner that just added an entry. A no-op while stopped. */
	wake(): void;
	getDiagnostics(): { abandonedPairs: number; timerArmed: boolean; lastPassAt: number };
}
```

The `pass:done` line is built as `pass:done trigger=%s entries=%d examined=%d deferred=%d` followed by `<tally>=%d` for each name in `tallies` order and then `abandoned=%d`; with the block drain's tallies `['solo', 'waiting', 'pushed', 'cleared', 'dropped']` that is the exact text the block drain prints today, which `docs/debugging.md` documents.

`UnderReplicationDrain` keeps its public surface unchanged — constructor signature, `UnderReplicationDrainDeps`, `UnderReplicationDrainConfig` with its `blockBudget` field and defaults, `DEFAULT_UNDER_REPLICATION_DRAIN_CONFIG`, `DrainPassResult`, `checkNow`, `getDiagnostics`, `start`, `stop`, and the re-exported `BlockDurabilitySink`, `DrainTrigger` and `DrainLibp2p` — because `NodeOptions.underReplicationDrain` is typed from the config and the existing spec constructs the deps. Internally it holds one `DrainScheduler<UnderReplicatedEntry, 'solo' | 'waiting' | 'pushed' | 'cleared' | 'dropped'>`, passes `entryBudget: config.blockBudget`, `protocol: buildBlockTransferProtocol(prefix)` only when `protocolPrefix` is set (today's rule), `source` over the ledger (`keyOf: entry => entry.blockId`), `entryLabel: 'block'`, its own `log`, and `drainEntry` = today's `drainEntry` body rewritten over the context (`reachable`, `noteFailure` replacing `countFailure`, `noteSuccess` replacing `this.failures.get(...).delete(peerId)`, `forgetEntry` replacing `forgetBlock`, `tally` replacing the counter increments). `checkNow` maps a `DrainPassReport` to a `DrainPassResult`: the five tallies by name, `abandoned`, the counts, and `skipped: 'no-eligible-peer'` mapped to `'no-pushable-peer'`.

Rejected: a base class the two drains inherit from. Composition keeps each drain's own deps and logger, keeps `UnderReplicationDrain`'s surface byte-for-byte, and lets each seam be bound in one place.

## Edge cases & interactions

- **Behaviour unchanged for blocks.** Every existing case in `packages/db-p2p/test/under-replication-drain.spec.ts` — named and unnamed entries, give-up and reconnect, partition skip, budget rotation, deferred triggers, re-check timer lapse, listener registration — passes with the spec file untouched. That suite is the verification; do not edit it.
- **A step that throws.** Today a throw out of `drainEntry` rejects the pass, which `maybeRun` logs (`pass error trigger=…`), and the `finally` still stamps the throttle (when the ledger was scanned) and re-arms the re-check. Keep exactly that: the scheduler does not catch per entry. Inspection.
- **Stop mid-pass.** The pass checks `running` between entries and bails, and `stop` does not await it (a push deadline must not hold a stop). Preserved. Inspection.
- **Give-up state across entries leaving.** `pruneState` drops counters for keys the source no longer lists; `forgetEntry` drops them at once. Preserved, now keyed by `keyOf`. Inspection.
- **Two schedulers on one libp2p.** Each registers and removes its own listeners; nothing is static or module-level. Inspection (the blob drain is the second instance).
- **Log namespace.** Lines keep the `under-replication-drain` namespace because the scheduler writes through the logger it is handed. Inspection against `docs/debugging.md`.
