GitHub #53 (kjeib); `gh issue view 53` has the repro script, about 30 s to run. All numbers below are the reporter's: sereus 1.20.0, optimystic 1.23.0, quereus 4.24.0, Node 24, file journal.

One machine, one transaction of one row plus three child rows, one secondary index:

| 200 transactions, ms per transaction by batch of 25 | |
|---|---|
| online | 11 12 13 13 13 12 13 13 |
| offline, back to back (the queue grows) | 54 67 69 79 86 94 98 115 |
| offline, each sent before the next (queue depth at most 1) | 79 81 82 83 83 84 87 90 (commit plus its send) |

Two effects: an offline commit with an empty queue costs about 4× an online one, and each commit slows with queue depth (54 → 115 ms across 200 queued). Sereus Health saw 118 ms per row loading 660 rows offline and now runs bulk imports online to avoid it.

CPU profile of the back-to-back run (32 s total, 38% idle): `structuredClone` 9.9 s, about half the busy time; `TextEncoder.encode` 1.6 s; `jsonEncodedBytes` 0.7 s. The `structuredClone` callers are `Tracker.tryGet` (about 5.8 s, several stacks), `CacheSource.tryGet` (1.1 s) and `CacheSource.peek` under `Tracker.pinBase` (0.4 s). One B-tree path step copies one block several times through stacked trackers and the cache. The reporter's guess that the layering is offline-specific has not been checked against the source.

## Expected

A commit in offline mode costs the same order as an online one, and its cost does not grow with the number of transactions queued ahead of it. A drain's own cost is a separate number: `Collection.commitHead` replays what is still staged after every head commit, and a `NOTE:` at that call already says this makes a drain quadratic in the queue length and names the remedy. This report may be the condition that note was waiting for; say so if it is.

## Constraints

The clones exist for reasons: `docs/internals.md` §Mutation Contracts, and callers apply operations to what a read returns. Removing one needs either proof its caller does not mutate, or a read-only path for callers that only read. The block contents a retry sends must stay byte-identical (`packages/db-core/test/retry-resends-identical-transforms.spec.ts`).

Measure before and after, with the reporter's shape at the plugin layer, and report the numbers in the implement handoff. Say how you measured; no unmeasured magnitudes.
