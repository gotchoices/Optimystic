# Blob protocol: frames, `stat` and `get`

docs/blobs.md designs native large-value ("blob") support. After `feat-a-node-stores-blob-pieces` a node stores a blob's 256 KiB pieces in an `IPieceStore` and answers `node.blobs.stat`/`read` from its own store. This ticket adds the wire half that the later fetcher (`feat-blob-fetcher-verifies-and-resumes`) and the network read (`feat-blob-pieces-move-between-machines`) build on: one new libp2p protocol, `${prefix}/db-p2p/blob/1.0.0`, its framing, a server that answers `stat` and `get`, and a client that sends them. It is the first protocol in this repository that carries several frames per stream and raw byte frames, so it does not use `ProtocolClient` (one JSON request, one JSON reply, one resend on a failed prepared stream) and brings its own frame reader, flow control and a deadline measured on progress instead of on the whole exchange.

Nothing here fetches, verifies or stores a piece; the client hands the caller each piece's bytes as they arrive and the caller decides. The server serves only what its piece store holds.

## Protocol id and registration

In `packages/db-p2p/src/blob/blob-protocol.ts`:

```ts
const BLOB_PROTOCOL_PATH = '/db-p2p/blob/';
const BLOB_PROTOCOL_VERSION = '1.0.0';
/** `${prefix}/db-p2p/blob/1.0.0`, the same shape as `buildBlockTransferProtocol`. */
export const buildBlobProtocol = (protocolPrefix: string = ''): string =>
	`${protocolPrefix}${BLOB_PROTOCOL_PATH}${BLOB_PROTOCOL_VERSION}`;
```

The node registers it through a new `blob` entry in the `services:` map of `createLibp2pNodeBase` (`packages/db-p2p/src/libp2p-node-base.ts`), beside `blockTransfer`, with `protocolPrefix: \`/optimystic/${options.networkName}\`` and `...inboundAuthorization` spread into its init exactly as the four database services do. The service registers its handler only through `registerProtocolHandler` (`packages/db-p2p/src/network/register-protocol-handler.ts`), which `test/dial-options-single-site.spec.ts` enforces, and which also accepts streams over limited relay connections.

The service needs, at construction time inside the `services` factory, the node's `LocalBlobService` (for `stat`) and `IPieceStore` (for `get`), both from `feat-a-node-stores-blob-pieces`. If that ticket constructs them after `createLibp2p`, move their construction above `createLibp2p`, next to `storageRepo`: they depend only on the resolved piece store and key-value store, which exist by then.

**Not in `preparedStreamProtocols`.** `preparedStreamProtocols` in `libp2p-node-base.ts` stays at four entries, and a comment there says why: a prepared stream exists to save one negotiation round trip on a small request, and `ProtocolClient` resends a request once when such a stream fails before the reply begins, which assumes a small idempotent request and a single reply. A blob `get` moves up to 16 pieces; one round trip is negligible against that, the client here does not go through `ProtocolClient`, and a pool would keep an idle blob stream per peer open for 30 s after every request. `Libp2pKeyPeerNetwork.connect` already returns a fresh stream for a protocol the pool does not list (`PreparedStreams.take` finds nothing, `replenish` ignores it), so no other change is needed.

## Wire

Every frame is an unsigned varint length followed by that many bytes: the `it-length-prefixed` format every other db-p2p protocol uses. A header frame's bytes are UTF-8 JSON; a piece frame's bytes are the piece, unencoded.

```ts
/** First and only frame the requester sends. `announce` and `held` are reserved for feat-a-referenced-blob-is-copied-to-its-cohort; they are decoded and answered here so the wire does not change later. */
export type BlobRequest =
	| { kind: 'stat'; refs: string[] }                  // 1..MAX_BLOB_STAT_REFS canonical references
	| { kind: 'get'; pieces: string[] }                 // 1..MAX_BLOB_GET_PIECES canonical piece ids, no duplicates
	| { kind: 'announce'; ref: string; scope: string }
	| { kind: 'held'; ref: string };

export type BlobLocalHolding = 'whole' | 'partial' | 'none';
export type BlobAnnounceAnswer = 'whole' | 'fetching' | 'declined' | 'not-responsible' | 'unreferenced';

/** First frame the responder sends. */
export type BlobAnswer =
	| { kind: 'stat'; holdings: BlobLocalHolding[] }    // positional: holdings[i] answers refs[i]
	| { kind: 'get'; held: boolean[] }                  // positional: held[i] answers pieces[i]
	| { kind: 'announce'; answer: BlobAnnounceAnswer }
	| { kind: 'held' }
	| { kind: 'refused'; reason: 'busy' | 'malformed' };
```

Frame sequence per request:

- `stat`: requester → `[header BlobRequest]`, then closes its write side. Responder → `[header {kind:'stat', holdings}]`, then closes.
- `get`: requester → `[header BlobRequest]`, then closes its write side. Responder → `[header {kind:'get', held}]`, then exactly one piece frame for each `held[i] === true`, in request order, then closes.
- `announce` / `held`: requester → `[header]`; responder → `[header]`, closes.
- Any request the responder will not serve: responder → `[header {kind:'refused', reason}]`, closes. `busy` means over its allowance (retry elsewhere or later); `malformed` means the request broke a rule above.

The responder reads exactly one request frame and never waits for the requester's end of stream before answering (the deadlock `BlockTransferService.handleRequest` documents). A second request frame on one stream is never read.

`encodeBlobHeader(value): Uint8Array` and `decodeBlobRequest(bytes): BlobRequest` / `decodeBlobAnswer(bytes): BlobAnswer` live in `blob-protocol.ts`. Decoding is `JSON.parse` followed by a shape check written out field by field (kind, array-ness, lengths, element types); any failure throws `BlobProtocolError`. References and piece ids are checked with the db-core parsers from `feat-blob-references-and-verified-piece-trees` (`parseBlobRef`, and its piece-id parser; if it exports none, add `parsePieceId(text): PieceId` beside `parseBlobRef` applying the same rules, since a piece id has the reference's spelling). The server answers a request that fails decoding with `refused: malformed`; the client treats an answer that fails decoding, has the wrong `kind`, or whose positional array length differs from the request as `BlobProtocolError`.

Errors, exported from `blob-protocol.ts`:

```ts
export const BLOB_TRANSFER_STALLED_CODE = 'BLOB_TRANSFER_STALLED';
/** No bytes moved on a blob stream for `ms`. Thrown by both ends. */
export class BlobTransferStalledError extends Error { readonly code = BLOB_TRANSFER_STALLED_CODE; constructor(peer: string, ms: number) }
/** The responder answered `refused`. */
export class BlobPeerRefusedError extends Error { constructor(peer: string, readonly reason: 'busy' | 'malformed') }
/** The other end broke the frame sequence: bad header, wrong kind, a frame over its cap, too many or too few piece frames. */
export class BlobProtocolError extends Error { constructor(peer: string, detail: string) }
```

`DialTimeoutError` from `protocol-client.ts` is reused for the dial.

## Frames over a libp2p 3 stream

`packages/db-p2p/src/blob/blob-frames.ts`.

**Reading.** `readBlobFrames(stream, deadline, caps)` returns an async iterator of frames. It pipes the stream (libp2p 3's `MessageStream` is `AsyncIterable<Uint8Array | Uint8ArrayList>`) through a pass-through generator that calls `deadline.touch()` on every raw chunk, then through `it-length-prefixed`'s `decode` with `maxDataLength: MAX_BLOB_PIECE_FRAME_BYTES` and an `onLength` callback that throws `BlobProtocolError` when the length about to be read exceeds the cap for the frame position (`MAX_BLOB_HEADER_BYTES` for the first frame, `MAX_BLOB_PIECE_FRAME_BYTES` after). `onLength` runs before any byte of the frame is buffered, so an oversized header is refused at its prefix. The decoder holds at most the frame being assembled plus what one transport chunk carried past it; each frame is yielded as soon as it is complete, and the consumer handles it (the caller verifies and stores a piece) before the next is decoded. A frame's bytes are taken with `Uint8ArrayList.subarray()`, which copies only when the frame spans chunks.

What libp2p queues below that is not bounded by this reader: the stream's async iterator pushes every arriving chunk into an unbounded queue and never pauses, and yamux keeps granting receive window as data arrives. The bound is therefore the request itself: a `get` names at most 16 pieces, so one stream can deliver at most 16 frames. Calling `stream.pause()` to hold the remote back was rejected: while paused, libp2p buffers incoming data up to `maxReadBufferLength` (4 MiB by default) and then resets the stream, and a yamux window grown past 4 MiB can exceed that, which would reset honest transfers of 1 MiB pieces. Record this as a `NOTE:` at `readBlobFrames`: worst case 16 pieces of 1 MiB queued per stream, 4 MiB for pieces this design writes; revisit (lower `MAX_BLOB_GET_PIECES`, or bound a get by declared child sizes) if memory on a phone shows it.

**Writing.** `sendBlobFrame(stream, payload, deadline, maxDataLength)`:

```ts
const accepted = stream.send(lp.encode.single(payload, { maxDataLength }));
deadline.touch();
if (!accepted) {
	await stream.onDrain({ signal: deadline.signal });
	deadline.touch();
}
```

`encode.single` returns a `Uint8ArrayList` of prefix and payload without copying the payload. `send` returning `false` means the transport's buffer is full; the sender waits for `onDrain` before writing again, and the wait is cut off by the same progress deadline, so a receiver whose transport stops accepting bytes makes the sender give up after one timeout instead of queueing without bound. This is the rule the `NOTE:` in `packages/db-p2p/src/cohort-topic/stream-util.ts` says a repeated writer must follow. `stream.close()` after the last frame is passed `{ signal: deadline.signal }` too, since it waits for unsent bytes to drain.

**Progress deadline.** `packages/db-p2p/src/blob/progress-deadline.ts`:

```ts
/** Aborts `signal` with BlobTransferStalledError when `touch()` has not been called for `ms`. */
export class ProgressDeadline {
	constructor(peer: string, ms: number);
	readonly signal: AbortSignal;
	touch(): void;          // records Date.now(); no timer churn
	stop(): void;           // clears the timer; idempotent
}
```

Built from an `AbortController` and one `unrefTimer` timer (Hermes has no `AbortSignal.timeout`): `touch` stores the time; when the timer fires it re-arms for the remainder if a touch happened since, and otherwise aborts. So a per-chunk touch costs one assignment. `ms` is the node's `LinkDeadlines.responseTimeoutMs` at both ends (`node.linkDeadlines`; a client and a service are built with it). The deadline measures time between any two chunks of bytes, not between pieces: a slow link that keeps delivering never trips it, and a dead one trips it within one timeout. On abort, both ends call `stream.abort(new BlobTransferStalledError(...))`.

## Server: `BlobProtocolService`

`packages/db-p2p/src/blob/blob-protocol-service.ts`, a libp2p `Startable` built by a `blobProtocolService(init)(components)` factory like `blockTransferService`.

```ts
export interface BlobProtocolServiceInit extends InboundStreamAuthorizationInit {
	protocolPrefix?: string;
}
export interface BlobProtocolServiceComponents {
	registrar: ProtocolRegistrar & { unhandle(protocol: string): Promise<void> };
	/** Local holdings only: never probes. */
	blobs: Pick<LocalBlobService, 'stat'>;
	pieces: Pick<IPieceStore, 'has' | 'get'>;
	/** LinkDeadlines.responseTimeoutMs of this node. */
	progressTimeoutMs: number;
	/** Set by feat-a-referenced-blob-is-copied-to-its-cohort. Absent: every announce is answered 'declined', as a node that takes no blobs would. */
	onAnnounce?: (fromPeer: string, ref: BlobRef, scope: string) => Promise<BlobAnnounceAnswer>;
	/** Set by the same ticket. Absent: a `held` is acknowledged and ignored. */
	onHeld?: (fromPeer: string, ref: BlobRef) => void;
}
```

Per inbound stream, in this order:

1. Derive `remotePeerId` from `connection.remotePeer.toString()` once. Run `this.authorization.deny(stream, remotePeerId)` (from `createInboundStreamAuthorization`) before reading anything; denied → return. Absent predicate → no check, as in the four database services.
2. Start a `ProgressDeadline`. Read the first frame through `readBlobFrames` (header cap) and stop iterating.
3. Decode. Malformed → answer `refused: malformed`.
4. `stat`: for each reference, `blobs.stat(ref)` and map its locality: `here` → `whole`, `partial` → `partial`, anything else → `none`. Answer.
5. `get`: take an allowance slot (per peer `MAX_BLOB_INBOUND_GETS_PER_PEER`, node `MAX_BLOB_INBOUND_GETS`, counted in two in-memory maps, released in a `finally`); none free → `refused: busy`. Otherwise `pieces.has` for each id, send the `{kind:'get', held}` header, then for each held id in order `pieces.get(id)` and `sendBlobFrame`. Read one piece at a time just before sending it, so the server holds one piece plus what the transport buffers. A piece that `has` reported and `get` then returns `undefined` for (a sweep removed it in between) breaks the promise the header made: abort the stream with `BlobProtocolError`; the client keeps what it already received.
6. `announce` → `onAnnounce` or `'declined'`; `held` → `onHeld?.(...)`, answer `{kind:'held'}`.
7. `await stream.close({ signal: deadline.signal })`; `deadline.stop()` in `finally`. Any throw → log and `stream.abort(err)`.

No reputation report on the server side: the server judges nothing it receives except the request shape.

## Client: `BlobProtocolClient`

`packages/db-p2p/src/blob/blob-protocol-client.ts`. One instance per node; per-peer state lives in callers.

```ts
export interface BlobProtocolClientInit {
	peerNetwork: IPeerNetwork;          // the node's Libp2pKeyPeerNetwork
	protocolPrefix: string;
	deadlines: Pick<LinkDeadlines, 'dialTimeoutMs' | 'responseTimeoutMs'>;
}
export interface BlobGetReply {
	held: PieceId[];                    // in request order
	notHeld: PieceId[];
	/** Yields each held piece as its frame completes, in `held` order. Must be iterated to the end or exited early (break/return), which aborts the stream. Throws BlobTransferStalledError, BlobProtocolError, or the stream's own error. */
	pieces: AsyncIterable<{ id: PieceId; bytes: Uint8Array }>;
}
export class BlobProtocolClient {
	constructor(init: BlobProtocolClientInit);
	stat(peer: PeerId, refs: readonly BlobRef[], options?: { signal?: AbortSignal }): Promise<BlobLocalHolding[]>;
	get(peer: PeerId, pieces: readonly PieceId[], options?: { signal?: AbortSignal }): Promise<BlobGetReply>;
	/** Cumulative frame bytes (length prefixes included) this client sent and received; diagnostics and the transfer measurement read it. */
	wireBytes(): { sent: number; received: number };
}
```

Both calls: refuse locally (throw `RangeError`) a list that is empty or over its cap. Open the stream with the dial deadline, send the request frame through `sendBlobFrame`, `await stream.close(...)` (write side only in libp2p 3: it resolves once the request is flushed, and reading continues), then read the answer under a `ProgressDeadline` started when the request is sent. The caller's `signal` aborts the stream with `signal.reason`. `get` resolves once the header is read; `pieces` then reads exactly `held.length` piece frames, and after the last one calls `stream.close()` (a frame after it is a `BlobProtocolError`; end of stream before it is `BlobProtocolError` 'truncated'). A `refused` answer throws `BlobPeerRefusedError`.

**Dial.** `ProtocolClient.openRequestStream` (private, in `packages/db-p2p/src/protocol-client.ts`) already opens a stream under a dial deadline, maps the timer to `DialTimeoutError` and forwards the caller's abort. Extract it into an exported module function `openStreamWithin(peerNetwork, peerId, protocol, options: { signal?: AbortSignal; dialTimeoutMs?: number; correlationId?: string }): Promise<Libp2pStream>` in the same file, keep its logging, have `ProtocolClient` call it, and have `BlobProtocolClient` call it with `deadlines.dialTimeoutMs`. Copying it was rejected (AGENTS.md: stay DRY).

## Key network: who speaks the protocol

```ts
/** Of `peerIds`, in order, those whose peerStore protocol list includes `protocol`; read through the peer record cache, so a peer with no record is left out. */
```

It reads `this.peerRecords.records(...)` exactly as `servingPeersOutside` does. `feat-a-referenced-blob-is-copied-to-its-cohort` uses the same method for "a peer whose protocol list lacks the blob protocol accepts no blobs".

## Edge cases & interactions

- **Denied peer.** A peer the `authorizeInboundStream` predicate refuses gets a reset before any frame is read. Verified by inspection of the handler order and by adding the blob protocol to `test/inbound-stream-authorization-node-wiring.spec.ts` (below).
- **Oversized header or piece frame.** Refused at the length prefix by `onLength` / `maxDataLength` before allocation. Inspection; the caps are named constants.
- **Header claims a piece and never sends it.** The client's progress deadline aborts the stream with `BlobTransferStalledError` within one `responseTimeoutMs`. Test.
- **Receiver stops reading.** The sender's `onDrain` wait is cut off by its progress deadline and the stream is aborted. Test.
- **Piece removed between `has` and `get` on the server.** Stream aborted with `BlobProtocolError`; the client sees the error after the pieces already yielded. Inspection.
- **Over allowance.** `refused: busy`; slots are released in `finally` on every exit path, including a stalled or aborted stream. Inspection.
- **Request with duplicate ids, an empty list, or more than the cap.** `refused: malformed` on the server; the client refuses to send such a list. Inspection.
- **Client exits the `pieces` iterator early.** The stream is aborted, not left half-read. Inspection.
- **Stock circuit relay.** A relayed connection with stock limits is reset after 128 KiB, under one piece; the client sees the stream error. Accepted by docs/blobs.md §Relays; nothing to do here.
- **Older peer without the protocol.** `peersServing` leaves it out; a dial to it would fail at negotiation anyway. Inspection.
- **Abort from the caller.** The stream is aborted with the caller's reason, and the deadline stopped. Inspection.
- **React Native bundle.** The new files import only `it-length-prefixed`, `uint8arraylist` types, libp2p interface types and db-core. `yarn check:rn` covers it.
