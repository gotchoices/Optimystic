# A redirect can send a reader to itself

Reported as GitHub #65 (VoteTorrent, `@optimystic/db-p2p` 1.27.0).

## What happens

A read-only browser node (FRET `profile: 'edge'`, serving no repo) sends a repo `get` for the `optimystic/schema` header to a host. The host answers with a redirect whose peer list contains the browser's own peer id. The browser picks itself, dials itself (`Can not dial self`), and the read fails as peers-unreachable. It depends on the ring seed: one seed failed 6 of 6 fresh loads in under a second, another passed 3 of 3.

## Read from the code (not run)

- **Reader.** The redirect branch of `RepoClient.processRepoMessage` picks `peers.find((p) => p.id !== currentIdStr) ?? peers[0]`, where `currentIdStr` is the peer just asked. It never excludes the local peer id, so when the asker comes first it picks itself; the "same peer" loop check only compares against the host. `ClusterClient.update` has the identical rule. Neither client holds the local peer id today (`RepoClient.create` takes the target, the peer network and the prefix).
- **Host.** `RepoService.checkRedirect` redirects to `responsiblePeerIds(keyNetwork, blockKey)` (the host's `findCluster` view) whenever the cohort is full-size and excludes the host, without removing the requesting peer. `ClusterService.checkRedirect` should be checked for the same shape.
- **Why an edge reader is in the host's cohort at all** is a separate question worth answering during the fix: `findCluster` admits a peer only when it is classified as serving this network (`membershipOf` in `packages/db-p2p/src/libp2p-key-network.ts`, from its protocol list or a remembered serving verdict). A peer that registers no repo or cluster handler should not be classified serving. If the edge node does register them, that is the gap `client-only-node` (plan) closes; if it does not, the classification is wrong somewhere.

## Expected

- A client never follows a redirect to its own peer id. When the list holds no peer other than the one just asked and self, the redirect is treated as an exclusion of that coordinator (the same outcome as any failed coordinator, so the transactor re-picks), not as a dial of self.
- A host never names the requesting peer in a redirect it sends.
- A unit test at the client reproducing the self-first redirect list.
