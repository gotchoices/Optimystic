# A wide-mesh watch test sometimes sees no notification wake

## The failure

From `packages/db-p2p`:

```
OPTIMYSTIC_INTEGRATION=1 node --import ./register.mjs node_modules/mocha/bin/mocha.js test/substrate-real-libp2p.integration.spec.ts --colors --reporter dot
```

```
AssertionError: a commit coordinated inside the storage group woke a watcher outside it by a delivered notification, with no tail read in between
+ expected - actual
-false
+true
```

Seen 2 of 10 full-file runs while implementing `client-only-node`, and 1 of 8 with that ticket's node factory swapped back to its prior version, so it predates that ticket. 0 of 3 runs of the case alone (`--grep "mesh wider than one storage group"`). It is part of `yarn test:integration`, so it can fail the release gate.

## What is known

An attempt counts only when, at the moment the wake is seen, no tail read has started since the commit and at least one frame for the topic has reached the watcher's subscriber registry. Each of the four attempts therefore failed one of the following ways:

- **No wake within 10 s.**
- **Woken by a tail read.** The watch service's tick read the tail before the notification arrived.
- **Woken with no frame counted yet.** The frame was still on its way when the wake was seen.

Nothing distinguishes these today.

The runner's triage agent began instrumenting the case and exited before its runs finished. Its instrumentation was committed by mistake in `22d81ea9` and removed again; its log is `tickets/.logs/pre-existing-error.2026-11-18T05-31-36-466Z.log`.

## Expected

The test passes every run. If the notification is genuinely lost or delayed past a tick, that is a product defect in the push path (a watcher outside the group must be woken by the push, and the tick is only the backstop), and the fix belongs there rather than in the test.

## Approach

1. Log per attempt which of the three outcomes above occurred. Also record whether a frame arrived later, within a few seconds, and whether the watcher stores the collection locally: in a mesh wider than one storage group it should not, so a `blockChangeNotifier` wake would be unexpected.
2. Run the full file 20 times or more.
3. If the frame arrives but after a tick read, the attempt loop has to synchronise with the tick, for example by waiting until a tick has just completed before committing. If no frame arrives, trace origination on the writer (`selfAppliedTail`, the cert lookup) and fan-out to the watcher's registration.
