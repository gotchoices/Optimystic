# The RPC dial deadline cannot be set per node

## Request

Sereus's gates take up to 2000 ms each to decide admission (`ADMISSION_DECISION_TIMEOUT_MS`,
cadre-core `link-budget.ts`). A cold relayed dial crosses up to two gates: the relay's and the target's.
That is application cost optimystic cannot see, and sereus does not want a per-gate allowance added
here. It will compute the totals itself and pass three values explicitly:

- `connectionManager.addressDialTimeout` = optimystic's cold-path open + 2 × 2000 ms;
- a matching `connectionManager.dialTimeout`;
- the RPC dial deadline (`dialTimeoutMs`).

Its one requirement: each of the three is individually overridable through `NodeOptions`, and an explicit
value is used exactly as given. The first two already are. The third is not.

## Today

`LinkDeadlines.dialTimeoutMs` comes only from `resolveLinkDeadlines(options.linkRoundTripMs)`, and every
client gets it as its fallback (`ProtocolClient` subclasses, block pushes). The `NodeOptions.linkRoundTripMs`
doc says "a caller's own `dialTimeoutMs`" wins. That only reaches a caller inside this package, not an
embedder.

## Proposed

- Add a node-level override, either `NodeOptions.rpcDeadlines?: Partial<RpcDeadlineDefaults>` or a
  single `NodeOptions.rpcDialTimeoutMs`. Prefer whatever matches the shape the cold-relay ticket leaves
  `LinkDeadlines` in. Apply it once, where `linkDeadlines` is resolved, so every client and every
  push that falls back to `linkDeadlines.dialTimeoutMs` sees it.
- Decide whether the response deadline gets the same override in the same change. Sereus did not ask for
  it, but it is the other half of `RpcDeadlineDefaults`, and leaving one of the two settable would be odd.
- Push deadlines that already have their own explicit fields (`pushDialTimeoutMs`) keep precedence over
  the node-level value.
- An explicit value is used as given: no floor and no derivation. Validate it the way `linkRoundTripMs` is
  validated, a finite number above zero and below the `setTimeout` ceiling, and throw otherwise.
- Docs: the `linkRoundTripMs` and `connectionManager` docs and the readme table list the new override
  beside the other two.
- Test in `link-deadlines.spec.ts` (or beside it): an explicit value replaces the derived one, and an
  invalid one throws.

## After release

Ship it in the same release as the two dial tickets; tell sereus-ec the version.
