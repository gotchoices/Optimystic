# A node reads blob references through its own transactor

First of three parts of `feat-blob-announcements-are-answered` (docs/blobs.md §Who may fetch and who may store: "A node takes a blob on another's behalf only after reading committed state and finding the reference in the scope the announcement names, and only when that scope is in the registry"). This part builds the reader. The receiver that uses it is the third part.

## The node's own `NetworkTransactor`

Nothing in `createLibp2pNodeBase` builds a transactor today; the Quereus plugin builds one in `CollectionFactory.createNetworkTransactor`. Move that construction into db-p2p, unchanged in behaviour:

```ts
// packages/db-p2p/src/node-network-transactor.ts
export interface NodeNetworkTransactorInit {
	peerId: PeerId;                    // libp2p PeerId of this node
	keyNetwork: IKeyNetwork & IPeerNetwork;  // whatever the plugin's resolveKeyNetwork returns today
	/** This node's coordinated repo; absent on a client, which coordinates nothing. */
	coordinatedRepo?: IRepo;
	/** This node's StorageRepo, so remote reads state what this node holds (`stateHoldingsOnReads`); absent on a client. */
	storageRepo?: StorageRepo;
	protocolPrefix: string;
	/** Absent: `resolveLinkDeadlines()`, the undeclared ones (a host-injected node built without `createLibp2pNode`). */
	linkDeadlines?: LinkDeadlines;
	localChangeNotifier?: IBlockChangeNotifier;
	clock?: HlcClock;
}
export function createNodeNetworkTransactor(init: NodeNetworkTransactorInit): NetworkTransactor;
```

It is the plugin's body from `const localStore = …` to the `new NetworkTransactor({ … })` return, with the `getRepo` closure (self → coordinated repo, throwing the existing "stores no blocks … a client is in no cohort" error when there is none; others → `RepoClient.create(peerId, keyNetwork, protocolPrefix)` wrapped by `stateHoldingsOnReads` when a store exists), `localPeerId: coordinatedRepo ? peerId : undefined`, and the deadline derivation. Move the comments and both `NOTE:`s with it verbatim. Type the init fields with the exact types the plugin passes today (read them off the plugin code; the shapes above name intent). Export it from `packages/db-p2p/src/index.ts`.

- The plugin's `createNetworkTransactor` keeps node creation, `registerNodeCohortReachability`, `resolveKeyNetwork` and the protocol prefix, then calls `createNodeNetworkTransactor({ peerId: node.peerId, keyNetwork, coordinatedRepo, storageRepo: node.storageRepo, protocolPrefix, linkDeadlines: node.linkDeadlines, localChangeNotifier: blockChangeNotifier, clock: node.hlcClock })`. Drop imports that become unused there.
- `createLibp2pNodeBase` builds one more, after the serving role is wired (so `coordinatedRepo` exists) and before `Object.assign(node, attachments)`, on both roles: `createNodeNetworkTransactor({ peerId: node.peerId, keyNetwork, coordinatedRepo: served?.coordinatedRepo, storageRepo: served?.storageRepo, protocolPrefix, linkDeadlines, clock: hlcClock })` — no `localChangeNotifier` (it reads, it does not watch). It is used only by the reference check below; do not attach it to the node. Rejected: a host-supplied reader option, which would leave every node built without it unable to authorize anything; and attaching it as `node.transactor`, which would invite hosts to write through a transactor whose change notifier is absent.

## `BlobReferenceCheck`

```ts
// packages/db-p2p/src/blob/reference-check.ts
export type ReferenceVerdict =
	| { kind: 'listed'; scope: BlobScope }
	| { kind: 'not-listed' }
	| { kind: 'uncertain'; reason: string };

export class BlobReferenceCheck {
	constructor(deps: { transactor: ITransactor });
	/** Registry first: a scope the registry does not list is `not-listed` with no read of that scope's tree. Then that one tree. */
	inScope(ref: BlobRef, scope: BlobScope): Promise<ReferenceVerdict>;
	/** Every registered scope, in the registry's (ascending) order, until one lists `ref`. For a reader keeping what it fetched. */
	anywhere(ref: BlobRef): Promise<ReferenceVerdict>;
}
```

Over `BlobScopeRegistry.enumerate(transactor)` and `BlobReferenceTree.listed(transactor, scope, [ref])`, both of which open read-only (`Tree.open` through `readCommittedTree`, never `createOrOpen`). The rules:

- `listed` only when the tree's listing has `certain: true` and contains `ref`. A tree listing that contains `ref` but is not certain is still `listed` (a listing is evidence of a reference; `certain` is about absences) — check `BlobListing`'s doc: "Every reference in `listed` is listed".
- A scope missing from the registry is `not-listed`, whether or not the enumeration was certain: either way it is not a scope this node may act on.
- A tree read that does not list `ref` and is not certain → `uncertain` (`reason: 'tree-uncertain'`).
- Any throw from either read — `BlockUnavailableError`, `BlockPossiblyStaleError` (which `readCommittedTree` normally absorbs) or anything else (which it rethrows) — → `uncertain` with the error's message as `reason`, logged once (`reference:read-failed scope=%s ref=%s err=%s` on `createLogger('blob:protocol')`), never swallowed silently.
- `anywhere`: registry not certain and nothing found → `uncertain`; certain and nothing found → `not-listed`; the first tree that lists it → `listed` with that scope. A tree that is uncertain is remembered, and if no later tree lists the ref the answer is `uncertain`.

Export it from `packages/db-p2p/src/index.ts`. Build one in `createLibp2pNodeBase` over the transactor above; the third part hands it to the receiver. Until then, keep it as a local the third part picks up (the implementer of this part may leave it unused with a one-line comment naming `feat-blob-announcements-are-answered`, or build it in that part instead — but the transactor is built here).

## Edge cases & interactions

- **The plugin's transactor is unchanged by the move**: same `getRepo`, same deadlines, same `localPeerId` rule, same clock. Verified by the plugin's existing suites (`yarn test` in `packages/quereus-plugin-optimystic`) and by inspection of the diff.
- **A client node** builds the transactor too: its `getRepo` hands back a `RepoClient` for every peer, and picking itself throws — the plugin's existing assertion. Inspection.
- **A collection never written** (registry or reference tree): `readCommittedTree` answers `exists: false, certain: true`, so an absent registry gives `not-listed` for every scope and an absent tree `not-listed`. Inspection.
- **No staging**: both reads open fresh handles that are never staged into; nothing this check does can write. Inspection.
- **Cost**: `inScope` is two opens (each the header and log tail) plus one enumeration pass and one descent; on a node in the trees' cohort these are local reads. Leave a `NOTE:` on `inScope`: it enumerates the whole registry to test one scope; if scopes ever number in the hundreds, read the one registry entry with a point lookup instead.

## Tests

`packages/db-p2p/test/blob-reference-check.spec.ts`, over db-core's `TestTransactor` (real `BlobScopeRegistry` and `BlobReferenceTree` written through it with `BlobScopeRegistry.register` and a `BlobReferenceTree.createOrOpen` + `stageAdd` + `tree.sync`/`replace`), with the transactor wrapped to count `get`s naming the reference tree's blocks (the tree's header block id is its collection id; count requests naming any block id that the tree's own handle reads — or simply every `get` made while `listed` runs for that scope, measured by wrapping before the call) and, for one case, to throw `BlockPossiblyStaleError` on the reference tree's header:

- A registered scope listing the ref → `listed` with that scope; `anywhere` finds it too.
- A scope the registry does not list → `not-listed`, and zero reads of that scope's tree.
- A reference-tree read that throws `BlockPossiblyStaleError` → `uncertain`.

No test of the transactor move beyond the plugin's suites.
