# The solo lines and the queued status name the lane

Last of four implement tickets from the plan `a-transaction-carries-its-lane`, and the only one with an observable change: reporting. An operator reading `commit:solo-cohort` can tell a lone write the merge stage will handle (`convergent`) from one it will not (`serializable`); an application following its queued transactions sees the same per entry. No admission rule moves: the solo path and the offline queue keep today's behaviour.

## The three solo lines

`CoordinatorRepo.commitSolo` logs `commit:solo-cohort`; the refusals of a write that asked not to be committed alone log `pend:solo-refused` and `commit:solo-refused` (docs/offline-sync.md §When to submit). Each gains a `lane` field read off the request the coordinator is handling: `PendRequest.lane` for the pend line, `CommitRequest.lane` for the two commit lines (the first ticket put the field on both so a commit line needs no memory of the pend). Omit the field when the request carries none (an older writer, or the re-send of a retained attempt), rather than inventing a value; the field's absence is then readable as "not stated". Add it to `soloLogFields` so the three lines cannot drift.

## The queued status

`EntryStatus.queued.lane` already exists in db-core (first ticket). The plugin's `QueuedTransactionStatus` `queued` variant gains `lane: Lane` beside `outlook`, present whenever the transaction is in the queue (unlike `outlook`, it needs no judgement, so it is present while `waitingFor` is `'restore'` too, read from the journal record; a record from before the field restores as `serializable`). `translate`, `translateListed` and the `entries()` listing pass it through. It is not announced on its own: it never changes for an entry's life, so there is no `lane-changed` status.

## Edge cases & interactions

- **A request with no lane field** omits the log field. By inspection of the three sites.
- **A restored transaction before it is back in the queue** reports the journaled lane, `serializable` for a record without one. By inspection of `deferredStatus`.
- **A partially committed entry** keeps one lane for every collection it wrote; the status reports it unchanged. By construction (first ticket).
- **The two docs that the pruned plan ticket is cited from** (`docs/crdt-sync.md` *When to start*) must name tickets that exist on the board or in `tickets/.pruned-tickets.jsonl` once this chain completes; `yarn lint:docs` does not check ticket names, so check by hand.
