# `node.blobs` reads, fetches and probes across machines

docs/blobs.md designs native large-value ("blob") support. Built so far: `node.blobs` is a `LocalBlobService` that answers from this machine only, nodes serve the blob protocol's `stat` and `get`, and the node builds a `BlobFetcher` (`wireBlobFetcher` in `packages/db-p2p/src/libp2p-node-base.ts`) that nothing calls yet — its result is held in an unused `_blobTransfer`. This ticket makes `node.blobs` a `NodeBlobService` that uses that fetcher, so `read` fetches what is not here as the read reaches it and honours `waitMs`, `fetch` brings the whole blob here, `stat` with `probe` asks the blob's cohort, and `onProgress` reports pieces and bytes fetched. Measuring transfer speed and wire size is the follow-on ticket `blob-transfer-is-measured`.

## Settled design decisions (differences from the plan ticket, with reasons)

- **The read's piece source is `verified: true`, so a fetched piece is hashed once, not twice.** The plan expected `readBlob` to hash each fetched piece again. It does not: the local piece source is already `verified` (docs/blobs.md §What is built — every piece in the store was produced by this node's builder or checked by the fetcher before it was stored). The network read uses the same local source, so no `NOTE:` about double hashing is needed.
- **The fetch session starts lazily, at the first piece the read finds missing.** A read of a blob that is entirely here starts no session, takes no hold, does no extra walk and looks up no cohort. A session started at the first miss is given the read's whole `offset`/`length`, so it fetches ahead through the rest of the range in batches while the read consumes. Pieces before the first miss were present and are not refetched.
- **`stat` probes only when the local answer is `unknown`.** A local `partial` stays `partial` whatever the cohort says (the plan's own rule), so asking would change nothing; `here` needs no asking.
- **The probe settles on the first positive answer.** Peers are asked in parallel; the first `whole` or `partial` answer settles it as `elsewhere` and the rest are aborted. With none, it waits for every peer to answer, fail or time out.
- **`holders` is `BlobHolderDeps`, shared with the fetcher.** `blobHolderCandidates(deps, ref, knownHolders)` already takes the candidate rule's inputs, so `NodeBlobService` takes the same `BlobHolderDeps` object the fetcher gets and calls it directly — one rule, no second closure. `wireBlobFetcher` builds the deps once and returns them with the client and fetcher.
- **Progress is reported for sessions `NodeBlobService` starts.** Every session it starts (read or fetch) goes through one private `startSession`, which keeps the per-reference counts. A piece stored by a session started on the fetcher directly (later background-copy work, if it does so) reports no progress; a later caller that wants progress for its sessions starts them through `NodeBlobService`. Counts per reference are dropped when the last of its sessions settles, so they are bounded by sessions in flight.
- **The local read path keeps one implementation.** Rather than reimplementing `read`'s last-read touch and record correction in `NodeBlobService`, `LocalBlobService` gains `readThrough(ref, options, missing)`: `read` as it is today, except that a piece not in the store is asked of `missing` instead of failing. `LocalBlobService.read` becomes `readThrough` with a `missing` that throws `BlobUnavailableError` (`not-here` for `from: 'here'`, `cohort-unreachable` otherwise — unchanged standalone behaviour).

## `LocalBlobService.readThrough`

```ts
/** Supplies a piece the local store lacks; resolves with its verified bytes or rejects with why it cannot. */
export type MissingPiece = (id: PieceId) => Promise<Uint8Array>;

/** `read`, with a piece that is not here asked of `missing` rather than failing the read. */
readThrough(ref: BlobRef, options: BlobReadOptions, missing: MissingPiece): AsyncIterable<Uint8Array>;
```

`readSource` takes the `MissingPiece` instead of a reason. The source stays `verified: true`. Everything else in `read` is shared: the signal checks between chunks, `touchLastRead`, and `correctRecord(ref, false)` when the read fails with `BlobUnavailableError`. Update the doc comments of `read`, `stat`, `fetch` and `onProgress` on `LocalBlobService`: they now describe the standalone, single-machine service, and say that `NodeBlobService` is what `node.blobs` is.

## `NodeBlobService`

`packages/db-p2p/src/blob/node-blob-service.ts`. Imports pure or type-only (it is exported from `src/rn.ts`).

```ts
export interface NodeBlobServiceDeps {
	local: LocalBlobService;
	fetcher: Pick<BlobFetcher, 'start' | 'onPieceStored'>;
	client: Pick<BlobProtocolClient, 'stat' | 'wireBytes'>;
	/** The same object the fetcher's candidate rule uses. */
	holders: BlobHolderDeps;
	/** LinkDeadlines.responseTimeoutMs: the per-peer budget of a stat probe. */
	probeTimeoutMs: number;
	/** Default Date.now (probe timing in the log line). */
	now?: () => number;
}

export class NodeBlobService implements BlobService {
	constructor(deps: NodeBlobServiceDeps);
	/** The single-machine service underneath; the blob protocol service answers from it, and tests reach its fetch door through it. */
	readonly local: LocalBlobService;
	/** Diagnostic: cumulative blob-protocol frame bytes this node sent and received (BlobProtocolClient.wireBytes). */
	wireBytes(): { sent: number; received: number };
}
```

`put`, `pin`, `unpin`, `announce` and `onDurability` delegate to `local` unchanged. The constructor subscribes once to `fetcher.onPieceStored` (see `onProgress`). No `start`/`stop`: the fetcher's and the local service's lifecycles stay where they are; a later ticket adds `start` when it needs one.

### `read(ref, options)`

- `from: 'here'`: exactly `local.read(ref, options)`.
- Otherwise: `local.readThrough(ref, options, missing)`, where `missing(id)` does:
  1. On the first call of this read, `startSession(ref, { priority: 'foreground', offset, length, waitMs, signal: readController.signal })`. `fetcher.start` is synchronous, so assign the session before any `await` and a second miss of the same read reuses it.
  2. `await session.stored(id)`, then `local.fetchStore().source.get(id)`. A rejection of `stored` (the session's `BlobUnavailableError`, `BlobCorruptError`, `RangeError`, or the signal's reason) propagates out of the read at the piece that needed it.
  3. A piece absent right after `stored(id)` resolved means something removed it under the session's `cached` hold, which nothing may do; throw an `Error` naming the reference and piece (an invariant violation, not a retryable condition).
- `readController` is an `AbortController` chained to the caller's `options.signal` (forward the caller's abort with its reason; detach the listener when the read ends). The read's `finally` aborts it, so a read that completes, throws, or whose consumer stops early (`for await` `break` calls `return`) leaves no session fetching beyond the batch already in flight — the fetcher finishes a sent request and keeps what it stores (docs/blobs.md §One request per piece). Abort it with a recognisable reason such as `new Error('blob read ended')`; the session's `fetch:failed` line will name it.
- A rejected `session.done` must never be unhandled: the fetcher already marks `done` handled, and `startSession`'s bookkeeping (below) attaches its own settle handler.

### `fetch(ref, options)`

`startSession(ref, { priority: 'foreground', waitMs: options?.waitMs, signal: options?.signal }).done`. The whole blob, foreground. A blob already whole here resolves at once (the session's first walk finds nothing missing and asks no one). `BlobFetchOptions` has only `waitMs` and `signal` today; pass through any field later added that `BlobFetchRequest` shares.

### `stat(ref, { probe })`

- Without `probe`: `local.stat(ref)`.
- With `probe`: `const here = await local.stat(ref)`. If `here.locality !== 'unknown'`, return it. Otherwise `const peers = await blobHolderCandidates(holders, ref)` and ask each in parallel: `client.stat(peerIdFromString(peer), [ref], { signal })`, each under its own `AbortController` aborted after `probeTimeoutMs` (arm with `armUnrefTimer`, cancel on settle) and also aborted when the probe settles. The first answer of `whole` or `partial` settles the probe: return `{ ...here, locality: 'elsewhere' }`. If none does, return `here`. A single peer's failure or timeout is ignored for the answer (it is counted in the log line). `size`, `heldBytes` and `durability` always come from `here`; a remote answer carries no size. Nothing is remembered between probes.
- Log `stat:probe ref=%s asked=%d answered=%d held=%s ms=%d` on a `blob:service` logger (`createLogger('blob:service')`), once per probe that asked anyone. `answered` counts peers that answered before the probe settled; `held` is the peer that answered positively, or `none`.

### `onProgress(listener)`

- `startSession(ref, request)` is the single private path for sessions `NodeBlobService` starts. It increments a per-reference session count in a `Map<BlobRef, ProgressCount>` (`{ sessions, pieces, bytes, size? }`), calls `fetcher.start`, and on `done` settling either way decrements the count and deletes the entry when it reaches zero.
- The `onPieceStored` listener: if the event's `ref` has an entry, add 1 piece and `event.bytes`; if `size` is unknown and `event.id === rootPieceId(ref)`, set it from `readBlobSize(ref, local.fetchStore().source)` (`packages/db-core/src/blob/reader.ts`; a raw root's size is its own length, a list root's is decoded once). Then emit `{ ref, piecesFetched, bytesFetched, size }` to every listener. A size lookup that throws is logged and leaves `size` absent. An event for a reference with no entry is ignored. Keep the listener synchronous apart from the one-off size read: emit after the size is resolved, but do not let a slow size read reorder events — resolve the size before counting the root piece's event, or emit the root's event once the size is known and later events after it (pick one; the simplest is to `await` the size read inside a per-reference promise chain).
- A listener that throws is logged (`progress:listener-threw err=%s`) and the others still run. `onProgress` returns an unsubscribe.

## Edge cases & interactions

- **`from: 'here'` never touches the network.** Delegates to `local.read`. Inspection.
- **Blob entirely here.** No session, no hold, no cohort lookup: `missing` is never called. Inspection.
- **Read consumer stops early / read throws.** `finally` aborts the session; a batch in flight finishes and its pieces are kept. Inspection.
- **Caller's signal.** Aborting `read` or `fetch` rejects with the signal's reason (the session forwards it to `stored` and `done`; `readThrough` also checks between chunks). Inspection.
- **Two reads of one blob at once.** Each read starts its own session; `PieceTraffic` makes them share one request per piece (pinned in `blob-fetcher.spec.ts`). Progress counts for the reference are shared and the entry lives until both sessions settle. Inspection.
- **A read range whose offset is past the end.** `readBlob` throws `RangeError` once the root list piece is here; the session's own plan throws the same, so whichever surfaces first is a `RangeError`. Inspection.
- **`waitMs`.** A read started before any holder has the bytes completes once a holder appears within `waitMs` of the last progress; without `waitMs` it fails at once with `not-held` (or `cohort-unreachable` with nobody to ask). Test.
- **A piece missing after `stored` resolved.** Thrown as an invariant violation, never as `BlobUnavailableError`. Inspection.
- **Stat probe with every candidate silent, or no candidates (cohort is only this node).** The local `unknown` stands; never `elsewhere` on silence. Inspection.
- **Stat probe timers.** Every per-peer timer is cancelled when the probe settles; nothing keeps the process alive (`armUnrefTimer`). Inspection.
- **Progress listener throws.** Logged; other listeners still called. Inspection.
- **Progress counts.** Entry deleted when the reference's last session settles, success or failure. Inspection.
- **Node stop during a read.** `fetcher.stop()` rejects the session with `Error('blob fetcher stopped')`, which surfaces from the read at the next missing piece. Inspection.
- **Stock relay.** A fetch over a relay with stock limits fails after 128 KiB (`peers-unreachable` or `cohort-unreachable`), keeps what it stored and resumes on a direct path (docs/blobs.md §Relays). Inspection; the resume is pinned in the fetcher spec.

## Tests

`packages/db-p2p/test/blob-network-read.spec.ts`, two real nodes over loopback TCP (`clusterSize: 2`, B dials A, wait until each node's `keyNetwork.peersServing(buildBlobProtocol(PREFIX), [other])` lists the other and B's `keyNetwork.findCluster(routingKeyForBlob(ref))` includes A), memory piece stores, a network name of its own. Reuse `localTcpAddr`/`until`/`concat`/`streamOf` from `blob-fetcher.spec.ts`; if that means copying them, move them to `packages/db-p2p/test/support/blob-mesh.ts` and import them from both specs instead.

- *Reads across machines, with progress*: A puts 600 KiB of deterministic bytes (three data pieces and one list piece). On B: `stat(ref)` is `unknown`; `stat(ref, { probe: true })` is `elsewhere`; reading it yields bytes equal to the input; `onProgress` reported 4 pieces, with the final event's `bytesFetched` equal to the sum of the four pieces' sizes and `size` equal to 600 KiB; afterwards `stat(ref)` is `here`. One test: these are the steps of one use.
- *`waitMs` keeps a read alive until a holder appears*: compute the reference of the deterministic content without storing it on A (`buildBlob` from `@optimystic/db-core` into a throwaway sink). B reads it with no `waitMs` and gets `BlobUnavailableError` reason `not-held`. Then B starts a read with `waitMs: 10_000`, and 300 ms later A puts the content; the read completes with the right bytes.

No test for `fetch` (a session's `done`, pinned by the fetcher tests), for `from: 'here'` (the local service's), or for the probe's timeout path (inspection).
