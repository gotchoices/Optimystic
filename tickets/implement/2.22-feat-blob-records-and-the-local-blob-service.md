# Blob records, the piece sweep, and the local blob service

docs/blobs.md designs native large-value ("blob") support. The format, builder and verified reader (`packages/db-core/src/blob/`) and the piece stores (`IPieceStore`, `MemoryPieceStore`, `FilePieceStore`) exist. This ticket builds the node-local half on top of them, as library code in `packages/db-p2p/src/blob/`:

- a durable **record** per blob saying why this node keeps it (its holds, docs/blobs.md §Holds);
- the **sweep** that deletes stored pieces no held blob needs, closed against the races that would delete a piece still being stored;
- `LocalBlobService`, a `BlobService` (`packages/db-core/src/blob/service.ts`) answering `put`, `stat`, `read`, `fetch`, `pin` and `unpin` from this machine alone.

Wiring it into the node (`node.blobs`, `NodeOptions.pieceStorage`) is the next ticket, `feat-a-node-stores-blob-pieces`. Fetching from other machines, announcing and durability are later tickets; their entry points exist here and say so.

Every new module is exported from `packages/db-p2p/src/index.ts`. Modules import each other directly, never through a barrel. Logging is `createLogger('blob:store')` from `packages/db-p2p/src/logger.ts`, i.e. `optimystic:db-p2p:blob:store`.

Use db-core's existing `rootPieceId(ref)` (`packages/db-core/src/blob/blob-ref.ts`) everywhere a root piece id is needed. Do not define a second one in db-p2p.

## Blob records

`blob-record.ts` holds the shape and its codec; `blob-record-store.ts` the store over the node's `IKVStore`.

```ts
/** Key prefix of every blob record in the node's IKVStore; one key per blob, `optimystic-blobs/<ref>`. */
export const BLOB_RECORD_KEY_PREFIX = 'optimystic-blobs/';
/** The owner a put with no `owner` is pinned under (docs/blobs.md §The node's blob service). */
export const DEFAULT_BLOB_OWNER = 'default';

export type BlobHold =
	| { readonly kind: 'pin'; readonly owner: string; readonly at: number }
	| { readonly kind: 'owed'; readonly at: number }
	| { readonly kind: 'responsible'; readonly at: number }
	| { readonly kind: 'cached'; readonly at: number };

export interface BlobRecord {
	readonly v: 1;
	readonly ref: BlobRef;
	/** The blob's byte size, once known. */
	readonly size?: number;
	/** Whether every piece was here when last checked. A hint: `stat` checks the pieces. */
	readonly whole: boolean;
	/** When the blob was last read here, ms since the epoch; at most `LAST_READ_RESOLUTION_MS` stale. */
	readonly lastReadAt?: number;
	/** Never empty in a stored record: a record whose last hold goes is deleted. */
	readonly holds: readonly BlobHold[];
}

export function encodeBlobRecord(record: BlobRecord): string;      // JSON
export function decodeBlobRecord(ref: BlobRef, text: string): BlobRecord; // throws BlobRecordFormatError
export class BlobRecordFormatError extends Error { constructor(readonly ref: BlobRef, reason: string) }
```

- **One key per blob**, JSON-valued like every other node record in the store. Rejected: one key per hold, which makes "every hold of this blob" a prefix listing and "is this blob held" a listing as well.
- **Holds.** At most one pin per owner and at most one hold of each other kind. `at` is when the hold was taken (the SQL ticket's 24-hour `unstaged` pin times out on it). A hold object may carry further fields a later ticket adds: the decoder validates `kind`, `at` (finite number) and, for a pin, `owner` (non-empty string), and keeps every other property as it found it, so adding a field is not a format change. An unknown `kind`, a missing required field, `v !== 1`, a `ref` that differs from the one the key names, a `size` that is not a non-negative safe integer when present, a non-boolean `whole`, a `holds` that is not an array, an empty `holds`, or text that is not JSON throws `BlobRecordFormatError`. This ticket creates only pins; `owed`, `responsible` and `cached` are created by `feat-a-referenced-blob-is-copied-to-its-cohort` and `feat-blob-pieces-move-between-machines`.
- **Namespace.** Add `BLOB_RECORD_KEY_PREFIX` to `NODE_KV_NAMESPACES` in `packages/db-p2p/src/storage/node-kv-namespaces.ts`, so a `FileKVStore` sharing the block store's directory keeps `optimystic-blobs/` out of the block listing. The name follows `optimystic-offline/`, chosen so a collection id is unlikely to share the first path segment.

```ts
/** What one `update` did. Both absent: there was no record and none was written. */
export interface BlobRecordChange {
	readonly before?: BlobRecord;
	readonly after?: BlobRecord;
}

export class BlobRecordStore {
	constructor(kv: IKVStore);
	get(ref: BlobRef): Promise<BlobRecord | undefined>;
	/** Every ref with a record. A key under the prefix whose suffix is not a reference (`isBlobRef`) is logged (`record:bad-key`) and skipped. */
	listRefs(): Promise<BlobRef[]>;
	/**
	 * Read, apply `change`, write: serialized per ref, so concurrent changes to one blob never lose
	 * one another. `change` returns the next record, or `undefined` to delete it; a record with no
	 * holds is deleted. Nothing is written when the encoding is unchanged, and nothing is deleted
	 * when there was no record.
	 */
	update(ref: BlobRef, change: (current: BlobRecord | undefined) => BlobRecord | undefined): Promise<BlobRecordChange>;
	/** `kv.flush?.()`; a store without `flush` is durable when its writes resolve. */
	flush(): Promise<void>;
}
```

**Serialization is the store's own per-ref promise chain** (a private `Map<BlobRef, Promise<unknown>>`, the entry removed when its chain drains), not `Latches` from db-core. `packages/db-p2p/src/storage/block-latch.ts` documents that `Latches.acquire(` appears exactly once in `packages/db-p2p/src`, as the discipline behind block write tokens; a second call site would break that check, and a per-instance chain is all one node's one service needs. A `change` callback that throws rejects that `update` and leaves the chain usable for the next one.

`get` and `update` read through `decodeBlobRecord`, so a malformed value under a valid key throws `BlobRecordFormatError` out of both.

## The sweep, and the race it must not lose

A piece is deleted only by the sweep, which deletes every stored piece in no held blob's tree (docs/blobs.md §Holds). Three things can make a piece live while a sweep is deciding: a `put` that has stored pieces but not yet written its record; a record written or changed after the sweep read the records (a put finishing, a `pin`); and a `put` storing a piece the sweep has just decided to delete. Each is closed explicitly.

**`SweepGate`** (`sweep-gate.ts`): an asynchronous shared/exclusive gate, writer-preferring.

```ts
export class SweepGate {
	/** Runs `fn` while no exclusive holder runs; waits while one runs or waits. */
	shared<T>(fn: () => Promise<T>): Promise<T>;
	/** Waits for every running shared holder to finish, blocks new ones, runs `fn`. One at a time. */
	exclusive<T>(fn: () => Promise<T>): Promise<T>;
}
```

Holds are never nested: a shared holder never calls `shared` or `exclusive` again (it would wait on an exclusive that waits on it). State this on the class. Two kinds of work take it shared: storing one piece, and changing one record. Neither spans an `await` on anything but its own store call. A holder whose `fn` rejects still releases the gate.

**In-progress pieces** (`InProgressPieces` in `piece-sweeper.ts`): a reference-counted set of piece ids (`add(id)`, `release(ids)`, `ids()`). A put adds an id **before** it calls `pieces.put` for it, inside the same shared hold, and releases its ids only after its record write has resolved, or when it fails.

**`PieceSweeper`** (`piece-sweeper.ts`):

```ts
export type BlobSweepResult =
	| { readonly kind: 'swept'; readonly deleted: number; readonly kept: number; readonly failed: number }
	| { readonly kind: 'aborted'; readonly reason: 'record-unreadable' | 'tree-unreadable'; readonly ref: BlobRef };

export class PieceSweeper {
	constructor(deps: { pieces: IPieceStore; records: BlobRecordStore; gate: SweepGate; inProgress: InProgressPieces; digest: BlobDigest });
	/** Called by every record change, inside its shared hold, before the write. */
	noteRecordChange(ref: BlobRef): void;
	/** Single-flight: a call while a sweep runs returns that sweep's promise. */
	run(): Promise<BlobSweepResult>;
}
```

`run()`:

1. **Start under the gate.** `gate.exclusive` creates the set `changed` of refs whose records change from now on (`noteRecordChange` adds to it while it exists). Taking the gate means every record change already running has finished, so step 3 reads it.
2. **Candidates.** Drain `pieces.list()` into an array.
3. **Live set.** For each ref of `records.listRefs()`: read its record (a `BlobRecordFormatError` aborts the sweep, `record-unreadable`); walk `walkBlobPieces(ref, source, { digest })` with a source `{ get, has, verified: true }` over the piece store (the store admits only checked pieces, `PieceSource.verified`), adding every id reported present. A walk that throws aborts the sweep (`tree-unreadable`). An aborted sweep deletes nothing.
4. **Decide and delete under the gate.** `gate.exclusive`: for every ref in `changed`, read the record again and, if present, walk it into the live set (a throw aborts as in step 3); add every id in `inProgress`; then delete every candidate not live, one `pieces.delete` at a time, counting a rejected delete in `failed` (logged `sweep:delete-failed`) and going on. Drop `changed` in a `finally`, on every path out of the sweep.
5. Log `sweep:done` with the counts, or `sweep:aborted` with the reason and ref. No `flush`: a delete that a crash undoes leaves an orphan for the next sweep.

Why this is enough, each by inspection of the order above:

- A piece of a put in progress is in `inProgress` when step 4 reads it, because the id is added before the piece is stored and released only after the record that names it is written, and a released id's record was written before step 4 (it changed after step 1, so it is in `changed`) or before step 1 (so step 3 read it).
- A record changed while steps 2 and 3 ran is in `changed` and walked again under the gate, where no record can change.
- A put that stores a piece of a deleted candidate waits on the gate in step 4, finds the piece absent afterwards (the `has` inside `put`), and writes it.

Accepted costs, each a `NOTE:` at its site: puts and record changes wait while step 4 deletes (bounded by the deletes, not by the walk); step 2 holds every id in memory (about 60 bytes each; page it if a node ever holds tens of millions of pieces); every sweep reads every held blob's list pieces (one list piece per 174 data pieces); one blob whose tree cannot be read (disk damage under a held blob) stops every sweep until it is unpinned, which keeps data rather than guessing at what that tree covered; a list piece that is missing leaves the pieces under it unwalked, so they are deleted (`feat-blob-pieces-move-between-machines` fetches list pieces before the pieces under them, which keeps this from deleting a fetch's progress).

**When it runs.** `LocalBlobService.sweep()` runs it now. The service schedules one, `sweepDelayMs` (default `DEFAULT_SWEEP_DELAY_MS = 5_000`) after: `start()`, to remove the orphans of a put a crash interrupted; a record's deletion; and a put that failed after storing a piece. Scheduling while a run is already scheduled does nothing; a timer firing during a run schedules one more after it. The timer is `armUnrefTimer`, injectable as `setTimer`. A scheduled sweep that rejects is logged (`sweep:failed`), never left as an unhandled rejection.

## The service

```ts
export interface LocalBlobServiceInit {
	readonly pieces: IPieceStore;
	readonly kv: IKVStore;
	/** Default `defaultBlobDigest()`. */
	readonly digest?: BlobDigest;
	/** Default DEFAULT_SWEEP_DELAY_MS. */
	readonly sweepDelayMs?: number;
	/** Default Date.now. */
	readonly now?: () => number;
	/** Default armUnrefTimer. */
	readonly setTimer?: (fn: () => void, ms: number) => () => void;
}

/** How stale a record's `lastReadAt` may be; a read writes the record only when it is older than this. */
export const LAST_READ_RESOLUTION_MS = 60_000;

export class LocalBlobService implements BlobService {
	constructor(init: LocalBlobServiceInit);
	/** Schedules the start-up sweep. */
	start(): void;
	/** Cancels a scheduled sweep and waits for a running one. Every method still works afterwards. */
	stop(): Promise<void>;
	sweep(): Promise<BlobSweepResult>;
	// BlobService (docs/blobs.md §The node's blob service):
	put(source: AsyncIterable<Uint8Array>, options?: BlobPutOptions): Promise<BlobPutResult>;
	stat(ref: BlobRef, options?: { probe?: boolean }): Promise<BlobStat>;
	read(ref: BlobRef, options?: BlobReadOptions): AsyncIterable<Uint8Array>;
	fetch(ref: BlobRef, options?: BlobFetchOptions): Promise<void>;
	pin(ref: BlobRef, owner: string): Promise<void>;
	unpin(ref: BlobRef, owner: string): Promise<void>;
	announce(ref: BlobRef, scope: BlobScope): Promise<void>;
	onProgress(listener: (event: BlobProgressEvent) => void): () => void;
	onDurability(listener: (event: BlobDurabilityEvent) => void): () => void;
}
```

Every record change goes through one private method, `changeRecord(ref, change)`: `gate.shared(() => { sweeper.noteRecordChange(ref); return records.update(ref, change); })`. When the returned change has a `before` and no `after` (a record was deleted), it schedules a sweep.

The service reads its own pieces through one source, `{ get, has, verified: true }` over the piece store: every piece in it was produced by this node's builder from the bytes themselves, so local reads are not hashed again (the `verified` contract on `PieceSource`). Consequence, recorded as a `NOTE:` at that source: a data piece whose bytes the disk altered without changing their length is served unnoticed by a local read; list pieces are still decoded and bounded, and every size is still checked. Hashing every local read was rejected: pure JavaScript hashing costs about 19 s per MB on an older phone (docs/blobs.md §References and pieces).

- **`put(source, { owner, signal })`.** `owner` defaults to `DEFAULT_BLOB_OWNER`; an empty string throws `RangeError`. Runs `buildBlob(source, sink, { digest, signal })` with a sink whose `put(id, bytes)` is `gate.shared(async () => { if (!mine.has(id)) { mine.add(id); inProgress.add(id); } await pieces.put(id, bytes); })`, `mine` being this put's own set, so an id repeated within one blob is counted once. The builder awaits the sink, so the put holds no more than the builder does. Then `pieces.flush()`; then `changeRecord` adding the owner's pin (unless that owner already pins it), `size`, `whole: true`, keeping every other hold and field an existing record has; then `records.flush()`; then resolve `{ ref, size }`. In a `finally`, release `mine` from `inProgress`. On any failure after a piece was stored, schedule a sweep and rethrow. Log `put:stored` (ref, size) or `put:failed` (reason). Two concurrent puts of one content therefore store one set of pieces and leave one record with both pins.
- **`stat(ref)`.** `probe` is ignored until `feat-blob-pieces-move-between-machines` (say so in the doc comment). `durability` is left absent until `feat-a-referenced-blob-is-copied-to-its-cohort`. Read the record, then:
  - root piece absent (`pieces.has(rootPieceId(ref))` false): `locality: 'unknown'`, `heldBytes: 0`, `size` from the record. If the record says `whole`, correct it to `whole: false` (`record:corrected`). This is how a node restarted on a memory piece store with a persistent key-value store reports honestly.
  - root present and the record says `whole` with a `size`: `'here'`, `heldBytes = size`.
  - otherwise walk `walkBlobPieces` over the local source. The blob's size is the root entry's `fileBytes` when the root is a list piece (the walk reads it from the root, so it is known whenever the root is here, as docs/blobs.md §The node's blob service says), else the record's, else, for a raw root, that one piece's length (one `get` of at most 1 MiB). `heldBytes` is the sum of `fileBytes` over the present data entries below the root (a repeated data piece counts at each position, so `heldBytes === size` exactly when every piece is here), or the raw root's length. Every piece present: `'here'`, and a record, if any, is corrected to `whole: true` with that `size`. Otherwise `'partial'`.
  - A walk that throws `BlobCorruptError` propagates.
- **`read(ref, { offset, length, from, signal, waitMs })`.** `yield*` `readBlob(ref, source, { offset, length, digest })` over the local source extended so its `get` throws `BlobUnavailableError(ref, reason, id)` for a piece that is absent, with reason `not-here` when `from === 'here'`, else `cohort-unreachable` (nobody can be asked until the transfer ticket). On that error, correct a `whole` record to `whole: false` before rethrowing. `BlobCorruptError` propagates unchanged and nothing past the fault is yielded (the reader's guarantee). Between chunks, a set `signal` ends the read by throwing `signal.reason`. `waitMs` is accepted and ignored until the transfer ticket. Before the first chunk, `void` a `changeRecord` that sets `lastReadAt` when the record exists and its value is absent or older than `LAST_READ_RESOLUTION_MS`, and otherwise returns `current` unchanged (so no record is created and nothing is written); errors are logged (`record:touch-failed`). It is not flushed, since a lost read time costs only eviction order.
- **`fetch(ref)`.** Resolves when `stat` says `'here'`; otherwise throws `BlobUnavailableError(ref, 'cohort-unreachable')`.
- **`pin(ref, owner)`.** `RangeError` on an empty owner. `changeRecord` adds `{ kind: 'pin', owner, at: now() }` unless that owner already pins it (then it returns `current`, and nothing is written); with no record, creates `{ v: 1, ref, whole: false, holds: [pin] }` (`stat` finds out what is here). Then `records.flush()`: a lost pin would let a restart sweep the blob.
- **`unpin(ref, owner)`.** Removes that owner's pin; no record or no such pin is a no-op. A record left with no holds is deleted and a sweep scheduled (through `changeRecord`). Then `records.flush()`.
- **`announce`.** Rejects with `Error('announcing a blob to its cohort is not built yet (feat-a-referenced-blob-is-copied-to-its-cohort)')`.
- **`onProgress`, `onDurability`.** Add the listener to a set and return its removal; nothing calls them yet.

## Edge cases & interactions

- **Crash after pieces are flushed, before the record.** Orphan pieces; the start-up sweep removes them. Covered by the aborted-put test, which produces the same state.
- **Crash after `put` resolved.** Pieces and record both survive, and the pin with them. Test (restart test below).
- **Sweep during a put.** In-progress pieces survive. Test, since this is the race that loses data.
- **A put that finishes after the sweep read the records.** Its pieces survive through `changed`. Test, built so that only `changed` protects them (see the tests).
- **A put that stores a candidate piece during step 4.** It waits on the gate and rewrites the piece. Inspection.
- **Two puts of the same content at once.** One set of pieces, one record with both pins. Test.
- **Two blobs sharing a piece; one unpinned.** The shared piece survives the sweep; the unshared one goes. Test.
- **Empty blob.** `buildBlob` of an empty source stores one zero-length raw piece, which is the reference. `stat` is `'here'` with size 0, a read yields no bytes. Test. A one-piece blob is the same raw-root case.
- **A stored piece found corrupt on read.** A malformed list piece or a size mismatch throws `BlobCorruptError` and nothing past it is served (the reader's guarantee, by inspection). A data piece altered on disk at its own length is not detected locally (the `verified` NOTE above). A corrupt piece stays stored, since a put of a present id writes nothing; replacing it is for the transfer ticket (docs/blobs.md lists it as open).
- **Record says whole, piece missing.** A read fails `not-here` (or `cohort-unreachable`), the record is corrected, and `stat` reports `'partial'`. Test.
- **Restart on a memory piece store with a persistent key-value store.** Records list every held blob, pins survive, `stat` says `'unknown'` and corrects the record. Test.
- **A malformed record under the prefix.** The sweep aborts and deletes nothing. Test, because deleting on a misread record would lose data.
- **A key under the prefix that is not a reference.** Skipped and logged by `listRefs`, so the sweep proceeds. Inspection.
- **`pin` of a blob with no pieces here, `unpin` of an unknown owner, a pin twice by one owner, a read of a blob with no record.** One record created, a no-op, one pin, no record created. By inspection of `changeRecord`'s callbacks and `update`'s no-write rules.
- **A `change` callback that throws.** That `update` rejects; the per-ref chain and the gate are released. Inspection.
- **The new key prefix read as a block id.** Covered by the existing file listing tests once it is in `NODE_KV_NAMESPACES`.
- **Nested gate holds.** None by construction; stated at `SweepGate`. A shared holder that awaited another hold would deadlock against a waiting sweep.
- **A sweep scheduled after `stop()`.** `stop()` cancels the timer; a later record deletion schedules again, which is harmless on a stopped node (the timer is unref'd). Inspection.
- **React Native.** Nothing here may use a Node-only API; `yarn check:rn` bundles db-p2p.

## Tests

`packages/db-p2p/test/local-blob-service.spec.ts`, over `MemoryPieceStore` and `MemoryKVStore` unless stated, with `sweepDelayMs` large and `sweep()` called directly. Test doubles here are small classes implementing `IPieceStore` or `IKVStore` over the memory stores, not mocks of modules.

- "a put is stored, read whole and by range, and held under `default` until unpinned": a 600 KiB put with no owner; `stat` is `'here'` with the size; a whole read and a range crossing a piece boundary return the right bytes; the record has one pin owned by `default`; after `unpin(ref, 'default')` and `sweep()`, `stat` is `'unknown'` and no piece is stored.
- "the empty blob": put of an empty source; `stat` `'here'`, size 0; a read yields zero bytes; its one piece is stored.
- "a sweep while a put is in progress keeps its pieces": a source that yields two pieces' worth, then awaits a promise the test holds; run `sweep()` to completion (the two pieces are listed as candidates and protected by `inProgress` alone); release the source; the put resolves and the blob reads whole.
- "a put that completes after the sweep read the records keeps its pieces": start a put whose source yields two pieces' worth then awaits promise X; wrap the key-value store so `list(prefix)` takes the inner store's answer first and then awaits promise Y before returning it; start `sweep()` and wait until the wrapped `list` is waiting (its pieces listing has already returned the put's two pieces as candidates); release X and await the put (record written, `inProgress` released); release Y; after the sweep the blob reads whole. Without `changed`, the sweep would delete the two pieces, so this pins step 4's re-walk.
- "an aborted put leaves pieces the next sweep removes": abort the `signal` after the first piece; `put` rejects; the piece store is non-empty; after `sweep()` it is empty.
- "two puts of the same content keep one set of pieces and both pins": concurrent puts with owners `a` and `b`; one record, two pins; unpin `a`, sweep: still `'here'`; unpin `b`, sweep: empty.
- "a piece shared by two blobs survives unpinning one": blobs A = P + Q and B = P + R, P a full 256 KiB piece of identical bytes; unpin A, sweep: B reads whole, Q is gone.
- "a missing piece fails a local read and corrects the record": delete one data piece from the store; `read(ref, { from: 'here' })` rejects with `BlobUnavailableError` reason `not-here`; without `from`, reason `cohort-unreachable`; `stat` is `'partial'`; the record says `whole: false`.
- "records and pins survive a restart; pieces are checked, not assumed": over `PowerLossPieceStore` and `PowerLossKVStore`, put; `powerLoss()` both and `reopen()` both. A service over a fresh `MemoryPieceStore` and the reopened key-value store: `stat` is `'unknown'` and the record now says `whole: false`. Then a service over the reopened piece store and key-value store: `stat` is `'here'` (the walk corrects the record to `whole: true`), the blob reads whole, and `unpin(ref, 'default')` deletes the record.
- "a malformed record stops the sweep": write a garbage value under `optimystic-blobs/<a valid ref>` and store an orphan piece; `sweep()` reports `aborted` with `record-unreadable` and the orphan remains.

No test for `announce`, the listener stubs or `SweepGate` alone: the stubs are verified by the type checker and by inspection, and the gate's one property that matters is pinned by the two sweep-race tests.
