# A node takes all its storage as one value

## Why

A node persists three kinds of thing, and today takes each as its own option, each defaulting to memory:

| Option | When absent |
|---|---|
| `NodeOptions.storage` | a `MemoryRawStorage`, reported only by the start-up durability line saying `none` |
| `NodeOptions.kvStore` | a `MemoryKVStore`, with a `node-wiring` warning. This store holds the blob records, the owed-blob ledger, the under-replication ledger, the clock's high-water mark and (after `a-node-keeps-its-transaction-state-where-it-keeps-the-rest`) the node's transaction state |
| `NodeOptions.pieceStorage` | a `MemoryPieceStore`, with a `node-wiring` warning |

Sereus built its nodes with a persistent block store and nothing else (sereus#67). Its blob pieces then went to a `MemoryPieceStore` and its blob records to a `MemoryKVStore`, so a photo put just before the phone went to the background was gone when the app woke. Nothing failed; a warning went to a log nobody reads on a phone. The Quereus plugin made the same mistake inside its own code once (backlog `debt-a-networks-storage-is-taken-from-one-collections-options`).

The cause is the shape of the options, not one host's oversight: three independent fields, each of which quietly works when left out. Every storage package already builds its three stores over **one** location — `FileRawStorage`, `FileKVStore` and `FilePieceStore` over one base path; the SQLite, IndexedDB and LevelDB stores over one open database handle — but a host has to know that and make all three calls itself.

Make the node take one value instead. Then there is no field to drop: a host either supplies the node's storage or it does not, and "does not" is one visible line at start-up rather than two warnings and a silence.

## What to build

### The type, in db-p2p

A new `packages/db-p2p/src/storage/node-storage.ts` holding three exported things. The storage packages depend on db-p2p, never the other way round, so the type lives here and the per-platform factories live in each storage package (`each-storage-package-opens-a-whole-nodes-storage`).

```ts
/**
 * Every store a node persists to, as one value. A host opens all of it in one call per platform;
 * there is no part of it a host can leave out.
 *
 * A client node (`servesBlocks: false`) reads `kv` and `pieces` and never touches `blocks` — it
 * stores no blocks for anyone (docs/internals.md §Client nodes). `blocks` is required anyway so
 * that one value serves either role and a host that changes the role changes one flag; an unused
 * block store over a location the node already holds costs nothing, since every backend's
 * constructor is lazy.
 */
export interface NodeStorage {
	/** Block revisions and their commit proofs. Read by a serving node only. */
	blocks: IRawStorage;
	/** Node-local records: the blob records, the owed-blob and under-replication ledgers, the clock's high-water mark, the node's transaction state. */
	kv: IKVStore;
	/** Blob pieces (docs/blobs.md §The local store). */
	pieces: IPieceStore;
}

/**
 * A {@link NodeStorage} that was opened and must be closed; what every platform factory returns.
 * The node never calls `close` — it closes no store it was handed — so the host closes it after
 * `stop()`.
 */
export interface OpenNodeStorage extends NodeStorage {
	close(): Promise<void>;
}

/** Storage that keeps nothing across a restart, for specs, demos and hosts that mean it. A fresh set of stores per call; its `close` does nothing. */
export function memoryNodeStorage(): OpenNodeStorage;
```

`NodeStorage` carries three stores and not four: the node's transaction-state store is built by the node over `kv` (`a-node-keeps-its-transaction-state-where-it-keeps-the-rest`), so there is one rule for it in one place on every platform and no field for a factory to forget. If a backend ever wants its own — a SQLite table rather than JSON under three key prefixes — that arrives as an optional fourth field whose absence keeps today's derivation; record that as a `NOTE:` tripwire on the type rather than building it now.

`memoryNodeStorage()` returns a **new** set of stores on every call. Two nodes in one process must not share one memory store, and nothing about the memory case wants to be shared.

Export the new module from **both** `packages/db-p2p/src/index.ts` and `packages/db-p2p/src/rn.ts`: `packages/db-p2p/test/entry-parity.spec.ts` compares the two line for line and fails if one is missing.

### The option

`NodeOptions.storage?: NodeStorage` replaces `storage`, `kvStore` and `pieceStorage`. Replace rather than add beside — backwards compatibility is not a concern in this repository yet — and delete `RawStorageProvider`, `KVStoreProvider` and `PieceStoreProvider` with them, including the re-exports in `packages/db-p2p/src/libp2p-node.ts` and `packages/db-p2p/src/libp2p-node-rn.ts`.

The instance-or-factory shape goes with them. It existed so the node could build a store lazily per field; with one value the host has already built everything by the time it calls, and a factory would only reintroduce the question of when it runs. (`MeshOptions.rawStorageFactory` in `packages/db-p2p/src/testing/mesh-harness.ts` and the Quereus plugin's own factory option are not `NodeOptions` and keep their own shapes.)

`RawStorageProvider`'s doc comment carries the one statement of who owns the read cache in front of the block store — that the node leases the shared cache and releases only its lease, that a host handing in an already-cached store keeps owning it, and which two cache constructions are accepted. That text is load-bearing; move it onto `NodeStorage.blocks` rather than losing it. `resolveStorage` keeps its job of putting `withReadCache` in front of the supplied block store, taking the store instead of a provider.

### One line when storage is left out

`resolveKvStore` and `resolvePieceStore` go away, and with them the two `WARN:` lines. In their place: when `options.storage` is absent, the node uses `memoryNodeStorage()` and logs exactly one `node-wiring` `WARN:` line naming every store it is keeping in memory and what is lost with each — for a serving node the blocks, the key-value store's five namespaces, the pieces and the transaction state; for a client the key-value store's high-water mark and blob records, and the pieces. Both lines end by naming the way out: supply `NodeOptions.storage`, or `memoryNodeStorage()` to say this was meant.

The test for the warning is simply whether the option is present. A host that passes `memoryNodeStorage()` gets no warning, which is the point. The start-up durability line (`logStorageDurability`, serving nodes only) is a separate, factual report about the supplied block store and stays exactly as it is.

A host can still hand-build a `NodeStorage` whose parts disagree — a file block store beside a `MemoryKVStore` — and that case is now silent, where today it warns. It is the host's deliberate composition and `IKVStore` has no durability to report, so the node cannot tell. Record a `NOTE:` tripwire at the resolve site: if a host ever reports being bitten by a mixed set, give `IKVStore` the `durability` field `IPieceStore` and `IRawStorage` already have and name the memory parts in the same line.

### The call sites

Nine files pass the three options today; all of them become one `storage:` field.

- `packages/reference-peer/src/cli.ts` — `NodeStores` and `openStores` already build exactly this shape with a `close` that releases the three in order. Make `openStores` return an `OpenNodeStorage` and keep closing it where it closes it now, including on a failed `createLibp2pNode`. It switches to the fs factory in `each-storage-package-opens-a-whole-nodes-storage`; here it just changes shape.
- `packages/upgrade-check/test/current-build.ts` — keep `openBackend` building its stores by hand. Its whole job is to reproduce the directory layout each release wrote, and for `fs` that is two directories (`blocks` and `kv`, as every `fixtures/*/fs.json` manifest declares), which no one-location factory can or should produce. Wrapping the three it already opens in one object is the entire change; its `close` stays its own.
- `packages/upgrade-check/writer/write-scenario.mjs` — the awkward one. That script is copied next to a **published** build and run there, and its header requires it to keep to API every fixture version has, back to 1.0.0-beta.3. A build before this change reads `storage` as a block store; a build after reads it as the whole value, so one options object cannot serve both. Keep `BACKENDS` as it is (hand-built, one set per layout) and make only `startNode` choose: probe the resolved `@optimystic/db-p2p` for the new API — a namespace import and `typeof dbP2p.memoryNodeStorage === 'function'`, the same idiom the file already uses for a piece store an older build lacks — and pass either `{ storage: { blocks: storage(), kv: kvStore, pieces: pieceStorage } }` or today's three fields. Note that `storage` is a factory in the old shape and the instance is wanted in the new one.
- `packages/db-p2p/test/util/two-machine-lifecycle.ts` — its `Machine` holds a `MemoryRawStorage` and a `MemoryKVStore` across a restart, which is the point of the helper. Hold one `OpenNodeStorage` per machine instead, built once and passed to both the first node and the restarted one, and update the `NetworkShape` `Omit` list.
- `packages/db-p2p/test/blob-copy.spec.ts`, `blob-fetcher.spec.ts`, `blob-network-read.spec.ts`, `blob-protocol-stalls.spec.ts` — each spawns nodes over a named piece store (and in one case a key-value and block store too) to watch pieces move between them. Each needs its own storage per node with the piece store it names; `{ ...memoryNodeStorage(), pieces: theirPieceStore }` is the minimum edit and keeps each node's other stores its own.

Every other `createLibp2pNode` caller passes no storage at all and keeps the memory default; they now get one warning instead of two.

## Edge cases & interactions

- **A client node and `blocks`.** A client builds no block store and never reads `options.storage.blocks`. Check that nothing on the client path touches it — `prepareServingStore` is the one function that resolves it and a client skips it. Verified by inspection plus the existing `packages/db-p2p/test/client-only-node.integration.spec.ts`.
- **`logIgnoredServingOptions`.** `storage` is on its list of options a client ignores. It must come **off**: a client uses two thirds of the value. `storageDurability` stays on the list. Getting this wrong makes a client log that it is ignoring the storage it is in fact using.
- **Two nodes over one location.** Unchanged by this ticket and still the host's business: `resolveStorage` keeps leasing the shared read cache per backing store, and the cross-process case is still unguarded (Invariant 5 in `packages/db-p2p/docs/storage.md`). What changes is that a host now hands one value to both nodes, or builds two.
- **One store identity per location.** `blockStoreCountsPieces` (`packages/db-p2p/src/storage/storage-monitor.ts`) leaves the piece store's bytes out when the two report one identity, so a node over one location counts its pieces once. That already holds for every platform's stores over one location; this ticket does not change it and the factories ticket asserts it.
- **A `NodeStorage` built from stores over different locations** still works — the monitor then counts the piece bytes separately, which errs toward reporting the node fuller than it is. `packages/upgrade-check` is exactly that case for `fs` and must stay green.
- **Both package entries.** `entry-parity.spec.ts` fails if `node-storage.js` is exported from one entry and not the other, and both must stay plain `export * from` lines.
- **`node-storage.ts` imports `MemoryPieceStore` from `../blob/`.** That direction already exists (`storage/node-kv-namespaces.ts` imports from `../blob/`), so no cycle; confirm the build agrees rather than assuming.
- **The React Native bundle.** `yarn check:rn` bundles the RN entry with Metro and compiles it with `hermesc`. A new module in the entry graph is new surface for it; run it.
- **`docs/debugging.md` mirrors the logger channels.** `packages/db-p2p/test/logger.spec.ts` fails if a `createLogger` channel has no row in that table. This ticket adds no channel — the warning goes out on the existing `node-wiring` logger — but the `node-wiring` row spells out the two `WARN:` lines being replaced and must be reworded to the one that replaces them.

## Tests

No new test. The shape is enforced by `tsc` (a `NodeStorage` with a part missing does not compile, which is the whole mechanism), the export by `entry-parity.spec.ts`, and the client's use of two of the three parts by `client-only-node.integration.spec.ts`. The one warning is a log line, and pinning its words would only duplicate the source.
