# Move all nine `forComponent` call sites onto `createLogger`

Step 2 of 3. Step 1 (`logger-factory-error-and-formatters`) widened `createLogger` so it can
replace libp2p's factory; this step performs the replacement. Step 3
(`lock-and-document-db-p2p-log-namespaces`) adds the lint rule, the structural guard tests and the
docs table — **do not do step 3's work here.**

Read step 1's ticket (or, once landed, the header comment it leaves in `src/logger.ts`) for why
the two factories differ: libp2p's `components.logger.forComponent(name)` is backed by `weald` and
adds no prefix, so `forComponent('db-p2p:cluster')` produces the bare namespace `db-p2p:cluster`,
which `DEBUG=optimystic:db-p2p:*` — the filter `docs/debugging.md` tells people to set — does not
match.

## The nine sites and their new namespaces

The source ticket listed six. There are nine: `libp2p-node-base.ts` has three more that the
original enumeration missed, which is itself evidence for step 3's lint rule.

| File | Current namespace | New |
|---|---|---|
| `src/cluster/service.ts` | `db-p2p:cluster` | `optimystic:db-p2p:cluster-service` |
| `src/repo/service.ts` | `db-p2p:repo-service` | `optimystic:db-p2p:repo-service` |
| `src/sync/service.ts` | `db-p2p:sync-service` | `optimystic:db-p2p:sync-service` |
| `src/dispute/service.ts` | `db-p2p:dispute` | `optimystic:db-p2p:dispute-protocol` |
| `src/network/network-manager-service.ts` | `db-p2p:network-manager` | `optimystic:db-p2p:network-manager` |
| `src/cluster/block-transfer-service.ts` | `db-p2p:block-transfer` | *(delete — see below)* |
| `src/libp2p-node-base.ts` ×3 | `db-p2p:spread-on-churn`, `db-p2p:arachnode`, `db-p2p:owned-block-seed` | the file's existing `wiringLog` |

### Why those names

Three of the six original names collide with a `createLogger` namespace that already exists for a
**different class in the same subsystem**. Merging or renaming, per case:

- **`cluster`** is taken by `ClusterCoordinator` (`src/repo/cluster-coordinator.ts`). Different
  class, different concern (consensus phases vs. inbound protocol handling). Rename the service to
  `cluster-service`; the coordinator keeps `cluster` and `docs/debugging.md`'s existing
  "Cluster consensus" recipe keeps meaning what it says.
- **`repo-service`** is taken by a module-level `debugLog = createLogger('repo-service')` in
  **the very same file** (`src/repo/service.ts`), used once, on the redirect path. Same class, same
  concern — **merge**: delete `debugLog` and log that line through `this.log`. Keep the namespace
  `repo-service` so the existing "Routing and redirect decisions" recipe keeps working, and note in
  the commit that this is what finally makes that recipe show the whole picture rather than half.
- **`dispute`** is taken by `DisputeService` (`src/dispute/dispute-service.ts`) — the subsystem
  itself. The protocol handler in `src/dispute/service.ts` is a different class, so give it
  `dispute-protocol`.
- **`block-transfer`** — `src/cluster/block-transfer-service.ts` already has a module-level
  `log = createLogger('block-transfer-service')`, and its `components.logger` is *optional* with
  that `log` as the documented fallback. So the component is pure redundancy: **delete
  `BlockTransferServiceComponents.logger` entirely** along with the ternary in the constructor, and
  pass `(msg, ...args) => log.error(msg, ...args)` as the authorization sink. This is the only site
  where the whole component field goes away rather than being retargeted.
- **`libp2p-node-base.ts`** — all three sites are node-wiring init failures reported
  opportunistically through `(node as any).logger?.forComponent?.(…)?.(…)`, i.e. they silently do
  nothing if the node has no logger. The file already has
  `const wiringLog = createLogger('node-wiring')` in scope. Replace all three with unconditional
  `wiringLog('<subsystem> init failed: %o', err)` (tags: `spread-on-churn`, `arachnode`,
  `owned-block-seed`). This adds no new namespaces, removes the `as any` reach-through, and makes
  the reporting unconditional — which is the point, since these are the lines that explain a
  half-started node.

**Do not add peer-id suffixing** to any of these, even though `ClusterServiceComponents` and
`RepoServiceComponents` both carry an optional `peerId`. The other ~40 namespaces in this package
are flat; `src/logger.ts` already carries a NOTE saying the mechanism is there for whoever needs
it. Keeping them flat also keeps exact-match `DEBUG` filters working, which the docs' recipes use.

## Type changes

Each of the five migrating services declares a components field for libp2p's logger and types its
`log` from `@libp2p/interface`. After migration the field is dead and the type is wrong.

- `src/cluster/service.ts`, `src/repo/service.ts`, `src/dispute/service.ts`,
  `src/network/network-manager-service.ts`: delete `logger: { forComponent: (name: string) => Logger }`
  from the components interface; drop `Logger` from the `@libp2p/interface` type-import list and
  import `type { Logger }` from `../logger.js` instead.
- `src/sync/service.ts`: delete `logger: ComponentLogger` from `SyncServiceComponents` and the
  local `type Logger = ReturnType<ComponentLogger['forComponent']>` alias; import ours. Drop the
  now-unused `ComponentLogger` type import.
- `src/cluster/block-transfer-service.ts`: delete the optional `logger?: { forComponent: … }` field
  and its doc comment.

### `logPrefix`

`ClusterServiceInit.logPrefix` and `RepoServiceInit.logPrefix` currently feed `forComponent`
directly, i.e. they let an embedder set an arbitrary root namespace — a second way to escape the
documented tree. Nothing in the repo sets either one. Keep the knob but **reinterpret it as a
sub-namespace**: `createLogger(init.logPrefix ?? 'cluster-service')`. Update each field's doc
comment to say it names a sub-namespace under `optimystic:db-p2p:`, not a full namespace.

## Test fallout

The five migrating services stop reading `components.logger`, so every spec that hands them a stub
logger has a dead property. Because those stubs sit in object literals with an explicit
`: ClusterServiceComponents` (etc.) annotation, TypeScript's excess-property check flags each one —
so `yarn build` / `yarn typecheck` will point at them. Known sites:

- `test/cluster-error-propagation.spec.ts` — `makeComponents`
- `test/cluster-service-redirect.spec.ts`
- `test/redirect.spec.ts`
- `test/repo-service-remote-get-consult.spec.ts`
- `test/inbound-message-caps.spec.ts` — `makeLogger()`, now unused; delete the helper
- `test/inbound-stream-authorization.spec.ts` — see below

Delete the dead `logger:` properties (and any helper that only produced them). Treat the compiler's
list as authoritative — do not assume the six above are exhaustive.

### `inbound-stream-authorization.spec.ts` needs a real rewrite

This one does not merely pass a stub — it **asserts through it**. `makeLogger()` returns
`{ logger, errors }` where `fn.error` pushes into `errors`, and three assertions (search for
`driven.errors`) check that a denial and a thrown authorization callback are logged. Once the
services log through `debug`, that array stays empty.

Rewrite the capture to go through `test/support/capture-log.ts`, which is how the rest of this
package asserts on log output:

- Wrap the call that drives the handler in
  `captureLog(['cluster-service', 'repo-service', 'sync-service', 'block-transfer-service'], async () => { … })`
  — `captureLog` accepts an array precisely so one run of the driving code can be watched across
  several namespaces.
- Assert with `hasLine(captured, 'inbound stream denied')` rather than `errors.join('\n')`.
  `hasLine` runs `util.format` over the captured argument list, so it sees `%s`-substituted text;
  `hasTag` only sees the literal template and would silently pass on the wrong line.
- `captureLog` enables `optimystic:db-p2p:<n>` **and** `optimystic:db-p2p:<n>:*`, so the `:error`
  child channel these lines land on is covered without further work.
- Delete `makeLogger` and the `errors` plumbing threaded through the `driven` fixture.

## Edge cases & interactions

- **The authorization sink is built in the constructor.** Every migrating service does
  `createInboundStreamAuthorization(init, this.protocol, (msg, ...args) => this.log.error(msg, ...args))`.
  `this.log` must be assigned *before* that line. It already is in all five — keep it that way when
  reordering constructor bodies.
- **`%p` and `%e` must survive.** Three lines format with them:
  `cluster/service.ts` ("error handling cluster protocol message from %p - %e"),
  `repo/service.ts`, `dispute/service.ts`. These only work because step 1 ported the specifiers
  onto `debug`. If step 1's port is missing or incomplete, these print literal `%p`/`%e` and no
  test currently covers them — add or keep a capture-based assertion on at least one of the three.
- **`captureLog` restores global `debug` state in a `finally`.** Nested or concurrent captures in
  the same process will clobber each other's enable-set. Mocha runs specs serially by default here;
  do not introduce a capture that spans an `await` on unrelated concurrent work.
- **`libp2p-node-base.ts`'s three sites are inside `catch` blocks and a `.catch(…)`.** Making the
  logging unconditional must not change control flow: `wiringLog(...)` returns `void`, and the
  `.catch(err => wiringLog(...))` arm must still swallow the rejection rather than rethrow.
- **`(node as any).logger` may still be read elsewhere** in `libp2p-node-base.ts`. Removing these
  three reads must not remove the field from the node — only these call sites change.
- **`BlockTransferService` fallback semantics change.** Today, with no `components.logger`, denial
  lines go to `log(...)` (the main channel); with one, to `componentLog.error(...)`. After the
  change they always go to `log.error(...)` — a different channel from today's fallback. That is
  intended (denials are errors), but it means `optimystic:db-p2p:block-transfer-service` alone no
  longer shows them; `optimystic:db-p2p:block-transfer-service:*` does. Check whether any spec
  captures that exact namespace and widen it if so.
- **Namespace rename is observable.** `cluster` → `cluster-service` and `dispute` →
  `dispute-protocol` are new strings. Grep `test/` and `docs/` for the old bare `db-p2p:cluster`
  and `db-p2p:dispute` before finishing; `docs/debugging.md` is step 3's job, but a *test* that
  pins an old string is this ticket's problem.
- **`node-service-set.spec.ts` and the `*-node-wiring.spec.ts` specs** assert on the shape of the
  services a node registers. Deleting a components field can change what a service constructor
  tolerates — run the full package suite, not a grepped subset.
