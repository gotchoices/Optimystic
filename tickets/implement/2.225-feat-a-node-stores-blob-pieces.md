# A node stores blob pieces

`feat-blob-records-and-the-local-blob-service` builds `LocalBlobService` (`packages/db-p2p/src/blob/local-blob-service.ts`) as library code. This ticket wires it into the node built by `createLibp2pNodeBase` in `packages/db-p2p/src/libp2p-node-base.ts`: a host passes a piece store the way it passes block storage and the key-value store, and reads and writes blobs through `node.blobs` (docs/blobs.md §The node's blob service).

## Options

- `NodeOptions` gains `pieceStorage?: PieceStoreProvider`, with `export type PieceStoreProvider = IPieceStore | (() => IPieceStore)`, documented like `kvStore`: the node never closes it; a host closes it after `stop()`. `FilePieceStore` from `@optimystic/db-p2p-storage-fs` shares `FileRawStorage`'s base path.
- `NodeOptions` gains `blobs?: { digest?: BlobDigest }`, the hashing port (docs/blobs.md §References and pieces). A supplied digest is passed to the service as given; checking it against the known answers (`checkBlobDigest`) is the host's call, as the db-core doc says.
- `resolvePieceStore(provider)` beside `resolveKvStore`: the instance, the factory's result, or a `MemoryPieceStore` with a `node-wiring` warning: `WARN: no pieceStorage supplied — using an in-memory piece store. Blob pieces this node stores will NOT survive a restart, while their records in the key-value store may, so such blobs then read as not here. Supply NodeOptions.pieceStorage (e.g. FilePieceStore) to keep them.`

## Both roles get `node.blobs`

A client (`servesBlocks: false`, docs/internals.md §Client nodes) builds the service too, over its own piece store and the key-value store it already keeps for the HLC clock. Reason: the writer of a blob is the first holder of its bytes ("Nothing leaves the machine yet", docs/blobs.md §The node's blob service), and a phone app that runs as a client is exactly the machine that picks a photo and puts it. A client holds only blobs its own host pinned; whether it serves them to its cohort is the transfer tickets' question. So `pieceStorage` and `blobs` are **not** added to `logIgnoredServingOptions`, and `blobs: BlobService` goes on `OptimysticNodeAttachmentsBase` in `packages/db-p2p/src/optimystic-node.ts`, documented as the node's blob service (docs/blobs.md §The node's blob service), local-only until the transfer and copying tickets land. The type is db-core's `BlobService`, so a later networked service can replace the value without changing the surface. Rejected: serving nodes only, which would leave a client with no way to store the blob its row is about to reference.

## Wiring

- Build the `LocalBlobService` right after `resolveKvStore`, over the resolved piece store, the resolved key-value store and `options.blobs?.digest`, for both roles.
- Put it on the `shared` attachment object (`blobs`), call `blobs.start()` right after `Object.assign(node, attachments)`, and install a stop wrapper immediately after that call that awaits `blobs.stop()` before the previous stop, the same shape as the existing wrappers (`const previousStop = node.stop.bind(node); node.stop = async () => { … await previousStop(); }`). Installing it right after the start keeps the factory's startup rollback able to unwind it (docs/internals.md, the rollback paragraph under *Cohort-Topic Origination Bridge*).
- The arachnode `StorageMonitor` construction inside `wireServingRole` passes the piece store as its third argument, so piece bytes count toward the node's reported use exactly once (`blockStoreCountsPieces` in `packages/db-p2p/src/storage/storage-monitor.ts`). Thread the resolved piece store into `ServingRoleContext` for it.

## Edge cases & interactions

- **A factory provider that throws.** It throws out of node construction before libp2p exists, as a `kvStore` factory's does. Inspection.
- **Memory piece store with a persistent key-value store.** The warning says what happens; `stat` reports such blobs `'unknown'` and corrects their records (pinned by the service's restart test). Inspection of the message.
- **Startup failure after the service started.** The stop wrapper is installed right after `start()`, so the rollback's `node.stop()` stops it. Inspection.
- **One directory, two identities.** A `FilePieceStore` given a different spelling of the block store's directory is counted twice by `StorageMonitor`; that is `blockStoreCountsPieces`'s documented behaviour, unchanged here.
- **A client given `pieceStorage`.** Used, not ignored, and not logged as ignored. Inspection of `logIgnoredServingOptions`.

No new test: the wiring is verified by the type checker (a field on `OptimysticNodeAttachmentsBase` that is never assigned is a compile error, per the comment above `shared`) and by inspection; the service's behaviour is pinned by `packages/db-p2p/test/local-blob-service.spec.ts`.
