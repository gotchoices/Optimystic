The last ticket of stage 1 of [docs/offline-sync.md §Implementation stages](../../docs/offline-sync.md#implementation-stages). Its prereqs give the two rows that had no type: `PromiseShortfallError` (cohort did not answer the pend) and `ValidityRejectedError` (validators judged it invalid). The table in [§Classifying an attempt's outcome](../../docs/offline-sync.md#classifying-an-attempts-outcome) is the specification; this ticket adds the predicate and settles two rows the table did not have.

## Interface

```ts
// packages/db-core/src/transaction/commit-failure-class.ts
export type CommitFailureClass =
	| { kind: 'cohort-unreachable'; error: PromiseShortfallError | BlockUnavailableError }
	| { kind: 'contention'; error: SyncRetryExhaustedError | CoordinatorStaleLossError }
	| { kind: 'guard-refused'; refusal: 'constraint' | 'concurrent-modification'; error: TreeGuardRefusedError }
	| { kind: 'rejected'; error: ValidityRejectedError }
	| { kind: 'too-large'; error: TransactionTooLargeError | BlockTooLargeError }
	| { kind: 'expired'; error: TransactionExpiredError }
	| { kind: 'torn-not-saved'; error: TornActionError }   // final: true
	| { kind: 'in-doubt'; error: TornActionError }         // final: false
	| { kind: 'partial'; error: CoordinatorPartialCommitError }
	| { kind: 'unknown'; error: unknown };

export function classifyCommitFailure(error: unknown): CommitFailureClass;
```

A pure function. Import each class from the module that defines it, never from a barrel (pitfall 6 in [docs/internals.md](../../docs/internals.md), enforced by `packages/db-core/test/barrel-import-cycle.spec.ts`). Export it from `packages/db-core/src/index.ts`.

## Rules

- **Type only, never text.** It reads `instanceof` and the structured fields `BlockUnavailableError.reason`, `TornActionError.final` — never `message`.
- **Top level only, never `cause`.** A commit-phase shortfall reaches a local writer nested as the `cause` of the transactor's plain aggregate (the commit side still throws it — see `offline-sync-typed-promise-shortfall`); that failure is in doubt, not "nothing sent", so walking `cause` would misclassify it. A wrapper that means something is its own row (`CoordinatorPartialCommitError`). The Quereus bridge's mapped errors (`ConstraintError`, `ConcurrentModificationError`) are not recognised here; stage 4 classifies the db-core error it already holds before mapping.
- **Rows** (most specific class first, since `SyncRevisionStalledError` extends `SyncRetryExhaustedError` and `TreeRangeTakenError` extends `TreeKeyTakenError`):
  - `PromiseShortfallError` → `cohort-unreachable`.
  - `BlockUnavailableError` with `reason` `'cohort-unreachable'` or `'peers-unreachable'` → `cohort-unreachable`; any other reason → `unknown` (the table names only those two; the others are transient read doubts and are retried as unclassified).
  - `SyncRetryExhaustedError` (and its subclass `SyncRevisionStalledError`), `CoordinatorStaleLossError` → `contention`. `CoordinatorStaleLossError` is the coordinator path's counterpart (it escapes bare only when a re-drive is safe) and is missing from the doc table — add it.
  - `TreeEntryChangedError` → `guard-refused` / `concurrent-modification`; any other `TreeGuardRefusedError` → `guard-refused` / `constraint` (its contract is "never downgraded to retryable", so a future subclass must not fall to `unknown`). `TreeDeleteGuardKindError` is outside that hierarchy (a malformed action) → `unknown`.
  - `ValidityRejectedError` → `rejected`.
  - `TransactionTooLargeError`, `BlockTooLargeError` → `too-large`. **New row:** the doc table has none, and left unclassified a write over the limit would be retried until `expireAfterMs` though it can never commit. The entry should fail with a new `QueuedFailureReason` `'too-large'`.
  - `TransactionExpiredError` → `expired`.
  - `TornActionError`: `final === true` → `torn-not-saved`; otherwise `in-doubt`.
  - `CoordinatorPartialCommitError` → `partial`.
  - Anything else, including `CoordinatorConcurrentStampError`, a plain `Error`, and non-`Error` values → `unknown`.

## Edge cases & interactions

- **A thrown network aggregate** (`Some peers did not complete: …`) from either phase → `unknown`. That is the in-doubt-safe answer the doc requires: the drain re-sends only under the attempt's own identity after a refresh. Covered by the test's `cause` case.
- **Exhaustive by type.** The switch over `kind` in consumers should be checked by the compiler (a `never` default in the test, or an `assertNever` helper if the codebase has one). By type.
- **Cross-realm / duplicated package copies** would defeat `instanceof`; the repo's single-copy constraint (`yarn lint:deps`) is what keeps that out. By inspection; mention in the doc comment.

## Tests

One table-driven spec, `packages/db-core/test/commit-failure-class.spec.ts`, one case per row that has real branching:

- `BlockUnavailableError` `'cohort-unreachable'` → `cohort-unreachable`; `'named-by-log'` → `unknown`.
- `TreeEntryChangedError` → `concurrent-modification`; `TreeKeyTakenError` and `TreeRangeTakenError` → `constraint`.
- `SyncRevisionStalledError` → `contention` (the subclass is not mis-ordered).
- `TornActionError` `final: true` → `torn-not-saved`; `final: false` → `in-doubt`.
- A plain `Error` whose message is exactly the super-majority sentence → `unknown` (proves no text is read), and a plain `Error` whose `cause` is a `PromiseShortfallError` → `unknown` (proves `cause` is not walked).
- `PromiseShortfallError` and `ValidityRejectedError` → their rows (the two types this stage added).

The single-class rows with no branching (`expired`, `too-large`, `partial`) need no case of their own.
