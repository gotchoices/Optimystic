## Design

### Live reads degrade for `'queue'` tables while offline

Every live read refreshes first (`mainTree.update()` and the index tree's `update()` in `runQuery` in `packages/quereus-plugin-optimystic/src/optimystic-module.ts`), and the DML path refreshes in its uniqueness probe and the synthesized-unique populate (`tree.update()` in `probeUniqueConstraint` and `ensureUniquePopulated`, `collection.update()` in `populateUniqueTree`). Route all of them through one vtab method, `refreshLive(tree)`, which behaves as today unless the controller says the mode is entered **and** this table's policy is `'queue'`. Then:

- if the reachability port says the cohort is unreachable, skip the refresh (no dial timeouts on every read) and serve the local view;
- otherwise refresh, and if it throws `BlockUnavailableError` with reason `cohort-unreachable` or `peers-unreachable` (the same two reasons `classifyCommitFailure` sorts as unreachable; reuse that set rather than a second list), log `offline:read-served-locally` once per table per episode and serve the local view;
- every other error propagates as today, including `BlockUnavailableError` with any other reason: a block this machine does not hold still fails the read.

Each outcome reports to the controller (`OfflineMode.noteLiveRefresh(servedLocally)`), which sets `readsServedLocally` on the queue state to the last report's value and publishes when it changes. A refresh that succeeds clears it.

The reachability port comes from `CollectionFactory.getCohortReachability(options)`: a registry keyed like transactors (`registerCohortReachability(key, port)` for tests and for stage 6's node attachment), answering `alwaysReachable` for every transactor until stage 6 wires the `network` one. The controller hands the same port to the queue (`OfflineQueueOptions.reachability`), so the drain and the reads ask one gate.

Committed reads (`committed.<Table>`) never refresh and are unchanged. A `'network'` table keeps today's fail-loud read in every mode.

## Edge cases & interactions

- **Mode off, cohort unreachable**: a live read fails as today. Test.
- **Mode on, `'network'` table, cohort unreachable**: fails as today with `BlockUnavailableError` reachable through `cause`. Test.
- **Mode on, `'queue'` table, refresh fails for unreachability**: the read serves committed blocks held plus every queued entry; `readsServedLocally` becomes true; after reconnect the next read refreshes and it becomes false. Test, driving unreachability through a wrapped transactor whose `get` answers `unavailable: 'cohort-unreachable'` while armed (the `registerTransactor` seam in `mesh-node-harness.ts`), since the mesh's `silentPeers` does not make a node's own replica unreadable.
- **Mode on, port says unreachable**: no refresh is attempted. Test with a registered port returning `false`, asserting the wrapped transactor saw no `get` for the read.
- **A block this machine does not hold** fails even in offline mode: a table never read on this node, read while unreachable, throws. Test: a second table node A has never touched.
- **The DML path's probe reads** degrade the same way, so an offline insert into a table with a unique column succeeds while unreachable. Test one insert.
- **A refresh that fails with another reason** (`claimed-elsewhere`, `named-by-log`, a `BlockPossiblyStaleError`) propagates. By inspection of the reason set.
- **The committed read path** is untouched. By inspection.
- **Index-driven read and full scan agree** on the local view while unreachable. Covered if the degraded-read test runs both plan shapes.
- **Degrade happens inside a transaction** too (a live `select` mid-transaction). Covered by the autocommit case only; by inspection otherwise, since `refreshLive` has no transaction branch.
