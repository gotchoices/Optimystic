# Blob announcements are answered

docs/blobs.md §Placement, copying and durability: a writer whose committed row references a blob *announces* it to the blob's cohort, and each member decides for itself whether to take it. §Who may fetch and who may store: "A node takes a blob on another's behalf only after reading committed state and finding the reference in the scope the announcement names, and only when that scope is in the registry and the node is in the blob's cohort. An announcement is a hint about where to look; it grants nothing."

Third of three parts. The prereqs built the node's reader of committed state (`BlobReferenceCheck` over the node's own `NetworkTransactor`), the client's `announce` and `held`, which peers accept blobs, and the `responsible` hold with its scope (`LocalBlobService.holdResponsible`). This part builds the receiving half of `announce`, the `blobs.hold` node option, readers keeping what they fetch, and restarting an interrupted pull. It does not track who still owes a copy, announce on its own, wire the `held` sink to anything but a log line, or report durability: that is `feat-blob-owed-copies-are-drained`.

## The receiver

```ts
// packages/db-p2p/src/blob/announce-receiver.ts
export interface BlobAnnounceReceiverDeps {
	selfId: string;
	hold: 'eager' | 'on-demand';
	keyNetwork: Pick<IKeyNetwork, 'findCluster'>;
	membership?: NetworkMembershipGate;
	limiter: AnnounceLimiter;
	references: Pick<BlobReferenceCheck, 'inScope' | 'anywhere'>;
	local: Pick<LocalBlobService, 'stat' | 'holdResponsible' | 'responsibleScope' | 'responsibleRefs'>;
	fetcher: Pick<BlobFetcher, 'start'>;
	client: Pick<BlobProtocolClient, 'held'>;
	/** How long `decide` may spend reading committed state before it answers `unreferenced`: half the node's `responseTimeoutMs` (below). */
	answerWithinMs: number;
	/** Default armUnrefTimer. */
	setTimer?: (fn: () => void, ms: number) => () => void;
}

export class BlobAnnounceReceiver {
	constructor(deps: BlobAnnounceReceiverDeps);
	/** The answer to one `announce`. Rejects only when the hold write fails (a local store fault). */
	decide(announcer: string, ref: BlobRef, scope: BlobScope): Promise<BlobAnnounceAnswer>;
	/** Reader repair, fire and forget: see below. */
	keepAfterRead(ref: BlobRef): void;
	/** Restart the pull of every blob holding `responsible` that is not whole here. */
	resume(): Promise<void>;
	/** Marks the receiver stopped: a pull that ends after this is logged as stopped, not given up, and nothing is sent. */
	stop(): void;
}
```

### `decide`, in this order

1. `hold === 'on-demand'` → `declined`, before any lookup.
2. **Membership.** `admittedBy(membership, announcer)` false → `unreferenced`, logged `announce:refused-peer`, before any lookup. (The inbound stream gate, when configured, already refused non-members; this covers a node with only a membership predicate.)
3. `findCluster(routingKeyForBlob(ref))` does not include `selfId` → `not-responsible`. A lookup that throws → `not-responsible` too (responsibility undetermined; the announcer asks again), logged `announce:cohort-unresolved`.
4. **Per-peer bound.** `limiter.admit(announcer)` false → `unreferenced`, logged `announce:limited`, with no committed-state read. After the cohort check on purpose: an honest peer whose cohort view differs from ours spends no allowance.
5. `references.inScope(ref, scope)`, run inside `limiter.readSlot(...)` and raced against `answerWithinMs` measured from the start of `decide` (so waiting for a slot counts). Anything but `listed` → `unreferenced`. Not done in time → `unreferenced`, logged `announce:read-slow`; the read keeps its slot until it finishes (so slow reads still bound the node's read work) and its result is discarded.
6. `local.stat(ref)` reports locality `here` → `local.holdResponsible(ref, scope)` and answer `whole`.
7. Otherwise `local.holdResponsible(ref, scope)`, then start (or join) the pull with `announcer` recorded as awaiting `held` (below), and answer `fetching`.

Every answer is logged `announce:answer peer=%s ref=%s answer=%s ms=%d` (on `createLogger('blob:protocol')`, replacing nothing: `BlobProtocolService` keeps its `serve:announce` line).

**Why the read is time-boxed.** Both ends of a blob exchange run a `ProgressDeadline` of one `responseTimeoutMs` with no bytes moving (`packages/db-p2p/src/blob/progress-deadline.ts`), and while `decide` reads, nothing moves: a decision slower than that would abort the stream on both sides. `answerWithinMs = linkDeadlines.responseTimeoutMs / 2` leaves the other half for the answer frame. An `unreferenced` from a slow read is the same answer as "could not read", which the announcer already retries. Rejected: sending a keep-alive frame while reading (a wire change for a case the retry already covers).

**The hold before the answer.** `holdResponsible` writes and flushes before `decide` returns, so a restart after `fetching` keeps the hold and `resume` finishes the pull. A second verification under another scope replaces the hold's scope; either scope authorizes. A hold write that throws makes `decide` reject; `BlobProtocolService` then aborts the stream (its existing `abandon` path), the announcer sees a reset and asks again.

**The `cached` hold.** The fetch takes a `cached` hold as every fetch does (docs/blobs.md §Holds); it is left beside `responsible`. Nothing evicts a blob that holds anything but `cached` (`feat-blob-cached-copies-stay-within-a-budget` counts cache-only blobs), and when `responsible` is later released the blob falls back to the cache budget as a blob that was read would. Rejected: removing `cached` after the pull, which costs a write and would drop a blob a reader had also read the moment `responsible` went.

### The pull and `held`

One pull per ref: `inFlight: Map<BlobRef, Set<string>>`, the announcers awaiting `held`.

- Starting: if the ref has an entry, add the announcer (when there is one) to its set and return. Otherwise create the entry and call `fetcher.start(ref, { priority: 'background', knownHolders: announcer ? [announcer] : [] })`. The announcer may be a writer outside the cohort and the only holder, which is why it goes in `knownHolders`; the fetcher still filters it like every candidate (`blobHolderCandidates`). A second announcer joining a pull in flight is not added to that session's candidates (sessions fix `knownHolders` at start); if the first session gives up, the second announcer's next announcement starts a fresh pull with it first. No `waitMs`: a pull fails after one round that leaves a piece unavailable, and the announcer's own drain re-announces.
- Resolved: delete the entry, then send `client.held(peerIdFromString(a), ref)` to each awaiting announcer the membership gate still admits; a send that fails is logged `held:send-failed` and not retried (the announcer's drain re-announces and is answered `whole`). The fetch session already marked the record whole.
- Rejected: delete the entry, keep the hold, log `fetch:gave-up ref=%s err=%s` (or `fetch:stopped` after `stop()`). The next announcement for the ref starts a fresh pull.

`resume()` lists `local.responsibleRefs()` and starts a pull with no announcer for each ref not `here`. The node calls it off the start path (`void receiver.resume().catch(...)`, logged).

### Reader repair

docs/blobs.md §Placement, copying and durability, "Readers repair". `keepAfterRead(ref)`: ignored when `hold === 'on-demand'` or a repair for the ref is already running (a `Set`); otherwise, in the background: `findCluster(routingKeyForBlob(ref))` includes `selfId` (a throw is logged and ends the repair), `local.responsibleScope(ref)` is undefined (already responsible: nothing to do), then `references.anywhere(ref)` inside `limiter.readSlot` (no per-peer allowance: this node asked itself). On `listed`, `local.holdResponsible(ref, verdict.scope)` and log `read:kept-responsible ref=%s scope=%s`. Any other verdict leaves the `cached` hold alone. Nothing here throws out of `keepAfterRead`.

`NodeBlobService` calls it: add `afterFetchedWhole?: (ref: BlobRef) => void` to `NodeBlobServiceDeps`, called from `startSession` when a session it started resolves and `local.stat(ref)` then reports `here` (stat failure logged, no call). Every session this service starts was started because something was missing: `readFetching` starts one only on a miss, and make `fetch` return at once without starting a session when `local.stat(ref)` is already `here` (its documented behaviour), so a `fetch` of a whole blob reads no committed state.

## The per-peer bound

```ts
// packages/db-p2p/src/blob/announce-limiter.ts
export class AnnounceLimiter {
	constructor(options?: { perPeerPerMinute?: number; readsInFlight?: number; maxPeers?: number; now?: () => number });
	/** Counts one announcement from `peer` in its current one-minute window; false once the window is full. */
	admit(peer: string): boolean;
	/** Runs `read` when fewer than `readsInFlight` reads are running, waiting its turn otherwise (FIFO); never refuses. */
	readSlot<T>(read: () => Promise<T>): Promise<T>;
}
```

Constants in `protocol-limits.ts`: `BLOB_ANNOUNCES_PER_PEER_PER_MINUTE = 600`, `BLOB_REFERENCE_READS_IN_FLIGHT = 4`, `BLOB_ANNOUNCE_PEERS_TRACKED = 4096`. A fixed window per peer (start time and count); an entry whose window has passed is reset on access; at `maxPeers` a new peer evicts the entry with the oldest window start. 600 per minute is above what an honest announcer sends: its drain examines at most 64 entries per pass with at least 15 s between passes (256 a minute), and the cohort reaction at most 64 per check with at least 60 s between checks — say so in the constant's comment. Leave a `NOTE:` at the eviction: a flood of fresh peer ids can evict a real peer's window, resetting its count early; bounded by the read concurrency, which no peer id can raise.

## Edge cases & interactions

- **Unregistered scope**: `unreferenced`, no reference-tree read (pinned by the prereq's reference-check spec; here the table case below asserts the answer).
- **Committed state unreadable or uncertain**: `unreferenced`, no pull, no hold (inspection: one branch for every non-`listed` verdict).
- **Announce before the receiver can see the commit**: `unreferenced`; the announcer asks again (end to end in the drain ticket).
- **On-demand**: always `declined`, before any lookup (test). Reader repair does nothing (inspection).
- **Not in the cohort by this node's own view**: `not-responsible`, no reads (inspection: step 3 precedes every read).
- **Hostile announcer**: real referenced blobs are bounded by the per-peer allowance; unreferenced ones cost registry reads within the same allowance and the shared read concurrency, and fetch nothing; malformed refs and bad scopes are refused by the codec before `decide` (inspection).
- **Slow read**: answered `unreferenced` within half a response timeout; the read keeps its slot until done (inspection).
- **Crash after `fetching`**: the hold was flushed before the answer; `resume` restarts the pull and the fetcher fetches only what is missing (inspection; restart test in the drain ticket).
- **Two announcers, one pull**: both recorded, one session, both sent `held` (inspection).
- **A `held` from a non-member**: dropped in the node's `onHeld` closure (inspection).
- **Pins and `cached` holds** are never removed by this part (inspection).
- **A read of an already-responsible blob**: reader repair finds the scope and reads nothing (inspection).
- **Node stop mid-pull**: the fetcher rejects the session; logged `fetch:stopped`, no `held` sent, hold kept (inspection).
