# Unreferenced blobs are reclaimed

A blob is kept on a machine while some hold names it (docs/blobs.md §Holds). A responsible machine takes a `responsible` hold on a blob once it finds committed state referencing it, and a writer keeps an `owed` hold and an owed entry until its cohort holds the blob; nothing releases either when the references go. This ticket adds the reference pass of docs/blobs.md §Lifetime: periodically, and on demand, each node reads every registered reference tree for the blobs it holds under `responsible` or owes, and releases a hold only for a blob that two counting passes at least a grace period apart (7 days by default) found listed nowhere. Releasing the last hold leaves the blob's pieces to the piece sweep. Cache eviction is `BlobCacheBudget` and is untouched.

Two prereqs, for two different reasons. `feat-a-blob-remembers-when-it-was-last-found-unreferenced` lands the marks and the conditional writes this pass is built on. `feat-a-held-blob-follows-its-cohort` lands no code this pass calls, but it rewrites the same docs/blobs.md status line and the same §Holds rows this ticket edits, and it is the last part of §Placement, copying and durability — so its documentation lands first and this ticket's §Lifetime rewrite is the next thing a reader of that document meets.

**This is the first code in the repository that deletes replicated data on a schedule.** Nothing reclaims block storage today (`gcEligibleBlocks` in `packages/db-p2p/src/libp2p-node-base.ts` is filled and never swept). Every rule below errs toward keeping: a wrong release deletes a file a committed row still names, on each holder independently, with nothing left to repair from.

## Where the pass reads from

Through the node's own `NetworkTransactor` — the one `createNodeNetworkTransactor` builds in `createLibp2pNodeBase` and `BlobReferenceCheck` already reads with — wrapped for each pass in a `ConfirmationRecordingTransactor`. It reads with `BlobScopeRegistry.enumerate(transactor)` and `BlobReferenceTree.listed(transactor, scope, refs)`, which open a fresh read-only handle on every call (`readCommittedTree`), refresh it to the newest committed state, and report `certain: false` for a read that threw `BlockUnavailableError` or `BlockPossiblyStaleError` or that received a below-floor answer. Nothing new is needed on either reader.

## `ConfirmationRecordingTransactor`

`packages/db-p2p/src/blob/confirmation-recording-transactor.ts`:

```ts
/** A read-only `ITransactor` for one reclaim pass. Every read asks the answering coordinators to
 *  consult in front of the answer (`BlockGets.awaitConsult`), and every block whose answer did not
 *  carry `GetBlockResult.cohortConfirmed` — including a block the result omits — is recorded. */
export class ConfirmationRecordingTransactor implements ITransactor {
	constructor(inner: ITransactor);
	/** Block ids whose answers no cohort member outside the answering node vouched for. */
	readonly unconfirmed: ReadonlySet<BlockId>;
	get clock(): HlcClock | undefined;			// the inner transactor's
	get(blockGets: BlockGets): Promise<GetBlockResults>;	// inner.get({ ...blockGets, awaitConsult: true }), then record
	getStatus(actionRefs: ActionBlocks[]): Promise<BlockActionStatus[]>;	// delegates
	pend(): Promise<PendResult>;				// throws ReclaimReadOnlyError
	cancel(): Promise<void>;				// throws ReclaimReadOnlyError
	commit(): Promise<CommitResult>;			// throws ReclaimReadOnlyError
}

/** A reclaim pass tried to write. Nothing in a pass writes, so this is a defect, not a condition. */
export class ReclaimReadOnlyError extends Error {}
```

- **Read-only by construction.** The three write methods throw rather than delegate: a pass that wrote would be a defect, and a transactor that quietly allowed it would hide one. `ITransactor`'s optional members (`queryClusterNominees`, `getLineage`, `pendMany`, `commitMany`) are omitted — a read path asks none of them, and omitting is how this type says so.
- **A `get` that throws records nothing and propagates.** The reader turns the two doubt-shaped errors into `certain: false` and lets anything else through, which the pass catches as a throw.
- **A block the result omits counts as unconfirmed**, as does a block whose entry carries no `cohortConfirmed`. The marker is positive (docs/internals.md §Consensus Execution, *A third, POSITIVE marker*), so absent means "not known to be confirmed" — including an answer from a peer that predates the field.
- One pass builds one of these, so `unconfirmed` accumulates across the registry read and every tree read of that pass.

## The predicate

One named, pure function holds every disqualifying condition from docs/blobs.md §Lifetime. A pass **counts** exactly when it returns an empty list. Separating it from the pass is what makes those conditions enumerable and testable without a network.

```ts
export type ReclaimNotCountedReason =
	| 'partition'			// detectPartition() was true at the start or the end of the pass
	| 'registry-threw'		// enumerate() threw
	| 'registry-uncertain'		// enumerate() answered certain: false
	| 'registry-absent'		// enumerate() answered exists: false while this node holds a responsible blob or owes one
	| 'tree-threw'			// some listed() threw
	| 'tree-uncertain'		// some listed() answered certain: false
	| 'unconfirmed-not-alone'	// some block answer was not cohortConfirmed and aloneFor(those blocks) was false
	| 'stopped';			// the pass was stopped before it applied anything

export interface ReclaimEvidence {
	readonly partitionAtStart: boolean;
	readonly partitionAtEnd: boolean;
	readonly registry: 'threw' | { readonly certain: boolean; readonly exists: boolean };
	/** Whether this node holds any `responsible` blob or owes one; an absent registry only disqualifies such a node. */
	readonly holdsAny: boolean;
	readonly trees: readonly { readonly scope: BlobScope; readonly outcome: 'threw' | 'certain' | 'uncertain' }[];
	readonly unconfirmedBlocks: number;
	/** `aloneFor` over the unconfirmed blocks; `undefined` when there were none. */
	readonly aloneForUnconfirmed: boolean | undefined;
	readonly stopped: boolean;
}

/** Every reason this pass does not count toward reclaiming; empty when it counts. In the declaration
 *  order of {@link ReclaimNotCountedReason}, so the log line and the report are stable. */
export function whyPassDoesNotCount(evidence: ReclaimEvidence): ReclaimNotCountedReason[];
```

How each rule in docs/blobs.md §Lifetime maps:

- **A read that throws**, including `BlockUnavailableError` for any reason and `BlockPossiblyStaleError`: the reader catches those two and answers `certain: false` (`tree-uncertain`, `registry-uncertain`); anything else it lets through and the pass catches it (`tree-threw`, `registry-threw`).
- **A registry that cannot be read or opened**: `registry-threw` or `registry-uncertain`. **A registry that reads as authoritatively absent while this node holds any responsible blob or owed entry**: `registry-absent` — the registry existed when those holds were taken. An existing registry with no scopes **counts**: every reference tree was unregistered, so every blob really is unreferenced there.
- **A below-floor answer**: the reader reports it as `certain: false`, so it arrives as one of the two `uncertain` reasons.
- **A pass during a detected partition**: `partition`, checked before the first read and after the last.
- **A read that rested on asking nobody, unless the node is alone**: the recording transactor collects every block whose answer lacked `cohortConfirmed`; when there are any, the pass asks `aloneFor` over exactly those blocks after its last read, and `false` gives `unconfirmed-not-alone`. An answer from another machine that lacked the marker — an older build, or a coordinator that itself asked nobody — makes `aloneFor` false anyway, since that machine is in the cohort.
- **A reference tree the registry lists that reads as authoritatively absent**: the reader answers it empty and certain, which is right; the "after a consult" half of trusting that is the confirmation rule above.

## `BlobReclaimPass`

`packages/db-p2p/src/blob/reclaim-pass.ts`:

```ts
/** Four passes a day. Bounds a release to between the grace period and the grace period plus six
 *  hours after the first counting pass, at four full reads of every registered reference tree a day
 *  on a node holding blobs; one hour would be 24. */
export const DEFAULT_RECLAIM_INTERVAL_MS = 6 * 60 * 60 * 1000;
/** Long enough for a starting node to have dialed its bootstrap peers and identified its cohort,
 *  although the confirmation rule already keeps a cold node's passes from counting. */
export const DEFAULT_RECLAIM_FIRST_PASS_DELAY_MS = 5 * 60 * 1000;

export interface BlobReclaimDeps {

	readonly owed: Pick<OwedBlobLedger, 'list' | 'clearUnlisted' | 'markUnlisted' | 'deleteIfUnlisted'>;

}

	readonly startedAt: number;

	 *  pass reports `false` with nothing in `notCounted` for `'nothing-held'` (there was nothing to
	 *  decide) and `['stopped']` for `'stopped'`. */

	readonly notCounted: readonly ReclaimNotCountedReason[];

	readonly responsibleChecked: number;

/** The on-demand entry, which is all the node attaches. */

	runNow(): Promise<ReclaimPassReport>;
}

export class BlobReclaimPass implements BlobReclaimOnDemand {
	constructor(deps: BlobReclaimDeps, options?: BlobReclaimOptions);
	/** Arm the first pass after `firstPassDelayMs`; each later pass `intervalMs` after the previous one ended. */
	start(): void;
	/** Run a pass now, or join the one running. Rejects after `stop`. */
	runNow(): Promise<ReclaimPassReport>;
	/** Clear the timer, mark stopped — a running pass then applies nothing further — and wait for it. */
	stop(): Promise<void>;
}
```

### One pass, in order

1. `startedAt = now()`. **Snapshot the work:** every blob record holding `responsible` with its mark (`records.responsibleMarks()`, already ascending by reference — references have one accepted spelling and compare as strings), and every owed entry with its scope and mark (`owed.list()`). If both are empty, return `skipped: 'nothing-held'` without reading anything.
2. `partitionAtStart = detectPartition()`. When true, read nothing: the pass does not count, and nothing is marked or cleared.
3. A fresh `ConfirmationRecordingTransactor` over `deps.transactor`.
4. `BlobScopeRegistry.enumerate(recorder)`. When it throws, answers `certain: false`, or answers `exists: false`, stop reading — step 8 still runs, so the report and the log say why.
5. **For each registered scope, in the registry's ascending order:** the references to ask about are the snapshot's responsible references not yet found listed by an earlier tree, together with the owed references whose entry names this scope. When that set is empty, skip the tree. Otherwise `BlobReferenceTree.listed(recorder, scope, refs)` inside a `try`; a throw is recorded as `threw` and logged. Add what it lists to the responsible listed set and to this scope's owed listed set. **Continue with the next tree whatever the outcome**, so references other trees list still have their marks cleared. Check the stopped flag between trees.
6. An owed entry whose scope the registry does not list is unlisted — that tree was unregistered when its collection was dropped.
7. When the recorder holds unconfirmed blocks, `cohort.aloneFor([...recorder.unconfirmed])`.
8. `partitionAtEnd = detectPartition()`, then `whyPassDoesNotCount(...)`.
9. **Apply**, unless stopped, one record or entry at a time, each write conditional on the record or entry as it is at that moment:
   - A responsible reference found listed by any tree, certain or not — a listing is evidence of a reference, and clearing only delays reclaiming — `records.clearUnreferenced(ref)` when the snapshot showed a mark.
   - An owed reference found listed by its own scope: `owed.clearUnlisted(ref)` when the snapshot showed a mark.
   - **Only when the pass counts**, for each responsible reference listed nowhere, `judgeMark(snapshotMark, startedAt, graceMs)`:
     - `'mark'` → `records.markUnreferenced(ref, startedAt)`;
     - `'release'` → `records.releaseResponsibleIfMarked(ref, snapshotMark)`; a record left with no hold is deleted by the record store and its pieces are left for the sweep;
     - `'keep'` → nothing.
   - **Only when the pass counts**, for each owed entry unlisted in its scope, the same decision on its mark; `'release'` is `owed.deleteIfUnlisted(ref, snapshotMark)` **first** and then, only if that wrote, `records.releaseOwed(ref)`.
   - **A pin is never read or changed.** A pinned blob that loses `responsible` or `owed` keeps its record and its pieces.
10. When any hold was released, `await records.sweep()` once.
11. Log the pass line and return the report.

**Why the conditional writes are the safety argument.** They are what make a pass safe against everything that changes holds while it reads. An announcement that took a `responsible` hold mid-pass cleared the mark, so the snapshot's mark no longer matches and nothing is released; a hold released and re-taken by the cohort reaction is the same. Every one of those conditions is the prereq ticket's "the change function is itself the condition", applied at that reference's turn in the store's own per-reference queue — there is no re-read and no lock.

**Order of the owed release.** Entry first, hold second: a crash between them leaves an `owed` hold with no entry, which keeps the blob — storage leaked, nothing lost. The reverse would leave an entry whose drain announces a blob this node no longer holds. Record the leak as a `NOTE:` at the release:

```
// NOTE: a crash between the entry delete and the hold release leaves an `owed` hold with no entry,
// which keeps the blob for ever — storage leaked, nothing lost, and the safe direction. If orphaned
// `owed` holds are ever seen, release an `owed` hold with no entry on the next pass.
```

**Durability of marks.** The record store and the ledger write a mark without forcing a flush, and flush a mark they drop (corrected in the prereq's review — the two directions are not equally safe to lose, and the methods' own comments carry the argument). A mark lost to a crash only delays reclaiming by one grace period; a release lost to a crash leaves the hold, which the next counting pass releases again, its mark still old enough. Do not "simplify" `clearUnreferenced`/`clearUnlisted` back to not flushing: a lost clear leaves an over-age mark on a reference that is listed again, and the first later pass that finds it unlisted then reclaims with no grace period at all.

**Schedule.** `start()` arms `armUnrefTimer` for `firstPassDelayMs`; each pass, from the timer or from `runNow`, re-arms the timer `intervalMs` after it **ends**, so passes never overlap and a long pass delays the next rather than stacking. `runNow` while a pass runs returns that pass's promise — joining is right here, unlike `BlobCacheBudget`'s single-flight-with-a-follow-on, because a pass's verdict is about committed state the joiner has not changed. A pass that throws outside its reads (a record store failure) is logged `reclaim:pass-failed` and the timer is re-armed; `runNow` rejects with the error.

**Not wired: cache enforcement after a release.** The `NOTE:` above `BlobCacheBudget` in `packages/db-p2p/src/blob/cache-budget.ts` names this ticket's releases as a way the cache can sit over budget, and sets the condition for acting: "if a node is ever seen sitting over budget with its reads idle, call `request()` from those releases too." That condition has not tripped, so do not wire it; a blob this pass releases that still carries `cached` is counted at the next enforcement. Leave the `NOTE:` as it is — it is already accurate about this pass.

## Edge cases & interactions

- **Two passes too close together.** The second, inside the grace period, keeps the mark unchanged. Test.
- **Referenced in between.** Unreferenced, referenced, unreferenced: the grace period runs from the third pass. Test.
- **One failing tree among many.** The pass does not count for any blob, and references other trees list still have their marks cleared. Test. The failing read is a `BlockPossiblyStaleError`, which also covers the stale-read case: both reach `certain: false` through the reader's one catch arm, and `BlockUnavailableError` takes the same arm, by inspection of `readCommittedTree`.
- **A node that cannot see its cohort.** A self-only view with a remembered member missing answers unconfirmed, `aloneFor` is false, and nothing is marked or released over two passes a grace period apart. Test.
- **A deployment of one machine.** Alone by the gate's test, holding the registry and the trees itself: passes count, and a blob unreferenced at two of them a grace period apart is released. Test.
- **Confirmed answers on a node that is not alone.** The pass counts without consulting `aloneFor` at all. Test.
- **Partition.** Not counted, and nothing is read when it is detected at the start. Test for the start; the end check feeds the same predicate field, by inspection.
- **Absent registry while holding.** Not counted. Test. **An existing, empty registry** counts and releases after two passes: the predicate table.
- **An owed blob whose row was deleted.** After two counting passes the owed entry and the `owed` hold are gone and the drain no longer lists it. Test.
- **An owed blob whose scope was unregistered.** Unlisted, released after two counting passes. Inspection — the same branch as the deleted row once the scope is missing from the registry.
- **Pinned blob.** Released from `responsible`; the record, the pin and the pieces stay. Test.
- **Restart between passes.** The first pass's mark is in the record store, so a second `BlobReclaimPass` over the same stores releases after the grace period. Test.
- **A hold re-taken after a stale mark.** A record marked long ago whose `responsible` hold is released and re-taken carries no mark, so one counting pass does not release it. Test — this is the conditional-write and clear-on-hold rule, the branch most likely to delete a live blob.
- **Shared pieces.** Two blobs share a piece; releasing one leaves the piece for the other after the sweep. Asserted once inside the one-machine test.
- **Hold changes during a pass.** Covered by the conditional writes. Inspection.
- **Clock going back or forward.** `judgeMark`'s own rule and its accepted-tradeoff `NOTE:`, both from the prereq. Inspection.
- **A reference that outlives its bytes** — an old revision of a row read from history — reads as `BlobUnavailableError` with the fetcher's reason, never a missing-block error. Inspection of the fetch path; nothing here changes it.
- **Re-referencing.** No release on one pass, at startup or ever: every release needs a mark from an earlier counting pass at least `graceMs` (at least one hour) older. Inspection of `judgeMark` and `resolveReclaimGraceMs`.
- **Large holdings.** One `listed` per registered tree, each one ordered walk over the tree with the references still unlisted, so cost is bounded by the trees' sizes rather than by blobs times trees. Two costs worth a `NOTE:` at the pass:

  ```
  // NOTE: `awaitConsult` makes each expired-window block a blocking consult, and the trees are read
  // one after another. If pass time shows up, read trees concurrently with a small bound.
  // NOTE: `aloneFor` makes one `findCluster` per distinct unconfirmed block, which on a node that IS
  // alone is every block of every tree it read — nothing confirms there, by construction. Local
  // lookups, once per pass; if they show up, have the gate answer for a set of routing keys with the
  // cluster lookups memoized.
  ```

- **Stop during a pass.** No write happens after the stopped flag is seen. Inspection.
- **A pass that joins another.** `runNow` returns the running pass's promise, so two callers see one report. Inspection.

## Tests

`packages/db-p2p/test/blob-reclaim-pass.spec.ts`. One harness, in the shape `packages/db-p2p/test/blob-reference-check.spec.ts` builds its committed state:

- Committed state in a db-core `TestTransactor`; registry and reference-tree entries written through `BlobScopeRegistry.register` and `BlobReferenceTree` staging plus `sync`; references made with `buildBlob`.
- Blob records and the owed ledger on `MemoryKVStore`; pieces in `MemoryPieceStore` behind a real `LocalBlobService`, whose `sweep` the pass reaches through `records`.
- `cohort` is a real `KeyNetworkCohortReachability` over a key-network double returning a fixed cohort and absent-member list, the shape `packages/db-p2p/test/cohort-reachability.spec.ts` uses.
- `partitionDetector` is a real `PartitionDetector`, driven into partition with `recordFailure`.
- `TestTransactor` answers never carry `cohortConfirmed`, so the confirmed-answers case uses a `TestTransactor` subclass whose `get` adds the marker to every entry — the same subclassing `WatchedTransactor` in the reference-check spec uses, which is simpler than wrapping a `DelegatingTransactor`.
- The clock is injected through `options.now`; `start()` is never called, so no timer is ever armed. `G` is the default grace period.

- **The predicate.** `whyPassDoesNotCount` over a table of evidence objects: empty for a clean pass; `partition` from either end; `registry-threw`, `registry-uncertain`, and `registry-absent` only when `holdsAny`; `tree-threw` and `tree-uncertain` from one tree among several; `unconfirmed-not-alone` only when `aloneForUnconfirmed` is false, and not when it is `undefined`; `stopped`; and an existing, empty registry with unconfirmed blocks this node is alone for counting. Several reasons at once come back in declaration order.
- **One machine releases after two passes a grace period apart.** Alone. Blobs A and B share a piece; A's reference is in a registered tree and B's is not; both hold `responsible`. Pass at `t`: B marked, A not. Pass at `t + G`: B's `responsible` hold is released, its record is gone, B's own pieces are swept, and the shared piece and A are untouched.
- **Too close together.** Passes at `t` and `t + G - 1`: B's mark is still `t` and it still holds `responsible`.
- **Referenced in between.** Pass at `t` (unlisted), add B to a tree, pass at `t + 1` (listed, so the mark is cleared), remove it, pass at `t + 2` (marked `t + 2`), pass at `t + G` (kept), pass at `t + 2 + G` (released).
- **One failing tree.** Alone, so the failing tree is the only reason. Several registered trees, one of them read through a transactor that throws `BlockPossiblyStaleError` for that tree's header; a blob listed in one of the clean trees has a mark from an earlier pass. Two passes `G` apart: nothing marked and nothing released, the listed blob's mark cleared, and the report says `tree-uncertain`.
- **A node that cannot see its cohort.** Self-only cohort with an absent-member list naming another peer: passes at `t` and `t + G` mark nothing, release nothing, and report `unconfirmed-not-alone`.
- **Confirmed answers count without being alone.** A cohort naming this node and another, answers marked confirmed: passes at `t` and `t + G` release B.
- **Partition.** Partition detected: the pass reports `partition`, `treesRead: 0`, and nothing is marked.
- **Absent registry.** Nothing registered and B held `responsible`: `registry-absent`, nothing marked.
- **An owed blob whose row was deleted.** An owed entry for B naming a registered scope that no longer lists it: after passes at `t` and `t + G` the entry and the `owed` hold are gone.
- **Pinned blob.** B pinned and `responsible`: after two passes `G` apart the `responsible` hold is gone and the pin, the record and the pieces remain.
- **Restart.** Pass at `t`; build a second `LocalBlobService`, `OwedBlobLedger` and `BlobReclaimPass` over the same `MemoryKVStore` and `MemoryPieceStore`; a pass at `t + G` on the new instance releases B. (A `PowerLossKVStore` is deliberately not used: marks are not flushed by design, so modelling a crash would pin a durability this ticket does not promise. What this case pins is that the mark lives in the store rather than in the pass.)
- **A re-taken hold is not released on one pass.** Mark B at `t`; release and re-take its `responsible` hold through `releaseResponsible` and `holdResponsible`; a pass at `t + G` marks it afresh instead of releasing it.
