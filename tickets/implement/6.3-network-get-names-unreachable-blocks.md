## The defect

`NetworkTransactor.get` (`packages/db-core/src/transactor/network-transactor.ts`) merges the per-coordinator batches, runs its one second-chance round, and then, if any requested block has no entry at all (`missingIds`), throws a plain `Error('Some peers did not complete: …')` for the whole read. The offline live-read degrade absorbs only `BlockUnavailableError` with an unreachability reason (`isCohortUnreachableRead`), so on a `network` transactor whose every request for a block failed in transport the read fails instead of being served locally, and `classifyCommitFailure` sorts the same failure in a write's refresh as `unknown`.

## Why the reachability gate does not make this moot

The gate (`offline-sync-reachability-gate`) answers "reachable" whenever the cohort names a member other than this node, and a member stays in the cohort for as long as FRET holds it live — up to `maxDeadGraceMs` (5 minutes by default) after a long-lived partner leaves. The plugin's own node runs `clusterSize: 1` (`CollectionFactory.createNetworkTransactor`), so half of a two-machine group's blocks have the partner as their only responsible peer and are read remotely. In that window the gate is open, the refresh goes out, every request fails in transport, and the read meets the aggregate. So the read path must type this failure itself.

## Design

The three-valued block answer already has the right value: `GetBlockResult.unavailable`, whose `'peers-unreachable'` reason means "part of the cohort answered, part was silent — or the consult threw outright". After the retry round, split `missingIds`:

- **Unanswered**: no batch carrying the block produced a response (every one errored, timed out, or was still in flight at the deadline). Return an entry for it flagged `unavailable: 'peers-unreachable'`, shaped as `CoordinatorRepo` shapes its own flagged absent entries (no block, empty state — read what that code returns and match it). Log `get:unanswered blockIds=… root=…` with the first batch error, the information the aggregate's message carried.
- **Answered but omitted**: some coordinator responded and its response left the block out. That is a protocol fault, not unreachability; keep throwing the aggregate for it, unchanged.

The other blocks of the read are returned as answered, instead of failing with their unanswered sibling.

Every consumer of a flagged entry already exists and is documented under *A block read has three answers* in docs/internals.md: `TransactorSource.tryGet` throws `BlockUnavailableError(id, 'peers-unreachable')`, `Collection.checkedLogTail` applies the same `answeredBlock` check, `NetworkTransactor.getStatus` throws. Read every other direct consumer of `ITransactor.get` / `NetworkTransactor.get` and confirm it checks `unavailable` before drawing a conclusion from an empty entry — at least `Collection.readLogEnds`, `Collection.readAttributed` / `readAlone` (the committed-tail reader the watch service uses), `NetworkTransactor.getStatus` and `refineInvalidatedStatuses`, and `getLineage`'s callers. A consumer that reads `entry.block` or `entry.state.latest` without checking the flag would now take an unreachable block for an absent one; fix any such site in this ticket.

## Consequences to state, not to change

- **Classification.** A write whose refresh meets this now sorts `cohort-unreachable` (wait) where it sorted `unknown` (retry only under the attempt's own identity). Both keep a queued entry queued; the queue's in-doubt flag is sticky and set by the drive record, not by the classification, so an entry that may have landed keeps its identity either way. The rule "the error thrown, never its `cause`" in `classifyCommitFailure` is about the commit-phase aggregate (`commitBlock`'s), which is untouched.
- **Error text.** A read that used to throw `Some peers did not complete: …` now throws `Block <id> is unavailable (peers-unreachable): …` from `TransactorSource`. Update specs that matched the old text for a `get`; leave the `pend` and `commitBlock` aggregates alone.

## Edge cases & interactions

- **Retry round answers it** → answered entry, no flag. Existing behaviour; by inspection.
- **One block unanswered, sibling answered** → sibling returned, unanswered one flagged. Test.
- **Block answered but omitted by a responding coordinator** → aggregate thrown as before. By inspection.
- **Batch still in flight at the deadline** → counts as unanswered. By inspection of `formatBatchStatuses`' `in-flight` status.
- **Merge ranking** → a flagged entry ranks lowest (`unavailable`), so a later answer for the block always replaces it; the new entries are created after the merge, so they never compete with a real answer. By inspection.
- **Live read in offline mode** → `refreshLive` now absorbs it through `isCohortUnreachableRead`; remove the `NOTE:` there that names this remedy and say in one line that the transactor types it.
- **`createOrOpen` probe** → an unanswered header probe now throws `BlockUnavailableError` (already the documented behaviour for a flagged probe) instead of the aggregate. By inspection.
