# Every store reports its bytes and its free space

## Why

The next ticket gives a node one storage allotment and makes it measure its use against the smaller of that allotment and what the disk can actually give. Two things are missing before it can:

- **No backend reports free space.** `IRawStorage` has `getApproximateBytesUsed`, and `IPieceStore` has `bytesUsed`, but nothing anywhere answers "how much more will this location take". So the only total a node has today is the invented 10 GB default in `StorageMonitorConfig`.
- **Everything being inside one measured location is an accident, not a fact.** Each shipping backend's `getApproximateBytesUsed` measures its *whole* location — the filesystem backend sizes the base directory (`approximateBytesUsed` in `packages/db-p2p-storage-fs/src/file-batch-backend.ts`), SQLite multiplies `page_count` by `page_size` over the whole database file, IndexedDB reads the whole origin's `navigator.storage.estimate().usage`, LevelDB sums every entry in the handle — so the key-value store's records and the node's transaction state *are* counted, but only because every `*NodeStorage` factory happens to build all three stores over one place. Only the piece half of that is checked (`assertBlockStoreCountsPieces` in `packages/db-p2p/src/storage/storage-monitor.ts`); a factory that moved the key-value store to a sibling location would silently stop counting the node's bookkeeping.

## What to build

### 1. A free-space measure, optional by presence

`RawStoreDriver.approximateBytesFree?(): Promise<number>` and the `IRawStorage.getApproximateBytesFree?(): Promise<number>` it feeds, under exactly the feature-detection rule the neighbouring optional members already state on both interfaces: a backend that cannot ask **omits the method entirely** and never installs a stub that answers 0. `KvRawStorage`'s constructor wires it only when the driver has one, beside its `getApproximateBytesUsed` wiring; `CachedRawStorage` passes it through as it passes `getApproximateBytesUsed`.

The contract to state on both:

- **What it answers:** the bytes this location will still accept, by the backend's cheapest honest measure. Advisory and may be stale, like `getApproximateBytesUsed`; it is the *location's* free space, not this store's share of it, so two stores over one location answer the same figure.
- **What a failure answers: it rejects.** It must never answer 0 on a failed read. 0 means "full", and a transient failure that read as full would make a node shed responsibility it did not need to shed. The consumer catches, logs and treats the figure as unknown for that scan — that is specified in the next ticket; here the contract is simply "reject, do not guess".
- **Presence is fixed for the store's life,** like `getStoreIdentity`.

Which backends have one, after checking each:

| Backend | Free space | How |
|---|---|---|
| `@optimystic/db-p2p-storage-fs` | **yes** | `fs.promises.statfs(basePath)` → `bavail * bsize`, after `open()`, in `FileBatchBackend` beside `approximateBytesUsed`. Verified present and working on win32 under this repository's Node. |
| `@optimystic/db-p2p-storage-web` | **yes** | `navigator.storage.estimate()` → `max(0, quota - usage)`, in the journal store beside its `approximateBytesUsed`. Origin-scoped, exactly as its used figure is, so the two agree. The method is **omitted at construction** when `navigator.storage?.estimate` is not a function, and **rejects** when the estimate carries no `quota` — never 0 for either. |
| `@optimystic/db-p2p-storage-ns` | **no** | The package is handed an open `SqliteDb`, not a path, and NativeScript offers no free-space call reachable from a database handle. Omitted; say so in the README. |
| `@optimystic/db-p2p-storage-rn` | **no** | The package is handed a `LevelDBLike` handle, with the same gap. Omitted; say so in the README. |
| memory (`MemoryStoreDriver`) | **no** | There is no disk. The free space of a `Map` is the heap, which is not a storage allotment. Omitted, for the same reason it omits `storeIdentity`. |

### 2. A store identity on the key-value store

`IKVStore.storeIdentity?(): StoreIdentity`, with the same contract wording `IPieceStore.storeIdentity` carries — one-directional, equality proves one location, inequality proves nothing, omitted rather than stubbed. Implemented by `FileKVStore` (`fileStoreIdentity(basePath)`, the same call `FileRawStorage` and `FilePieceStore` make) and by `SqliteKVStore`, `IndexedDBKVStore` and `LevelDBKVStore` (`identityForHandle` on the handle, under each package's existing scheme constant: `SQLITE_HANDLE_SCHEME`, `IDB_HANDLE_SCHEME`, `LEVELDB_HANDLE_SCHEME`). Omitted by `MemoryKVStore`, since two memory stores are independent — the reason `MemoryStoreDriver` omits it.

**No `bytesUsed` on `IKVStore`.** This was considered and declined, and the reason belongs in the interface's own words: in every shipping backend the key-value store lives inside the location the block store measures whole, so a figure of its own would have no consumer, and an interface member nobody implements is worse than none. What makes the node's bookkeeping *counted* is the assertion below, which turns it from an accident into a construction fact. Park the tripwire as a `NOTE:` beside `storeIdentity`: a backend that ever keeps its key-value store somewhere the block store does not measure must add a `bytesUsed` to it, because the accounting surface will otherwise report that store's bytes as unmeasured.

### 3. One coverage assertion for all three stores

New module `packages/db-p2p/src/storage/store-coverage.ts`, holding the coverage rules that today sit in `storage-monitor.ts` (the next ticket replaces that module, so move them out now):

- `blockStoreCountsPieces(storage, pieces)` — moved unchanged, including its `NOTE:`. It stays the fallback rule for a hand-built or memory storage value, where no identity is reported.
- `assertOneMeasuredLocation(storage: NodeStorage, location: string)`, replacing `assertBlockStoreCountsPieces`. It throws unless **all three** hold: the block store has a `getApproximateBytesUsed`; it reports a `getStoreIdentity()`; and both `kv.storeIdentity?.()` and `pieces.storeIdentity?.()` equal it. The message names the location and which part disagreed, as the existing helper's does.

The four `*NodeStorage` factories call the new helper in place of the old one, passing their location as they already do (`basePath`, `'this SQLite handle'` and friends). `memoryNodeStorage()` still asserts nothing, for the reason already recorded: its stores report no identities, deliberately, and the monitor's fallback rule is correct for memory.

Export `blockStoreCountsPieces` and `assertOneMeasuredLocation` from `packages/db-p2p/src/index.ts`; drop `assertBlockStoreCountsPieces`.

### 4. Docs

- `packages/db-p2p/docs/storage.md` — §7 and §8: the free-space capability and the table of which backends have it; that the one assertion now covers all three stores, so the node's bookkeeping is counted by construction rather than by coincidence.

## Edge cases & interactions

- **A failed `statfs` or a quota-less estimate must not read as full.** Covered by the reject-don't-guess rule above, stated on the interface and honoured by both implementations. Verified by inspection of each implementation plus the test below for the fs path if it can be provoked cheaply; the consumer side is the next ticket's.
- **`navigator.storage` absent (Node under `fake-indexeddb`, which is how the web package's specs run).** The method is then omitted at construction, so a web store under Node reports no free space at all — the same answer `ns` and `rn` give. Verified by inspection: there is no way to stub `navigator.storage` in that harness today, which is why the existing `getApproximateBytesUsed` case there asserts only "a number ≥ 0".
- **`statfs` on a path that does not exist yet.** `approximateBytesFree` calls `open()` first, as `approximateBytesUsed` does, so the directory exists by the time `statfs` sees it.
- **Two stores over one location answer one free figure.** That is the contract, and it is why the account in the next ticket asks the block store and nobody else. By inspection.
- **`CachedRawStorage` and `withReadCache`.** A cache in front of a store must not hide the capability, exactly as it must not hide `getApproximateBytesUsed` or `getStoreIdentity`; the passthrough is conditional on the inner store having one. By inspection, beside the existing passthroughs.
- **The `fs` factory's one-set-per-directory map.** Untouched: the assertion runs inside `openDirectory`, where the old one did, so it fires once per directory rather than once per holder.
- **`packages/upgrade-check/test/current-build.ts`** deliberately hand-builds its stores over a two-directory `fs` layout and must keep doing so — it calls neither the factory nor the assertion. Check it still compiles and is left alone.
- **A storage package's kv store and block store disagreeing on identity** is now a throw at the first open rather than silent under-counting. That is the point; it also means a future backend cannot ship a split layout without noticing.

## Tests

Two, both on logic with real branching, both in files that already own the contract:

- **`assertOneMeasuredLocation` refuses a key-value store whose identity differs** — in the `FileRawStorage store identity` suite in `packages/db-p2p-storage-fs/test/file-store-identity.spec.ts`, beside the piece-store case that already lives there. Pure, no I/O: a real `FileRawStorage` and `FilePieceStore` over one base path with a `MemoryKVStore` for the `kv`, which reports no identity. This is the half of the invariant that is new, and the one that would otherwise fail silently.
- **The `fs` free-space figure is positive and the method is present** — one case in the same package, over a temp directory: `getApproximateBytesFree` exists on a `FileRawStorage` and answers a number above 0. Thin, but it is the only end-to-end check that `statfs` is reachable from this package on the platform the suite runs on, and the whole allotment chain rests on it.

Nothing else: the three omissions are the absence of a method (a type and a `NOTE:`, not a behaviour), the `storeIdentity` additions are one expression each returning a value the sibling store already returns, and the `KvRawStorage` / `CachedRawStorage` passthroughs are wiring the compiler checks.
