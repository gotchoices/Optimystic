# Blob pieces in the browser's IndexedDB database

`IPieceStore` (`packages/db-p2p/src/blob/piece-store.ts`) is the store for the immutable pieces a blob is cut into (docs/blobs.md §The local store). It exists with `MemoryPieceStore`, `FilePieceStore` (`packages/db-p2p-storage-fs`), `SqlitePieceStore` (`packages/db-p2p-storage-ns/src/sqlite-piece-store.ts` — the closest model for this ticket) and the conformance suite `runPieceStoreConformance` with `PieceStoreHarness` and `conformancePieceId` (`packages/db-p2p/src/testing/piece-store-conformance.ts`, published as `@optimystic/db-p2p/testing/conformance`).

This ticket adds `IndexedDBPieceStore` to `@optimystic/db-p2p-storage-web`: a `pieces` object store in the database `openOptimysticWebDb` opens, sharing the handle with `IndexedDBRawStorage`, `IndexedDBKVStore` and the identity helper. It is not a `RawStoreDriver` store and does not go through the journal: each piece is raw bytes in its own transaction.

## Schema and version 5

Version 4 is already taken by `commitProofs`. In `packages/db-p2p-storage-web/src/db.ts`:

- `OptimysticWebDB` gains `pieces: { key: string; value: Uint8Array }` (key is the `PieceId` string; `PieceId` from `@optimystic/db-core` may be used as the key type if it is a string brand), with a bullet in the schema comment: piece bytes keyed by the piece's id string, stored by structured clone, written and read only by `IndexedDBPieceStore`.
- `DEFAULT_DB_VERSION` goes from 4 to 5, and the comment above it adds "and to 5 for `pieces`".
- The `upgrade` hook adds `if (!db.objectStoreNames.contains('pieces')) db.createObjectStore('pieces');` beside the others, so a database at versions 1 to 4 gains only what it lacks and keeps every record. Out-of-line keys, like every other store here.

A version 5 database cannot be opened by a build that asks for version 4: the browser refuses the open with a `VersionError`. That is a downgrade, outside the guarantee that an older build's data opens on a newer build; the README says so. Another tab still holding an older connection makes this tab's open wait; that case, and the test that an existing database survives the bump, belong to `debt-indexeddb-version-upgrade-is-untested-and-unhandled` (now in `tickets/plan/`), which already carries a "version 5 (pieces)" arm.

## `IndexedDBPieceStore`

New module `packages/db-p2p-storage-web/src/indexeddb-piece-store.ts`, exported through `src/index.ts`'s `export *`.

```ts
export type IndexedDBPieceStoreOptions = IndexedDBDurabilityOptions;
export const PIECE_LIST_PAGE = 1000;

export class IndexedDBPieceStore implements IPieceStore {
	/** `'power-loss'` where puts are strict transactions, else `'process-crash'`; fixed at construction. */
	readonly durability: StoreDurability;
	constructor(db: OptimysticWebDBHandle, options?: IndexedDBPieceStoreOptions);
	/** The identity `IndexedDBJournalStore` reports over this handle: `identityForHandle('idb-handle', db)`. */
	storeIdentity(): StoreIdentity;
	has(id: PieceId): Promise<boolean>;
	get(id: PieceId): Promise<Uint8Array | undefined>;
	put(id: PieceId, bytes: Uint8Array): Promise<void>;
	delete(id: PieceId): Promise<void>;
	list(): AsyncIterable<PieceId>;
	bytesUsed(): Promise<number>;
	flush(): Promise<void>;
}
```

Imports: `identityForHandle`, `IPieceStore`, `StoreDurability`, `StoreIdentity` from `@optimystic/db-p2p` (as `SqlitePieceStore` does); `resolveStrictDurability`, `transactionDurability`, `IndexedDBDurabilityOptions` from `./durability.js`; `createLogger` from `./logger.js`.

- **`put` is one transaction per piece, strict where the browser honours it.** `strict = resolveStrictDurability(options)`, `durability = strict ? 'power-loss' : 'process-crash'`, as `IndexedDBJournalStore`'s constructor does. The body:

```ts
const tx = this.db.transaction('pieces', 'readwrite', { durability: transactionDurability(this.strict) });
const write = async (): Promise<void> => {
	if (await tx.store.getKey(id) === undefined) await tx.store.put(wholeBufferBytes(bytes), id);
};
await Promise.all([write(), tx.done]);
```

  The presence check and the write share one transaction, so a present id writes nothing; `Promise.all` observes `tx.done`, so a failed request is never an unobserved rejection. One transaction per piece, not one across a blob, so a long stream never holds a transaction open (IndexedDB commits an idle transaction, and the builder awaits its source between pieces). A strict transaction completes only once the browser has put it on the disk, so a put that has resolved is durable and **`flush()` resolves at once**: there is nothing held to sync. This is what docs/blobs.md §The local store already says of IndexedDB ("makes each put durable itself"). Rejected: relaxed puts with a strict flush, because IndexedDB promises nothing about which relaxed transactions survive a power cut, so a later strict transaction would not cover them (the reason `IndexedDBJournalStore` journals); and holding puts in memory until flush, which would keep a whole blob in memory. Say this in the class doc comment.
- **`wholeBufferBytes`.** Structured clone of a typed array stores its whole `ArrayBuffer`, so a piece handed as a view into a larger buffer would store the larger buffer and read back as a view into it. A private function returns `bytes` when `byteOffset === 0 && byteLength === buffer.byteLength`, otherwise `bytes.slice()`. (Same shape as the one in `sqlite-piece-store.ts`; here it is required, not a precaution. Do not share across packages — two lines.)
- **`has`** is `(await this.db.getKey('pieces', id)) !== undefined`, which reads no value. **`get`** is `this.db.get('pieces', id)`; structured clone returns a fresh array, so a caller changing it changes nothing stored. **`delete`** is `this.db.delete('pieces', id)` at the browser's default durability: a lost delete leaves an orphan piece the next sweep removes, which is not worth a disk sync per deleted piece.
- **`list`** pages: `getAllKeys('pieces', range, PIECE_LIST_PAGE)`, the first range `undefined` and each later one `IDBKeyRange.lowerBound(last, true)`, each page an already-materialized array read under its own implicit transaction, so no cursor is held across the consumer's awaits (the same rule `listBlockIds` keeps) and no page loads every id at once. Stop when a page returns fewer than `PIECE_LIST_PAGE` keys.
- **`bytesUsed`** opens one readonly transaction and walks `openCursor` over `pieces`, summing each value's `byteLength`, awaiting `tx.done`. It reads every stored byte. Acceptable because when the piece store shares the block store's handle — the configuration the README documents — `blockStoreCountsPieces` (`packages/db-p2p/src/storage/storage-monitor.ts`) sees equal identities and never calls it: the block store's figure (`navigator.storage.estimate()`) already covers the whole origin. The walk runs only for a piece store a host put over another handle or database, and then the figure is counted twice, since the origin estimate already includes it (erring toward "fuller", as the `NOTE:` on `blockStoreCountsPieces` already accepts). Leave a `NOTE:` at `bytesUsed` saying both: the walk reads every piece and runs only off the documented configuration; if it ever shows in a profile, keep each piece's size under a second key range and sum that instead. A failure is logged under `createLogger('storage:pieces')` and answers 0, as `approximateBytesUsed` does.
- **`storeIdentity`** returns `identityForHandle('idb-handle', db)`, computed once in the constructor — equal to `IndexedDBJournalStore.storeIdentity()` (and so `IndexedDBRawStorage.getStoreIdentity()`) over the same handle object. `identityForHandle` (`packages/db-p2p/src/storage/store-identity.ts`) memoizes per scheme in a `WeakMap` keyed by the handle object, so both calls over one handle return the same string.
- **No `close`.** The handle is shared; the host closes it after the node has stopped, as for the other stores here. The store holds nothing to release.

## Edge cases & interactions

- **An existing database at versions 1 to 4.** Opens at 5 with an empty `pieces` store and every other record intact, by the `objectStoreNames.contains` guards. Test owned by the debt ticket. Inspection here.
- **This database opened by an older build.** Refused by the browser (version 5 over a request for 4). Downgrade, stated in the README; not handled.
- **Another tab on an older version.** The open waits; owned by the debt ticket.
- **A browser that ignores `durability`.** Every put is relaxed, `durability` reports `'process-crash'`, and flush still resolves at once; the node reads `durability` to know what it got. Inspection.
- **Two puts of one id at once.** IndexedDB runs two `readwrite` transactions over one store one after the other, so the second sees the key and writes nothing. Covered by the conformance suite's concurrent-put case.
- **A view into a larger buffer.** Stored at its own length. Test (below).
- **A zero-length piece.** Structured clone stores an empty array; a zero-length view into a larger buffer is sliced. Conformance covers the empty piece.
- **A 1 MiB piece.** Round-trips through the conformance suite's large case under `fake-indexeddb`; browsers impose no per-value limit near that size.
- **Quota.** A put past the origin's quota rejects with the browser's `QuotaExceededError`, the transaction aborts, and nothing is stored; the blob service's `put` fails with it. No handling beyond letting it propagate (the `Promise.all` makes sure it propagates rather than escaping unobserved).
- **Crash between a put and the blob's record.** The piece is stored, the record is not; the sweep removes the orphan. Inherited.
- **Block-store listing.** `listBlockIds` reads `metadata` keys only, so pieces never appear as blocks. Inspection.
- **Journal recovery.** `IndexedDBJournalStore`'s apply transaction names `APPLY_STORES`, which must not include `pieces`. Inspection.

## Tests

`packages/db-p2p-storage-web/test/indexeddb-piece-store.spec.ts`, importing `fake-indexeddb/auto` first, as the other specs do:

- `runPieceStoreConformance('IndexedDB pieces', …, { persistent: true })`, with a harness built like the `'IndexedDB'` one in `test/indexeddb-storage.spec.ts`: a fresh database name per case through `openOptimysticWebDb`, the store built with `{ strictDurability: true }` (fake-indexeddb honours the option without advertising it; see `supportsStrictDurability`), `reopen` closing the handle and opening the same name, `cleanup` closing it.
- One case: a piece put as a 1 KiB view into a 1 MiB buffer reads back with `byteLength` 1024 over a buffer of 1024 bytes, and `bytesUsed` reports 1024. It pins `wholeBufferBytes`, which no shared case covers and whose absence wastes the difference silently.

No paging test: `list` paging is the `getAllKeys` + `lowerBound` loop, simple enough to read; add one only if the conformance suite cannot exercise more than one page and the implementer finds an off-by-one risk worth pinning.
