# Reconcile path certification + persist the verified proof

Third of three tickets from `accept-certified-claims-in-repair`. Selection rules + shared
`cluster/certified-claims.ts` helper landed in `certified-claim-selection`; the read path landed
in `certified-claims-read-repair` (see `CoordinatorRepo.queryClusterForLatest`,
`repo/coordinator-repo.ts:1044-1082` — the pattern to mirror). Read-repair acquisition and
commit-time reconcile share ONE callback instance (`libp2p-node-base.ts:905` passes
`reconcileBlock` to both), so everything here lands on both paths.

## Resolved design (investigation complete — implement as written)

### A. `cluster/reconcile-block.ts`

Current state: `toCandidate` (:84) discards `entry.proof`; no certification anywhere.

New imports: `certifyClaim, certifyContent, isAttributableProofFailure, type ProofAnchoring`
from `./certified-claims.js`; add `certifiedEquivocation, certifiedContentEquivocation` to the
existing `./quorum-restore.js` import; `type BlockCommitProof` from `./commit-proof.js`;
add `ActionId` to the db-core type import (needed to build `ProofClaim`).

`ReconcileCandidate` gains:
- `proof?: BlockCommitProof` — carried by `toCandidate` from `data.proof` (the archive keys the
  proof inside the same revision entry — `storage/struct.ts:18-35` — so mis-pairing is
  structurally blocked; say so in the doc comment).
- `revCertified?: boolean`, `contentCertified?: boolean` — verdicts injected by the
  certification pass, never from mere proof presence.
- `contentRejected?: boolean` — set on `digest-mismatch` only: the served bytes provably
  contradict the proof's declared digest; the block is dropped from the content quorum.

`ReconcileBlockDeps` gains:
- `superMajorityThreshold: number` (required — verification needs it).
- `anchoring?: ProofAnchoring` (optional, observational layer 2).
- `saveReplicatedBlock` widens to `(blockId, block, source, verifiedProof?: BlockCommitProof) => Promise<void>`.
  Doc: proof passed ONLY when it was verified against these exact bytes.

Certification pass (new helper, run after `candidates` are collected, before selection;
parallel `Promise.all` over candidates, skip those without `proof`). Thresholds:
`{ superMajorityThreshold: deps.superMajorityThreshold, simpleMajorityThreshold: 0.5 }` — 0.5
HARDCODED, not the config value, mirroring `coordinator-repo.ts:1065-1069` (members enforce
`count > total/2`; verifying against the 0.51 config default would reject proofs real cohorts
produce — repeat that comment). Claim is `{ blockId, rev: c.rev, actionId: c.actionId as ActionId }`.

- Candidate WITH block → `certifyContent(proof, claim, c.block, thresholds, deps.anchoring)`:
  - `{revCertified:true, contentCertified:true}` → set both flags.
  - `{revCertified:true, contentCertified:false, failure:'digest-mismatch'}` → `revCertified = true`
    (the claim half genuinely passed), `contentRejected = true`, penalize serving peer
    (`PenaltyReason.InvalidRestoration`, context `` `reconcile:${blockId}` ``, best-effort
    try/catch — mirror `penalizeProofService` in coordinator-repo.ts:1337-1344). Repair
    continues — other holders still counted.
  - `failure:'no-digest-declared'` → `revCertified = true`, content stays an ORDINARY
    uncertified carrier (still in the hash quorum), no penalty.
  - `revCertified:false` → nothing certified; candidate stays an ordinary uncertified
    corroborator (do NOT drop its vote — a peer that could fabricate a bad proof could equally
    have sent none); penalize only when `isAttributableProofFailure(failure)`. Log a
    `reconcile:proof-uncertified` line with `{ blockId, peerId, rev, failure }` (mirror
    `cluster-fetch:proof-uncertified`).
- Candidate WITHOUT block → `certifyClaim(proof, claim, thresholds, deps.anchoring)` →
  `certified` sets `revCertified`; same failure logging/penalty rule.

Selection wiring:
- `revClaims`: spread `...(c.revCertified ? { certified: true } : {})` into each `RevClaim`.
- On rev-selection decline, BEFORE the existing `reconcile:no-rev-quorum` log: ask
  `certifiedEquivocation(revClaims)`; if non-undefined log
  `reconcile:certified-equivocation` with `{ blockId, rev, actionIds }` (mirror
  coordinator-repo.ts:1095-1100). Ask ONLY on a decline — a conflict can coexist with a
  successful selection (corroborated pair strictly above the top certified rev wins).
- On certified success log `reconcile:certified-selected` with
  `{ blockId, rev, claimants: selected.supporters.length }` (mirror :1136-1142).
- `hashCarriers` (:123): filter adds `&& !c.contentRejected`; return type becomes
  `(BlockHashCandidate & { proof?: BlockCommitProof })[]`; each entry spreads
  `...(c.contentCertified ? { certified: true } : {})` and
  `...(c.contentCertified && c.proof ? { proof: c.proof } : {})` (proof carried only when it
  certified these bytes — that is the only proof safe to persist).
- On content decline, before `reconcile:no-content-quorum`: ask
  `certifiedContentEquivocation(hashCandidates)`; if non-undefined log
  `reconcile:certified-content-equivocation` with `{ blockId, rev: selected.rev, hashes }` —
  two certified hashes at one `(rev, actionId)` means the cohort's keys signed two digests into
  one revision; without this it logs identically to a routine shortfall.
- After `selectQuorumBlock` agrees:
  `const certifiedCarrier = hashCandidates.find(c => c.certified === true && c.hash === agreed.hash)`.
  Detection is sound: `selectQuorumBlock`'s certified branch fires iff exactly one distinct
  certified hash exists, so a defined `agreed` with a certified carrier at `agreed.hash` ⇔ the
  certified rule won.
  - `penalizeContradictingContent` runs ONLY when `certifiedCarrier` is undefined (corroborated
    win). Mirrors the read path's rule (coordinator-repo.ts:1296-1306): an unanchored proof
    must not be able to convict the honest cohort — anyone holding N keys can mint a proof that
    verifies; penalizing dissenters against it hands a forged proof a reputation lever. Copy
    that rationale into a comment, referencing `feat-cluster-membership-threshold-cert-anchoring`.
  - `await deps.saveReplicatedBlock(blockId, agreed.block, { actionId: selected.actionId, rev: selected.rev }, certifiedCarrier?.proof)`.
    A corroboration-won block with no certified carrier persists no proof (today's behavior).
- Cohort cost note (comment): verification bounded by `MAX_PROOF_SIGNERS` (256, the helper's
  cap) × cohort width — fine.

`ReconcileBlockCallback` (`cluster/cluster-repo.ts:79`) is UNCHANGED — the proof is internal to
the deps, not the callback signature.

New cases (new inner `describe`):
1. **Single certified holder heals where corroboration declines**: one peer, valid proof with
   matching digest, `repairCorroborationClusterSize: 10` (the config the existing
   "still demands two corroborators" test uses to force a decline). Expect: saved once,
   payload right, `saved[0].proof === proof`, no penalties.
2. **Digest-contradicting content rejected, server penalized, repair continues**: two peers,
   SAME valid proof (digest = honest bytes); `evil` serves tampered bytes, `honest` serves
   matching bytes; `repairCorroborationClusterSize: 10`. Expect: heal lands honest payload
   (evil dropped from content quorum; honest's certified content wins where 1-of-2 hash quorum
   would decline), penalties `[{ evil, InvalidRestoration }]`, `saved[0].proof === proof`.
3. **Unparseable proof → ordinary uncertified corroborator, no penalty**: two peers serving the
   same block, both attaching `{ v: 1, bogus: true } as unknown as BlockCommitProof`
   (`malformed-proof` — non-attributable), `repairCorroborationClusterSize: 4`. Expect: heals
   by plain corroboration, penalties empty, `saved[0].proof === undefined`.
4. **Certified rev equivocation declines + distinct log**: two peers, valid proofs for the same
   rev under DIFFERENT actionIds (two `makeSignedProof` calls, different cohorts is fine —
   layer 1 accepts). Expect: saved 0, no penalties (both proofs verified; which side is wrong
   is unknowable), `captureLog('reconcile-block', ...)` shows
   `reconcile:certified-equivocation` with both actionIds.
5. **Certified content equivocation declines + distinct log**: two proofs for the SAME
   `(rev, actionId)` declaring DIFFERENT digests (commitA digest = blockA, commitB digest =
   blockB); each peer serves the bytes matching its own proof. Rev selection converges (one
   action); content declines. Expect: saved 0, log
   `reconcile:certified-content-equivocation` with both hashes.
6. **Corroboration-only heal persists no proof**: two proof-less peers agreeing,
   `repairCorroborationClusterSize: 4`. Expect `saved[0].proof === undefined`.

All existing cases must pass with only the harness-default additions (uncertified behavior
byte-identical).
