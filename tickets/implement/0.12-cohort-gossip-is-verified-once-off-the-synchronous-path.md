# Cohort gossip is verified once, off the synchronous path

GitHub [#49](https://github.com/gotchoices/Optimystic/issues/49). Third of three tickets from the plan `feat-idle-cohort-gossip-costs-a-phone-little`. `cohort-gossip-sends-a-frame-only-when-something-changed` cuts how many frames arrive. This ticket cuts what each one costs.

## What happens to an inbound frame today

1. The `protocols.gossip` handler in `registerCohortTopicProtocols` (`host.ts`) calls `maybeInstantiateColdSibling(frame)`. That decodes the frame and, when this node holds no engine for its coord and the frame is tier 0, runs the synchronous signature check.
2. It then calls `FretCohortGossipTransport.deliver`, which hands the raw bytes to **every** subscribed bus: one per coord engine plus the node-level participant bus. The reporter counted 19.
3. Each bus's `onInbound` (`packages/db-core/src/cohort-topic/gossip/bus.ts`) decodes the frame again, drops it unless its `coord` names this bus, and the one matching bus runs `verifyInbound`. db-p2p binds that to `verifyGossip`: `verifyPeerSig` over `cohortGossipSigningPayload` plus a membership check.

`verifyPeerSig` uses `@noble/curves`' `ed25519.verify` directly, because `verifyInbound` is synchronous (the comment at the top of `peer-sig.ts` explains why). The reporter measured it at 2.4 ms in Node and about 40 ms on a Galaxy S7. So each frame is decoded once per engine, and the one verify that runs is the slowest available.

## What libp2p's verify does instead

`peerIdFromString(id).publicKey.verify(data, sig)` returns `boolean | Promise<boolean>` (`@libp2p/interface`). In `@libp2p/crypto` 5.1.x:

- **Node** (`dist/src/keys/ed25519/index.js`): `crypto.verify` from `node:crypto`, which is native and synchronous.
- **Browser / React Native** (`index.browser.js`, which Metro picks through the package's `browser` field): WebCrypto `subtle.verify({ name: 'Ed25519' })` when a probe at module load (`webCryptoEd25519SupportedPromise`) finds it, and noble otherwise. A phone app gets native verification only if its runtime provides WebCrypto Ed25519, for example through `@serfab/cadre-rn`'s polyfill (sereus#33). The polyfill must be installed **before** `@libp2p/crypto` is first imported, because the probe runs once. Without it the cost is noble's, the same as today. That is no regression, but no gain on that phone either; this ticket's saving there is the decode fan-out and the cut from the prerequisite ticket.

## The design

**One decode, routed by coord.** Change the db-core port `ICohortGossipTransport` in `packages/db-core/src/cohort-topic/ports.ts`. Today's `onMessage(handler: (from, msg: Uint8Array) => void)` becomes a subscription by coord to decoded frames:

```ts
/** Subscribe to inbound cohort gossip naming `coord`; returns an unsubscribe handle. A frame reaches a handler
 *  decoded, and, when the transport authenticates frames, only after its signature verified. */
onGossip(coord: RingCoord, handler: (g: CohortGossipV1) => void): () => void;
```

`broadcast(coord, msg: Uint8Array)` is unchanged. Outbound frames are still encoded by the bus.

The bus (`TransportCohortGossipBus`) subscribes with its own coord, stops decoding, and keeps its `isOurCoord` check as a cheap defensive guard. It then runs `verifyInbound`, merges, and fires its handlers, as today. Document `verifyInbound` as the bus's own gate, which is membership in db-p2p's binding. The signature is now the transport's job. Update the module comment at the top of `bus.ts` and the `verifyInbound` doc.

**The transport routes; the host authenticates.** `FretCohortGossipTransport` keeps its subscribers in a map keyed by `bytesKey(coord)`. `deliver(g: CohortGossipV1)` hands the frame to that coord's subscribers only. Expose a touch-free `hasSubscriber(coord)`. `subscriberCount` stays the total over all coords: its doc says it tracks live engines plus the participant bus, and tests use it to watch registry eviction.

The `protocols.gossip` handler becomes, in order:

1. Decode once. Drop and log a malformed frame.
2. Drop it before any signature work unless the transport has a subscriber for `g.coord`, or the frame is a tier-0 cold-sibling candidate (`treeTier === 0` and no subscriber). The cheap routing check comes before the expensive verify, as `onInbound` already does. `hasSubscriber` is touch-free, which also retires the `NOTE:` in `maybeInstantiateColdSibling` about `findByCoord` bumping LRU recency before the gate.
3. In live-signer mode (`options.privateKey` present), require a non-empty `signature` and `await verifyPeerSigAsync(fromMember bytes, cohortGossipSigningPayload(g), signature)`. Drop the frame on `false`. Key-less mode skips this, as today.
4. If there is no subscriber for the coord, run the cold-sibling path. It now takes the decoded, signature-checked frame and keeps its existing membership and root-group checks, minus its own signature check.
5. `gossipTransport.deliver(g)`. Look up subscribers **after** the await, never before.

**The new primitive.** Add `verifyPeerSigAsync(signer, payload, sig): Promise<boolean>` to `peer-sig.ts`, beside `verifyPeerSig`, with the same signer forms. Like `verifyPeerSig` it is total: `false` for a non-Ed25519 id, a missing key, or any throw or rejection, and it never rejects. Its doc comment states the platform behaviour above, including the polyfill-ordering requirement. `verifyPeerSig` stays for the synchronous ports that still need it.

**Membership-only bus gates.** `verifyGossipSig` disappears. `verifyGossip` becomes a membership-only predicate (`fromMember` decoded as a peer id is in the member list). The participant bus and each engine bus keep their `rootPlaced` rule checks in front of it, exactly as written today.

**One more verify that can go async for free.** `FretCohortThresholdCrypto.collectFrom` (`threshold-crypto.ts`) is already async and verifies each collected signature chunk with `verifyPeerSig`. The reporter's profile put part of the remaining Ed25519 time there. Switch that one call to `await verifyPeerSigAsync`. The synchronous `ICohortThresholdCrypto.verify` port (used when a notice or certificate is checked, not per gossip round) stays on noble. Commit-proof verification, the profile's other remainder, already goes through libp2p's async verify (`verifyBlockCommitProofClaim` in `packages/db-p2p/src/cluster/commit-proof.ts`). On the S7 it ran on noble only because that runtime has no WebCrypto Ed25519, so it gains from a native polyfill exactly as gossip does, with no change here.

## Edge cases & interactions

- **Frames verified out of order.** Two frames can finish verifying in the opposite order to their arrival. Every merge is reorder-safe: records last-writer-wins by `lastPing`, evictions gated on `lastPing`, the member view by `timestamp`, child deltas by `effectiveAt`. Inspection; note it in a comment at the handler.
- **An engine closed or evicted while its frame was verifying.** Its bus has unsubscribed, so the lookup after the await finds no handler and the frame is dropped. Inspection (step 5 ordering).
- **Two subscribers for one coord** (the participant bus at the node's own coord and an engine serving the same coord) both receive the frame after a single verify. Inspection.
- **A cold sibling instantiated by one frame while another for the same coord is verifying.** The existing re-check after the root-group read (`registry.findByCoord(coord) !== undefined` → return) still covers it, and the second frame is then delivered to the new engine's bus. Inspection.
- **A tier-d > 0 frame for a coord with no subscriber** is dropped without a verify, as today. Inspection.
- **Stricter acceptance.** Node and WebCrypto verify strict RFC 8032, while noble accepts ZIP215, which is wider. Every signer here (libp2p `PrivateKey.sign`, `signPeerSig`) produces RFC 8032 signatures, so no honest frame is refused. A crafted non-canonical signature noble would have taken is now refused. Accepted; say so in `verifyPeerSigAsync`'s doc.
- **Key-less mode** delivers unsigned frames with no verify, as today. Covered by the existing key-less tests in `gossip-cadence.spec.ts`.
- **No wire change.** Mixed versions interoperate untouched.
- **The reactivity push-state driver** uses only `broadcastOver` on this transport and is unaffected.
- **Back-pressure.** The one-way handler now awaits a verify per frame. With the prerequisite ticket's rate this is about one frame per engine per ping interval. Nothing new to bound.

## Tests

No new behaviour needs a new test beyond one primitive check. The existing specs already pin the behaviours this ticket must keep: the bad-signature drop and the non-member drop (`gossip-cadence.spec.ts`, "drops a gossip from a cohort member whose signature does not verify" and its sibling), per-coord routing ("a gossip for coord A merges only into coord A's store"), cold-sibling instantiation, two-node replication, and the key-less cases. Adapt them to the port change; frames delivered through the host handler now settle after an await, so a test may need to await the handler's promise before asserting.

- In `peer-sig.spec.ts`, add `verifyPeerSigAsync` beside the `verifyPeerSig` cases it mirrors: a valid signature passes, a tampered payload fails, a non-Ed25519 or malformed id resolves `false` without rejecting. Keep it to the cases that differ in code path.
- Adapt `packages/db-core/test/cohort-topic/gossip.spec.ts`'s `FanoutTransport` and the fake transport in `packages/db-p2p/test/cohort-topic/service.spec.ts` to `onGossip`.
