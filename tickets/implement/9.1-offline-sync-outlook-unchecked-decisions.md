The first built the facts plumbing (the vtab records `WriteFact`s through the bridge, savepoint-aware; the judgement reads `EntryFacts`). This one adds a second record kind — the decisions each described statement made against other rows — computes `unchecked` from them, and adds the `via: 'unchecked'` dependencies. The design is [§Unchecked decisions](../../docs/offline-sync.md#unchecked-decisions) and [§Dependencies between entries](../../docs/offline-sync.md#dependencies-between-entries); where the `TableWrite` contract (`../quereus/docs/write-scope.md`) differs from what the doc assumed, the rules below are the resolution, and the doc is updated to them.

## What the description gives, and how it is read

A `TableWrite` carries `selection` (`none` for INSERT; `rows` with `key` and bound `values` when the WHERE pins a unique key by equality; `global` otherwise), `reads` (`TableWatch`es: everything the write reads other than the target rows' own key — WHERE and SET inputs, an INSERT's source query, the constraint subqueries; a watch on the target table appears only for non-key columns), and `constraints` (`WriteConstraint`s with `kind`, `locality`, `references`). A `WatchScope` is `full`, `rows`, `groups` or `rowsByGroup`. Three things the doc assumed are not there and are resolved as follows:

- **Reads are not labelled by origin.** A foreign key's parent read is a watch on the parent table (`full`, a known imprecision of the analysis); a CHECK's subquery read is a watch on whatever table it reads, indistinguishable from a `SET` subquery. Rule: a watch on a table some `foreign-key-child` constraint `references` is a `foreign-key` decision; a cross-row `check` constraint is reported as a `check` decision on the **written** table (not the table its subquery read, which the doc said), and its subquery's watch is still reported as a `read` — one decision too many rather than one too few.
- **The target row is not separated from the rest.** Rule: a watch on the target table no wider than the selection is the target row itself and is dropped — a `rows` watch under a `rows` selection (the guard covers the row), any watch under a `global` selection (the `row-selection` decision covers it). A target-table watch wider than a `rows` selection (`set x = (select max(x) from t) where id = ?`), and every target-table watch under an INSERT's `none` selection, is a `read`.
- **Binding modes are four, the doc's are three.** `full` → `global`; `rows` → `row`; `groups` and `rowsByGroup` → `group`.

So, per described statement (`uncheckedOf(write, target)` in write-description.ts, pure):

| From | Decision |
|---|---|
| `operation` update/delete with `selection.kind === 'global'` | `row-selection` on the target, scope `global` |
| each `foreign-key-child` constraint | `foreign-key` on `references` (the target when absent), scope from the matching read watch when one exists, else `global`; that watch is consumed |
| each `foreign-key-parent` constraint (DELETE, or UPDATE of a referenced column) | `foreign-key` on `references`, scope `global` |
| each `assertion` constraint | `assertion` on `references` (the target when absent), scope `global` |
| each `check` constraint with `locality === 'cross-row'` | `check` on the target, scope `global` |
| each remaining read watch not dropped by the target rule | `read` on the watch's table, scope mapped as above |
| `primary-key`, `unique`, `not-null`, row-local `check` | nothing: guards or row-local |

Each decision keeps, beside the three public fields, what the dependency rule needs: the Quereus `QualifiedName` of the table (lowercased) and, for a `rows` watch, its `key` columns and bound `values` tuples. A tuple still holding a `ParamScopeValue` (unbound — should not happen on the hook) widens the decision to `global`.

Dedupe per statement by (table, kind, scope), merging `rows` tuples; the entry's list is the statements' lists concatenated in statement order and deduped the same way.

## Recording

- `WriteFact` gains `{ kind: 'statement'; unchecked: readonly UncheckedRead[] }` and `{ kind: 'undescribed' }`.
- The vtab records a statement fact **once per `TableWrite` object** (the engine hands one object per execution): `TransactionBridge.noteWriteDescription(write, describe: () => UncheckedRead[])` keeps a `WeakSet<TableWrite>` on `TransactionState` and appends a `statement` fact the first time it sees an object. An `update()` call with no `writeScope` appends `undescribed`. Every arm records it, DELETE included, before the arm's staging (a statement that then fails is truncated by the savepoint mark either way).
- `foldWriteFacts` produces `EntryFacts.unchecked` (deduped, statement order) and `EntryFacts.complete` (no `undescribed` record). The upsert `DO UPDATE` arm's INSERT object counts as described: its reads and constraints are the statement's.

## Judging

- `OwnJudgement` gains `unchecked: readonly UncheckedRead[] | 'not-computed'`: `'not-computed'` when the transaction's facts are absent or incomplete, else the folded list. Frozen with the own judgement; `withoutCollections` leaves it alone (a decision is a statement's, not a collection's).
- `outlookFrom` adds dependencies `via: 'unchecked'`: for each decision, with scope `row` and every tuple encodable to a main-tree key (below) the earlier entries whose segment in that main collection wrote one of those keys (`WriteIndex.writersWithin` with a `key` span, unreadable segments included); otherwise, and for `group`/`global`, every earlier entry with a segment in any collection of that table, and every deferred record whose `tables` name it. An entry already listed `via: 'guard'` stays `'guard'`; each transaction is listed once, in queue order. `kind` ignores these dependencies.
- `EarlierEntry` gains `tables` (the controller already computes it for `FollowedEntry`), and `WriteIndex` keeps writers per table beside writers per collection.
- Rendering: `unchecked` as `{ table, kind, scope }[]`, the `rows` and qualified name stripped; `table` is the published rendering (`main.Conversations`) when the table is published, else Quereus's lowercased `schema.table`.

Encoding a `rows` tuple to a main-tree key needs the table's key codec. Bundle the judgement's schema access into one interface the controller implements, replacing the bare `describe` argument:

```typescript
export interface OutlookSchema {
  describe(collectionId: CollectionId): CollectionDescription;
  /** The table Quereus names, when a vtab has published it: its rendering, its main tree, and the
   *  main-tree key of a row a read pinned by `key` = `values`; `undefined` when `key` is not the
   *  table's primary key (any order, case-insensitive) or a value cannot be encoded. */
  table(name: QualifiedName): { readonly name: string; readonly collectionId: CollectionId; rowKey(key: readonly string[], values: readonly SqlValue[]): string | undefined } | undefined;
}
```

`TableOutlookSource` gains `mainTree(): { collectionId; keyColumns; rowKey } | undefined` (reads `rowCodec` and `tableSchema.primaryKeyDefinition` at call time, encodes through `asPrimaryKeyTuple` and `createPrimaryKey` after reordering the values into key order). `OfflineMode` keeps a lowercased index of its published tables for `table(name)`.

## Edge cases & interactions

- **The doc's test-plan case** — a conversation inserted under a natural key, then a message under `StampId()` referencing it: the message's `foreign-key` decision on `main.Conversations` is `global` (the parent read is whole-table in Quereus), so it depends on the conversation's entry `via: 'unchecked'` by the table rule, and is assured. Verified by test.
- **A row-scoped read matched by key** — `insert into Messages … select … from Conversations where id = 'c1'` reads `rows` on Conversations; the dependency is on entries that wrote `c1`, not on every writer of the table. Verified by test (one SQL-level case pins the encoder and the key span together).
- **A read of an unpublished table** (one declared on another module): decision reported with Quereus's name, dependency by table name against earlier entries' `tables` (which only lists this plugin's tables, so none) — by inspection.
- **`row-selection` with a target watch** (`update … set done = 1 where status = 'open'`): one `row-selection`, no `read`; `set n = n + 1 where id = ?`: nothing. Unit-tested.
- **Cross-row CHECK**: a `check` on the written table plus a `read` on the subquery's table. Unit-tested; the double is documented.
- **`foreign-key-parent` on DELETE**: `foreign-key` on the child table, `global`. Unit-tested.
- **Cascade child writes** make the entry `incomplete` → `'not-computed'`; the assured/exposed judgement is unaffected. By inspection.
- **Partial commit** keeps `unchecked`; a terminal status drops it with the judgement. By inspection.
- **A statement whose first row throws after the fact was recorded** — the statement-level savepoint truncates it. By inspection (the first ticket's rule).
- **Dependency ordering and dedupe**: guard before unchecked for one transaction, `seq` order overall. Covered by the existing ordering test shape; assert on the message case.
- **Deferred records**: matched by table for `group`/`global` and for unencodable `row` reads, never by key (their writes are not staged). By inspection.
