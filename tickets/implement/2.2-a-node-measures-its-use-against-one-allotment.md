# A node measures its use against one allotment

## Why

`StorageMonitor` (`packages/db-p2p/src/storage/storage-monitor.ts`) is the only thing on a node that has an opinion about how full it is, and three things are wrong with it:

- **Its total is invented.** `StorageMonitorConfig.totalBytes` defaults to 10 GB and is never compared with the disk. A host that sets nothing gets a node that believes it has 10 GB whatever the machine actually has.
- **It is configured in the wrong place.** The option is `arachnode.storage`, under the ring-membership settings, so only a serving node with FRET has one — yet the figure is about the node's storage, which a client node also fills (blob records, blob pieces, the owed-blob ledger).
- **It is built in the wrong place.** The monitor is constructed inside the `if (fret)` block in `libp2p-node-base.ts`, so nothing but ring selection can read it. The blob cache budget, which spends the same disk, has an unrelated figure of its own.

## What to build

### 1. One allotment option

`NodeOptions.storageAllotment?: StorageAllotmentOptions`, a top-level sibling of the existing `NodeOptions.storageDurability` (the shape to copy):

```ts
export interface StorageAllotmentOptions {
	/**
	 * How many bytes of this machine the operator gave the network. Absent means "as much as the
	 * disk has", and then the effective total is whatever the backend reports.
	 */
	bytes?: number;
	/** Lifetime (ms) of the memoized scan; today's `usedBytesCacheTtlMs`, default 60_000, `0` disables. */
	usedBytesCacheTtlMs?: number;
	/** Injectable clock (Unix ms) for the memoization TTL; today's `now`. */
	now?: () => number;
}
```

`bytes` is validated when the node is built and **throws** rather than clamping when it is not an integer above 0 — the rule and the shape `resolveBlobCacheBudgetBytes` already uses for `blobs.cacheBudgetBytes`.

`arachnode.storage` and `StorageMonitorConfig` go away; `arachnode` keeps `enableRingZulu`. The two test-only overrides `StorageMonitorConfig.usedBytes` and `availableBytes` go away with them, and with them the "only short-circuit the backend when used/available is explicitly supplied" branch: a spec that wants to fake the measurement hands in a fake `IRawStorage`, which is what the existing spec's own `makeStorage()` helper already builds. `usedBytesCacheTtlMs` and `now` survive because they are the seams for the memoization, which has no other way to be tested.

### 2. The accounting surface

New module `packages/db-p2p/src/storage/storage-account.ts`, replacing `storage-monitor.ts` (delete it; its coverage predicates moved to `store-coverage.ts` in the prereq):

```ts
export interface StorageCapacity {
	/** The operator's allotment, absent when none was configured. */
	readonly allotmentBytes?: number;
	/**
	 * What this location will hold at all: the measured use plus the free space the backend reports.
	 * Absent when the backend reports no free space, or the read failed on this scan.
	 */
	readonly locationBytes?: number;
	/** The smaller of the two above over whichever are present; absent when neither is. */
	readonly totalBytes?: number;
	/** What was measured, unclamped; 0 when nothing can be measured. */
	readonly usedBytes: number;
	/** `max(0, totalBytes - usedBytes)`; absent exactly when `totalBytes` is. */
	readonly availableBytes?: number;
}

export class StorageAccount {
	constructor(storage: NodeStorage, options?: StorageAllotmentOptions);
	capacity(): Promise<StorageCapacity>;
}
```

- **`usedBytes`** is the block store's `getApproximateBytesUsed` (0 when it has none) plus the piece store's `bytesUsed()` when `blockStoreCountsPieces` is false — today's rule and today's code, moved across unchanged, including the 60-second memoization and its single-flight. The prereq's `assertOneMeasuredLocation` is what makes the block store's figure cover the key-value store and the node's transaction state too, so that single figure is the whole of what the node stores. **Unclamped**, unlike today: a node over its allotment reports more used than its total, which is the thing the next ticket has to act on. `availableBytes` floors at 0 instead.
- **`locationBytes`** is `usedBytes + getApproximateBytesFree()`, read **inside the same memoized scan** so the two figures can never come from different moments. A rejection of the free read is caught, logged once for that scan, and leaves `locationBytes` (and therefore the location's half of the total) unknown for that scan — never 0.
- **Cost and cadence:** one block-store scan (a directory walk, a `PRAGMA`, an origin estimate or a key iteration, depending on backend) plus one free-space call plus, on a hand-built or memory value, the piece store's figure — all behind the one 60-second memo and single-flight, because ring selection asks several times per operation. State this on the class, as `StorageMonitorConfig.usedBytesCacheTtlMs` states it today.

Extract the total as a pure function so it can be pinned and read in one place:

```ts
/** The smaller of the two figures over whichever are present; undefined when neither is. */
export function effectiveTotalBytes(allotmentBytes?: number, locationBytes?: number): number | undefined;
```

### 3. What ring selection does with an unknown total

`RingSelector` takes a `StorageAccount`. Three sites change, and each change is behaviour that has to be stated rather than left to fall out of arithmetic:

- **`determineRing`** — with `availableBytes` undefined the node cannot price its coverage at all, so it answers **ring 0**, the whole keyspace. Not `-1`: unknown is not "low", and `-1` means "below `minCapacity`", which this node has not established. Ring 0 is also what the invented 10 GB total produced in practice, so this keeps a memory-storage node where it already was.
- **`shouldTransition`** — with `totalBytes` or `availableBytes` undefined it folds **nothing** into the EWMA and answers `{ shouldMove: false }`. A node that cannot measure its storage does not shift rings; the smoothed signal would otherwise be seeded from a figure that does not exist. Log it once (not per tick).
- **`createArachnodeInfo`** — `ArachnodeInfo.capacity` becomes **optional**, present exactly when `totalBytes` is known and then carrying `{ total, used, available }` as it does today (the field names on the wire are unchanged). A node that cannot measure its storage advertises no capacity rather than a made-up one.

`ArachnodeFretAdapter.getRingStats` then **skips a peer whose info carries no capacity** — out of both the peer count and the capacity total, so `avgCapacity` stays an average over the peers that actually said. A ring where nobody said yields no stat for that ring, which falls through to `estimateNetworkData`'s existing bootstrap estimate. That is the right answer: the aggregate is a sum of what peers claim, and a peer that claims nothing must not be read as claiming zero.

### 4. Where the account lives

Build it **once per node, outside the `if (fret)` block, on both roles**, from the resolved `NodeStorage` and `options.storageAllotment`, and expose it as `storageAccount: StorageAccount` on `OptimysticNodeAttachmentsBase` (`packages/db-p2p/src/optimystic-node.ts`) so a client node has one too. The arachnode block reads **that instance** rather than constructing its own, so one memoized scan serves ring selection, the cache budget (next ticket) and an operator's dashboard.

### 5. The start-up line

One `node-wiring` line on both roles, beside `logStorageDurability` and modelled on it, naming the allotment (or that none was configured), the location figure (or that this backend reports no free space), and the effective total. When **neither** is known it is a `WARN:` saying that the node cannot tell how full it is, that ring selection will neither narrow nor widen on storage grounds until an allotment is set, and how to set one. This line is what replaces the silent 10 GB. Also say, at ordinary level, when the allotment is below `RingSelectorConfig.minCapacity` (100 MiB), since such a node can serve nothing.

### 6. reference-peer

`--storage-capacity <bytes>` becomes `--storage-allotment <bytes>` — "capacity (for ring selection)" is no longer what the figure is — feeding `storageAllotment: { bytes }`. `parseStorageCapacity` and its message follow the name. `logRingInfo` logs the account's `capacity()` rather than the raw override it was handed, so the operator sees the effective total and not just what they typed.

### 7. Docs

- `packages/db-p2p/docs/storage.md` — a new **§9 A node's allotment and what counts against it**: the one option, the effective-total rule and its four arms, that the three stores' bytes are one figure because of the §8 assertion, which backends report free space, the memoized cost, and what a node does when it can measure neither.
- `docs/arachnode-ring-handoff.md` — §1.4 (what the decision reads) and §Key code sites: `StorageAccount` in place of `StorageMonitor`, and the two unknown-capacity rules above.
- `docs/arachnode.md` §Capacity Management and Ring Adjustment — that the capacity in `-log2(capacity/demand)` is now the node's allotment bounded by the disk.
- `packages/db-p2p/readme.md`'s component list, and the `StorageMonitor` mentions in the `ns`, `web` and `rn` READMEs and in `leveldb-storage.ts` / `leveldb-like.ts` / `file-piece-store.ts` / `piece-store.ts` / `i-raw-storage.ts` / `kv-raw-storage.ts` comments.

## Edge cases & interactions

- **Neither allotment nor free space** (NativeScript, React Native, memory, and any web store under Node): total unknown. Ring selection answers ring 0 and never shifts; the start-up line warns. This is the case every memory-storage spec in the repository is in, so the ring behaviour of those nodes must be checked against today's: today a memory node computes `coverage = 10 GiB / estimateNetworkData(...)`, which is above 1 with no ring stats and so already answers ring 0, and move-in is unreachable from ring 0 while move-out needs 85 % of a total it does not have. The one real change is that a memory node with peers reporting ring stats no longer specializes off them at bootstrap. State that in the handoff.
- **A free-space read that fails intermittently.** One scan's total goes unknown and comes back on the next; `shouldTransition` declines to move for that tick rather than reading the node as full. This is why the free read rejects instead of answering 0 (the prereq's contract).
- **Allotment larger than the disk.** `effectiveTotalBytes` takes the smaller, so the disk wins and the operator's over-promise is bounded rather than believed.
- **Allotment smaller than current use.** `usedBytes` exceeds `totalBytes`, `availableBytes` is 0, and `usedPercent` in `shouldTransition` is above 1 — which trips the move-out arm, the existing behaviour for a full node. Nothing else changes here; acting on it is `a-node-stays-within-its-allotment`.
- **The unclamped `usedBytes`.** Every consumer of the figure must tolerate `usedBytes > totalBytes`: `shouldTransition`'s ratio (fine, it compares against a threshold below 1), `availableBytes` (floored), and `ArachnodeInfo.capacity.used` on the wire (peers read only `available`). Check each.
- **Mixed versions.** An older peer reading an `ArachnodeInfo` with no `capacity` would dereference `arachnode.capacity.available` in its own `getRingStats` and throw. Accepted under this repository's stated position on backwards compatibility, and the only node that advertises none is one that cannot measure its storage — in practice a memory-storage node, which is a test mesh. Say it in the handoff rather than guarding it.
- **A client node's account.** It has no `fret`, no ring selection and (today) nothing reading the account, but it is built and exposed anyway: it is what the next ticket's cache budget reads, and a client fills a disk with blob pieces exactly as a serving node does. Its block store is the one it never reads, and measuring it is still right — the three stores share a location.
- **The `restoration-coordinator` spec casts `{ ringDepth }` as an `ArachnodeInfo`.** Making `capacity` optional makes that cast honest rather than breaking it; check it still compiles.
- **`RingSelector`'s two mock monitors** (`MockStorageMonitor` in `ring-selector.spec.ts` and in `ring-shift-coordinator.spec.ts`, both passed through a cast) need the new method name and shape. Rename them with the class.

## Tests

Four, each pinning a named rule with real branching. `packages/db-p2p/test/storage-monitor.spec.ts` becomes `storage-account.spec.ts`, keeping the cases that still have a subject (the TTL memoization, the single-flight, the rejected-scan retry, the piece-identity branch) and dropping the two override cases and the `clamps used to total` case, whose rule this ticket reverses.

- **`effectiveTotalBytes` over its four arms** — allotment only, location only, both (the smaller wins), neither (undefined) — one table-driven case over the pure function.
- **A rejected free-space read leaves the total unknown and does not report the node full** — the arm that would otherwise shed responsibility on a transient failure.
- **`determineRing` answers 0, and `shouldTransition` answers no move, on an unknown capacity** — in `ring-selector.spec.ts`, whose mock already exists; two cases, one per rule, because they are two separate rules a future edit could break independently.
- **`getRingStats` leaves a capacity-less peer out of both the count and the average** — one case; the alternative (counting it as zero) is the silent misreading this rule exists to prevent.

No test for the start-up line (its words), the option validation (one `RangeError` the compiler and one `throw` already express, under a rule stated at `resolveBlobCacheBudgetBytes` and tested nowhere), the attachment (wiring `tsc` checks), or the reference-peer flag rename.
