# Each storage package opens a whole node's storage

## Why

After `a-node-takes-all-its-storage-as-one-value` a node takes one value, `NodeStorage` — a block store, a key-value store and a piece store. Building that value is still three constructor calls over one location, and the host has to know that the location has to be the same one for all three. Getting it wrong is not loud: two spellings of one directory read as two store identities, so the node counts its blob pieces twice and reports itself fuller than it is (`blockStoreCountsPieces` in `packages/db-p2p/src/storage/storage-monitor.ts`), and for files a second piece store over one directory is not supported at all — its open deletes the first's in-flight temporary files and fails its next put (the `NOTE:` on `FilePieceStore`).

So each storage package should offer the one call a host actually wants: here is the location, give me everything a node persists to.

## What to build

One function per storage package, each returning the `OpenNodeStorage` db-p2p declares, each named for its backend so a host that imports two packages gets two distinct names (`packages/upgrade-check` imports the fs and React Native packages together today):

| Package | Function | Location |
|---|---|---|
| `@optimystic/db-p2p-storage-fs` | `fileNodeStorage(basePath, options?)` | one base path |
| `@optimystic/db-p2p-storage-ns` | `sqliteNodeStorage(db, options?)` | one open SQLite database |
| `@optimystic/db-p2p-storage-web` | `indexedDbNodeStorage(db, options?)` | one open IndexedDB handle |
| `@optimystic/db-p2p-storage-rn` | `levelDbNodeStorage(db, options?)` | one open LevelDB handle |

Each builds that package's three stores over the given location with their existing defaults — including the key-value stores' default `'optimystic:txn:'` prefix, which the identity helpers in the same packages depend on not colliding with. `options` is the union each package's stores already take (the write group's `idleFlushMs` and friends, the fs packages' checkpoint settings, the web package's strict-durability flag); pass it to each store that accepts it rather than inventing a new shape.

Put each in its own `src/node-storage.ts` and export it from the package's `src/index.ts`.

### Who closes what

`close()` releases what the factory opened, in the order the hosts that do this by hand already use, and **nothing else**:

- **fs** closes the piece store, then the key-value store, then the block store — the order `openStores` in `packages/reference-peer/src/cli.ts` and `openBackend` in `packages/upgrade-check/test/current-build.ts` both use. The last store over the directory is what checkpoints the shared write-ahead log and removes the lock, so the order matters.
- **ns, web and rn** close the stores that hold writes in memory and leave the **handle alone**: the host opened it (`openOptimysticNSDb`, `openOptimysticWebDb`, `openOptimysticRNDb`), the host may be sharing it with the identity helper or with Quereus, and the host closes it after. Say so on each function and in each readme. Three of the four piece stores hold nothing and have no `close`; only call what exists.

### One location, asserted

Each factory ends by asserting its own result: `blockStoreCountsPieces(storage.blocks, storage.pieces)` must be true, because both stores were built over one location and must report one store identity. Throw with a message naming the two identities if it is not. This is the boundary check that keeps a future edit — a piece store moved to a sibling directory, a second handle opened inside the factory — from silently making the node double-count its pieces. It costs one comparison of two strings at construction.

### The fs factory returns one storage per directory

`fileNodeStorage` keeps a process-wide map from **resolved** base path to the storage it opened, hands back the same value for the same path, and counts holders: the stores are closed when the last holder closes, and the entry is dropped then, so a later call over that path opens them afresh.

This is not a convenience. For files the location is named by a path rather than held as an object, so two calls over one directory is the easy mistake, and for the piece store it is a *documented-unsupported* state — unlike the block store and the key-value store, which already share one write-ahead log and one lock per directory and are designed for several instances. Reference counting is the pattern this repository already uses one layer down (`FileWriteLog` releases per-store references and the last one checkpoints and unlocks) and one layer up (`SharedCachePool` leases). Making one directory mean one set of stores turns a documented hazard into an unrepresentable one.

The handle-taking packages need none of this: the host already holds one handle and passes it, and their piece stores are stateless wrappers over it, so two sets over one handle are harmless. `memoryNodeStorage()` keeps returning a fresh set per call, as `a-node-takes-all-its-storage-as-one-value` specifies.

### reference-peer

`openStores` becomes `fileNodeStorage(options.storagePath)` for `--storage file` and `memoryNodeStorage()` for memory, and its hand-written `close` chain goes with it. Keep the comment's point — that the node never closes a store it was handed, so the CLI closes the storage after `node.stop()` and also on a failed `createLibp2pNode` — and keep the explanation of why memory storage is passed explicitly rather than left out: a memory peer loses its state across a restart anyway, and the explicit value is how it says it meant to.

## Edge cases & interactions

- **A spec that wants two independent sets of fs stores over one directory.** Memoization changes what two `fileNodeStorage(dir)` calls give back, and in particular the key-value store's and block store's in-memory write groups become shared where two hand-built instances each had their own. Before assuming nothing depends on that, grep for specs that build two `FileRawStorage` over one directory and read one's writes through the other — `packages/quereus-plugin-optimystic/test/legacy-commit-atomicity.spec.ts` builds a bare `FileRawStorage` beside the one the plugin opens, and reasons explicitly about a warm read cache being shared per directory. A spec that genuinely needs a second independent instance keeps constructing the store directly; the factory is for hosts.
- **`close()` on a holder that is not the last** is a no-op for the underlying stores. A spec that closes to force a checkpoint and then expects a cold read from disk gets neither while another holder is alive. Name this on the function; it is the same shape as a read-cache lease, which `packages/db-p2p/docs/storage.md` already explains, and it is why `packages/upgrade-check` keeps building its stores by hand (its `fs` layout is two directories anyway).
- **A path spelled two ways.** `path.resolve` is what the memoization keys on, which is what `FileRawStorage` and `FilePieceStore` already resolve for their store identity, so the two agree. It does not follow symlinks or normalise case, so two spellings that resolve differently are two entries and two sets of stores — the same under-approximation `identityForHandle` makes deliberately, and the same consequence (double-counted pieces, and for the piece store a failed put). Record it as a `NOTE:` tripwire beside the map.
- **Closing twice.** A host calling `close()` twice on one storage must not release two holders. Make the returned value's `close` idempotent per holder.
- **A rejected close.** The fs chain uses `try`/`finally` so a failing piece-store close still closes the other two; keep that, and decide what the holder count does when a close rejects — releasing the holder is right, since the host cannot usefully retry a half-closed set.
- **`upgrade-check` does not use these factories.** Its job is to reproduce the directory layout each release wrote, which for `fs` is two directories (`blocks` and `kv`, as every `fixtures/*/fs.json` manifest declares). It keeps building its three stores by hand. Confirm it is still green; nothing here should touch it.
- **The React Native bundle.** A new module in the rn package's entry graph is new surface for Metro and `hermesc`; run `yarn check:rn`.
- **Logging.** If a factory logs anything, it uses its package's existing channel (`storage:file`, `storage:sqlite`, `storage:indexeddb`, `storage:leveldb`) — a new `createLogger` channel needs a row in `docs/debugging.md` or `packages/db-p2p/test/logger.spec.ts` fails. Prefer logging nothing: the node already reports its storage at start-up.
- **Dependency declarations.** `scripts/check-undeclared-deps.mjs` fails on a bare import a workspace does not declare. Each factory imports only its own package's modules and `@optimystic/db-p2p`, which each already declares; confirm rather than assume.

## Tests

Two cases, both in `packages/db-p2p-storage-fs/test/file-store-identity.spec.ts`, which already exists for exactly this contract:

- **One location, one identity.** `fileNodeStorage(dir)` gives a block store and a piece store for which `blockStoreCountsPieces` is true, so a node over it counts its pieces once. This pins the claim §The local store makes in `docs/blobs.md` and is the thing the factory's own assertion protects.
- **One directory, one storage.** Two `fileNodeStorage(dir)` calls return the same value; closing one leaves the stores usable; closing the last releases them, and a call after that opens a fresh set. This is the reference counting, which is real branching logic with a real invariant behind it.

Nothing for the three handle-taking factories: each is three constructor calls over a handle the caller passed, with no branch in it, and the identity assertion inside each is what would fail if that stopped being true. One test per behaviour, and that behaviour is already covered by the fs pair plus each package's existing store suites.

## Docs

Each storage package's readme has a section on handing stores to a node — the fs one spells out `pieceStorage` and `kvStore` and what happens without each, twice. Replace that with the one call, saying in each: what the location is, that the three stores share it and therefore report one store identity so pieces are counted once, who closes what (and for ns/web/rn that the handle stays the host's), and for fs that one directory means one set of stores in this process.

`packages/db-p2p/docs/storage.md` and `docs/blobs.md` §The local store were brought up to the one-value shape by the previous ticket; add to each the fact that every storage package now opens the whole of it in one call, and name the four functions.
