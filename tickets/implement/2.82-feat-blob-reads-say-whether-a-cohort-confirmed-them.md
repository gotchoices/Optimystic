# Block reads say whether a cohort confirmed them

docs/blobs.md §Lifetime lets a machine release a blob only on "a certain answer", and excludes "a read that rested on asking nobody, unless the node is alone by the test the offline queue's reachability gate applies". The read path cannot say that today. A coordinator whose view of a block's cohort holds only itself answers an absent block as authoritatively absent, unflagged (the `'unasked'` absence verdict in `CoordinatorRepo`, docs/internals.md "A block read has three answers"), and serves a held block from its own copy for a whole read-repair window armed by that same self-only exit. A caller receives the same `GetBlockResult` it would have received after the whole cohort answered. So a node that merely cannot see its cohort, and a node that really is the only machine, are indistinguishable from the reader's side, and so are both from a node whose cohort confirmed the answer.

This ticket adds the smallest piece that lets `feat-unreferenced-blobs-are-reclaimed` tell the three apart: a positive per-answer marker set by the answering coordinator when a cohort member outside it vouched for the answer, a per-read request field that makes the answering coordinator run a window-demanded consult before answering instead of behind the answer, and a method on the reachability gate that says whether this node is alone for given blocks. No existing behaviour changes: nothing reads the marker except the reclaim pass, and the request field is set only by it.

## Wire fields (`packages/db-core/src/network/struct.ts`)

On `BlockGets`, beside `skipWindowConsult`:

```ts
/** The asker wants each block's answer to rest on a consult made for this read wherever the read
 *  path would otherwise answer from the coordinator's own copy and consult behind the answer: a held
 *  block whose lazy read-repair window has expired, or that `readRepairSampleRate` picked, is consulted
 *  BEFORE it is answered, as under `'paranoid'`. Reads inside the window are answered as before. Set
 *  only by the blob reclaim pass, whose reads must be confirmable ({@link GetBlockResult.cohortConfirmed}).
 *  Whole-read, forwarded on every batch like {@link skipWindowConsult}. A peer that predates the field
 *  ignores it and answers as before, without the marker, which the asker reads as unconfirmed. When both
 *  are set, `awaitConsult` wins. */
awaitConsult?: true;
```

On `GetBlockResult`, beside `unconfirmedAheadRev`:

```ts
/** Set by the answering coordinator when at least one cohort member other than itself vouched for this
 *  answer: the consult made for this read, or the one that armed the read-repair window the answer was
 *  served under, heard from EVERY member of the coordinator's non-self cohort view, at least one such
 *  member exists, and nothing it heard is ahead of what is served; or the window was armed by a commit
 *  that another cohort member co-signed. POSITIVE on purpose: absent means "not known to be confirmed",
 *  so an answer from a repo that predates the field, a `TestTransactor`, a solo-self consult, a consult
 *  with a silent member, a background consult or a sync read all read as unconfirmed. Never set beside
 *  `unavailable` or `unconfirmedAheadRev`. Nothing but the blob reclaim pass reads it. */
cohortConfirmed?: true;
```

`downstreamGets` forwards `awaitConsult` exactly as it forwards `skipWindowConsult` — one more conditional spread. Nothing else on either side of the wire needs touching: `narrowBlockGets` spreads the fields it does not narrow, so a later packing round carries `awaitConsult`; `RepoService` hands the operation to `CoordinatorRepo.get` verbatim, so no protocol change and no version gate (the same argument docs/transactions.md records for `floors`).

`NetworkTransactor.get`'s merge keeps each chosen entry whole, so the marker travels with the entry it describes, and it plays no part in `rankOf`, `beats` or `isAuthoritative` (verified by inspection at `packages/db-core/src/transactor/network-transactor.ts` lines 279–425).

## `CoordinatorRepo` (`packages/db-p2p/src/repo/coordinator-repo.ts`)

### The stamp records whether it vouches

`FreshnessStamp` gains `vouched?: true` — absent means not vouched, so `setLastSeenForTest` keeps writing an unvouched stamp with no change. `markBlocksSeen` changes to take one object, so every caller states it rather than inheriting a default:

```ts
private markBlocksSeen(blockIds: readonly BlockId[], basis: { vouched: boolean; floor?: number; quiet?: QuietCohort }): void
```

and writes `...(basis.vouched ? { vouched: true } : {})` beside the two conditional spreads it already has. Callers, and the value each passes:

| Caller | `vouched` |
|---|---|
| `fetchBlockFromCluster`'s solo-self exit | `false` |
| `fetchBlockFromCluster`'s `cohort-too-small` arming, local-current exit and convergence exit | that exit's consult verdict (below) |
| `noteCohortCommitApplied` | `applied.cohortSize > 1` (`CohortCommitApplied.cohortSize` is `Object.keys(record.peers).length`, so it counts this node; above one means a member outside it signed) |
| the cluster commit path's three `armFreshness` sites (lines 3685, 3725, 3912) | `true` — that path runs consensus with at least one other member |
| `commitSolo` | `false` |

### `fetchBlockFromCluster` returns `vouched: boolean`

A required field, so an exit added later has to say which it means — the same reason `currency` is a required union there. One shared predicate:

```ts
/** Every member of the non-self cohort view answered, at least one exists, nothing heard is ahead of
 *  what this node serves, and no peer claimed the block exists when this node holds none. Deliberately
 *  conservative: partial silence does not vouch, although the read path serves it unflagged and arms the
 *  window on it — a silent member may hold a revision the others missed, and the one consumer of this
 *  marker deletes data. */
function consultVouches(answered: readonly string[], silent: readonly string[], currency: CurrencyVerdict, absence: AbsenceVerdict): boolean {
	return answered.length > 0 && silent.length === 0 && currency.kind === 'nothing-ahead' && absence !== 'claimed';
}
```

The three exits that ask nobody — no `clusterLatestCallback`, empty cohort, solo-self — return `false`. Past the consult there are four `return`s from three distinct `(absence, currency)` pairs: the two inside the `if (!corroborated)` block share one pair, so compute `consultVouches(...)` once there and hand it to both; the local-current exit and the convergence exit each compute their own from their own `absence` and `currency`.

Both of `fetchBlockFromCluster`'s callers destructure the result (`readRepairBlock` line 1136, `runHeldBlockConsult` line 1778); the background one ignores `vouched`, since a consult behind a read never marks the answer that read already gave.

### `readRepairBlock` sets the marker

One helper, called last on each path, after the entry has been replaced by the refreshed read and after every flag has been applied:

```ts
/** Set `cohortConfirmed` on `results[blockId]` when `vouched` and the entry carries neither
 *  `unavailable` nor `unconfirmedAheadRev`. */
private markCohortConfirmed(results: GetBlockResults, blockId: BlockId, vouched: boolean): void
```

| Path in `readRepairBlock` | `vouched` passed |
|---|---|
| inside the window (`!isMissing && !isStale`) | `this.readRepairMode !== 'off' && this.lastSeenCommitMs.get(blockId)?.vouched === true` |
| `skipWindowConsult` early return | not called |
| quiet span still vouches | `stamp.vouched === true` |
| background consult started | not reached when `awaitConsult` is set (see below); otherwise not called |
| blocking consult | the `vouched` `fetchBlockFromCluster` returned |
| consult threw (the `catch` arm) | not called |

The inside-window path runs **before** the local `stamp` variable exists (that is read only for an expired window), so it reads `lastSeenCommitMs` itself. It is gated on the mode because `readRepairMode: 'off'` never consults a held block, so an `'off'` node's stamp can be arbitrarily old — in `'lazy'` the inside-window stamp is at most one `readRepairWindowMs` old, or a quiet span's length. Consequence, stated out loud: on an `'off'` node no held block is ever confirmed, and the reclaim pass there counts only when the node is alone.

A `get` without `clusterLatestCallback`, and a `skipClusterFetch` (sync) read, never enter `readRepairBlock` at all, so they are unmarked with no code of their own.

### `awaitConsult`

Two lines in `readRepairBlock`: `const background = windowOnly && !this.awaitWindowConsults && !blockGets.awaitConsult;`, and the `skipWindowConsult` early return is skipped when `awaitConsult` is set. Nothing else changes — the blocking path already runs the consult, logs its trigger, refreshes the entry and records the stamp.

## `KeyNetworkCohortReachability.aloneFor` (`packages/db-p2p/src/network/cohort-reachability.ts`)

```ts
/** True when, for every distinct block, `findCluster` assembles exactly this node and the self-only
 *  view passes the test `reachable` applies to one (`whyNotAlone`: no remembered serving member
 *  missing, no bootstrap peer awaited, no identify in flight). False when any cohort names another
 *  member — unlike `reachable`, which answers true then — is empty, or its lookup throws. Never throws. */
async aloneFor(blockIds: readonly BlockId[]): Promise<boolean>
```

Implemented over a private `judgeAlone(blockId): Promise<UnreachableReason | 'other-members' | undefined>` that shares `whyNotAlone` with `judgeCohort`. A false answer logs `reachability:not-alone reason=%s block=%s` once per call, for the first block that failed; it does not touch `lastAnswer` (whose one-line-per-change contract belongs to `reachable`) and wakes no listeners.

Why a second method rather than widening `reachable`: an unconfirmed answer is acceptable only from a node that is alone, and `reachable` is also true when the cohort names another member — which is exactly when an unconfirmed answer must not count, because that member was either not asked or did not vouch.

**Where it is visible.** Declare it as an exported interface and intersect it into `NodeCohortReachability`, so `node.cohortReachability.aloneFor` is reachable for the reclaim pass:

```ts
/** What the blob reclaim pass needs beyond {@link ICohortReachability}: see {@link KeyNetworkCohortReachability.aloneFor}. */
export interface CohortAloneness { aloneFor(blockIds: readonly BlockId[]): Promise<boolean>; }

export type NodeCohortReachability = ICohortReachability & Required<Pick<ICohortReachability, 'onChange'>> & CohortAloneness;
```

Deliberately NOT on db-core's `ICohortReachability`: that would force an answer out of `alwaysReachable` and every other implementer for a question only a node with a real key network can answer, and the offline queue — its one consumer — does not ask it.

## Edge cases & interactions

- **A node alone in its view with a remembered member missing.** Absent answers are `'unasked'` and unmarked, held blocks are served under a solo-self stamp and unmarked, and `aloneFor` is false (`absent-members`). Covered by the solo-self test plus the `aloneFor` test.
- **A genuine one-machine deployment.** Answers are unmarked; `aloneFor` is true. The reclaim pass relies on that pair. Covered by the `aloneFor` test and the reclaim ticket's one-machine test.
- **A window armed by a full consult, then a read inside it.** Marked. Test.
- **A consult with one silent member.** Served unflagged as today, not marked. Test.
- **Window expired, lazy mode.** Without `awaitConsult`, unchanged: answered at once, consult behind, not marked. With it, consulted first and marked when the consult vouches. Test.
- **Floor-demanded consults and `'paranoid'`.** Already blocking, so already marked by the consult's verdict with no extra code. Inspection.
- **A claim that is not ahead of what this node holds.** `absence` is `'claimed'` while `currency` is `nothing-ahead`, so `consultVouches` refuses — the conservative direction, and the shape the silent-member test also lands in. Inspection plus that test.
- **A remote coordinator.** Its answer carries its own marker over the wire, set by the same code. A remote that predates the field sends none: unconfirmed, the safe reading. Inspection.
- **Two coordinators answering one block.** `NetworkTransactor.get`'s merge breaks an equal-rank tie on served revision alone, so a confirmed entry can lose to an unconfirmed entry at a newer revision and the merged answer then carries no marker. The safe direction (reads as unconfirmed), and not worth a rank of its own — the marker must not change which content a read returns. Inspection.
- **The marker never sits beside a doubt marker.** `markCohortConfirmed` checks both. Inspection.
- **Existing behaviour.** No caller other than the reclaim pass sets `awaitConsult`, and nothing branches on `cohortConfirmed`. No spec in `packages/db-p2p/test` or `packages/db-core/test` deep-equals a whole `GetBlockResult` (checked), so the new field breaks no assertion; `markBlocksSeen` is private, so the signature change is confined to this file, and `setLastSeenForTest` writes the stamp directly and is untouched.
- **Cost.** `awaitConsult` makes an expired window's consult block the read; it is set only by a pass that runs every few hours. Inspection.

## Tests

New: `packages/db-p2p/test/coordinator-repo-cohort-confirmed.spec.ts`. Copy the cohort-of-three construction from `packages/db-p2p/test/coordinator-repo-read-repair.spec.ts` (`makeClusterPeers`, `makeKeyNetwork`, `makePresentStorageRepo`, a `clusterLatestCallback` the test controls and that answers self from the local revision) and the deterministic clock plus `awaitWindowConsults` seam from `packages/db-p2p/test/coordinator-repo-solo-read-repair-window.spec.ts`. Four cases:

- **A whole cohort's answer is marked.** A missing block whose two other cohort members both resolve `undefined` ("holds nothing"): the absent answer carries `cohortConfirmed` and no `unavailable`. Then a held block whose two members both answer at the local revision: the first read takes the local-current exit and arms the window, and a second read inside that window is marked.
- **A silent member leaves a present answer unmarked.** A held block, window expired, `awaitConsult: true`: one member answers at the local revision, the other's callback rejects. The answer carries no `unavailable`, no `unconfirmedAheadRev` and no `cohortConfirmed`.
- **A self-only view is never marked.** Cohort view is this node alone: the absent answer for a missing block is unmarked; a held block read twice (the first read takes the solo-self exit and arms the window, the second is served inside it) is unmarked both times.
- **`awaitConsult` consults before answering.** Lazy mode, `awaitWindowConsults` false, a held block whose window has expired, a cohort whose callback answers at the local revision. Without the field the read returns before the callback has been called and is unmarked; with it the callback has been called by the time the read returns and the answer is marked.

Extend `packages/db-p2p/test/cohort-reachability.spec.ts` with one `describe('aloneFor')` of three assertions, over the key-network double already there: a cohort of `[SELF, PARTNER]` is `reachable` true and `aloneFor` false; a self-only cohort with nothing absent and nothing awaited is true for both; a self-only cohort whose `absentCohortMembers` names a peer is `aloneFor` false.
