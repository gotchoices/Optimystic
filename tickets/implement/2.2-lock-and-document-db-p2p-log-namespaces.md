# Lock the namespace tree shut, and finish the reference table

Step 3 of 3. Steps 1 and 2 fixed the instances; this step fixes the **class** — it makes the next
author's wrong choice fail loudly instead of silently, and makes the documentation match reality.

Do not start until `migrate-services-off-libp2p-logger-factory` has landed: both guards below
assert "zero occurrences", which will not hold before it.

## Why this step exists separately

`packages/db-p2p` had nine log channels sitting outside `optimystic:db-p2p:`, and three of them
were missed by a careful manual enumeration written specifically to list them. That is the tell:
the trap is that an author writing a new service picks whichever logger factory is nearest to hand
(libp2p's `components.logger.forComponent(...)` is right there in the components object it already
has), and nothing anywhere says one of the two is wrong. Fixing nine call sites without closing
that door just resets the counter.

## 1. Lint rule

`eslint.config.js` is a flat config that already gates `packages/*/src/**/*.ts` on `no-console`,
for essentially this reason ("route stray library logging through each package's `debug` logger").
Add a sibling block using `no-restricted-syntax`:

- **`CallExpression[callee.property.name='forComponent']`** — message: libp2p's component logger
  creates a namespace outside `optimystic:*`, which `DEBUG=optimystic:db-p2p:*` never matches; use
  this package's `createLogger` from `src/logger.ts`.
- **`ImportDeclaration[source.value='debug']`** — message: import `createLogger` from your
  package's `logger.ts` rather than constructing `debug` channels directly, so every namespace is
  rooted in the documented tree.

The `debug` rule needs two exemptions, both pre-existing and legitimate:

- `packages/*/src/logger.ts` — the seven package logger factories; they *are* the chokepoint.
- `packages/reference-peer/src/cli.ts` — already exempted from `no-console` for the same reason
  (it is an executable entry point, not library code). Confirm it still imports `debug` before
  exempting; if step 2's work happened to remove that import, drop the exemption instead of
  carrying a dead one.

In flat config, express exemptions as a later config block that re-sets the rule to `'off'` for
those `files:` globs. Keep the SCOPE comment at the top of `eslint.config.js` accurate — it
currently says `no-console` is "the only enforced rule". Update that sentence.

Verify with `yarn lint` (zero findings) and by temporarily reintroducing one `forComponent` call to
confirm the rule actually fires — a `no-restricted-syntax` selector that matches nothing is
indistinguishable from a rule that works.

## Edge cases & interactions

- **The guard tests must not read `dist/`.** `packages/db-p2p/dist/` contains compiled copies of
  every file being scanned, including the `.d.ts` files that still mention `forComponent` in doc
  comments. A recursive walk rooted at the package directory instead of `src/` passes before the
  fix and fails after it, which is the worst possible failure mode.
- **The `forComponent` scan will also match comments and type declarations.** After step 2 there
  should be none in `src/`, but if a legitimate prose mention survives (e.g. explaining *why* the
  ban exists, in `src/logger.ts`), the assertion needs an explicit allowance for that one file —
  decide deliberately rather than deleting the explanation to satisfy a regex.
- **`network:get-manager` and `storage:restoration` contain a colon**, so they are nested channels,
  not flat ones. The docs-completeness assertion must match them literally; a check that splits on
  `:` will not find them in the table.
- **The lint rule's `forComponent` selector matches by property name only**, so it would also flag
  an unrelated future method called `forComponent` on some other object. Nothing like that exists;
  the message should name the actual concern so a false positive is diagnosable rather than
  mysterious.
- **`test/` is deliberately not covered by either guard.** Specs legitimately build stub objects
  with a `forComponent` property to satisfy libp2p-shaped interfaces, and `capture-log.ts`
  legitimately imports `debug` — that is its whole job. Scope both the lint block and the scans to
  `src/`.
- **Other packages.** The lint rule is written against `packages/*/src/**`, not just db-p2p, so a
  future package that embeds libp2p inherits the guard. The structural tests stay db-p2p-local
  (they read that package's `src/`); do not try to generalize them across the workspace in this
  pass.
