# A commit proof is stored once, not once per block

Reported as GitHub #60 (Sereus; optimystic 1.27.0, file storage, solo node). The prereq adds a commit-proofs store keyed by `messageHash` to every backend; this ticket makes the kernel use it.

## What happens today

A commit's `BlockCommitProof` carries the commit `RepoMessage` verbatim, whose commit operation lists every block id and declared digest. `StorageRepo.persistProofIfContentMatches` saves that proof under each committed block's `(blockId, rev)` key (`IBlockStorage.saveBlockProof` → `KvRawStorage.saveBlockProof` → `RawStoreDriver.putProof`). Bytes retained per commit therefore grow as blocks-touched squared. The reporter measured (5 commits × 500 rows): proofs 1.4×, 5.7× and 11.7× the block data at 1, 4 and 8 secondary indexes (816 proof files for 7 distinct proofs at 4); on a real load, 7.0 GB after 10 of 15 commits, 94% proofs, one 528 KB proof stored 3,383 times. Not re-measured here; the layout follows from the code. This is the revisit condition of the `NOTE:` on `persistProofIfContentMatches`, which has tripped.

## Design

The `proofs` store keeps its `(blockId, rev)` key and its meaning — "this revision has a proof" — but its value becomes a **reference**; the proof itself lives once per node in the commit-proofs store under its `messageHash`.

```ts
/** A revision's entry in the proofs store: the messageHash of the proof in the commit-proofs store. */
type ProofRef = { proofRef: string };
/** What a proofs-store entry may hold: a reference, or — written before this change — the whole proof. */
type StoredProofEntry = ProofRef | BlockCommitProof;

// IRawStorage — raw slot access, used by RawStorageDriverAdapter; no logic
getProofEntry(blockId, rev): Promise<StoredProofEntry | undefined>;
saveProofEntry(blockId, rev, entry: StoredProofEntry): Promise<void>;
```

`IRawStorage.getBlockProof` and `saveBlockProof` keep their signatures and become the composed operations, implemented once in `KvRawStorage`:

- **`saveBlockProof(blockId, rev, proof)`**: ensure the commit-proofs store holds a proof under `proof.messageHash`, then write `{ proofRef: proof.messageHash }` to the slot. The shared record is written **before** the reference, so by the flush contract's prefix rule (rule 3 at `RawStoreDriver.flush`) a reference never survives a crash without its target.
- **Ensuring the shared record is first-writer-wins**: if a record is already stored under the hash, it is kept. A per-kernel memo of hashes known stored — a bounded map from hash to the in-flight-or-settled promise (1024 entries; `LruMap` as the responsibility cache uses) — means a commit of N blocks reads and writes the shared record once, not N times, and that two concurrent saves of one message join one write. A rejected promise is removed from the memo and rethrown. On a memo miss: `driver.getCommitProof(hash)`, and `putCommitProof` only when absent. The memo is never wrong in the stale direction: nothing deletes a commit proof, and a store that faults rejects every later write until it is reopened, which builds a new kernel.
- **`getBlockProof(blockId, rev)`**: read the slot. A `ProofRef` resolves through `getCommitProof`; a missing target logs `storage:proof-ref-dangling` and answers `undefined` (no proof is always a legitimate answer — every consumer already handles it). Any other entry is a proof written before this change and is returned as is. `NOTE:` at that arm: legacy entries are read, never rewritten; if a deployed store ever needs that space back, add a pass that rewrites them as references.
- **`RawStorageDriverAdapter`** maps the driver's `getProof`/`putProof` onto `getProofEntry`/`saveProofEntry` instead of `getBlockProof`/`saveBlockProof`, so the read-cache composition (`CachedRawStorage`, which `withReadCache` puts in front of node storage) passes references and the shared record through unchanged rather than resolving and re-expanding them.
- **A cheap presence check.** `IBlockStorage.hasBlockProof(rev)` (`getProofEntry(...) !== undefined`). `StorageRepo.backFillProof` uses it instead of `getBlockProof`, which would now read and decode the shared proof only to test presence — on every duplicate certified push (the `NOTE:` in `saveReplicatedBlock` counts that path's cost as one key lookup; keep it true).

Why the key is safe to take from the proof: every proof reaching `saveBlockProof` is either built on this node (`buildBlockCommitProof` from its own consensus record, `mintSoloCommitProof`) or verified (`verifyBlockCommitProofClaim` recomputes `messageHash` from the message and rejects a mismatch). State that as the precondition on `saveBlockProof`'s doc. A wrong reference would in any case fail closed at `servableProof`, which checks the proof's message names the `(blockId, rev, actionId)` it serves.

Unchanged, by construction: which revisions get a proof (`persistProofIfContentMatches`' digest-match rule, `backFillProof`'s rules, the restore wire's stripping of unverified proofs in `BlockStorage.restoreBlock`), and what `servableProof`, repair, push and certified-claim selection read — `getBlockProof` returns the same artifact. Replace the tripped `NOTE:` on `persistProofIfContentMatches` with a sentence saying the proof is stored once per node and referenced per revision.

## Decisions on the questions the report also asked

- **Retention.** A proof is kept as long as any revision references it. No revision-delete site exists, so no reference counting is needed until one does; say that at `saveBlockProof` and in the docs. Revision retention itself is backlog `feat-cold-range-transform-offload`, which now carries an arm for this (a sweep that drops revisions must count or sweep shared proofs). `revs/` and `proofs/` are kept indefinitely today; the docs say so.
- **Wire.** Unchanged here. Every push carries one block (`pushBlockToPeers` in `packages/db-p2p/src/cluster/block-transfer-service.ts`), so a per-request de-duplication by `messageHash` would de-duplicate nothing, and the proof cannot be cut to one block's claim because the signatures cover the whole message (`computeClusterMessageHash`, `computeClusterCommitHash`); changing what they cover breaks every stored proof and every mixed-version cohort. The quadratic cost on the wire is real for the push paths (a commit of N blocks pushed to one peer sends N copies), and is backlog `feat-a-commit-proof-crosses-the-wire-once-per-peer`.

## Edge cases & interactions

- **A commit of N blocks** stores one shared record and N references. Test (below).
- **A store written before this change**: slots holding whole proofs read as before; new revisions on the same block get references. Test (below), and the upgrade check over real 1.27.0 data.
- **Back-fill onto a slot holding a legacy proof**: `hasBlockProof` is true, so it is left alone, as today. Inspection.
- **Back-fill onto an empty slot whose message is already stored** (another block of the commit kept the proof at commit time): only the reference is written. Inspection — follows from first-writer-wins.
- **Two proofs for one message with different signature sets** (this node's own record and a later verified push): the first stored serves every block of that commit. `NOTE:` at the ensure step, as an accepted tradeoff: a later verified proof is not preferred over the first; the only known way the first fails verification is an older-build member whose own record carried a late promise (docs/internals.md, *Mixed versions*), which already makes that member's own proof its own loss; revisit if such proofs are seen in the field. Today the same member serves the failing proof for every block it committed; after this change also for a block whose slot was empty and later back-filled.
- **Concurrent saves of one message under different block latches** (the commit apply and a certified push of another block): joined through the memo's in-flight promise. Inspection.
- **Shared write fails**: no reference is written; `persistProofIfContentMatches` already catches, logs `commit:proof-persist-failed` and carries on, and the memo entry is dropped so a later save retries. Inspection.
- **Dangling reference**: answers `undefined`, logged. Unreachable given the write order; inspection.
- **Restore path**: `BlockStorage.saveRestored` writes its caller-verified proof through `saveBlockProof`, so it is de-duplicated too; unverified archive proofs are still never stored. Inspection.
- **Through the read cache** (`CachedRawStorage`): the conformance suite already runs the composition, so the two new conformance cases cover it.

## Tests

- Conformance (`raw-storage-conformance.ts`), every backend and composition: one proof saved for three blocks reads back equal for each, and the store holds it once (`getCommitProof(hash)` defined; each `getProofEntry` a reference). A slot written with a whole proof through `saveProofEntry` reads back through `getBlockProof`. `makeProof` already gives distinct `messageHash`es per marker; the existing proof cases (round-trip, per-block-per-revision, "a later save replaces the proof for that revision only") stay as they are.
- Upgrade check: read back one proof the older build stored — the latest revision of a block it committed, through the node's storage — and check it names that block. Gate it on whether the fixture holds a proofs-store record (fs: a `proofs/` path; LevelDB: a tag-`0x06` key), not on a version list. Expose the storage on `CurrentBuild` for it.
- No new test for the memo, the in-flight join or the dangling arm.
