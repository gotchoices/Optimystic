Fourth of the five stage-4 tickets (see `4.1-offline-sync-plugin-mode-and-sealing`). Two independent protections, each small.

## Design

### The schema-change gate

A statement that changes a table's **storage shape** is refused while any entry that wrote that table is queued ([§Schema changes](../../docs/offline-sync.md#schema-changes)): creating or dropping an index, adding or dropping a column, dropping the table. DDL that changes no stored shape is allowed: a tag change, a CHECK constraint added or dropped by name, a column rename (`renameColumnSchemaOnly` touches no row).

One method on the controller, `OfflineMode.assertNoQueuedEntries(schema, table)`, throws `QueuedEntriesBlockSchemaChangeError` (a `QuereusError` with `StatusCode.BUSY`, carrying `table` and the queued `transactionIds` in queue order, exported from both entries) when any entry's collections intersect the table's collection ids. The table's collection ids come from the bridge's collection-to-table record (ticket 4.1); an entry in doubt or being submitted counts like any other.

Call sites in `packages/quereus-plugin-optimystic/src/optimystic-module.ts`, each right after its `whenCatalogPersisted()` drain and before anything is written: `createIndex`, `dropIndex`, `destroy`, and the `addColumn` and `dropColumn` arms of `alterTable`. `create` is gated only when it re-declares a live table whose column list or primary key differs from the current declaration (an identical re-declare, the ordinary warm restart, is allowed). Inside `apply schema` a refused step is unwound by the engine like any other failed step; the gate throws before the step's batch checkpoint writes anything.

Once the entries settle, the same statement succeeds.

### Invented collections

A table declared but never written has no committed header; `Collection.createOrOpen` staged one in the tracker. A queued entry for such a table must not commit that header if another machine has created the collection meanwhile ([§Invented collections](../../docs/offline-sync.md#invented-collections)).

The protection should already be in the drain: both drivers open their cycle with a refresh (`Collection.commitHead` and `TransactionCoordinator.commitEntry`), and that refresh (`Collection.updateInternal`) re-reads the header with no remembered tail id. Three outcomes, which are exactly the doc's three:

- header found: the collection bootstraps its context from the committed tail, walks the log, adopts the revision, and replays its sealed segments over the committed state (`replayActions` resets to the empty baseline once a context is adopted, so the invented header's insert is dropped); a segment the replay refuses is recorded and reported as on any rebase;
- header authoritatively absent: nothing adopted; the head tracker is built from the invented baseline and the entry commits the header, as a first write does today;
- header unavailable: `readLogEnds` throws `BlockUnavailableError`, which `classifyCommitFailure` sorts as `cohort-unreachable` for the two unreachability reasons and `unknown` otherwise — either way the entry waits.

So the work is to **prove it and pin it**, not to add a probe. Write the db-core test first, at the collection tier: handle A invents a tree and seals one segment under an entry; handle B over the same id creates the collection and commits a row; A's `commitHead` lands A's row in B's collection, B's handle reads both rows, the collection has one header and one log, and A's `committedRevision()` is now defined. Then the same over `commitEntry` with an index tree. If either fails, fix `updateInternal` for the invented case (likely suspects: `inventedBaseline` not cleared on adoption so a later restore's replay arm reinstates it; the `Tree`'s held btree root not re-read after the header changes under it), keeping the fix inside `Collection`.

Also pin that an invented collection with a sealed segment, whose refresh finds the header absent and whose cohort is unreachable, leaves the entry queued with `waitingFor: 'cohort'` (the TestTransactor can be made to answer the header read `unavailable: 'cohort-unreachable'`; see `packages/db-core/test/network-transactor.spec.ts` for the shape).

Document in docs/offline-sync.md §Invented collections that the probe **is** the cycle's opening refresh, naming `updateInternal`; replace the `Collection.open` phrasing.

## Edge cases & interactions

- **Gate on a table whose entry is in doubt.** Refused like any other; the message names the transaction. By inspection.
- **Gate inside `apply schema`.** A refused `create index` step is unwound by the engine; the catalog batch commits the pre-step state. Test one `apply schema` with a queued entry: the apply fails, the error reaches the caller, and the table is unchanged.
- **`drop table` with queued entries** is refused; after the entries settle the drop succeeds and the dropped table's collections leave the bridge's record. Test.
- **Allowed DDL with queued entries**: `alter table … set tags`, a CHECK added by name, a column rename. Test one of them (the tag change), inspection for the rest.
- **The re-declare arm of `create`.** An identical `create table` with queued entries passes; one adding a column is refused. Test both.
- **Index tree invented beside an existing main collection** (a joiner's `create index` while offline on a table the founder had rows in): the index segment's replay runs over the adopted index collection like the main one. Covered by the `commitEntry` db-core case.
- **Joiner scenario at SQL level.** Node A (joiner) declares a table it has never read, goes offline, inserts; node B (founder) creates the same table (same URI) and inserts a row meanwhile; node A reconnects and drains: the drain adopts B's collection, both rows are on B, one header, one log. Test in `test/offline-mode-invented-collection.spec.ts`.
- **Joiner whose row collides with the founder's** fails with `constraint` through the adopt-and-replay refusal; the status is reported before the entry is sent. Add as a second case of the joiner spec.
- **A restored header after restart** is stage 5's; nothing here.
