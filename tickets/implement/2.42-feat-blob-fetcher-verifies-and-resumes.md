# Blob fetcher: verify, resume, schedule

After `feat-blob-protocol-frames-stat-and-get` a node can ask a peer for up to 16 pieces of a blob and receive them as raw frames, and after `blob-fetch-building-blocks` it has the holder rule (`blobHolderCandidates`), the round classification (`unavailableOutcome`), the stream limits (`BlobGetSlots`) and a door into the local store that the sweep is safe against (`LocalBlobService.fetchStore()`, a `BlobFetchStore`). This ticket builds `BlobFetcher`, the one code path that receives pieces: it works out which pieces a blob (or a byte range of it) still lacks here, asks holders in batches, checks every piece against the id that named it before storing it, penalizes a peer that sends wrong bytes and asks someone else, resumes an interrupted transfer by asking only for what is missing, shares one request per piece between concurrent callers, and limits streams so background copying never holds up a read. `feat-blob-pieces-move-between-machines` builds `node.blobs.read`, `fetch` and `stat` with `probe` on it; `feat-a-referenced-blob-is-copied-to-its-cohort` uses it with background priority.

## What the prereq chain already provides (no db-core change needed)

- **The planner.** `walkBlobPieces(ref, source, { offset, length })` in `packages/db-core/src/blob/reader.ts` yields every piece of the tree (or of the part covering the range) in tree order, a list piece before its children, each with `present`; an absent list piece's subtree is skipped. So its `present: false` entries are exactly the **frontier**: missing pieces whose parent is present, plus the root when it is missing. It decodes and bounds every present list piece and throws `BlobCorruptError` for a malformed one, and throws `RangeError` for an offset past the end once the root is present. No range planner and no `pieceMatches` are added.
- **The per-piece check.** `checkPiece(id, bytes, digest, ref)` in `packages/db-core/src/blob/verify.ts` throws `BlobCorruptError` (`piece-too-large`, then `digest-mismatch`). The codec is already one of raw and dag-pb, because every id the fetcher asks for is either the parsed root or a child a decoded list piece named. `MAX_BLOB_PIECE_BYTES` equals `MAX_BLOB_PIECE_FRAME_BYTES`, and the client's framing refuses a longer frame before reading it.
- **Errors.** `BlobUnavailableError(ref, reason, pieceId?)` and `BlobCorruptError` in `packages/db-core/src/blob/errors.ts`.

## Module and types

`packages/db-p2p/src/blob/blob-fetcher.ts`:

```ts
export type { FetchPriority } from './blob-get-slots.js';

export interface BlobFetchRequest {
	priority: FetchPriority;
	/** Byte range; absent means the whole blob. Same meaning as BlobReadOptions. */
	offset?: number;
	length?: number;
	/** Peers known to hold the blob (an announcer, a peer that answered a stat); asked first, in this order, still filtered like every candidate. */
	knownHolders?: readonly string[];
	/** Keep retrying while no reachable holder can supply a missing piece, until no piece has arrived for this long. Absent or 0: fail after the first round that leaves a piece unavailable. */
	waitMs?: number;
	signal?: AbortSignal;
}

export interface PieceStoredEvent { ref: BlobRef; id: PieceId; bytes: number; peer: string }

/** One caller's fetch of one blob. */
export interface BlobFetchSession {
	/** Resolves when every piece the range needs is here; rejects with BlobUnavailableError, BlobCorruptError, RangeError (offset past the end), the signal's reason, or a local store fault. */
	readonly done: Promise<void>;
	/** Resolves when `id` is here (at once when it already is). Rejects when `done` rejects first, or, if `done` resolves with `id` still absent (an id outside the range), with RangeError. For a reader that consumes pieces as they arrive. */
	stored(id: PieceId): Promise<void>;
}

export interface BlobFetcherDeps {
	client: BlobProtocolClient;
	/** The candidate rule's inputs (BlobHolderDeps), passed through to blobHolderCandidates. */
	holders: BlobHolderDeps;
	reputation: Pick<IPeerReputation, 'reportPeer'>;
	store: BlobFetchStore;
	digest: BlobDigest;
	/** Default: a BlobGetSlots with the protocol-limits defaults. One per node. */
	slots?: BlobGetSlots;
	/** Default Date.now. */
	now?: () => number;
	/** Default armUnrefTimer. */
	setTimer?: (fn: () => void, ms: number) => () => void;
}

export class BlobFetcher {
	constructor(deps: BlobFetcherDeps);
	start(ref: BlobRef, request: BlobFetchRequest): BlobFetchSession;
	onPieceStored(listener: (event: PieceStoredEvent) => void): () => void;
	/** Rejects every running session and every later start with an Error('blob fetcher stopped'), aborts streams in flight, cancels retry timers; resolves once every session has settled. */
	stop(): Promise<void>;
}
```

The plan listed `selfPeerId`, `blobProtocol`, `keyNetwork` and `membership` as separate deps and `pieces: IPieceStore` and `records: BlobRecordStore`; they are folded into `holders` and `store` respectively. `stop` is added because the node needs a teardown that stops dialing and cancels the unref'd wait timers before transports close.

## What a session does

`start` returns at once (`parseBlobRef(ref)` first: a non-reference throws `BlobRefError` synchronously, since it is the caller's bug); the work runs in the background and settles `done`. Each session has its own `AbortController`, aborted with the reason of the caller's `signal` or of the fetcher's stop signal, combined by hand as in `RepoClient` (`packages/db-p2p/src/repo/client.ts`; Hermes has no `AbortSignal.any`), and its listeners removed when the session settles.

1. **Nothing missing.** Walk the range over `store.source`. If no entry is absent, resolve. No hold, no cohort lookup, no peer asked. (`feat-blob-pieces-move-between-machines` relies on this: a local read costs no `findCluster`.)
2. **Hold, then plan again.** Otherwise `store.holdCached(ref)` and walk again: the first walk ran under no hold, so a sweep may have removed pieces it saw present; the hold now protects whatever this walk sees (see `BlobFetchStore`). Take the frontier from this walk: its absent ids, in tree order, each once (a repeated data piece is yielded at each position).
3. **Rounds.** A round recomputes candidates (`blobHolderCandidates(holders, ref, request.knownHolders)` minus the session's corrupt-excluded peers), so a holder that connects during a `waitMs` wait is found. Per round, keep for each frontier piece a map peer → `'not-held' | 'no-answer'`, and a set of peers that failed in this round.
4. **Batches**, one at a time per session (re-planning needs the previous batch's list pieces). Choose the peer: the first candidate, not failed this round, that has no answer recorded for at least one frontier piece that is not in flight elsewhere. Acquire its slot (`slots.acquire(peer, priority, sessionSignal)`) **before** choosing pieces, so a session waiting for a slot claims no pieces another session could be fetching. Then the batch: frontier pieces, in tree order, not in the fetcher's in-flight map and with no answer recorded from this peer, up to `MAX_BLOB_GET_PIECES`. Empty batch → release the slot and re-choose. Assert that no id in the batch is already in the in-flight map, register each, then `client.get(peerIdFromString(peer), batch, { signal: fetcherStopSignal })` — the fetcher's stop signal, not the session's: a batch already sent is left to finish (16 pieces at most, bounded by the progress deadline) because another session may be waiting on its pieces and what it stores is kept anyway. Release the slot and clear the in-flight entries in a `finally`. On the reply:
   - ids the header lists as not held → record `not-held` for this peer.
   - each piece frame → `checkPiece(id, bytes, digest, ref)`. Good → `store.storePiece(ref, id, bytes)`, then resolve the in-flight entry as stored, emit `PieceStoredEvent` (a throwing listener is logged, `fetch:listener-threw`, and does not stop the others), note the progress time. `BlobCorruptError` → discard the bytes, `reputation.reportPeer(peer, PenaltyReason.InvalidRestoration, \`blob-piece ${id}\`)` once, add the peer to the session's corrupt-excluded set and to the session's corrupt map for that piece, log `fetch:penalized`, and stop reading this reply (`break`, which aborts the stream): the rest of the batch is recorded `no-answer` for this peer, which is moot since it is never asked again in this session. Any other error from `checkPiece` (the digest port failing) or from `storePiece` (a store fault) rejects the session with it.
   - a thrown `get` or a throw while iterating the pieces (dial failure, `BlobTransferStalledError`, `BlobPeerRefusedError`, `BlobProtocolError`, stream reset) → log `fetch:holder-failed`, add the peer to this round's failed set, and record `no-answer` for it against every frontier piece it has not answered, so the round can end. Pieces already stored stay stored. A busy peer (`BlobPeerRefusedError('busy')`) is the same: `no-answer` for the round; a later round may try it again.
   After the batch: drop the stored ids from the frontier; if any stored piece is a list piece (`pieceKind(id) === 'list'`), walk again and take the frontier afresh (its children are now known). Walking only then keeps a large blob's fetch from walking the whole tree after every batch.
5. **Pieces in flight elsewhere.** A frontier piece that another session has in flight is not requested; the session awaits that attempt (the in-flight entry is a promise resolving to whether the piece was stored). Stored → drop it from the frontier. Not stored → it is back in this session's frontier. So two reads of one blob request each piece once. A foreground session waiting on a piece in a background batch waits for that batch: put a `NOTE:` at the in-flight map saying it is bounded by one batch of 16 pieces and the progress deadline, and to request in parallel at foreground only if reads are measured waiting on it.
6. **Round end.** When every frontier piece not in flight elsewhere has an answer from every candidate (or there are no candidates), walk again. Nothing absent → done (below). Otherwise classify the first absent piece in tree order: `unavailableOutcome` over one entry per round candidate (its recorded answer) plus one `corrupt` entry for each peer in the session's corrupt map for that piece. `corrupt` → `BlobCorruptError('digest-mismatch', piece, ref, 'every holder that had it served bytes that do not match')`; `unavailable` → `BlobUnavailableError(ref, reason, piece)`. If `waitMs` is set and less than `waitMs` has passed since the last stored piece (or since the session started), log `fetch:wait`, wait `BLOB_WAIT_RETRY_INITIAL_MS` doubling to `BLOB_WAIT_RETRY_MAX_MS`, capped by the time left, on an unref'd timer the session signal cancels, and run another round from the walk; else reject with the classified error. A piece arriving resets the wait clock (and the backoff to its initial value).
7. **Done.** For a session with no range (`offset` and `length` both absent), `store.markWhole(ref, size)` with the size from the final walk (the root list's `fileBytes`, or a raw root's byte length read from `store.source`); a ranged session changes nothing more. Resolve.

A planner throw (`BlobCorruptError` from a stored list piece with a correct hash and bad structure, or `RangeError` for an offset past the end once the root is here) rejects the session with it; nothing is retried and nobody is penalized, since another holder would serve the same bytes. A failed or aborted session keeps the hold and the pieces it stored, which is what makes the next session resume; evicting cached blobs is `feat-unreferenced-blobs-are-reclaimed`'s.

**`stored(id)`.** Check `store.source.has(id)` first; otherwise register a waiter keyed by `(ref, id)` that the fetcher resolves when it stores `id` for any session (so a read's waiter is satisfied by a background session's piece too). When the session's `done` rejects, its waiters reject with the same error; when `done` resolves, remaining waiters for ids still absent reject with `RangeError`. Waiters are removed when settled, so the map does not grow.

**Abort.** The session signal rejects `done` and every `stored` waiter with `signal.reason`, stops the session from acquiring slots or starting batches, and cancels its wait timer. It does not abort a batch already sent (above).

## Edge cases & interactions

- **Wrong bytes from one holder, right bytes from another.** The read succeeds, the bad piece is never stored, the bad peer is penalized once and not asked again in the session. Test.
- **Every holder serves wrong bytes, or one does and the rest do not hold it.** `BlobCorruptError`; nothing stored for that piece. The classification test in the prereq covers the row; the corrupt-map bookkeeping by inspection.
- **Correct hash, malformed structure.** `BlobCorruptError` from the walk, no penalty, no retry. Inspection.
- **Interrupted fetch.** Pieces stored before the interruption stay; the next session plans against the local store and asks only for what is missing. Test.
- **Partial holder.** Pieces it lacks come back not held in its header and go to the next candidate in the same round. Inspection.
- **Header lies, stalled stream.** `no-answer` for the unreceived pieces; the next candidate is asked. Inspection (the stall itself is pinned by `packages/db-p2p/test/blob-protocol-stalls.spec.ts`).
- **Busy holder.** `no-answer` for the round; asked again next round. Inspection.
- **Refused by the membership predicate, banned, not speaking the protocol, self.** Never dialed: the one filter in `blobHolderCandidates`. A blob whole here starts no network work. Inspection.
- **Solo node, or every candidate silent.** `cohort-unreachable` at once, or after `waitMs`. Inspection.
- **Concurrent sessions on one blob.** One request per piece; the second waits on the first's attempt and takes the piece back if it failed; the assertion at the batch seam. Inspection plus the assertion.
- **Session waiting for a slot.** Claims no pieces until it holds the slot, so it cannot hold up another session's fetch of those pieces. Inspection.
- **Foreground behind background.** Separate slot pools; a foreground batch to a peer with an open background stream opens its own. Only a piece already in a background batch makes a read wait (the `NOTE:` at the in-flight map). Inspection.
- **Sweep during a fetch.** The hold is taken before the planning walk that decides what is present, and every piece is stored through `BlobFetchStore.storePiece`, which `blob-fetch-building-blocks` proved safe against a running sweep. Inspection.
- **A piece deleted after the session believed it present** (only eviction, a later ticket, can do this to a held blob). The final walk before resolving catches it and the round goes on. Inspection.
- **Crash mid-fetch.** Nothing is flushed. Pieces and the hold may or may not be on disk; orphans are swept and the next read fetches them again. Accepted; inspection. `feat-a-referenced-blob-is-copied-to-its-cohort` flushes before reporting `held`; say so in a `NOTE:` at `markWhole`'s call.
- **Range past the end.** `RangeError` once the root is here, from the walk. Inspection.
- **`findCluster` throws.** Empty cohort for that round, logged by the holder rule. Inspection.
- **Node stops during a fetch.** `stop()` rejects sessions, aborts the batches' streams, cancels wait timers. Inspection.
- **`waitMs` with no progress.** Stops once `waitMs` passes with no piece stored; a piece arriving resets the clock. Exercised end to end in `feat-blob-pieces-move-between-machines`.

## Tests

`packages/db-p2p/test/blob-fetcher.spec.ts`, real nodes over loopback TCP built with `createLibp2pNode` (see `packages/db-p2p/test/blob-protocol-stalls.spec.ts` for the shape), `clusterSize` 3, connected to each other, each with a piece store passed through `NodeOptions.pieceStorage`. Because the node's own fetcher is not an attachment, each test builds a `BlobFetcher` over node B's parts: a `BlobProtocolClient` over `nodeB.keyNetwork` and `nodeB.linkDeadlines`, `holders` from B's key network, `nodeB.reputation` (wrapped to record `reportPeer` calls), `store: nodeB.blobs.fetchStore()` (`node.blobs` is typed as db-core's `BlobService`, so narrow it with `instanceof LocalBlobService` and fail the test otherwise, rather than casting; `feat-blob-pieces-move-between-machines` later changes the attachment's type). That exercises everything but the wiring, which is inspection. Blobs are put on the holding nodes with `node.blobs.put`.

- *Wrong bytes*: node A's piece store is a small decorator over `MemoryPieceStore` whose `get` returns one data piece's bytes with a byte flipped; node C holds the same blob unaltered; B starts a foreground session with `knownHolders: [A, C]`. `done` resolves, B's store holds the correct bytes for every piece (read back with `readBlob` over B's store, which hashes), and the wrapped reputation saw exactly one `InvalidRestoration` report, against A.
- *Resume*: nodes built with `rpcDeadlines: { responseTimeoutMs: 500 }`. Node A holds a blob of 8 data pieces under one list piece (pieces cut by the builder's default size). A decorator over A's piece store counts `get` calls per id and holds the call for the fifth data piece on a promise the test controls. B's first session (`knownHolders: [A]`; C holds nothing) gets the list piece, then the first four data pieces, then stalls; the progress deadline ends the stream and `done` rejects with `BlobUnavailableError` (do not pin the reason). B's store holds the list piece and the first four data pieces. The test releases the held call and B starts a second session, which resolves. Every id was served by A once, except the held piece (twice: the stalled attempt and the retry). This pins that an interrupted fetch keeps what it stored and asks only for the rest. (Aborting B's signal would not interrupt anything: a batch already sent runs to its end.)

The helper that builds nodes and blobs is local to the spec file; `feat-blob-pieces-move-between-machines` may move it into a shared test helper if it needs the same shape.
