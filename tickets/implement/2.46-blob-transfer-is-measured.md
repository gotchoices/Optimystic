# Measure blob transfer and record it in docs/blobs.md

The last paragraph of docs/blobs.md §What this answers in GitHub #63 states an *expected* cost ("one hash and one store write per piece on the writer, the same on each receiver, and a wire size of the content plus a few kilobytes of list pieces per 45 MiB") and says the work that builds the transfer measures time per MB and bytes on the wire and states the result there. `feat-blob-pieces-move-between-machines` built that transfer (`node.blobs.read` fetching from other machines, and `NodeBlobService.wireBytes()`); this ticket takes the measurement.

## The bench

`packages/db-p2p/test/bench-blob-transfer.mjs`, run as `node test/bench-blob-transfer.mjs` from `packages/db-p2p` after `yarn build`, in the manner of `test/bench-findcluster.mjs` (imports `../dist/src/index.js`; a header comment with what it measures, how to run it, and the result once taken). It is not a mocha spec and runs in no script.

- Two nodes over loopback TCP, each `createLibp2pNode({ port: 0, networkName: 'bench-blob-transfer', bootstrapNodes: [], fretProfile: 'edge', clusterSize: 2, clusterPolicy: { allowDownsize: true, sizeTolerance: 1.0 }, arachnode: { enableRingZulu: false } })`, memory piece stores (the default). B dials A; wait until each lists the other in `keyNetwork.peersServing(<blob protocol id>, …)` and B's `keyNetwork.findCluster` for a blob routing key includes A. The blob protocol id is `buildBlobProtocol('/optimystic/bench-blob-transfer')`, exported from the package.
- For sizes 1 MiB, 3 MiB and 16 MiB of random bytes (1 MiB and multi-MiB are the GitHub #63 shapes; 3 MiB is the transaction that never committed over a relay): `A.blobs.put` the bytes, then on B time `for await (const _ of B.blobs.read(ref))` from first call to last chunk. Fresh random content each repetition, so B's piece store never already holds it. Repeat `N` times (default 5, `N` env var) and report the median.
- Per size report: milliseconds per MiB, and bytes on the wire per MiB of content from `B.blobs.wireBytes()` (sent plus received, the delta across the read). Print, once, that this counts blob-protocol frames (length prefixes, headers, pieces) and not noise or yamux framing, which the transport adds beneath every protocol alike.
- Stop both nodes at the end, also on failure.

## Recording the result

Run it. Replace the "expected cost" sentence at the end of docs/blobs.md §What this answers in GitHub #63 with the measured numbers (a small table per size: ms per MiB, wire bytes per MiB of content and the overhead above the content), the machine in one phrase (CPU, OS, Node version), the date and the command. Compare against the doc's figures for the base64-in-a-row path: the 1.7 s per MB GitHub #63 reported and the 0.2 to 0.3 s per MiB that path costs now (docs/blobs.md §Why), and its expansion of 2.75 to 4 times the size (the large-value table in docs/internals.md §A transaction's size limit). Say plainly that this is loopback with memory stores, so it measures the protocol and hashing, not a link or a disk. If the wire overhead is more than a few kilobytes per 45 MiB above the content, say so in the doc rather than rounding it away, and name what the extra bytes are if the counts make it evident (frame headers per `get`, list pieces).

Also put the measured figures and date in the bench's header comment, as `bench-findcluster.mjs` does.

## Edge cases & interactions

- **Cohort not yet formed.** The read only finds A through the cohort; the wait before measuring is what makes the first repetition valid. Inspection.
- **Warm-up.** The first repetition of the first size includes JIT warm-up; the median over `N` absorbs it. If it does not (the first is an outlier that moves the median at `N` = 5), discard one warm-up read before timing and say so in the header.
- **Logs.** Run without `DEBUG`, so logging does not distort timing.
