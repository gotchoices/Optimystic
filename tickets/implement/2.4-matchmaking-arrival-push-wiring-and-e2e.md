# Matchmaking arrival push — node wiring, end-to-end proof, docs

Last of five tickets (chain in `matchmaking-arrival-push-wire-and-selection`). Prereqs supply the db-core formats and selection, the cohort-side `ArrivalPushDriver` with the host's `onRecordAdded` hook, the seeker loop, and the seeker-side `ArrivalPushReceiver` plus real renew/withdraw.

## Node wiring (`libp2p-node-base.ts`, the `cohortTopic.enabled` block, beside the matchmaking query handler)

- Build one `ArrivalPushReceiver`. Register it on `matchmakingProtocols.arrivalPush` with `registerArrivalPushHandler`. Attach it to the node as `node.matchmakingArrivalPush` through `OptimysticNodeAttachments` (typed, no cast — see backlog `debt-node-attachment-reads-bypass-typed-surface` for why), so an application building `createLibp2pMatchmakingSeekerSession` can pass it as `arrivalPush`.
- Build one `ArrivalPushDriver`: `selfPeerId`, `slots = createSlotAssigner(createRingHash())`, `sign` over `nodePrivateKey` (the query handler's pattern), and `send` from the new `arrival-push-send.ts`. Subscribe it with `host.onRecordAdded(driver.onRecordAdded)`.
- Teardown, in the existing cohort-topic/matchmaking stop wrapper and registered next to the resources it releases (the post-start rollback depends on that order): unsubscribe from the host, `driver.stop()`. The protocol is already unhandled through `matchmakingProtocolList` once `arrivalPush` is in it.

## The libp2p `send` binding (`arrival-push-send.ts`)

`createArrivalPushSend({ node, selfPeerId, receiver, protocol, maxBytes, streamOpen, log })` returns the driver's `send(contactHint, frame)`:

1. Resolve the seeker's peer id from `contactHint`. The doc calls the format application-defined; accept the two forms this codebase produces: a peer-id string (the real transport's default, `selfPeerId`) and a multiaddr ending in `/p2p/<id>` (the mesh harness's form). Anything else → log, resolve `undefined` (dropped, no throw).
2. The resolved peer is this node → `receiver.receive(frame, selfPeerId)`, no dial. (The method is `receive`, not `handle`: `test/dial-options-single-site.spec.ts` flags any `.handle(` member call under `src/` as a raw libp2p handler registration.)
3. A multiaddr hint → merge it with `mergePeerAddresses` first. That is the single peerStore writer, and it already caps addresses per peer. The hint is attacker-supplied, but merging an address only allows a dial attempt, authenticated by peer id at the handshake: the same trust boundary as `ClusterRecord.peers` (see docs/internals.md §Third-Party Address Learning). This is how a relay-only seeker can be reached: it advertises its circuit address as its contact hint.
4. `requestResponse(node, peerId, protocol, frame, maxBytes, streamOpen)` with the node's `linkDeadlines` stream-open delays, as the cohort-topic host's dials use. A rejection → log, resolve `undefined`.

A seeker reachable only through a relay that advertises a bare peer id is not reachable from a member that holds no address for it. Its pushes fail and it falls back to the safety poll. That is the doc's stated degradation; note it in the doc's edge cases.

## Mock-mesh end-to-end (`matchmaking-mesh-harness.ts`)

- Give each harness member a driver (subscribed to its real `CohortTopicHost.onRecordAdded`) and a receiver. Its `send` routes in-process: resolve the hint's peer id to the harness member and call that member's `receiver.receive(frame, senderIdStr)`. No mock libp2p protocol is needed, the same way `queryCohort` is stubbed in-process today.
- The harness walk transport (`buildWalkTransport`) gains a `pushOnArrival` seek option: build the `MatchmakingSeeker` with it, subscribe to the seeker member's receiver, and expose `pushes`. The harness `renew` stays a touch-free no-op unless the test needs the record to outlive a TTL on the virtual clock.
- The driver's coalesce timer must run on the harness's virtual time. Inject `setTimer` so a test can advance past `coalesceMs` deterministically (the driver as built takes no `clock`; it needs none).

Mesh tests, in `mesh-walk.spec.ts` or a new `mesh-push.spec.ts`, each mapped to a doc bullet:

- *Fresh arrival pushes to longest waiters*, on real hosts and real gossip: a push-opted seeker hangs out at the root with fewer than `wantCount` providers; a new provider registers; after the gossip round and `coalesceMs` the seeker's walk returns it, having issued no query beyond the immediate one. Run the same scenario with the seeker on the poll path as a contrast assertion in the same test (it finds the provider through polls).
- *Only one member pushes per selected seeker* on a multi-member cohort: count `send` calls across members.

Keep it to these. The arithmetic and every per-rule case are pinned at the unit tier by the prereqs.

## Real-socket integration (`substrate-real-libp2p.integration.spec.ts`, env-gated)

One new case after the existing seeker-walk case: a remote push-opted seeker (its node's `matchmakingArrivalPush` passed to `createLibp2pMatchmakingSeekerSession`) walks a topic with fewer providers than it wants; a provider registers on another node mid-hang-out; the walk returns the provider before its first safety poll. This is the only place the libp2p `send` binding, the real renew (the seeker must survive past one 10 s TTL if the test runs that long — size patience so it does), and contact-hint resolution run over real sockets. It runs under `yarn test:integration`, not `yarn test`.

Bind `selfServe.renew` on the seeker's transport (to `resolveRenew(host.registry, r, Date.now())` from `cohort-topic/host.ts`), and `selfServe.register` / `selfServe.query` likewise if the case can land on a self-routed primary. In the mesh this spec builds, every node is in every cohort, so the seeker node can be its own registration's slot primary: running the existing seeker-walk case with `DEBUG=optimystic:db-p2p:matchmaking-query*` showed exactly that, logging "the slot primary is this node and no selfServe.renew is bound; skipped" for its close-time withdraw (the line now reads "the cohort member to send it to is this node and no selfServe.renew is bound; skipped", since a withdraw now goes first to the member that admitted the register). Without the binding every renew is skipped in that layout, and the record lapses after one TTL. (Found by `matchmaking-arrival-push-seeker-transport`.)

## Edge cases & interactions

- Node without `cohortTopic.enabled`: no receiver, no driver. A seeker transport built there without `arrivalPush` takes the poll path; with `pushOnArrival: true` and no receiver it throws at construction (prereq rule). Inspection.
- Contact hint that names neither form → push dropped, logged (inspection).
- Seeker is its own slot primary → in-process delivery (covered if the mesh test's seeker happens to be primary; otherwise inspection).
- Startup failure after the driver subscribes → the rollback unwinds it (wrapper registered next to the subscription; inspection against `test/startup-rollback.spec.ts`'s pattern).
- Pushes do not change `queriesPerMin` (inspection: the driver never calls `recordQuery`).
