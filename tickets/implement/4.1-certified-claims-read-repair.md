# Read-repair: verify proofs, certify claims, penalize only provable misbehavior

Second of three tickets from `accept-certified-claims-in-repair` (see
`certified-claim-selection` for the settled selection rules and the shared
`cluster/certified-claims.ts` helper this ticket consumes).

## CoordinatorRepo integration (`repo/coordinator-repo.ts`)

- `queryClusterForLatest` (:963): claims already carry `proof` (built at :1019 from
  `CertifiedActionRev` answers — that wiring landed with `serve-block-commit-proof`). After the
  claims array is built, verify every claim's proof in parallel via `certifyClaim` with
  `{ superMajorityThreshold: this.superMajorityThreshold, simpleMajorityThreshold: 0.5 }`
  (0.5 hardcoded per `ProofThresholds` doc — members enforce `count > total/2`), setting
  `claim.certified` on success. The comment block at :1015-1018 ("selectQuorumRev ignores it")
  must be rewritten — it becomes false here.
- **Penalize at verification time**, independent of selection outcome: a proof whose failure is
  attributable per `NON_ATTRIBUTABLE_PROOF_FAILURES` → `reportPeer(peerId,
  PenaltyReason.InvalidRestoration, 'read-repair:<blockId>')`, best-effort/never-throw like the
  existing sites. Non-attributable failures (unknown-signer, non-ed25519-signer,
  malformed-signature, legacy-record, malformed-proof, oversized cap) are NEVER penalized —
  mirrors `VerifyOutcome.penalize` (`cluster-repo.ts:63`): never penalize a peer whose identity
  wasn't proven. A failed-verification claim stays in the claim set UNCERTIFIED (it still
  corroborates by peer count, as today).
- `selectQuorumRev` now runs with certified flags. When it returns `undefined`, check
  `certifiedEquivocation(claims)` and log a distinct line (e.g.
  `cluster-fetch:certified-equivocation`) before the existing `no-quorum` handling; the
  existing decline path (uncorroboratedRev doubt, `reportRepairDeadlock`) runs unchanged either
  way. Note `reportRepairDeadlock`'s `sole-holder` message is now only reachable for a lone
  UNCERTIFIED holder (a certified lone holder converges before it) — its wording stays accurate;
  optionally add a sentence noting a cohort commit proof would lift the floor.
- Anchoring: `CoordinatorRepoComponents` gains optional `proofAnchoring?: ProofAnchoring`,
  threaded through `coordinatorRepo(...)` factory + constructor to `certifyClaim`. Production
  wiring leaves it absent (next ticket documents that at the composition root); the helper
  logs unanchored acceptance internally regardless.

## Penalty rework — `penalizeContradictingRevClaims` (:1221)

Folds `tickets/backlog/debt-read-repair-penalty-provable-only.md` (delete that file as part of
this ticket — its analysis is absorbed here):

- **Drop** the `rev > selected.rev` branch: a peer can honestly be ahead (in-flight commit
  landing on part of the cohort; the 1-second per-peer consult deadline dropping honest holders
  from the sample). Weight 30 vs deprioritize threshold 20 means one false hit deprioritized an
  honest, up-to-date peer.
- **Keep** the same-rev/different-actionId branch — two actions cannot both be the commit at one
  revision (works for both certified and corroborated `selected`).
- The "genuinely provable" additions (bad-proof service, digest-contradicting content) land via
  the verification-time penalties above and the reconcile ticket — don't duplicate them here.
- Rewrite the method's NOTE (:1213-1219): the honest-leader hazard it describes is what this
  change removes.
- Optionally refresh `PenaltyReason.InvalidRestoration`'s doc comment (`reputation/types.ts:23`)
  to name proof-service misbehavior.
