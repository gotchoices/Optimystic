Part 2 of stage 6 of [docs/offline-sync.md §Implementation stages](../../docs/offline-sync.md#implementation-stages): the hard form of the gate, under the maintainer decision of 2026-10-25 recorded in [§When to submit: the reachability gate](../../docs/offline-sync.md#when-to-submit-the-reachability-gate). The gate (`offline-sync-reachability-gate`) is a heuristic — the routing view can change between its check and the commit — so the coordinator itself must refuse the lone write.

## What exists

`CoordinatorRepo` (`packages/db-p2p/src/repo/coordinator-repo.ts`) short-circuits a cohort of at most one peer: `pendSolo` applies the pends locally, `commitSolo` mints a one-peer proof and commits locally, and both answer with `soloCohortDurability` — `local` naming `absentCohortMembers` as `unconfirmed`, or `unrouted`. `commitSolo` already logs `knownAbsent` and `awaitingBootstrap`. Nothing refuses.

## Design

### The option and where it travels

- `SyncOptions.refuseSoloCommit?: boolean` (`packages/db-core/src/collection/struct.ts`). Documented as: refuse to let the write be committed by a lone node that knows of absent cohort members, awaits a bootstrap peer, or could not route the write; a genuinely alone node still commits. Default off; only the offline queue sets it.
- On the wire: `PendRequest.refuseSolo?: true` and `CommitRequest.refuseSolo?: true` (`packages/db-core/src/network/struct.ts`). **Omitted, never `false`**, for the preimage reason `baseRevs` and `soleReservation` give: requests are hashed verbatim into cohort signatures, and a write that does not set it must serialize exactly as before. A coordinator on an older build ignores it; no version gate (the gate is then the only protection — say so in the field's comment).
- `Collection`: the flag is a property of the write's attempt cycle, like the in-flight action id, so every send of the cycle carries it — `syncAttempts`' sends, the head commit's `HeadCommitHandle.send`, **and** the re-send a refresh makes to finish a torn attempt (`Collection.completeOwnEntry`, the `source.transact` call there). Record it beside the in-flight mark (`beginInFlightAction(actionId, { refuseSolo })`, cleared by the same disposer) rather than threading it through every refresh signature; `HeadCommitOptions` extends `SyncOptions`, so `commitHead` gets it for free.
- `TransactorSource.transact` is at eight positional parameters; convert its trailing optionals (`priority`, `blockDigests`, `baseRevs`) and the new flag into one `TransactOptions` bag. Two `src` callers and three test files.
- `TransactionCoordinator`: `WriteContext` (`packages/db-core/src/transaction/entry-commit.ts`) gains `refuseSolo?: true`, set from the `SyncOptions` the coordinator path was given (`commitEntry`'s `submit`, and `commit`/`execute` for uniformity); the pend and commit request builders in `coordinator.ts` (the one at the `soleReservation` spread, and the commit request beside it) spread it in.
- `NetworkTransactor`: every place that rebuilds a request per coordinator batch must keep the field — `pend`'s per-batch requests, `pendMany`, `commitInOneRound`, `commitTailThenSweep`, `commitBlock` (positional; add it), `commitMany`. A miss here silently drops the protection for that path, so read each builder.

### The refusal

In `CoordinatorRepo`, one helper decides, from the cohort resolution and the first block (the block `soloCohortDurability` already uses), whether a solo write carrying the flag is refused:

- cohort not resolved, or resolved to one peer that is not this node (`unrouted`) → refuse (`unrouted`);
- resolved to this node → refuse when `absentCohortMembers` (minus self) is non-empty (`absent-members`) or `awaitingBootstrapContact()` (`awaiting-bootstrap`);
- otherwise not refused: the node is genuinely alone and commits at `local` as today.

`pendSolo` (and so `pendMany`'s solo branch) refuses when any request of the batch carries `refuseSolo`, **before `applyPendsInOrder`** — nothing is reserved. The answer is a **`ShortfallFailure`**, built through `PromiseShortfallError(...).toFailure()`, so it rides the path every promise shortfall already takes: returned rather than thrown (`CoordinatorRepo.pend` returns a shortfall ahead of the stale classifier), rebuilt as the aggregate by `NetworkTransactor`'s `refusalFrom`, stopped on by name in `write-attempts.ts` and `TransactionCoordinator`'s pend phase, and sorted `cohort-unreachable` by `classifyCommitFailure` — so the queue waits for the cohort and nothing new is needed downstream. The shortfall describes the cohort this node expected: `approvals: 1`, `rejections: 0`, `silentPeers` = the absent members, `peerCount = 1 + silentPeers.length`, `needed = max(2, ceil(superMajorityThreshold × peerCount))`. Add one optional field to `PromiseShortfall`, `soloRefused?: 'absent-members' | 'awaiting-bootstrap' | 'unrouted'`, set only on this path, so a log or an application can tell "refused to write alone" from "a consensus round heard too few"; the error's message stays the class's fixed sentence (a downstream repository matches it). Log `pend:solo-refused` with the reason, `knownAbsent`, short `absentPeers`, `awaitingBootstrap`.

`commitSolo` refuses on the same rule when any request carries `refuseSolo`, before the proof is minted or anything applied. A commit cannot return a shortfall (it is "a pend answer only"; the commit side reads a returned refusal as a confirmed conflict), so it returns a conflict-shaped `StaleFailure` with a new reason constant (`SOLO_COMMIT_REFUSED_REASON`, exported beside `COMMIT_NOT_DURABLE_REASON`), and logs `commit:solo-refused`. This arm is reached when the pend ran on a real cohort and the partner dropped before the commit re-resolved a solo cohort: the writer cancels and retries, the retry's pend meets the pend-side refusal, and the write stops as `cohort-unreachable`. Nothing of the write was stored by this node's commit.

### The queue

`OfflineQueueOptions.allowSoloCommit?: boolean` (`packages/db-core/src/offline/queue.ts`). Unless it is `true`, `OfflineQueue.send` adds `refuseSoloCommit: true` to the `SyncOptions` it hands `commitHead` and `commitEntry`. Nothing else in the tree sets the option: writes outside offline mode keep today's solo short-circuit (backlog `6.5-partition-healing` is unchanged). The plugin's `offline.allowSoloCommit` registration key is ticket `offline-sync-cohort-reachability`.

## Edge cases & interactions

- **Genuinely alone** (no absent member, nothing awaited, routed to self) → commits `local` with empty `unconfirmed`, exactly as today. Mesh test (one-node or unpartitioned case is already covered by existing solo specs; assert in the new spec that the `allowSoloCommit` arm and the alone arm both commit).
- **Absent member known** → pend refused, nothing pended locally, entry stays queued `waitingFor: 'cohort'`. Mesh test.
- **Awaiting bootstrap** / **unrouted** → refused. By inspection of the one helper (all three reasons go through it); the absent-member case exercises the path end to end.
- **Pend on a real cohort, commit solo** → conflict-shaped commit refusal, cancel, retry, pend-side refusal. A unit test at `CoordinatorRepo` level if its spec has a solo-cohort fixture that can be given an absent member (commit with `refuseSolo` → `success: false`, `reason === SOLO_COMMIT_REFUSED_REASON`, nothing committed); otherwise by inspection.
- **Multi-collection entry** (`commitEntry`, `pendMany` / `commitMany`) → the field is on every request; any request carrying it refuses the batch. If one collection's commit landed on a real cohort and another's meets the commit-side refusal, the coordinator's existing partial-commit arm applies and the queue finishes the remainder (`OfflineQueue.partiallyCommitted`). By inspection.
- **Torn attempt re-sent by a refresh** (`completeOwnEntry`) → carries the flag from the cycle state. By inspection; name it in the field's comment.
- **In-doubt stickiness** → the queue marks an entry in doubt when its drive record is written, before the send; a refused pend leaves it in doubt (as any shortfall does), so `discard` is refused until a terminal outcome. Existing behaviour, unchanged; note it in docs/offline-sync.md §Classifying an attempt's outcome if that section does not already say a shortfall after a send keeps doubt.
- **Remote coordinator** → the field travels on the repo protocol as plain JSON, so a coordinator whose own view is solo refuses on the writer's behalf. By inspection of `RepoService` / `RepoClient` (verbatim JSON).
- **Mixed versions** → an older coordinator ignores the field and commits `local`; the gate is the only protection. By inspection; stated in the field comment and the doc.
- **Preimage stability** → unset means absent from every request, so every existing signature and every stored record is byte-identical. By inspection (grep each spread for `...(x ? { refuseSolo: true } : {})`).
- **Identify in flight** → not part of this rule (the ticket's stated rule is absent members or an awaited bootstrap peer); the gate covers that window. NOTE at the helper: if a lone commit is ever traced to a write made while identify was in flight, add the gate's `identifying` arm here too (needs `IdentifyProgress` in reach of `CoordinatorRepo`, whose constructor is at seventeen positional parameters — add it to an options object, not positionally).

## Tests

Extend `packages/db-p2p/test/offline-queue-mesh.spec.ts` (two-member mesh, an `OfflineQueue` over one collection, the gate left at `alwaysReachable` so only the refusal stands between the drain and a lone commit):

- Partner cut off — `failures.partitionSides` so node A's view is self-only and (with `offline-sync-reachability-gate`) names B absent, plus whatever transport cut keeps A's transactor from coordinating through B (`failingPeers` / a `wrapRepo` failure, as the harness allows) — an enqueued entry is never `committed`; it reports `queued` with `waitingFor: 'cohort'` after its attempt, and neither node holds a committed revision of the collection's header. Heal: it drains, `committed`, both nodes read it.
- Same cut, queue built with `allowSoloCommit: true`: the entry commits, its durability is `local` with B in `unconfirmed`.
