# Acting on the signed validity marker for disputes

## Why

Block-then-escalate (`docs/right-is-right.md` §Design of Record) blocks a transaction when any cohort member rejects it *on validity*, and ejects whichever side a ruling goes against. The marker itself — a signed, structured `validity` field on reject votes, set only for the five `TransactionValidator` refusals the design of record classes as validity — moved to the implement ticket `signed-validity-marker-on-reject-votes`, because the offline-sync writer classification needed it first. What remains here is the dispute side of it. Later tickets (`dispute-commit-path-block`, `dispute-post-commit-challenge`) act on the marked evidence.

## Shape

- **Engine health.** A member whose own engine is flagged unhealthy (`EngineHealthMonitor.isUnhealthy`) signs its validity refusals *without* the marker, so they count as ordinary rejections and cannot block another writer. `ClusterMember` takes an optional `isEngineHealthy` hook; absent means healthy. (The monitor lives in `DisputeService`; wiring the hook at the composition root is part of this ticket only if the service is already constructed there — otherwise leave the hook unsupplied and say so in the handoff.) Note the side effect on writers: an unmarked refusal is no longer typed as a permanent rejection at the writer (`offline-sync-typed-validity-rejection`), so it is retried instead — the intended direction for a member that cannot trust its own engine.
- `ClusterCoordinator.executeTransaction`'s dispute-marking branch builds `disputeEvidence` from **marked** rejects only, which resolves the existing NOTE about expiry votes landing there. Counting (`rejectionCount`, thresholds, `ValidatorRejectionError`) is unchanged: a marked reject is still a reject.

## Edge cases & interactions

- **A record with only unmarked minority rejects** is no longer flagged `disputed`; say in the handoff whether anything reads `disputed` for such records today.
- **Engine-health flips mid-record**: a member signs once per record, so the marker reflects its health at signing time. By inspection.

## Tests

- One test that an unhealthy engine's validity refusal is signed unmarked.
- One test that `disputeEvidence` excludes an unmarked reject beside a marked one.
