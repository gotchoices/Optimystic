# Blob pieces in the browser's IndexedDB database

`feat-a-node-stores-blob-pieces` defines `IPieceStore` (in `packages/db-p2p/src/blob/`), the store for the immutable pieces a blob is cut into (docs/blobs.md §The local store), with an in-memory and a filesystem implementation and a conformance suite every implementation runs. This ticket adds `IndexedDBPieceStore` to `@optimystic/db-p2p-storage-web`: a `pieces` object store in the database `openOptimysticWebDb` opens, sharing the handle with `IndexedDBRawStorage`, `IndexedDBKVStore` and the identity helper. It is not a `RawStoreDriver` store and does not go through the journal: each piece is raw bytes in its own transaction.

The interface, as the prerequisite defines it (`PieceId` from `@optimystic/db-core`, `IPieceStore` from `@optimystic/db-p2p`):

```ts
interface IPieceStore {
	has(id: PieceId): Promise<boolean>;
	get(id: PieceId): Promise<Uint8Array | undefined>;
	put(id: PieceId, bytes: Uint8Array): Promise<void>;   // caller has verified the bytes; a put of a present id writes nothing
	delete(id: PieceId): Promise<void>;
	list(): AsyncIterable<PieceId>;
	bytesUsed(): Promise<number>;
	flush(): Promise<void>;
	readonly durability: StoreDurability;
	close?(): Promise<void>;
}
```

## Schema and version 4

In `packages/db-p2p-storage-web/src/db.ts`:

- `OptimysticWebDB` gains `pieces: { key: PieceId; value: Uint8Array }`, with a bullet in the schema comment: piece bytes keyed by the piece's id string, stored by structured clone, written and read only by `IndexedDBPieceStore`.
- `DEFAULT_DB_VERSION` goes from 3 to 4, and the comment above it adds "and to 4 for `pieces`".
- The `upgrade` hook adds `if (!db.objectStoreNames.contains('pieces')) db.createObjectStore('pieces');` beside the others, so a version 1, 2 or 3 database gains only what it lacks and keeps every record. Out-of-line keys (the key passed to `put`), like every other store here.

A version 4 database cannot be opened by a build that asks for version 3: the browser refuses the open with a `VersionError`. That is a downgrade, outside the guarantee that an older build's data opens on a newer build; the README says so. Another tab still holding a version 3 connection makes this tab's open wait for it; that case, and the test that an existing database survives the bump, belong to `debt-indexeddb-version-upgrade-is-untested-and-unhandled`, which this ticket updates (below) rather than duplicates.

## `IndexedDBPieceStore`

New module `packages/db-p2p-storage-web/src/indexeddb-piece-store.ts`, exported through `src/index.ts`'s `export *`.

```ts
export type IndexedDBPieceStoreOptions = IndexedDBDurabilityOptions;

export class IndexedDBPieceStore implements IPieceStore {
	/** `'power-loss'` where puts are strict transactions, else `'process-crash'`; fixed at construction. */
	readonly durability: StoreDurability;
	constructor(db: OptimysticWebDBHandle, options?: IndexedDBPieceStoreOptions);
	/** The identity `IndexedDBJournalStore` reports over this handle: `identityForHandle('idb-handle', db)`. */
	storeIdentity(): StoreIdentity;
	has(id: PieceId): Promise<boolean>;
	get(id: PieceId): Promise<Uint8Array | undefined>;
	put(id: PieceId, bytes: Uint8Array): Promise<void>;
	delete(id: PieceId): Promise<void>;
	list(): AsyncIterable<PieceId>;
	bytesUsed(): Promise<number>;
	flush(): Promise<void>;
}
```

- **`put` is one transaction per piece, strict where the browser honours it.** `strict = resolveStrictDurability(options)` from `durability.ts`, as the other stores take it. The body:

```ts
const tx = this.db.transaction('pieces', 'readwrite', { durability: transactionDurability(this.strict) });
const write = async (): Promise<void> => {
	if (await tx.store.getKey(id) === undefined) await tx.store.put(wholeBufferBytes(bytes), id);
};
await Promise.all([write(), tx.done]);
```

The presence check and the write share one transaction, so a present id writes nothing; `Promise.all` observes `tx.done`, so a failed request is never an unobserved rejection. One transaction per piece, not one across a blob, so a long stream never holds a transaction open (IndexedDB commits an idle transaction, and the builder awaits its source between pieces). A strict transaction completes only once the browser has put it on the disk, so a put that has resolved is durable and **`flush()` resolves at once**: there is nothing held to sync. That is what the block store's flush gives in the same browser, no more. Rejected: relaxed puts with a strict flush, because IndexedDB promises nothing about which relaxed transactions survive a power cut, so a later strict transaction would not cover them (the reason `IndexedDBJournalStore` journals); and holding puts in memory until flush, which would keep a whole blob in memory.
- **`wholeBufferBytes`.** Structured clone of a typed array stores its whole `ArrayBuffer`, so a piece handed as a view into a larger buffer would store the larger buffer and read back as a view into it. A private function returns `bytes` when `byteOffset === 0 && byteLength === buffer.byteLength`, otherwise `bytes.slice()`.
- **`has`** is `(await this.db.getKey('pieces', id)) !== undefined`, which reads no value. **`get`** is `this.db.get('pieces', id)`; structured clone returns a fresh array, so a caller changing it changes nothing stored. **`delete`** is `this.db.delete('pieces', id)` at the browser's default durability: a lost delete leaves an orphan piece the next sweep removes, which is not worth a disk sync per deleted piece.
- **`list`** pages: `getAllKeys('pieces', range, PIECE_LIST_PAGE)` with `PIECE_LIST_PAGE = 1000`, the first range unbounded and each later one `IDBKeyRange.lowerBound(last, true)`, each page an already-materialized array read under its own implicit transaction, so no cursor is held across the consumer's awaits (the same rule `listBlockIds` keeps) and no page loads every id at once.
- **`bytesUsed`** opens one readonly transaction and walks `openCursor` over `pieces`, summing each value's `byteLength`. It reads every stored byte. That is acceptable because the block store's figure (`navigator.storage.estimate()`, which covers the whole origin and so these pieces) is what the node uses whenever the piece store shares the block store's database, which is the configuration the README documents; the walk runs only for a piece store a host put in another database. Leave a `NOTE:` saying so, with the remedy if it ever shows in a profile: keep each piece's size under a second key range and sum that instead. A failure is logged under `createLogger('storage:pieces')` (namespace `optimystic:db-p2p-storage-web:storage:pieces`) and answers 0, as `approximateBytesUsed` does.
- **`storeIdentity`.** `feat-a-node-stores-blob-pieces` decides whether to add a piece store's bytes to the node's storage figure ("counted once", docs/blobs.md §The local store). The expected form of that rule is equality of store identities, so this returns the identity the block store computes over the same handle. If the prerequisite states the rule through another member, implement that member with this meaning instead, and drop `storeIdentity`.
- **No `close`.** The handle is shared; the host closes it after the node has stopped, as for the other stores here. The store holds nothing to release.

## Edge cases & interactions

- **An existing version 1, 2 or 3 database.** Opens at 4 with an empty `pieces` store and every other record intact, by the `objectStoreNames.contains` guards. Test owned by the debt ticket; this ticket adds version 4 to that ticket's arms.
- **This database opened by an older build.** Refused by the browser (version 4 over a request for 3). Downgrade, stated in the README; not handled.
- **Another tab on version 3.** The open waits; owned by the debt ticket.
- **A browser that ignores `durability`.** Every put is relaxed, `durability` reports `'process-crash'`, and flush still resolves at once; the node reads `durability` to know what it got. Inspection.
- **Two puts of one id at once.** IndexedDB runs two `readwrite` transactions over one store one after the other, so the second sees the key and writes nothing. Inspection.
- **A view into a larger buffer.** Stored at its own length. Test (below).
- **A 1 MiB piece.** Round-trips through the conformance suite's large case under `fake-indexeddb`; browsers impose no per-value limit near that size.
- **Quota.** A put past the origin's quota rejects with the browser's `QuotaExceededError`, the transaction aborts, and nothing is stored; the blob service's `put` fails with it. No handling beyond letting it propagate.
- **Crash between a put and the blob's record.** The piece is stored, the record is not; the sweep removes the orphan. Inherited.
- **Block-store listing.** `listBlockIds` reads `metadata` keys only, so pieces never appear as blocks. Inspection.

## Tests

- `packages/db-p2p-storage-web/test/indexeddb-piece-store.spec.ts`, importing `fake-indexeddb/auto` first, as the other specs do:
  - The shared suite from `feat-a-node-stores-blob-pieces` (expected as `runPieceStoreConformance` from `@optimystic/db-p2p/testing/conformance`; use whatever name and harness shape it exports), registered persistent, with a harness built like the `'IndexedDB'` one in `test/indexeddb-storage.spec.ts`: a fresh database name per case through `openOptimysticWebDb`, the store built with `{ strictDurability: true }` (fake-indexeddb honours the option without advertising it; see `supportsStrictDurability`), `reopen` closing the handle and opening the same name, `cleanup` closing it.
  - One case: a piece put as a 1 KiB view into a 1 MiB buffer reads back with `byteLength` 1024 over a buffer of 1024 bytes, and `bytesUsed` reports 1024. It pins `wholeBufferBytes`, which no shared case covers and whose absence wastes the difference silently.
