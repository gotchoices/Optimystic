# Blob references and the piece-tree builder

docs/blobs.md is the design of record for native large-value ("blob") support (GitHub #63). This ticket is the first half of its foundation in `packages/db-core`: the format of a blob reference and of a piece id, the hashing port, the code that turns a byte stream into pieces and a reference with exactly the bytes `ipfs add --cid-version 1` writes, the service and error types every later blob ticket implements, and the blob routing key. The second half, `feat-blob-references-and-verified-piece-trees`, adds the reader that checks pieces received from elsewhere. All of it is pure logic with no network or disk access.

New code lives in `packages/db-core/src/blob/`. Modules inside that directory import each other by file, never through `blob/index.ts` (internals.md §Common Pitfalls 6, enforced by `test/barrel-import-cycle.spec.ts`). `blob/index.ts` re-exports every module listed below, and `packages/db-core/src/index.ts` gains `export * from "./blob/index.js";`.

## References and piece ids (`blob/blob-ref.ts`)

```ts
import type { CID } from 'multiformats/cid';

declare const blobRefBrand: unique symbol;
declare const pieceIdBrand: unique symbol;
/** A blob's reference: the CID of its root piece, CIDv1, sha2-256, codec raw or dag-pb, lowercase base32. One spelling per blob, so references compare as strings. */
export type BlobRef = string & { readonly [blobRefBrand]: true };
/** A piece's CID in the same canonical spelling. The key in every piece store and on the wire. */
export type PieceId = string & { readonly [pieceIdBrand]: true };

export const RAW_CODEC = 0x55;
export const DAG_PB_CODEC = 0x70;
export const SHA2_256_CODE = 0x12;

/** Throws BlobRefError unless `text` is a canonical reference. */
export function parseBlobRef(text: string): BlobRef;
export function isBlobRef(text: unknown): text is BlobRef;
/** Same rule as parseBlobRef; throws BlobRefError. */
export function parsePieceId(text: string): PieceId;
/** The root piece of a blob: the same string. */
export function rootPieceId(ref: BlobRef): PieceId;
/** The canonical piece id of a CID that has already passed `isPieceCid`; version 0 is re-spelt as version 1. */
export function pieceIdOfCid(cid: CID): PieceId;
/** Codec raw or dag-pb, multihash sha2-256 with a 32-byte digest. Version not checked (a link inside a list piece may be CIDv0). */
export function isPieceCid(cid: CID): boolean;
/** Decode an already-branded id back to a CID (never throws for a branded value). */
export function cidOfPiece(id: PieceId): CID;
```

The parse rule, in order: `typeof text === 'string'` and `text.length <= 128` (a canonical reference is 59 characters; the cap keeps a hostile megabyte string out of the decoder); first character `b`; `CID.parse(text, base32)` from `multiformats/cid` and `multiformats/bases/base32` succeeds; `cid.version === 1`; `isPieceCid(cid)`; `cid.toString(base32) === text`. The last rule rejects every alternative spelling (uppercase base32 decodes under a different prefix and fails the first rule; padding or trailing characters fail the round trip). Any throw from `CID.parse` is caught and rethrown as `BlobRefError` with the decoder's message as `detail`. `pieceIdOfCid` returns `cid.toV1().toString(base32)`, which keeps the multihash and codec and so names the same bytes.

## Errors (`blob/errors.ts`)

```ts
export class BlobRefError extends Error {
	constructor(readonly text: string, readonly detail: string);   // message quotes at most the first 80 characters of text
}

export type BlobUnavailableReason = 'not-here' | 'not-held' | 'peers-unreachable' | 'cohort-unreachable';
export class BlobUnavailableError extends Error {
	constructor(readonly ref: BlobRef, readonly reason: BlobUnavailableReason, readonly pieceId?: PieceId);
}

export type BlobCorruptReason =
	| 'digest-mismatch'      // bytes do not hash to the CID that named them
	| 'piece-too-large'      // a piece, or a declared leaf size, above MAX_BLOB_PIECE_BYTES
	| 'unsupported-codec'    // a link to a codec other than raw or dag-pb
	| 'unsupported-hash'     // a link whose multihash is not sha2-256 with 32 bytes
	| 'malformed-encoding'   // dag-pb or UnixFS bytes that do not decode
	| 'not-a-file-node'      // a dag-pb piece with no UnixFS Data, or a UnixFS type other than file
	| 'list-carries-data'    // a UnixFS file node with bytes of its own
	| 'no-links'             // a list piece with no children
	| 'too-many-links'       // above MAX_BLOB_LIST_LINKS
	| 'too-deep'             // a list piece below MAX_BLOB_LIST_DEPTH list levels
	| 'empty-child'          // a declared child size of zero
	| 'size-mismatch'        // block sizes and links disagree in count, child sizes do not add up to what the parent declared, or a leaf's length differs from its declared size
	| 'size-too-large';      // a total above Number.MAX_SAFE_INTEGER
export class BlobCorruptError extends Error {
	constructor(readonly reason: BlobCorruptReason, readonly pieceId: PieceId, readonly ref?: BlobRef, detail?: string);
}

export class BlobDigestError extends Error {
	constructor(detail: string);
}
```

`BlobUnavailableReason` mirrors `BlockUnavailableReason` in `packages/db-core/src/network/struct.ts`; the meanings are docs/blobs.md §The node's blob service. `BlobCorruptError.ref` is optional because `checkPiece` (next ticket) checks one piece without knowing which blob asked. Each class sets `this.name`, as `BlockUnavailableError` does.

## Limits (`blob/limits.ts`)

```ts
/** Leaf size the builder writes (256 KiB). */
export const BLOB_PIECE_BYTES = 262_144;
/** Children per list piece the builder writes (kubo's balanced layout). */
export const BLOB_LIST_LINKS = 174;
/** Largest piece a reader accepts, from any tool. */
export const MAX_BLOB_PIECE_BYTES = 1_048_576;
/** Most children a reader follows in one list piece. 1024 is the default of the JavaScript IPFS importer (Helia), so blobs it made with defaults are readable; a 1 MiB piece could hold about 20,000 links, so this limit, not the piece size, is the one that binds. */
export const MAX_BLOB_LIST_LINKS = 1024;

export const MAX_BLOB_LIST_DEPTH = 8;
```

## Hashing (`blob/digest.ts`)

```ts
/** SHA-256: bytes in, 32 bytes out. */
export type BlobDigest = (bytes: Uint8Array) => Promise<Uint8Array>;
/** crypto.subtle where it exists, else @noble/hashes. Memoized: the same function on every call. */
export function defaultBlobDigest(): BlobDigest;
/** Runs the known answers; resolves to `digest` itself, or rejects with BlobDigestError naming the first wrong answer. */
export function checkBlobDigest(digest: BlobDigest): Promise<BlobDigest>;
/** Exported from this module for tests only (not from blob/index.ts). */
export function selectBlobDigest(subtle: SubtleDigest | undefined): BlobDigest;
interface SubtleDigest { digest(algorithm: 'SHA-256', data: Uint8Array): Promise<ArrayBuffer> }
```

- **The choice.** `defaultBlobDigest` reads `(globalThis as { crypto?: { subtle?: SubtleDigest } }).crypto?.subtle` once and passes it to `selectBlobDigest`. With `subtle`: `async bytes => new Uint8Array(await subtle.digest('SHA-256', bytes))`. Without: `async bytes => sha256(bytes)` from `@noble/hashes/sha2.js` (already a db-core dependency, used by `cohort-topic/ring-hash.ts`), and one log line on `createLogger('blob')` (namespace `optimystic:db-core:blob`): `blob:digest-fallback` saying no native SHA-256 was found and the JavaScript one is in use. It is the line that explains a slow phone (docs/blobs.md measured 19 s per MB).
- **Rejected: `multiformats/hashes/sha2`.** Its browser build, which Metro resolves for React Native, calls `crypto.subtle.digest` with no check, so on Hermes, which has no `crypto.subtle`, every hash would throw. Its Node build uses `node:crypto`, which `crypto.subtle` already covers on every supported Node.
- **Known answers** (FIPS 180-2 examples, hex): empty input → `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`; `abc` → `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`; `abcdbcdecdefdefgefghfghighijhijkijkljklmnomnopnopq` (56 bytes, two compression blocks) → `248d6a61d20638b8e5c026930c3e6039a33ce45964ff2167f6ecedd419db06c1`. The check rejects a result that is not a `Uint8Array`, is not 32 bytes long, differs from the answer, or a digest that throws (wrapped, with the cause). It is the host's job to call it at installation (`NodeOptions.blobs.digest` in db-p2p, a later ticket); the default is not re-checked at run time.

## Pieces in and out (`blob/pieces.ts`)

```ts
export interface PieceSink { put(id: PieceId, bytes: Uint8Array): Promise<void> }
export interface PieceSource {
	get(id: PieceId): Promise<Uint8Array | undefined>;
	/** Optional: lets a tree walk learn whether a data piece is here without reading it. */
	has?(id: PieceId): Promise<boolean>;
	/** True only when every piece `get` returns has already been checked against its id, as a piece store's are (it admits only checked pieces). The reader then skips hashing; it still decodes and bounds every list piece. A source that returns bytes from another machine unchecked must leave this unset. */
	readonly verified?: boolean;
}
```

`has` and `verified` are optional additions to the shared shape; an `IPieceStore` (db-p2p) satisfies both interfaces structurally. Content is hashed once when written and once when received (docs/blobs.md §Design principles); `verified` is what keeps a local read from hashing a third time.

## List pieces (`blob/list-piece.ts`)

```ts
export interface ListChild { readonly cid: CID; readonly fileBytes: number; readonly treeBytes: number }
/** dag-pb bytes of a UnixFS file node over `children`, in order. */
export function encodeListPiece(children: readonly ListChild[]): Uint8Array;
```

Encoding, exactly as kubo writes it: `dagPb.encode({ Data: new UnixFS({ type: 'file', blockSizes: children.map(c => BigInt(c.fileBytes)) }).marshal(), Links: children.map(c => ({ Hash: c.cid, Name: '', Tsize: c.treeBytes })) })`. Three details are load-bearing and the vectors prove them: `Name` is present and empty (an absent name encodes differently); `Tsize` is the child's cumulative size — for a raw leaf its byte length, for a list piece its own encoded length plus the sum of its links' `Tsize`; `marshal` writes `filesize` as the sum of `blockSizes` and omits mode and mtime. The reader's decode half is added by `feat-blob-references-and-verified-piece-trees` in the same file.

## The builder (`blob/builder.ts`)

```ts
export interface BuildBlobOptions { digest?: BlobDigest; signal?: AbortSignal }
export function buildBlob(source: AsyncIterable<Uint8Array>, sink: PieceSink, options?: BuildBlobOptions): Promise<BlobPutResult>;
```

- **Leaves.** Copy source bytes into a fresh `Uint8Array(BLOB_PIECE_BYTES)`; when it is full, hash it, `await sink.put(id, piece)`, and start a new buffer. A fresh buffer per piece because a sink may keep the array it was given (a memory store does). Source chunks of any length are accepted, empty ones included; the builder never keeps a reference to a source chunk. At the end, a non-empty partial buffer is emitted as `subarray(0, filled)` copied to its own array; if no leaf was emitted at all (empty source), one zero-length leaf is emitted. A leaf's CID is `CID.createV1(RAW_CODEC, Digest.create(SHA2_256_CODE, await digest(bytes)))` (`multiformats/hashes/digest`).
- **Levels.** `levels: ListChild[][]`, level 0 holding leaf links. Appending to level k: push the child; when level k holds `BLOB_LIST_LINKS` children, encode them as a list piece, hash it, `await sink.put`, clear level k and append the list piece's link to level k+1 (its `fileBytes` the sum of the children's, its `treeBytes` its encoded length plus the children's `treeBytes`). At the end, for k from 0 upwards: if level k is the highest non-empty level and holds exactly one child, that child is the root; otherwise, if level k is non-empty, flush it the same way (whatever its count) into level k+1. A blob of exactly one leaf therefore has that leaf's raw CID as its reference, and a trailing group of one is wrapped in its own list piece, which is what kubo's balanced builder and the JavaScript importer both do. Memory held: one leaf buffer plus at most 173 child links per level.
- **Order.** Every piece is put after all the pieces it names, so a caller can store pieces as they arrive. Puts are sequential: the next piece is not started until the previous `put` resolves, which is the back-pressure.
- **Result.** `{ ref: parseBlobRef(rootCid.toString(base32)), size }` with `size` the total byte count (a JavaScript number; 2^53 bytes is not reachable by a stream in practice, by inspection).
- **Failure.** A source that throws, or a `sink.put` that rejects, propagates and no reference is returned. `signal` is checked with `signal.throwIfAborted()` before each source chunk is consumed and before each `put`. Pieces already put stay in the sink; protecting and later sweeping them is the caller's business (`feat-a-node-stores-blob-pieces`).
- **Digest.** `options.digest ?? defaultBlobDigest()`. The builder does not call `checkBlobDigest`; a host's digest is checked when installed.

## Edge cases & interactions

- Empty source, a source of exactly 262,144 bytes, and 262,145 bytes: the raw-leaf / list-piece boundary. Vectors.
- Exactly 174 leaves (one list piece) and 175 leaves plus a byte (two levels, the trailing group of one wrapped). Vectors.
- Source chunk sizes do not change the result: empty chunks, one-byte chunks, chunks spanning several pieces. Test.
- Three levels (more than 174 × 174 leaves, about 7.4 GiB) is not vector-tested; the level logic is the same code at every level, by inspection.
- Source throws, sink rejects, or signal aborts part way: rethrown, no reference. Inspection.
- A wrong or wrong-length host digest: refused by `checkBlobDigest`. Test.
- Hermes without `crypto.subtle`: falls back and logs once. `selectBlobDigest(undefined)` is tested against the known answers; the Metro bundle is proved by `yarn check:rn`.
- Hostile reference strings (huge, non-string, other multibases, CIDv0, other hashes, truncated, other codecs, non-canonical): `BlobRefError`. Test.
- `db-core` stays free of libp2p and FRET: the two new packages import neither. `test/no-fret-import.spec.ts` stays green.
- `isBlobRef` on a `PieceId` of a raw or dag-pb piece answers true, since any piece can be a root. Intended; by inspection.
