# A blob's owed copies are drained

docs/blobs.md §Placement, copying and durability, "Copying" and "Durability". `announce(ref, scope)` makes this node owe the blob to its cohort until every member that accepts blobs holds it. This ticket builds the durable owed entry, the drain that announces to owed members (on the shared `DrainScheduler`), the durability classes and their events, `stat`'s durability field, and the `held` path into the entry. With it, a committed reference survives the writer going offline once the cohort holds it. The reaction to cohort changes for blobs already held is the next ticket, `feat-a-referenced-blob-is-copied-to-its-cohort`.

## The owed ledger

`OwedBlobLedger` in `packages/db-p2p/src/blob/owed-blob-ledger.ts`, over the node's `IKVStore`.

```ts
/** Key namespace: `owed-blobs/<ref>` → JSON(OwedBlobEntry). Added to `NODE_KV_NAMESPACES`. */
export const OWED_BLOB_KEY_PREFIX = 'owed-blobs/';

export type OwedBlobEntry = {
	readonly ref: BlobRef;
	/** The reference tree the receivers verify against. The latest `announce` replaces it; any listing scope authorizes. */
	readonly scope: BlobScope;
	/** Peers confirmed to hold the whole blob — answered `whole`, or sent `held` — by peer-id string, never this node. */
	readonly holders: readonly string[];
	/** Milliseconds since the epoch; the drain examines entries oldest first. */
	readonly recordedAt: number;
};

export class OwedBlobLedger {
	constructor(kv: IKVStore);
	/** Create the entry, or replace an existing entry's scope keeping its holders and recordedAt. */
	record(ref: BlobRef, scope: BlobScope): Promise<OwedBlobEntry>;
	/** Add confirmed holders; never creates an entry (an entry deleted meanwhile stays deleted). */
	addHolders(ref: BlobRef, peerIds: readonly string[]): Promise<OwedBlobEntry | undefined>;
	get(ref: BlobRef): Promise<OwedBlobEntry | undefined>;
	/** Oldest `recordedAt` first. */
	list(): Promise<OwedBlobEntry[]>;
	/** Answered from an in-memory index after the first load. */
	size(): Promise<number>;
	delete(ref: BlobRef): Promise<void>;
}
```

The stored entry keeps the members **known to hold** the blob, not the members still missing it: the owed members are derived afresh from the cohort on every pass (`owed = accepting cohort members − holders − this node`), which is how an entry "follows the cohort" as docs/blobs.md requires. docs/blobs.md describes the entry as holding "the cohort members not yet known to hold it"; that set is what the drain computes from this record. Holders that leave the cohort stay listed (a copy is a copy) and simply stop counting, since durability is counted over current members.

Each public call is serialized per ref and flushes the store (`IKVStore.flush`) before it returns, as `KvUnderReplicationLedger` does. Extract that class's private `serialized` into `KeyedSerialQueue` in `packages/db-p2p/src/keyed-serial-queue.ts` (`run<T>(key: string, operation: () => Promise<T>): Promise<T>`, the same "after every earlier operation for this key, whatever its outcome; drop the key when nothing waits" semantics) and use it in both ledgers. Stored entries are parsed and checked like `parseEntry` in the block ledger; a malformed entry reads as absent and is logged, never deleted by a read. No size cap: entries are bounded by the blobs this node announced, and `feat-unreferenced-blobs-are-reclaimed` drops entries whose scope stopped listing the blob. Add `OWED_BLOB_KEY_PREFIX` to `NODE_KV_NAMESPACES` and to the namespace lists in `packages/db-p2p-storage-fs/README.md` and the comment in `FileKVStore.keyToPath`.

## Durability

`packages/db-p2p/src/blob/blob-durability.ts`. `BlobDurability` and `BlobDurabilityEvent` are db-core types from `feat-blob-references-and-verified-piece-trees`; they are defined by `feat-blob-reference-format-and-tree-builder`, which lands first, and this ticket fills them as defined there:

```ts
// packages/db-core/src/blob/ (service types)
export interface BlobDurability {
	readonly quorum: DurabilityQuorum;
	/** Accepting cohort members known to hold the whole blob (this node included when it is one). */
	readonly confirmed: number;
	/** Cohort members that accept blobs, this node included when it does; 0 when `unrouted`. */
	readonly accepting: number;
	/** Accepting members not yet known to hold it, by peer-id string. Absent when the cohort could not be named. */
	readonly unconfirmed?: readonly string[];
}
export interface BlobDurabilityEvent { readonly ref: BlobRef; readonly durability: BlobDurability }
```

```ts
export interface BlobCohortView {
	/** False when `findCluster` threw or named nobody. */
	readonly resolved: boolean;
	/** Members that accept blobs: this node when it is in the cohort and `blobs.hold` is `'eager'`; every other member whose acceptance is not `refuses` and that is not remembered as declining; and every member `absentCohortMembers` names (counted as owed, as for a block write). */
	readonly accepting: readonly string[];
}

/** docs/blobs.md §Placement, copying and durability, "Durability", exactly. */
export function classifyBlobDurability(view: BlobCohortView, holders: ReadonlySet<string>, selfId: string): BlobDurability;
```

`holders` is the entry's `holders` plus this node when its record says the blob is whole. With `n = |accepting ∩ holders|` and `k = |accepting|`:

- `unrouted` — `!view.resolved`. `holders` reports the size of the holder set, `accepting` 0.
- `local` — no accepting member other than this node (`accepting` minus self is empty), whatever `n`: a group where nobody else accepts blobs stays `local` and the writer keeps the blob. Also `local` whenever `2n <= k` and not every accepting member holds it: this node alone, or fewer than a strict majority. This is wider than a commit's `local`, because a commit is not acknowledged below a majority and a blob is usable from its first copy.
- `majority` — `2n > k` and `n < k`.
- `full` — `n === k` and some accepting member other than this node exists (so at least one holder is not this node).

A member whose acceptance is `unknown` (not yet identified) counts as accepting: an unidentified member is owed until it is known not to take blobs, which errs toward keeping the writer's copy.

## The drain

`BlobCopyDrain` in `packages/db-p2p/src/blob/blob-copy-drain.ts`, a `Startable` holding one `DrainScheduler<OwedBlobEntry, BlobCopyTally>`:

```ts
export type BlobCopyTally = 'unrouted' | 'solo' | 'waiting' | 'announced' | 'full';
export type BlobCopyDrainConfig = DrainSchedulerConfig;   // defaults equal to the block drain's: 5000, 15000, 30000, 64, 5
export type BoundBlobAnnouncer = (peerId: string, ref: BlobRef, scope: BlobScope) => Promise<BlobAnnounceAnswer>;

export interface BlobCopyDrainDeps {
	libp2p: DrainLibp2p;
	selfId: string;
	hold: 'eager' | 'on-demand';
	keyNetwork: Pick<IKeyNetwork, 'findCluster' | 'absentCohortMembers'>;
	partitionDetector: Pick<PartitionDetector, 'detectPartition'>;
	membership?: NetworkMembershipGate;
	/** `buildBlobProtocol(prefix)`: a peer is eligible only once it lists it. */
	blobProtocol: string;
	ledger: OwedBlobLedger;
	records: BlobRecordStore;
	announce: BoundBlobAnnouncer;
	acceptance: (peerId: string) => Promise<BlobAcceptance>;
	emit: (event: BlobDurabilityEvent) => void;
	/** A peer was confirmed to hold `ref` (answered `whole` or sent `held`). The cohort reaction feeds this to its monitor. */
	onHolderConfirmed?: (ref: BlobRef, peerId: string) => void;
}

export class BlobCopyDrain implements Startable {
	constructor(deps: BlobCopyDrainDeps, config?: Partial<BlobCopyDrainConfig>);
	start(): Promise<void>;
	stop(): Promise<void>;
	checkNow(): Promise<DrainPassReport<BlobCopyTally>>;
	/** Record the owed entry for a just-announced blob, compute and emit its first durability, and wake the drain. */
	owe(ref: BlobRef, scope: BlobScope): Promise<void>;
	/** A `held` from `peerId` (the protocol service has already checked membership). */
	noteHeld(peerId: string, ref: BlobRef): Promise<void>;
	/** Recompute and, when changed, persist and emit `ref`'s durability; finish it at `full`. */
	settle(ref: BlobRef): Promise<BlobDurability | undefined>;
	isDeclining(peerId: string): boolean;
	noteDeclined(peerId: string): void;
}
```

The per-entry step, given the scheduler's context:

1. Resolve the cohort view: `findCluster(routingKeyForBlob(ref))` (a throw → unresolved) and `absentCohortMembers?.(key)`; acceptance per member through `deps.acceptance`; declining peers excluded. Classify; persist and emit when changed (below). Unresolved → tally `unrouted`, stop.
2. `full` → finish (below), `forgetEntry`, tally `full`, stop.
3. No accepting member other than this node → tally `solo`, stop. Nothing is counted against anyone.
4. Owed = accepting members other than this node, minus the entry's holders (absent members stay in it; `reachable` drops them because they are not connected). `context.reachable(owed)` empty → tally `waiting`, stop.
5. Announce to each reachable peer in turn and act on the answer:
   - `whole` → collect as a holder; `noteSuccess`; `onHolderConfirmed`.
   - `fetching` → `noteSuccess`; nothing recorded (its `held` will come). A peer answering `fetching` is never abandoned: it has taken a `responsible` hold and is pulling. NOTE to leave at the site: such a peer is re-announced every pass until its `held` arrives, one small request per pass; if a stuck pull ever makes that show up, stop announcing to a peer that answered `fetching` within the last `n` passes.
   - `declined` → `noteDeclined(peer)`; `noteSuccess`.
   - `not-responsible`, `unreferenced`, a rejected call (timeout, reset, `BlobPeerRefusesError`) → `noteFailure` (the scheduler abandons the peer for this entry after `maxAttempts` until it reconnects). Logged `announce:answer ref=… peer=… answer=…` or `announce:unreachable`.
   Tally `announced`. Then `addHolders` with the collected peers and re-run the classification; at `full`, finish and `forgetEntry`.

**Persisting and emitting.** The current durability lives on the blob record (`BlobRecord.durability?: BlobDurability`, added to the record type `feat-a-node-stores-blob-pieces` defined), so `stat` reads it and a restart does not re-emit an unchanged class. A computed value that differs from the stored one in `quorum`, `holders` or `accepting` is written (flushed), then emitted. Each listener is called in a `try`, a throw logged (`durability:listener-threw`), as `StorageRepo` isolates its listeners.

**Finishing at `full`.** In this order: write the record's durability (`full`), delete the owed entry, remove the record's `owed` hold, emit the event. A crash between the steps leaves the `owed` hold without an entry, which keeps the bytes (the safe direction); `feat-unreferenced-blobs-are-reclaimed`'s pass covers owed holds as it covers owed entries.

**Declining peers** are a per-peer in-memory set (a node declines because of its `blobs.hold`, not per blob), cleared for a peer by the scheduler's `onPeerReturned` when its only connection opens. While remembered, the peer is not owed and does not count as accepting.

## Wiring

- **`NodeBlobService.announce(ref, scope)`**: reject a scope that is empty or over `MAX_BLOB_SCOPE_CHARS` with `RangeError`; add the record's `owed` hold (creating the record if absent — a writer may announce a reference it copied from another row without holding the bytes), flushed; then `drain.owe(ref, scope)`. The hold is written before the entry so a crash between them leaves a hold, never an entry announcing a blob nothing keeps. `announce` resolves when the entry is durable and the first event has fired; it never waits for a copy.
- **`NodeBlobService.onDurability`** registers a listener on the drain's emitter; **`stat`** returns the record's `durability` field when present (otherwise none).
- **`held`**: `BlobProtocolService`'s held sink (logging only since the previous ticket) calls `drain.noteHeld`, which `addHolders` (ignored with no entry), calls `onHolderConfirmed`, and `settle`s.
- **`createLibp2pNodeBase`**: build the drain outside the arachnode `if (fret)` gate, beside `UnderReplicationDrain` and for the same reason (it needs the key network, the node's stores and libp2p's connection events, not FRET), bound to the node's `BlobProtocolClient.announce`, `blobAcceptanceOf` over `node.peerStore`, the `membership` gate and `partitionDetector`; start it after the blob service; stop it in a stop wrapper. `NodeOptions.blobs.copy?: Partial<BlobCopyDrainConfig> & { enabled?: boolean }`; `enabled: false` leaves entries recorded and unsent, like the block drain. Expose `(node as any).blobCopyDrain` for tests, as the block drain is exposed.
- Logger: `createLogger('blob:copy')` → `optimystic:db-p2p:blob:copy`; scheduler `entryLabel: 'blob'`.

## Edge cases & interactions

- **Two of five accepting members hold it.** `local` with `confirmed: 2`, not `majority` (test of the classification).
- **This node is the only accepting member.** Every other member refuses the protocol, is on-demand (declined) or none exists: the class stays `local`, the entry and `owed` hold stay, passes tally `solo` (test).
- **On-demand peer.** Answers `declined`, remembered until it reconnects, not owed and not counted meanwhile; asked again after its connection reopens (test).
- **Different cohort views.** A peer this node counts in the cohort answers `not-responsible`: not remembered as declining, counted under the give-up rule, asked again on a later pass, abandoned after `maxAttempts` until it reconnects (test).
- **Announce before the receiver sees the commit.** `unreferenced`, then `fetching` once the receiver's read sees it (two-node test).
- **Restart mid-copy.** The entry and the `owed` hold survive on the node's store; the drain's start pass resumes announcing; the receiver's `resume` finishes its pull from missing pieces (two-node test with stores kept across a restart).
- **Partition.** No pass runs while `detectPartition()` is true: the scheduler returns `skipped: 'partition'` before reading the ledger (the assertion lives in the scheduler, pinned by the block drain's suite).
- **Non-members.** Never eligible (the scheduler's membership filter); a `held` from one is dropped by the protocol service. Inspection.
- **A member without the blob protocol.** Acceptance `refuses`: neither announced to nor counted. Unidentified: not eligible this pass, counted as owed. Inspection.
- **`held` for an entry already finished, or from a peer outside the cohort.** No entry → ignored; outside the cohort → recorded as a holder but not counted. Inspection.
- **Holder count changes without a class change** (three of seven, then four… still `majority`): an event fires, since `holders` changed; the SQL two-commit pattern (`feat-sql-columns-hold-blob-references`) waits on the class. Inspection.
- **Concurrent `owe`, `noteHeld` and a pass on one ref.** Ledger writes are serialized per ref; the pass re-reads the entry through `addHolders`' return. A `settle` racing a pass may emit the same new value twice only if both compute before either persists — guard by running `settle` under the ledger's per-ref queue key (`KeyedSerialQueue.run('settle:' + ref, …)`). Inspection.
- **The block drain is untouched.** Its suite passes; only its spec's `MockLibp2p` moves to `packages/db-p2p/test/support/drain-libp2p.ts` (parameterized by the protocol ids an identified peer lists) so both drain specs share it, with no change to any test body.
