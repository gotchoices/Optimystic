# React Native storage syncs once rn-leveldb can

From the plan `mobile-and-browser-storage-keep-the-durability-window` (GitHub #37, which kjeib raised for this backend).

## What is missing upstream

`gotchoices/rn-leveldb` 3.11 (`cpp/react-native-leveldb.cpp`) runs `put`, `delete` and `write(batch)` with `leveldb::WriteOptions()`, whose `sync` is false, and no JavaScript method takes a sync flag. LevelDB's documentation: with `sync = false`, "if the machine crashes, some recent writes may be lost". So a phone running Optimystic loses, on a power cut or operating-system crash, writes it already reported holding to other machines, and nothing on this side can prevent it.

## Proposed upstream API (the recommended default)

```ts
class LevelDB {
	/** As today, plus: `options.sync` true writes the batch with `leveldb::WriteOptions.sync = true`. */
	write(batch: LevelDBWriteBatch, options?: { sync?: boolean }): void;
}
```

That is all this repository needs. `react-native-storage-commits-groups-through-the-journal` routes every native write through one batch write, so a sync flag on `put` and `delete` is not needed (harmless if added). No change to LevelDB's recovery options is needed either: the journal (`journal-batch-backend`) stops at the first missing record itself, so LevelDB's habit of skipping a damaged record no longer breaks write order.

Alternatives rejected:

- **A separate `sync()` method.** LevelDB has none; it would have to be a synced write of an empty batch, which syncs only the current log file and so does not cover unsynced writes left in an older one.
- **A database-wide "always sync" open option.** Every write group would then pay a sync, which the maintainer's 2026-10-15 decision rules out for phones.
- **Patching LevelDB recovery to stop at the first damaged record** (what RocksDB calls point-in-time recovery). Not needed with the journal, and a much larger change to a vendored library.

If nothing is done, React Native nodes keep today's guarantee: a write survives the app crashing, not the phone losing power. The node says so in its start-up log line, and `packages/db-p2p/docs/storage.md` says so per backend. The change is fully reversible; it only adds an option.

## Work here once it lands

- Raise the `rn-leveldb` peer range in `packages/db-p2p-storage-rn/package.json` to the release.
- `RNLevelDBNative.write(batch, options?: { sync?: boolean })` in `src/rn-opener.ts`; the adapter passes the flag and reports `canSync: true`. If both old and new binding versions must be supported, detect the release rather than assume it; otherwise just require it.
- Check that `@quereus/plugin-react-native-leveldb`, which shares the native module (see `RNLevelDBNative`'s doc comment), is unaffected by the new optional argument.

- A device check: a node on a phone writes, the phone is hard-reset inside the window and after it, and the writes after the window survive. `classic-level` already covers the synced path in the unit suite.
