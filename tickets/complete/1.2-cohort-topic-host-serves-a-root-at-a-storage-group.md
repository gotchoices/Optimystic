# Cohort-topic host: serve a root at a storage group — complete

Second of three tickets for the decision in `docs/reactivity.md` § Origination point. The prereq gave db-core root placement (`RegisterV1.rootKey`, `ChildLinkV1.rootKey`, the `rootPlaced` flags, `RootPlacement`, the optional `ITopicRouter.routeToRoot`); this ticket made the db-p2p host honor it, landed as `ticket(implement): cohort-topic-host-serves-a-root-at-a-storage-group`. Nothing produces root-placed frames until the third ticket (`reactivity-notifications-need-the-tail-cohort-to-be-the-topic-cohort`) binds the host option to the key network, so a running node is unchanged by this landing.

## What landed

**The option.** `CohortTopicHostOptions.rootGroup?: RootGroupOptions` (`host.ts`): `membersAt(coord)` is the root group at a coordinate (async, reads the peerStore) and `quorumRatio` the ratio of `rootPlacedMinSigs`. Without it the host refuses every root-placed frame (`unwilling_cohort`, reason "root placement not served"), the router has no `routeToRoot`, and nothing else changes.

**Snapshots.** `RootGroupSnapshots` (same file): a per-coord `LruMap` of `{ members, memberStrs, cohortEpoch = H(sorted members), readAt }`, capped at `coordEnginesMax` like the engine registry. `ensure` returns a held snapshot younger than `gossipIntervalMs` or reads afresh (concurrent reads of one coord share one `membersAt`), `refresh` always reads, `drop` runs on engine eviction. A root-placed engine captures the snapshot at creation and re-reads it at the start of every `gossipRound`. `cohortEpochOf` is the one epoch derivation for both the FRET assembly and the snapshots.

**Placement per coordinate.** `EnginePlacement { rootPlaced, rootKey? }` is fixed when an engine is created; `CoordRegistry.forCoord` takes it and `reconcilePlacement` refuses a later frame claiming the other rule for the coord (`CoordPlacementMismatchError`), refuses a tier-`d ≥ 1` frame naming a different root key, and lets an engine created without a key adopt the first key it is shown. `CoordEngine` exposes `rootPlaced`, `placement`, `rootKey`.

**Site by site.** Register dispatch (`prepareRootPlacedCoord` admission: served-under-the-other-rule, group unavailable, self outside the group → `unwilling_member` naming the group); child-link dispatch (a tier-1 link's parent resolved root-placed after the same check, refusals mapped to `rejected`); the engine (cohort from the snapshot, threshold read at each signing, rotation counted over the predecessor under the ratio, `/sign` requests and gossip frames stamped `rootPlaced`, willingness quorum a majority of the group, cert cached in the verifier under the placement); `/sign` endorsement (view per request: the served engine's, or an on-demand snapshot); gossip (inbound gate refuses the other rule, membership checked against the engine's own view, cold-sibling instantiation reads the group and requires self in it); membership fetch (`FretMembershipSource.fetch(coord, { rootPlaced: true })` asks the group through `rootGroupPeers`); trust anchor (`FretTrustAnchor.directAnchor(cert, tier, placement)` judges a root-placed cert against the held group at any tier, "unknown" with no snapshot, self outside the group, or a group of self alone); notice verification (`NoticeApplyTarget.placement`); router (`FretTopicRouter.routeToRoot` dials each member's `/register` in order, serves a member that is this node in process, answers `unwilling_cohort` when nobody answers); the `/register` protocol body shared as `handleRegisterFrame`.

**Docs.** `docs/cohort-topic.md` § Root placement at a routing key gained the db-p2p host paragraph; `docs/internals.md` § Service composition names the exception.

## Review findings

Reviewed the implement-stage diff (`ticket(implement): cohort-topic-host-serves-a-root-at-a-storage-group`) before the handoff summary, then traced every site the handoff listed against the db-core contracts it depends on: the walk's root step and `unwilling_member` retry (`walk.ts`), `RootPlacement` / `rootPlacedMinSigs` / `createCohortSigner` (`sig/threshold.ts`), the verifier's placement-keyed cache and `heldUnder` rule (`membership/verifier.ts`), `handleSignRequest`'s self-and-requester membership gates, `FretCohortThresholdCrypto.assemble`'s `selfEligible` handling, the gossip transport's self-exclusion in `broadcastOver`, `addressing.coord`'s rule that a root key changes only the tier-0 coordinate, and the parent-side demotion unlink (verifies the child's cert under the default rule, which is correct: the child is a FRET cohort).

**Checked and sound.** The forwarder's child link reads the engine's root key lazily (the `registerWithParent` callback builds the frame at call time), so a key adopted after creation reaches a tier-1 link. `maybeInstantiateColdSibling` re-checks the registry after its async group read, so a register landing mid-read does not race a second engine. The `/sign` endorser and the engine bus both refuse a frame claiming the other rule before touching the group. `rootGroupMembersFor` calling `engine.cohort()` from the resolver and the anchor is a read with an idempotent side effect (`rotationState.observe` returns on an unchanged epoch), the same observation the engine makes itself. `routeToRoot` answers `unwilling_cohort` without `retryAfterMs`, which the walk handles (`backoffRetryMs(0)`). The parent-unlink path passes no placement, which is right.

**Minor, fixed inline.**

- `parentRootPlaced` in `createCoordEngine` was a constant computed at creation, so a tier-1 engine created without a root key (a gossip-instantiated cold sibling, a deeper child's link) that later adopted one would never read the root group before fanning a demotion to its parent. It is now read at each use.
- `createDynamicThresholdSigner` in `host.ts` built a throwaway `createCohortSigner(crypto, 0)` just to borrow its `verifyThreshold`. `createCohortSigner` (`packages/db-core/src/cohort-topic/sig/threshold.ts`) now accepts `number | (() => number)` and the host passes `minSigsNow` directly; the wrapper is gone. Existing callers pass numbers and are unchanged.

**Major, filed.** The membership protocol serves one node-wide certificate (`FretMembershipPublishSink.latest`, and the `/membership` handler discards the coordinate the request names), so a node in two cohorts answers a fetch for one with the other's cert. Pre-existing and named in the handoff; root placement makes the two-cohort shape routine and the third ticket deploys it. The open `fix/membership-verifier-accepts-a-certificate-for-another-coordinate` covers the verifier side only, so the serving side is filed as `fix/the-membership-protocol-serves-one-certificate-for-every-cohort-a-node-is-in` (`repro: static`, with the confirming spec described). No other site touched by this ticket is claimed by an open ticket; `bug-cohort-topic-router-hashes-a-coordinate-as-a-key` touches the router but `routeToRoot` deliberately avoids `routeAndAct`, which that ticket records.

**Tripwires (recorded as `NOTE:` at the site).**

- `requireRootGroup` in `host.ts`: the snapshot store is one `LruMap` shared with on-demand `/sign` reads, so a flood of root-placed sign requests at distinct coords landing between a dispatch path's `ensure` and the engine's creation could evict the entry just filled, failing that register on the stream. Remedy named there (hand the snapshot through `EnginePlacement`).
- Already in the implementation and left as they are: the unbound-root-key tradeoff at `dispatchRegister`, the rotated-past engine at `createCoordEngine`, the group-of-one guard at `rootGroupView`, and the willingness quorum read once at engine creation (comment at the `createWillingnessCheck` call).

**Considered and declined to file.** Paths with no test (tier-1 child linking to a root group, each `CoordPlacementMismatchError` refusal, the demotion fan-out to a root-group parent, the on-demand `/sign` snapshot fill, the router's in-process self path): traced by hand and consistent; a test for each would restate the implementation rather than pin a specification branch, and the third ticket's end-to-end run is where the tier-1 and self paths get real coverage. `RootGroupSnapshots.ensure` ages snapshots with `Date.now()` while the host takes an injectable `now` for frame timestamps: the two clocks serve different purposes (a read cadence versus a signed timestamp) and no spec needs to steer the cadence. `host.ts` is 3790 lines (`wc -l`), 802 of them from this diff; a split is not filed here because no class-level invariant retires it and the file's sections are already delimited, but the next ticket that adds a subsystem to it should carve one out.

**Tests cut.** None: the three added specs each pin a branch of the specification (the ratio threshold against a group the default `minSigs` cannot meet, the group-of-one and no-option refusals, the anchor's root-group judgement).

**Docs.** `docs/cohort-topic.md` and `docs/internals.md` read against the code after the fixes and still describe it; `yarn lint:docs` resolves every citation.
