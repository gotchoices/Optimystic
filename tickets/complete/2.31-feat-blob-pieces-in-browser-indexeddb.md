# Blob pieces in the browser's IndexedDB database

## What was built

`IndexedDBPieceStore` (`packages/db-p2p-storage-web/src/indexeddb-piece-store.ts`) implements `IPieceStore` over a new `pieces` object store in the database `openOptimysticWebDb` opens, sharing the handle with the block store, the key-value store and the identity helper. It is outside the journal and the `RawStoreDriver` kernel.

- `DEFAULT_DB_VERSION` raised 4 → 5; the `upgrade` hook creates `pieces` only when missing, so an older database keeps every record.
- A put is one `readwrite` transaction (strict where the browser supports it) that checks for the id and writes nothing when present; `Promise.all([write(), tx.done])` makes a failed request (quota included) reject the call. A piece handed as a view into a larger buffer is sliced first, since structured clone stores the whole buffer.
- `flush` is a no-op (each resolved strict put is on the disk); `durability` is `'power-loss'` with strict transactions, else `'process-crash'`.
- `list` pages `getAllKeys` 1000 at a time with an exclusive lower bound; `bytesUsed` sums values over one cursor (never called when sharing the block store's handle).
- `storeIdentity` uses the new exported `IDB_HANDLE_SCHEME`, shared with `IndexedDBJournalStore`, so over one handle the pieces are counted once (the block store's figure is the origin estimate).
- Docs: `docs/blobs.md` (status, §The local store, §Platforms and limits), `packages/db-p2p/docs/storage.md` §7, and the package README (usage, persistence table, version 5, durability). The README usage snippet now actually passes `storage`, `kvStore` and `pieceStorage` to `createLibp2pNode`.

Tests: the shared `runPieceStoreConformance` suite (persistent) plus one case pinning the view-into-a-larger-buffer slice.

## Review findings

Read the implement diff (`ticket(implement): feat-blob-pieces-in-browser-indexeddb`) first, then the sibling stores (`SqlitePieceStore`, `FilePieceStore`), the `IPieceStore` contract, `blockStoreCountsPieces`, and the callers of `put`/`delete`/`flush` in `packages/db-p2p/src/blob/`.

- **Correctness of `put`** — checked: the `getKey` then `put` inside one transaction is the supported idb pattern (only IndexedDB requests are awaited, so the transaction does not auto-commit); concurrent puts of one id serialize on the `readwrite` store; both rejections are observed through `Promise.all`; a zero-length piece passes `wholeBufferBytes` unchanged. No defect.
- **`delete` and the flush contract** — found: `IPieceStore.flush` promises that every put *and delete* resolved before it survives the crashes `durability` names, and this store reports `'power-loss'` while its deletes run at the browser's default (relaxed) durability that no later flush covers. The file and SQLite stores do cover deletes. Harmless today: the only caller of `delete` is the sweep, which never flushes its deletes by design, and a lost delete only leaves an orphan the next sweep removes. Recorded as an accepted-tradeoff `NOTE:` at `IndexedDBPieceStore.delete` with the revisit condition (a caller that needs a durable delete), replacing the narrower doc comment there. No ticket.
- **Byte counting** — checked `blockStoreCountsPieces`: one identity over one handle, and `IndexedDBRawStorage.getApproximateBytesUsed` always exists, so `bytesUsed` is not called in the documented configuration. Its error path logs and answers 0, as `SqlitePieceStore` does. The `NOTE:` on its cost stands.
- **Version bump / upgrade** — the upgrade from versions 1–4 is untested and an open blocked by another tab's older connection still hangs silently; both are already an arm ("version 5 (blob pieces)") of `debt-indexeddb-version-upgrade-is-untested-and-unhandled` in `tickets/plan/`, so not re-filed. `packages/upgrade-check` has no IndexedDB fixture (its readme says object-store layout changes are not covered), so nothing there needed updating. No other code opens the database with a hard-coded version.
- **Docs** — read every file the change touches plus `packages/upgrade-check/readme.md`: store counts (ten object stores, seven data stores) are right, the README usage snippet now matches `NodeOptions` (`storage`, `kvStore`, `pieceStorage`), `docs/blobs.md` §The local store already says an IndexedDB store makes each put durable itself. Nothing stale found.
- **Tests** — kept both: the conformance suite is the project's required contract check, and the view test reproduces a real defect class (it fails without the slice). Nothing added: the delete finding is a documented tradeoff, not a defect a test would pin.
- **Type safety / hygiene** — no `any`; file is 133 lines; `IDB_HANDLE_SCHEME` is now public through `export *`, mirroring `SQLITE_HANDLE_SCHEME` — left as is.
- **Not verifiable here** — no real browser was run: strict-durability semantics, quota refusal, and a browser ignoring `durability` rest on inspection, as for the block store.

Validation: `yarn build` and `yarn test` in `packages/db-p2p-storage-web` (77 passing), eslint over the package, and `yarn lint:docs` all pass.
