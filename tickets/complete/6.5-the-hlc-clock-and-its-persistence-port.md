# The hybrid logical clock and its persistence port

First of the three Stage 1 tickets of docs/crdt-sync.md §Migration Path. `every-log-entry-and-transaction-carries-its-hlc` and `a-node-observes-the-hlcs-it-reads-and-stores` (both in `implement/`) build on it.

## What landed

- `Hlc` (`wallMs`, `logical`, `nodeId`, plain JSON), `compareHlc`, `legacyHlc` and `isHlc` in `packages/db-core/src/hlc/hlc.ts`.
- The persistence port `HlcClockStore { load(); save(hlc) }`, `DEFAULT_HLC_PERSIST_INTERVAL_MS` (1 s), `DEFAULT_HLC_RESTART_SLACK_MS` (10 s, derived from db-p2p's relaxed flush window cap plus the persist interval) and `restartFloor` in `packages/db-core/src/hlc/clock-store.ts`.
- `HlcClock` and `clockOf` in `packages/db-core/src/hlc/clock.ts`. `new HlcClock(...)` is in memory only; a store-backed clock is built only by the async `HlcClock.start(...)`, which loads its mark first. `now()` issues above the mark; `observe()` raises it; saves are debounced to one per interval, immediate on a jump, fire-and-forget with one in flight, failures logged as `hlc:save-failed`. A failed or malformed load starts the clock from the local clock alone, logged.
- `ITransactor.clock?`, carried by `NetworkTransactor` (`NetworkTransactorInit.clock`), `TestTransactor` (default node id `'test'`) and `DelegatingTransactor`; transactors that declare none fall back through `clockOf` to one process-wide clock in node id `'local'` (matching `TransactionSession.create`'s default peer id).
- docs/crdt-sync.md §HLC Generation and Causal Tracking names the implementation.

## Review findings

Read the `ticket(implement): the-hlc-clock-and-its-persistence-port` diff first, then the handoff, then the two downstream implement tickets to check the API suits them.

- **Correctness — fixed: the clock could issue one HLC twice after observing a huge logical count.** `isHlc` accepted any finite `logical`, and `now()` computed `prior.logical + 1`. Past `Number.MAX_SAFE_INTEGER` the `+ 1` stops changing the value, so after observing a peer's HLC with logical at or near 2^53 two issues in the same millisecond came out equal, breaking the uniqueness `compareHlc`'s doc relies on (and the third ticket feeds `observe` from the wire). Fixed at both ends: `isHlc` now requires `logical` to be a non-negative safe integer (what a clock actually issues), and `HlcClock.next` carries into `wallMs + 1, logical 0` when the prior count is already at the top of the safe range. Reproduction added as one case of the existing table test (`an observed logical count at the top of the safe-integer range carries into wallMs`), which fails on the old code. Downstream impact: a pend whose `logical` is negative, fractional or unsafe is now reported `hlc:malformed` by the third ticket rather than observed, which is the right answer.
- **Tripwire — parked: a crash loop drifts the HLC ahead of wall time.** `start` saves the restart floor, so each restart faster than the slack resumes a further slack above the last one, without bound. Conditional on HLCs deciding order (Stage 2). Recorded as a second `NOTE:` at `DEFAULT_HLC_RESTART_SLACK_MS` beside the implementer's lost-jump note, with the remedy (wait out the floor at start).
- **The implementer's lost-jump tripwire:** kept as a `NOTE:`. It is conditional on Stage 2 ordering by HLC; there is no current-release anchor that orders by it, so it is below the filing bar.
- **Debounce keyed on the offered mark rather than a confirmed save:** accepted as designed; a failing store is retried on the next interval of advance rather than on every issue, which bounds log and store load.
- **API fit for the downstream tickets:** checked. The static `HlcClock.start` suits the third ticket's node wiring (it awaits the clock before building `StorageRepo` and the transactor). `clockOf` suits the second ticket's four mint sites. `TestTransactor`'s `'test'` node id is what the second ticket's retry spec will assert.
- **Wrappers that implement `ITransactor`:** the only ones in `src/` are `NetworkTransactor`, `DelegatingTransactor` (forwards the clock) and the reference peer's `LocalTransactor` (falls back through `clockOf`, as intended). The Quereus plugin's `network` transactor is wired to the node's clock by the third ticket.
- **Resource cleanup:** no timers or subscriptions; an in-flight save is not awaited on stop, which the restart slack covers. Nothing to clean up.
- **Type safety / error handling:** a synchronous throw from a store binding is converted to a rejection and logged, never reaching `now()`; options are range-checked; the empty node id is refused. No `any`.
- **Source hygiene:** files are small (largest, `clock.ts`, under 200 lines); comments state constraints rather than narrate. No change needed.
- **Tests:** the table-driven spec pins the clock's specified behaviour (local ahead, observed ahead, same-millisecond, backwards local clock, both restart cases, save schedule) on logic with real branching; nothing in it restates the implementation or verifies a mock. One case added for the defect above; nothing cut. `clockOf`, the transactor fields and exports are wiring and stay untested.
- **Docs:** docs/crdt-sync.md names the four new symbols and its citations resolve. docs/internals.md and §Stage 1 of docs/crdt-sync.md are deliberately left to the third ticket, which owns them.
- **Performance:** `now()` is constant time with no allocation beyond the returned object; saves are at most one per second under load. Nothing found.
