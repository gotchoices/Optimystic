## What landed

`throttleProtocolMerges(peerStore, self, options?)` in `packages/db-p2p/src/network/protocol-merge-throttle.ts` wraps `node.peerStore.merge` and `delete`. It is installed in `createLibp2pNodeBase` before `node.start()`. A merge into a remote peer's record whose data is exactly `{ protocols: [one] }` (the shape libp2p 3.3.11's `Connection.newStream` and `onIncomingStream` use) reaches the store at most once per 60 s per (peer, protocol). The first merge for a pair always goes through. Every other merge passes straight through, and so does every merge into this node's own record. A rejected merge records nothing. Deleting a peer forgets it, because libp2p 3 dispatches no deletion event and FRET deletes records. Memory is an `LruMap` of 256 peers. There is no timer.

`packages/db-p2p/test/libp2p-merges-protocol-per-stream.spec.ts` pins the libp2p behaviour on two real loopback nodes. It fails on the libp2p release carrying #3692, which is the signal to delete the throttle. It also fails if libp2p moves the call or changes its shape.

## Review findings

Read the diff from `ticket(implement): protocol-merge-throttle` first, then checked the libp2p 3.3.11 and `@libp2p/*` sources installed under `packages/db-p2p/node_modules` for every `peerStore.merge` call.

- **Defect, fixed: the node's own record was throttled.** libp2p's registrar merges `{ protocols: [protocol] }` into the node's own record on every `handle()`, the exact shape the throttle intercepts, and `unhandle()` removes the protocol with a `patch`. Identify builds what it advertises from that self record. So a `handle` → `unhandle` → `handle` of one protocol inside a minute (a service stopped and restarted on the same node) would have had its re-add held back, and the node would have advertised itself without that protocol until it next handled it. If that protocol was cluster or repo, peers would classify the node as foreign. Fixed: the throttle now takes `self` and passes its merges straight through, and the install site passes `node.peerId`. Added one spec case reproducing it ("never holds back a merge into this node's own record"). The module doc comment and `docs/internals.md` now say self is exempt.
- **Other one-protocol merges in the dependency tree:** the only call sites passing a single-key `protocols` merge are the two in `connection.js` (the target) and the registrar (fixed above). Identify, dial queue, circuit relay, bootstrap and discovery all merge other keys and pass through.
- **Installation target:** `Connection` calls `this.components.peerStore.merge(...)`, a property lookup at call time, so replacing the method on `node.peerStore` (the same object) before start intercepts it. The implementer's one-off check against real nodes confirms this.
- **Cross-platform:** `AbortSignal.throwIfAborted` on the held-back path is already used by libp2p itself (`connection-manager/index.js`, `random-walk.js`), so the change adds no new requirement on React Native. `yarn check:rn` passes.
- **Races:** a delete and a merge of one peer serialise on the store's per-peer lock, and either order leaves the throttle's state consistent with the store (forgotten after the delete, or re-recorded by a merge that ran after it). Concurrent first merges are not shared, as the implementer chose, to keep one stream's abort signal from failing another stream's negotiation. Accepted.
- **Deviations the implementer flagged:** the `delete` wrapper replacing the absent `peer:delete` event, and a held-back merge returning the peer's most recent `Peer` rather than that pair's. Both agreed: libp2p's callers ignore the value.
- **Tests:** kept both implementer specs. Each pins a branch or a premise and none tests a mock of our own code. Added the one reproduction above. The untested rejected-merge retry is by inspection: recording happens only after the `await`.
- **Docs:** `docs/internals.md` §Third-Party Address Learning: reworded the clumsy parenthetical about the "only writer" and added the self exemption. `docs/debugging.md` row and the `prepared-streams.ts` `NOTE:` are accurate. The Network Membership Predicate and peer-record-cache text still holds, because the first stream's merge still reaches the store.
- **Tripwires:** none added. The one conditional risk, libp2p moving the call so the throttle is silently bypassed, is already covered by the pinning spec, which is not env-gated.
- **Resource cleanup, error handling, type safety:** no timer and no listener, so nothing to tear down. Errors from the real merge or delete propagate unchanged. No `any`.
- **Filed tickets:** none. The only major finding was fixed here.
