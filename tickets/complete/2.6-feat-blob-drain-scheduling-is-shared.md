# The drain's scheduling is shared

## What was built

`DrainScheduler<TEntry, TTally>` in `packages/db-p2p/src/repo/drain-scheduler.ts` holds everything around the per-entry work that used to live in `UnderReplicationDrain`: the triggers (`start`, `connection:open`, `peer:identify`, the re-check timer, `checkNow`, and a new `wake()`), the debounce and minimum-interval throttle with its one-timer-pulled-earlier rule, pass serialization, partition suppression, the eligible-peer set (connected, deduplicated, membership gate, optional peer-store protocol check), the rotating per-pass budget, the per-(entry, peer) give-up rule with reconnect reset, and the pass log lines, written through the owner's logger.

The owner supplies a `DrainEntrySource` (`list`, `size`, `keyOf`) and a `DrainEntryStep` that receives a `DrainEntryContext` (`reachable`, `noteFailure`, `noteSuccess`, `forgetEntry`, `tally`). `onPeerReturned` is an optional callback fired when a peer's only connection opens, after its give-up state is forgotten; the block drain does not pass it, the blob drain (`feat-blob-owed-copies-are-drained`) uses it to clear its declining memory.

`UnderReplicationDrain` keeps its public surface (constructor, deps, config with `blockBudget`, defaults, `DrainPassResult`, `checkNow`, `getDiagnostics`, `start`, `stop`, re-exports of `BlockDurabilitySink`, `DrainTrigger`, `DrainLibp2p`); its `drainEntry` is the old body rewritten over the context, and `checkNow` maps the scheduler's report to `DrainPassResult` (`no-eligible-peer` → `no-pushable-peer`). The printed `pass:done` and `peer:abandoned` lines are byte-identical to before.

The ledger and partition detector are read through `this.deps` on every pass (the spec reassigns `deps.ledger`, `deps.partitionDetector` and `deps.emit` after construction); `libp2p`, `membership` and the protocol id are captured at construction.

## Review findings

Read the `ticket(implement): feat-blob-drain-scheduling-is-shared` diff against the pre-refactor `under-replication-drain.ts` line by line.

- **Behaviour parity (checked, holds).** Scheduling, throttle, timer, pass serialization, scanned-only throttle accounting, budget rotation, failure counting, abandonment, reconnect reset, disconnected-peer forgetting and state pruning are moved verbatim. Protocol rule unchanged (`protocolPrefix: ''` still checks `buildBlockTransferProtocol('')`). Log output identical. Laziness: the old code read every dep lazily; the new code captures `libp2p`, `membership` and `protocolPrefix`. No code or test reassigns those after construction, so this is not a behaviour change in practice; left as is.
- **Minor, fixed: `wake()` was logged as `trigger=manual`,** indistinguishable from `checkNow` in `pass:done`. The blob drain will call `wake()` on every announce, so a log reader needs to tell the two apart. Added `'wake'` to `DrainTrigger` and `wake()` now schedules under it. No consumer switches on the trigger value.
- **`pushablePeers` one-line method (considered, kept).** It exists to hold the block-specific `NOTE:` (an entry naming a refused or client-rebuilt peer never settles) at the site three doc citations name. Inlining would mean retargeting those citations for no gain.
- **`DrainPassReport.tallies` cast** (`Object.fromEntries(...) as Record<TTally, number>`): the type system cannot prove a mapped `readonly TTally[]` covers every key; contained to `emptyReport`, acceptable.
- **Exports.** `DrainTrigger`/`DrainLibp2p` reach the barrel through both `export *` modules; they resolve to the same binding, so no ambiguity (build and `entry-parity` spec pass).
- **Resource cleanup / error handling.** `stop()` clears both timers and the pending trigger and removes both listeners; an in-flight pass bails between entries. Pass and start errors are logged, never swallowed. Unchanged from before.
- **Tests.** None added, none cut. The unedited `under-replication-drain.spec.ts` pins every scheduling behaviour through the one current user; `wake()` and `onPeerReturned` are exercised by the blob drain ticket, their first caller.
- **Docs.** `packages/db-p2p/docs/repo.md`, `docs/internals.md` §UnderReplicationDrain and `docs/blobs.md` "Copying" name `DrainScheduler`. `docs/debugging.md`'s `under-replication-drain` row still describes the lines correctly (output unchanged). No doc enumerates trigger values, so the `'wake'` addition needed no doc change.
- **Source hygiene.** `drain-scheduler.ts` is 445 lines, one class plus its types; comments state why, not what.
- No tripwires added; no tickets filed.
