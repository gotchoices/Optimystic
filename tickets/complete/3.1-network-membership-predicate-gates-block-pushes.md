# The membership predicate gates the raw-ring replication paths

`NodeOptions.isNetworkMember` (from the prereq) already governed the key network's cohort and coordinator choices. Four senders bypass the key network and take candidates from FRET (the peer-discovery ring), whose membership any connected peer can join. Each now takes an optional `membership?: NetworkMembershipGate` — the one instance `createLibp2pNodeBase` builds beside the key network — and drops every candidate it refuses before dialing. With no predicate the gate is `undefined` and every filter admits everything (`admittedBy`), so behaviour is unchanged.

| Path | What is filtered | Consequence of a refusal |
| --- | --- | --- |
| `SpreadOnChurnMonitor.performSpread` | expansion targets outside the FRET cohort | not pushed; not in the spread event's `targets` |
| `RingShiftCoordinator.buildOwnersMap` | qualifying holders per shed block | neither pushed a shed block nor counted toward the floor; an unmet floor rolls the shift back |
| `RestorationCoordinator.restore` | my-ring candidates and each inner ring's partition-filtered list | never asked for an archive |
| `UnderReplicationDrain.pushablePeers` | connected peers | not pushable; an entry owing only refused peers waits |

`RebalanceMonitor` and `BlockTransferCoordinator` take owners from `findCluster` (production always wires `keyNetwork` into the rebalance monitor) and were covered by the prereq.
