## Summary

A concurrent same-row UPDATE, DELETE, REPLACE-over-an-occupied-key, displacing primary-key move, or secondary-UNIQUE eviction now refuses the losing writer at commit with `concurrent modification: another writer changed or removed the row in <table> at primary key (…)`, instead of replaying its main-table action over the rival's row while its index delta, computed against a row image the collection no longer holds, landed beside it. Every main-table entry whose index delta came from a pre-write image carries an `unchanged` guard on the stored entry as read. INSERT at a key the probe found clear is guarded `absent` under every conflict disposition, so a racing INSERT OR IGNORE or INSERT OR REPLACE is refused as a duplicate key and the sequential retry honours the disposition. The bridge renders the new refusal class through a per-collection renderer, and a new `decodePrimaryKey` on the row codec turns the framed tree key back into the row's logical values for the message.

Two pre-existing defects the new spec exposed were filed by the implementer rather than fixed: `fix/6.35-blind-index-delete-is-logged-but-never-applied` (a DELETE from a handle whose index tree never fetched the entry leaves the entry in storage forever) and `backlog/bug-unique-enforcement-tree-set-differs-across-handles`. The error-type question for both refusal classes is appended to `backlog/bug-concurrent-unique-refusal-is-not-a-constraint-error`.

## Implement-stage record (kept for reference)

**The guard, in the vtab** (`optimystic-module.ts`). A module-level `unchanged(entry)` builds `{ kind: 'unchanged', expected: entry }` over the stored entry as read (`StoredRowEntry = [framedPk, encodedRow]`), never a re-encoding. `requirePreWriteRow` returns `{ row, entry }` (`PreWriteImage`); `UniqueCollision` and `PkMoveDecision`'s `displace` arm carry the entry the probes already held. Guarded: same-key UPDATE; both halves of a primary-key move (delete half `unchanged(oldEntry)`, insert half `unchanged(displacedEntry)` for a REPLACE onto an occupied key, else `absent` under every resolved action); DELETE; INSERT at a clear key, `absent` under every disposition; INSERT OR REPLACE at an occupied key, `unchanged(existingEntry)`; each secondary-UNIQUE eviction, `unchanged(collisionEntry)`. Index trees carry no guard: an index entry is keyed `indexKey ‖ pk`, so a stale delta can only be prevented at the main-table action. `keepExisting` has no SQL producer any more; it stays in db-core as a documented, serialized log form.

**The message, in the bridge** (`txn-bridge.ts`). `registerEntryChangedRenderer(collectionId, render)` beside `registerKeyTakenMessage`; `mapCommitRefusal` walks the cause chain for `TreeGuardRefusedError` and dispatches by class through `renderRefusal`. The vtab registers the renderer for its main collection only and renders through `concurrentModificationMessage`. Still a plain `Error` with `cause`.

**Key decoding, in the codec** (`row-codec.ts`). Public `decodePrimaryKey(key)`, the rendering-only inverse of `createPrimaryKey`, decoding each framed part under its primary-key column's affinity.

**Client-visible behaviour changes.** A racing same-row UPDATE, DELETE, REPLACE-over-occupied-key, displacing move, or UNIQUE eviction fails the loser's commit with the concurrent-modification message, in both commit modes. INSERT OR IGNORE and INSERT OR REPLACE at a key a rival takes first are refused with the ordinary UNIQUE message instead of being admitted; a sequential retry swallows or replaces as before. A live read inside a doomed transaction can throw where it used to return the reader's own staged value.

**Tests.** `test/concurrent-row-change-refusal.spec.ts` (now 19 tests): every `unchanged` arm with a sequential retry after each refusal, a control for a rival INSERT sharing the indexed value, the false-UNIQUE-refusal shape, three within-transaction chains, session mode across two tables, and the three key-type renderings. `test/concurrent-insert-refusal.spec.ts`: IGNORE and REPLACE clear-key races flipped to refusal plus retry. `test/two-node-index-mutation-sweep.spec.ts`: the replay model deleted, racing cases assert the first committer fulfils and the second is refused (or both fulfil when one side inserts beside), every case closing on the two-way index check on both nodes. `test/external-commit-visibility-after-rollback.spec.ts`: the in-transaction read now asserts the early refusal.
