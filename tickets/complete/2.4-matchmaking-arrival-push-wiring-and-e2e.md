# Matchmaking arrival push — node wiring, end-to-end proof, docs (complete)

Last of five tickets in the arrival-push chain. Implemented in `ticket(implement): matchmaking-arrival-push-wiring-and-e2e`.

## What was built

- **libp2p delivery** — `createArrivalPushSend` in `packages/db-p2p/src/matchmaking/arrival-push-send.ts` is the driver's `send`. It reads the seeker's contact hint with `contactHintTarget` (a bare peer id, or a multiaddr whose last component is `/p2p/<id>`; anything else, including a circuit address naming only the relay, is logged and dropped), delivers in process to a seeker on this node, otherwise merges a multiaddr hint through `mergePeerAddresses` and dials the arrival-push protocol under the node's link deadlines. It never rejects.
- **Node wiring** — in the cohortTopic block of `createLibp2pNodeBase`: one `ArrivalPushReceiver` (handler registered, exposed as the typed `node.matchmakingArrivalPush`) and one `ArrivalPushDriver` (slot rule, node-key signing shared with the query handler, the send above) subscribed to `host.onRecordAdded`. Teardown unsubscribes and stops the driver before the matchmaking protocols are unhandled, in the existing stop wrapper.
- **Timer seam** — the receiver takes an injectable `setTimer`; the default `armUnrefTimer` in `packages/db-p2p/src/unref-timer.ts` is now shared with the driver.
- **Mesh harness** — every member runs a real driver and receiver on one shared virtual time; `startSeek` / `advance` let arrivals land inside a hang-out; deliveries are recorded in `pushSends`; `MatchResult.queries` counts the walk's queries.
- **Tests** — `mesh-push.spec.ts` (fresh arrival pushes to the waiting seeker with no query past the immediate one while a poll-path seeker is never pushed; each selected seeker is pushed exactly once, by its slot primary), `arrival-push-send.spec.ts` (contact-hint reading, including the relay mis-target), and real-socket case 5d (a remote push-opted seeker returns a provider that arrived mid-hang-out with one query).
- **Docs** — `docs/matchmaking.md` §Arrival push gains an Implemented callout and decisions, §Hang-out callout and §Test expectations mapping updated, query-count wording reconciled; `docs/internals.md` gains an "Arrival push" subsection; `docs/cohort-topic.md` and `docs/debugging.md` updated.

## Review findings

Read the implement diff first, then every touched source, test and doc file, plus `query-transport.ts` (the seeker transport the wiring feeds), `peer-address-book.ts`, `stream-util.ts` and `protocols.ts`.

**Checked and correct (no change):**
- *Wiring and teardown.* The driver, receiver and handler are created once, after the query handler, inside the block whose rollback wrapper is installed up front; the undefined-guarded bindings match the established rollback pattern. `matchmakingProtocolList` includes `arrivalPush`, so the handler is unhandled on stop. Unsubscribe-then-stop order means no arrival can schedule a push after the driver's timers are cleared.
- *Send binding.* Self check runs before the merge (and `mergePeerAddresses` itself refuses self). A self-delivered push is signed by the node key and verified against the node's own id, so the receiver's signature check holds on that path. Dial failures are logged and resolve `undefined`, which the driver already treats as a failed delivery. The fire-and-forget peerStore merge before the dial is the same pattern `ClusterClient` / `RepoClient` use for redirect targets.
- *Type safety.* `matchmakingArrivalPush` is on `OptimysticNodeAttachments`; no new casts in source. The harness's member index and `mesh.nodes` index align (`buildMesh` pushes in member order), so `pushPeers[index]` is the right member.
- *Harness virtual time.* `advance` fires timers in due order including ones armed by fired timers; ties go to arming order. Teardown unsubscribes and stops every driver.
- *Docs.* Read each changed section; citations, protocol ids and query-count arithmetic agree with the code. `yarn lint:docs` clean.

**Tests (cut/add):** none cut — the two mesh specs are the only end-to-end composition of driver, host signal, slot rule and walk; `arrival-push-send.spec.ts` pins a branching parse rule (the relay mis-target) nothing else exercises; case 5d is the only real-socket proof. None added — no defect found that a test would reproduce.

**Fixed inline (minor):**
- `docs/matchmaking.md` §Arrival push's "Real renew and withdraw on both paths" claim held only when a self-routed renew has `selfServe.renew` bound; the bullet now says so, what happens without it (record lapses after one TTL, walk falls back to its safety poll), and points at the follow-up below.

**Filed (major):**
- `backlog/feat-node-offers-matchmaking-self-serve` — the implementer's first known gap. An application on a node that is in its own topic's cohort (every node, in a small deployment) can only bind `MatchmakingSelfServe` by casting to reach `cohortTopicHost`; without it a self-routed register/query throws and a self-routed renew is skipped, which on the push path lets the seeker record lapse mid-hang-out. Filed at the representation rung: the node should offer the binding on its typed surface and the seeker session should use it by default. Pre-existing for register/query; made more costly by push walks hanging out longer. Not fixed inline: it is a public-surface decision outside this ticket's files and needs the register admission path served in process.

**Tripwires (`NOTE:` at the site):**
- `arrival-push-send.ts`, before the dial: the dialed peer is whatever the hint names, unchecked against the registering participant, so a seeker can steer a member's pushes at a third party (bounded by provider arrivals × capacityBudget). Revisit if it shows up as abuse by requiring the hint's peer to equal the participant.
- `matchmaking-mesh-harness.ts`, `SETTLE_MS`: work needing more than 10 ms of real time before arming its next virtual timer is skipped past within one `advance`; if a push spec flakes on a slow machine, make `advance` wait for quiescence.

**Other known gaps from the handoff, weighed:**
- Case 5d uses `createLibp2pMatchmakingTransport` + `SeekerWalkClient` rather than the session: accepted — the session hides the transport, and the observable proof (parked on pushes, one query) needs it. The session passes `arrivalPush` through by type.
- Untested branches of `createArrivalPushSend` (self delivery over a real node; multiaddr-hint merge over real sockets): accepted — both are short, read correctly, and the mesh harness covers the hint parsing with the production `contactHintTarget`.
- Real renew over real sockets not asserted; ~1.6% of 5d runs fall back to in-process delivery: accepted as test-coverage limits, no defect behind them.
