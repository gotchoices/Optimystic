# A renewal whose primary is this node is served in process

## What landed

- `FretTopicRouter.dialMember` (`packages/db-p2p/src/cohort-topic/topic-router.ts`) answers a dial addressed to this node through `handleLocally` instead of opening a libp2p stream (libp2p refuses a self-dial). A throw from the local handler propagates, which the callers treat exactly as a remote dial failure (renewal counts a failed ping; the walk propagates).
- `createCohortTopicHost` (`packages/db-p2p/src/cohort-topic/host.ts`) now always passes `selfPeerId` and `handleLocally` (→ `handleRegisterFrame`) to the router; only `rootGroupMembers` stays conditional on root placement.
- `docs/cohort-topic.md` §TTL and renewal states that a self-primary renewal is answered in process.
- Test: `topic-router.spec.ts` → "serves a dial addressed to this node in process, opening no stream".

## Review findings

Read the `ticket(implement): a-renewal-whose-primary-is-this-node-is-served-in-process` diff first, then the surrounding router, host and the two `dialMember` callers (`CohortTopicService.renewalTransport` in `packages/db-core/src/cohort-topic/service.ts`, the walk's direct-dial retry in `packages/db-core/src/cohort-topic/walk.ts`).

- **Correctness — checked, no defect.** The local path calls the same `handleRegisterFrame` the inbound `/register` handler runs, so renew, withdraw (tombstone), child-link and re-attach/`unwilling_member` register frames get byte-identical answers. Error semantics match: an inbound handler throw resets the stream and the remote dialer's `requestResponse` rejects; locally the throw rejects the same promise. No recursion risk: `resolveRenew`, `dispatchChildLink` and `dispatchRegister` (with no cohort list) do not dial back through the router. `handleRegisterFrame` is declared after the router but only called at dial time, after host construction completes (the root-group branch already relied on this).
- **Behavioural consequences — checked, intended.** A self-primary registration no longer fails three pings and migrates to `backups[0]` every epoch; its withdraw tombstone now evicts locally instead of waiting out the TTL; a self-addressed walk member retry is answered in process. No existing test depended on the old failure-driven migration (full cohort-topic grep run green).
- **Minor — fixed inline.** The comment heading `handleRegisterFrame` in `host.ts` still said it was shared only with "the router's local root step"; updated to "the router's in-process self-dials".
- **Tests.** The one added test pins the contract (a self-addressed dial opens no stream and returns the handler's reply with the frame passed verbatim) at the lowest layer that reproduces the defect; kept. No host-level test added: the host change is wiring (two options passed unconditionally), which the testing bar excludes.
- **Docs.** `docs/cohort-topic.md` §TTL and renewal and the root-placement paragraph (which already described the root-group self-serve) read correctly; `docs/internals.md` §Registration-record lifecycle needs no change (it does not describe the dial transport). `yarn lint:docs` clean.
- **Sibling instance noted, not in scope.** Matchmaking's seeker transport has its own self-primary hook (`MatchmakingSelfServe` in `packages/db-p2p/src/matchmaking/query-transport.ts`) and does not go through `FretTopicRouter.dialMember`; it is unaffected and already handles the case.
- **Type safety / resource cleanup / performance.** Nothing to report: no new types, no resources opened on the local path (it removes a stream open), one string comparison per dial.
- **Tripwires.** None recorded.
