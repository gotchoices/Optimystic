# Blob records, the piece sweep, and the local blob service

Library code in `packages/db-p2p/src/blob/`, exported from both `index.ts` and `rn.ts`; not yet wired into the node (that is `feat-a-node-stores-blob-pieces`).

- `BlobRecord` / `BlobHold` and their JSON codec (`decodeBlobRecord` validates the known fields and keeps every other property as found); `BlobRecordStore` over the node's `IKVStore`, one key per blob under `optimystic-blobs/`, changes serialized per ref by its own promise chain, never writing a record its decoder would refuse, deleting a record whose last hold goes.
- `SweepGate` (writer-preferring shared/exclusive), `InProgressPieces` (reference-counted ids of pieces a put has stored before its record exists) and `PieceSweeper`, which deletes every stored piece in no held blob's tree, closed against a put in progress (`inProgress`), a record changed after the records pass (`changed`, re-walked under the exclusive gate) and a put storing a just-deleted piece (it waits on the gate and rewrites it).
- `localPieceSource`, the unhashed `verified` local source, with the accepted-tradeoff `NOTE:` on same-length disk corruption.
- `LocalBlobService`: `put`, `stat`, `read`, `fetch`, `pin`, `unpin` from this machine alone; `announce` rejects and the listener stubs never fire until the transfer and copying tickets. Sweeps are scheduled after `start()`, a record's deletion, and a put that failed after storing a piece.
- `BLOB_RECORD_KEY_PREFIX` in `NODE_KV_NAMESPACES`; docs/blobs.md (status, records, holds and sweep, what is built and what waits) and the `blob:store` row in docs/debugging.md.

## Review findings

Read the `ticket(implement): feat-blob-records-and-the-local-blob-service` diff against the implement ticket's spec before the handoff, then ran the code.

**Correctness / race reasoning.** Walked each of the sweeper's three guards against the order of operations, and the gate for deadlock: every record change and piece store runs inside one shared hold; a per-ref chain predecessor is always already inside its own shared hold (the chain is only entered from `changeRecord`), so a shared holder waiting on the chain cannot deadlock against a waiting sweep; a record unpinned mid-sweep keeps its pieces for that sweep (conservative) and its deletion schedules the next. No defect in the race design.

**Defect found and fixed (minor, fixed inline).** A string that is not a canonical reference passed to `pin` (or to `read`, whose unawaited last-read touch takes the same path) while a sweep ran was noted into the sweep's `changed` set before `BlobRecordStore` refused it; the sweep's re-walk then called `records.get` on it, `BlobRefError` escaped `walkRecord` (which only absorbs `BlobRecordFormatError`), and the whole sweep rejected. `LocalBlobService.changeRecord` now parses the ref before entering the gate, so nothing invalid is ever noted. Reproduced first (the new test failed with the `BlobRefError` stack through `PieceSweeper.decideAndDelete`), then fixed: test "a change refused for a string that is not a reference leaves a running sweep unharmed".

**Docs.** docs/blobs.md said the `whole` hint "never stands in for looking at the pieces", but `stat` deliberately trusts `whole` with a `size` while the root piece is here (the spec's fast path). Reworded to say what the code does, and the `BlobRecord.whole` field comment to match. Every other file the change touches (blobs.md sections, debugging.md row and count, the `FileKVStore` namespace comment, both entry barrels) was read and agrees with the code. `yarn lint:docs` passes.

**Tests.** The implementer's ten tests each pin a named behaviour from the spec; none restates the implementation or verifies a mock, so none was cut. Added one for the defect above and one for a contract nothing exercised: "deleting a record schedules a sweep that removes its pieces, and stop waits for it" (injected timer; covers the schedule-on-deletion path, a fired timer's run, and `stop` waiting on it). Still unexercised and left to inspection, as the ticket decided: `SweepGate` alone, the store's no-write/no-delete rules, a throwing `change` callback, `listRefs` skipping a bad key, each decoder rejection, the timer firing during a run, `sweep:failed`, and `announce` / the listener stubs.

**Error handling, resource cleanup.** Correction and last-read writes are logged and swallowed by design (a hint, documented as `record:correct-failed` / `record:touch-failed`); scheduled-sweep failures are logged, never unhandled; `changed` is dropped in a `finally`; `inProgress` is released in the put's `finally`. Nothing else eats an exception.

**Type safety, modularity, size.** No `any`; the one `as unknown as BlobRecord` follows full validation. Files are 85–415 lines with small single-purpose functions; comments state constraints rather than narrate. No change.

**Performance.** The costs the spec named carry `NOTE:`s at their sites (candidate ids held in memory, every sweep reading every held blob's list pieces, puts waiting while the decide step deletes). Each read now also notes its ref for a running sweep's re-walk through the last-read touch; that is one record read per read during a sweep and needs no tripwire.

**Tripwires / accepted tradeoffs.** None added. Existing `NOTE:`s left as decided: the unhashed local read, and one unreadable held tree stopping every sweep.

**Validation.** `yarn build` and `yarn test` in db-p2p: 3760 passing, 84 pending, 0 failing. `yarn lint:docs` and `yarn check:rn` pass; `eslint` clean on `src/blob` and the spec.
