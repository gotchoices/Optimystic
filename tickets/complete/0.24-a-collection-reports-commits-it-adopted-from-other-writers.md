# A collection reports commits it adopted from other writers

Part of GitHub #58. The dependent ticket `a-materialized-view-follows-rows-other-members-commit` consumes this in the Quereus plugin.

## What was built

`CollectionInitOptions.onExternalCommits?: (rev: number) => void`, threaded through both `Collection` open sites and exposed on `Tree` via `TreeCollectionOptions`. A refresh (`Collection.updateInternal`) calls it once, synchronously, from the end of `Collection.forgetAndAdopt` (the await-free adopt step), when the adoption is `adopt-divergent`, or `adopt` and the walk found an action entry other than the in-flight write's own (`ownEntry`) or any durable invalidation (`Collection.walkedOthersWrites`). `rev` is the adopted revision. A `refuse` verdict never reports. A throw out of the callback is caught and logged as `collection:external-commits-callback-threw`. `RefreshReport` and `update()`'s return type are unchanged.

Test: `packages/db-core/test/collection-external-commits.spec.ts` — handle A commits; handle B commits through `TailLandsButReportsStale` (its refresh finishes and consumes its own torn entry); A refreshes. A's callback fires once at the adopted revision, B's never.

## Review findings

Read the implement commit (`ticket(implement): a-collection-reports-commits-it-adopted-from-other-writers`) first, then the surrounding refresh code.

- **Correctness of the "own commit never counts" claim — checked, holds.** Every successful own commit advances the held revision past its entry before any later refresh: `foldOwnCommit` → `recordCommitted` on the sync and head-commit paths, and `recordCommitted` at each coordinator success site (`commitOnceLatched`, the partial-commit fold, `execute`, `commitEntry`). A torn own entry is matched by `inFlightActionId` (set by sync, commitHead and the coordinator) and excluded. A refresh meeting an in-flight head commit returns before `forgetAndAdopt`. The idle path (`tailShowsNothingNewer`) returns before the walk.
- **Invalidations re-reported on every refresh? — checked, no.** `Log.getFrom` takes the context revision from the tail entry whatever its kind, so after adopting past an invalidation the held revision covers it, and `getInvalidationsFrom(held.rev)` stops before it on the next walk. An invalidation-only refresh reports once.
- **`refuse` with walked entries — not reachable.** `getFrom(held.rev)` only returns entries above the held revision, and a context below the held revision cannot carry any; the verdict gate is belt-and-braces, as the handoff said.
- **Over-report cases (accepted, no change).** Two handles of one `Database` report each other's commits (in the ticket). A further case found here: a write abandoned with `TornActionError` and `final: false` clears its in-flight mark; if its entry later turns out to have landed, the next refresh reports it as another writer's. That is an over-report of the handle's own write, never a missed external change, so it costs at most one redundant view refresh — same class the ticket already accepted; no tripwire needed.
- **Callback placement / await-freedom — checked.** The call is the last statement of `forgetAndAdopt`, after `advanceContext` and `keepLogEnds`, with no `await` in the method; it precedes the replay, so a replay throw still leaves the call made (correct: the adoption stands).
- **Error handling — checked.** Guarded like `viewChanged`; logs id, tag, revision and message.
- **Type safety / threading — checked.** Only two `new Collection(...)` sites exist and both pass the new argument; `Tree.buildInit` spreads `options`, and `Tree` sets no `onExternalCommits` of its own, so nothing overrides the caller's. The 12-positional-parameter constructor is a maintainability smell but every parameter has a distinct type and there are exactly two call sites; left as is.
- **Tests — kept as written.** The one case pins the own-versus-other branch (the implementer's mutation check confirms it fails if every entry counts) and the positive report; no test added — the remaining branches (idle, deferred, invalidation-only, refuse, callback throw) are each a single early return or a guard already readable at the site.
- **Docs — one fix.** `docs/internals.md` carries the new bullet and the "last cache move" wording fix; read both, accurate. `docs/debugging.md`'s `collection` namespace row did not list the new log line; added `collection:external-commits-callback-threw` there.
- **Source hygiene.** Comments state constraints and why, not narration. `collection.ts` is very large, but this change adds ~60 lines to an existing method family and is not the place to split it.
