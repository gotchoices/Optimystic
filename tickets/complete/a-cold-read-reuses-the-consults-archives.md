# A cold read reuses the consult's archives

GitHub [#39](https://github.com/gotchoices/Optimystic/issues/39), arm 1. A joiner attaching a two-table strand made 16 sequential `sync` requests for 8 distinct blocks, each fetched twice (`cluster-fetch:certified-selected` then `reconcile:certified-selected`), about 1.6 s of a ~2.4 s attach over a relay. Arm 2 (`a-collection-open-reads-its-log-ends-once`) is independent.

## What was built

A read-repair pass (`CoordinatorRepo.fetchBlockFromCluster`) is a consult followed, when the cohort corroborates a revision ahead of this node, by an acquisition. Both used to send each cohort peer the identical `requestBlock({ blockId, rev: undefined })`, whose reply is the peer's whole archive; the consult kept only the claim and threw the bytes away.

- `ClusterLatestCallback` resolves `ClusterLatestAnswer` = `CertifiedActionRev & { archive?: BlockArchive }`. The three-way contract (claim / `undefined` = holds nothing / rejection = silent) is unchanged.
- `queryClusterForLatest` returns `consulted: ConsultedArchives` (a per-peer map): archive-carrying claim → the archive; holds nothing → `undefined`; silent → `undefined`; claim without an archive (the asker's stand-in, a test double) → absent, so the acquisition still asks that peer; self → absent.
- `restoreCorroborated` passes the map to `acquireBlockFromCohort`; `ReconcileBlockCallback` has an optional fourth argument. `createReconcileBlock`'s `fetchAnswer` builds a peer's answer from the map when the peer is in it (through the shared `answerFrom`) and only calls `fetchArchive` otherwise. The commit path passes no map and is unchanged.
- The real `clusterLatestCallback` returns `{ ...claim, archive }`; the `CommitLogTrustAnchor` adapter strips the archive. The mesh harness attaches `serveBlockArchive(...)` so mesh specs run the reuse path.
- Docs updated: `docs/transactions.md` step 2 and the `cohortQueryTimeoutMs` row, `docs/internals.md` (*A behind member actively reconciles*), `packages/db-p2p/docs/cluster.md`, `docs/debugging.md` (`noArchive` now also counts a peer silent in the read's consult).

Accepted on purpose: a peer silent in the consult is not asked again by the acquisition (it is heard by the next consult), and the restored revision is exactly the one the consult saw rather than whatever a re-fetch would return.

## Review findings

Read the `ticket(implement): a-cold-read-reuses-the-consults-archives` diff first, then the handoff.

- **Correctness of the reuse.** Checked by reading that the consult's request and `fetchArchiveFromPeer`'s are identical (same `requestBlock({ blockId, rev: undefined })`, same `withinRequestBudget` with `cohortQueryTimeoutMs`), so a reused archive is byte-for-byte what a fetch would have returned at that moment. `latestClaimFromArchive` and reconcile's `toCandidate` read the same top revision entry, so the consult and the acquisition cannot disagree on what a peer claims. The proof verification and content gate still run on the reused bytes in reconcile, and penalties for a contradicting peer are unaffected. No change needed.
- **Memory.** `claims` copies only `peerId/rev/actionId/proof`, so the archive does not leak into the unsettled-claim memo or any other long-lived state; the map lives only for one `fetchBlockFromCluster` call. The anchor adapter strips it too. No change needed.
- **Silent and stand-in peers.** Silent → `undefined` → reconcile `no-archive`, which is what the production fetch returned for an unreachable peer before, so the commit-path conflation note at `PeerAnswer` still holds (the implementer extended it). The stand-in holding something is absent from the map and is fetched; holding nothing is `undefined`, which is right since it has nothing to give. No change needed.
- **Edge case, logged only:** a peer that answers `success: true` with an archive whose top revision carries no action is now counted `noArchive` in a read-path `reconcile:no-rev-quorum` line, where a direct fetch would have counted it `behind`. The decision is identical (neither is a candidate); only that diagnostic count differs, and only for a malformed archive. Left as is, no tripwire: it is not conditional on any likely future change.
- **Mesh harness.** Its consult still rejects for `silentPeers` and now serves the same unpinned archive `makeFetchArchive` would, so mesh specs exercise the production shape. The extra in-memory `serveBlockArchive` per consult is cheap. No change needed.
- **Tests.** The new spec `a block it has never seen costs one request to the peer that holds it` pins the #39 contract (implementer reports it fails at 2 with the map ignored); the reworked absence spec keeps a control on its counter. Neither restates the implementation. No tests added or cut.
- **Docs.** Read every doc the change touches; they match the code. `MAX_HELD_BLOCK_CONSULTS`'s comment still mentions acquisition's archive fetches over the sync protocol; still true for peers the consult has no archive from, so left.
