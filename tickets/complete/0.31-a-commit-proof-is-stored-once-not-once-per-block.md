# A commit proof is stored once, not once per block

Second half of GitHub #60 (Sereus; optimystic 1.27.0, file storage, solo node). The prereq added a commit proofs store keyed by `messageHash` to every backend; this change makes the storage kernel use it.

## What landed

- The proofs store keeps its `(blockId, rev)` key; its value is now `{ proofRef: messageHash }` (`ProofRef`, `StoredProofEntry` in `i-raw-storage.ts`), and the proof itself is stored once per node in the commit proofs store.
- `KvRawStorage.saveBlockProof` writes the shared record first (first writer wins, accepted-tradeoff `NOTE:` at `storeCommitProofIfAbsent`), then the reference; a per-kernel memo of up to 1024 message hashes (`storedCommitProofs`) makes a commit of N blocks read and write the shared record once, joins concurrent saves of one message, and drops a rejected save so the next one retries.
- `KvRawStorage.getBlockProof` resolves a reference (a missing target logs `proof-ref-dangling` on the new `storage` namespace and answers no proof) and returns an entry holding a whole proof — what every earlier build wrote — as it is.
- `IRawStorage.getProofEntry` / `saveProofEntry` give raw access; `RawStorageDriverAdapter` maps the driver's proofs store onto them so `CachedRawStorage` passes references through. `IBlockStorage.hasBlockProof` answers presence from the entry alone, used by `StorageRepo.backFillProof`.
- Measured on one solo node with file storage (5 commits of 500 rows, 4 secondary indexes): proofs went from 834 files and 26.3 MB to 834 references and 14 proofs in 196 KB (the full table is in the `ticket(implement): a-commit-proof-is-stored-once-not-once-per-block` handoff; the summary is in docs/internals.md).

Tests: two conformance cases (one proof saved for three blocks is stored once and each entry refers to it; a legacy whole-proof entry reads back), run against every backend and composition; an upgrade-check case that reads, over each of the 38 released fixtures, the proof the older build stored for the diary log tail's latest revision and checks it names that `(blockId, rev, actionId)`.

## Review findings

Read the `ticket(implement): a-commit-proof-is-stored-once-not-once-per-block` diff first, then the handoff.

**Checked, no defect found**
- Write ordering: the shared record is written (or found) before the reference on every path, including a memo hit, which awaits the same promise that wrote the record — so the flush contract's prefix rule keeps no reference without its target.
- Memo: rejection drop is identity-checked (`peek(...) === storing`), so an evicted-then-replaced entry is not removed by a stale rejection; the returned promise carries the rejection to every joined caller, and `persistProofIfContentMatches` / `backFillProof` already log a proof-persist fault instead of failing the commit. No unhandled rejection: the `.catch` branch is a handled derivative. The snapshot-at-call-time contract (conformance "saveBlockProof snapshots") holds because the encode happens synchronously on a miss; on a hit nothing of the caller's object is stored.
- Composition: in `CachedRawStorage` the outer kernel composes and the inner storage sees only raw entries (`getProofEntry` / `saveProofEntry`) and raw commit-proof reads and writes, so no double resolution and no reference stored as a proof. Every `IRawStorage` implementation (the kernel, and the three test wrappers) gained the two methods.
- Legacy read: `isProofRef` keys on a string `proofRef`, which no `BlockCommitProof` carries; the upgrade-check case proves real fs and LevelDB data from 1.0.0-beta.3 through 1.27.0 reads back.
- Callers of `getBlockProof` (`servableProof`, `served-repo-proxy`, `StorageRepo.getBlockProof`) get the same artifact as before; the presence-only caller (`backFillProof`) now does one key lookup.
- The `messageHash` precondition is enforced by `BlockCommitProof`'s type; only a cast can violate it, so no runtime check was added.
- Docs: storage.md (choke-point quote, latch note, §5 composition, fs layout), internals.md *Persistence and retention*, debugging.md namespace row, and the four backend READMEs all describe the new layout.

**Found and fixed in this pass**
- docs/internals.md, the bullet "Proof retention is per revision, and not retroactive" (under *The certified exception*) said a proof-less revision keeps no proof even if later certified evidence arrives, contradicting the back-fill that `StorageRepo.saveReplicatedBlock` performs on a certified push of an already-held `(rev, actionId)`. Rewritten to say a proof-less revision gains one only by that back-fill, and that a member whose bytes diverged never does. (Pre-existing staleness, flagged by the implementer.)

**Tripwires / conditional concerns** — none new. The two conditional costs (an in-flight memo entry evicted under 1024 concurrent messages degrading first-writer-wins to last-writer for that message; a dangling reference, unreachable under the prefix rule, read by `hasBlockProof` as present so back-fill would not repair it) are already stated at the memo's doc and the `proof-ref-dangling` site.

**Tests** — kept as written: the two conformance cases pin the storage contract across every backend at no measurable cost, and the upgrade-check case pins reading data released builds wrote. No test cut; none added (no defect in code was found). The fixture changes (`messageHash` on a cast proof in `block-storage.spec.ts`, wrapper methods in three test doubles) are required by the new interface.

The build was the implement commit's (review changed no source).
