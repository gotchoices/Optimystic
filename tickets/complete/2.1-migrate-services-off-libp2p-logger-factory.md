# Complete: db-p2p services migrated off libp2p's logger factory

Step 2 of 3. Every remaining `components.logger.forComponent(name)` call in `packages/db-p2p/src`
is gone; all nine sites now build their channel with the package's own `createLogger`, so a single
`DEBUG=optimystic:db-p2p:*` shows every line the package writes. Step 3
(`lock-and-document-db-p2p-log-namespaces`, in `implement/`) still owes the lint rule, the
structural guard tests, and the `docs/debugging.md` namespace table.

## What landed

| File | Namespace now |
|---|---|
| `src/cluster/service.ts` | `createLogger(init.logPrefix ?? 'cluster-service')` |
| `src/repo/service.ts` | `createLogger(init.logPrefix ?? 'repo-service')` (module-level `debugLog` merged into `this.log`) |
| `src/sync/service.ts` | `createLogger('sync-service')` |
| `src/dispute/service.ts` | `createLogger('dispute-protocol')` |
| `src/network/network-manager-service.ts` | `createLogger('network-manager')` |
| `src/cluster/block-transfer-service.ts` | the file's own `log.error` (optional `logger` component deleted) |
| `src/libp2p-node-base.ts` ×3 | the file's `wiringLog`, plus a new `node-wiring:arachnode` child |

`ClusterService` and `DisputeProtocolService` were renamed (`cluster-service`, `dispute-protocol`)
because `cluster` and `dispute` already belong to `ClusterCoordinator` and `DisputeService`. Five
components interfaces lost their `logger` field; `BlockTransferServiceComponents` lost its optional
one. `logPrefix` on the cluster and repo services now names a sub-namespace under
`optimystic:db-p2p:` rather than a full libp2p namespace, so an embedder can no longer use it to
move lines outside the documented tree.

## Review findings

### Checked and clean

- **Migration is complete.** `grep -rn forComponent packages/db-p2p/{src,test}` returns only prose
  (one explanatory comment in `libp2p-node-base.ts`, three in `test/logger.spec.ts`). Repo-wide,
  no other package contains the symbol. `grep -rn "logger:"` across `packages/*/src` and
  `packages/db-p2p/test` returns nothing, so no construction site still passes the removed field.
- **No external construction sites.** Every `new RepoService` / `ClusterService` / `SyncService` /
  `DisputeProtocolService` / `BlockTransferService` / `NetworkManagerService` in the workspace is
  inside `packages/db-p2p` (63 sites, all `src/` factories or `test/`). The interface break is real
  for a downstream embedder — the package is published as `@optimystic/db-p2p@0.28.0`, not private —
  but nothing in this repo is affected, and a 0.x minor carrying a breaking change is this repo's
  existing convention.
- **`logPrefix` cannot escape the tree.** `createLogger` concatenates `optimystic:db-p2p:` onto
  whatever it is handed, so the doc comment's claim holds by construction, not by convention. A
  value like the old `'db-p2p:repo-service'` produces a redundant but still in-tree namespace.
- **The auth-spec namespace assertion is load-bearing.** Verified by mutation: renaming
  `cluster-service` to a wrong value in `src/cluster/service.ts` fails 3 assertions across
  `inbound-stream-authorization.spec.ts` (lines 318, 334) and `cluster-error-propagation.spec.ts`
  (line 182), then reverted. A sink-was-called stub would have passed.
- **`%p` / `%e` substitution reaches the sink.** `debug` resolves its own formatters and splices
  the consumed arguments out before calling `debug.log`, leaving `%s` for downstream
  `util.format` — which is why the new specs assert through `hasLine` rather than `hasTag`. The
  reasoning in the spec comments matches what `debug` actually does.
- **Error paths stay safe.** Both `%p` sites read `connection?.remotePeer`, and `createLogger`'s
  `%p`/`%e` formatters have nullish guards, so an absent connection logs `undefined` rather than
  throwing inside a catch block.
- **`repo-service` still means what the docs say.** `this.log` has exactly one non-error call site
  (the redirect line); everything else goes to the `:error` child. So
  `DEBUG=optimystic:db-p2p:repo-service` still shows redirect decisions and nothing more, and
  `docs/debugging.md`'s "Routing and redirect decisions" recipe is unchanged in meaning.
- **Docs outside the namespace table need nothing.** `packages/db-p2p/readme.md`,
  `packages/db-p2p/docs/*`, and all of `docs/` contain no mention of `forComponent` or
  `components.logger`, and no recipe names `arachnode`, `node-wiring`, `spread-on-churn` or
  `owned-block-seed`. `docs/optimystic.md`'s consensus recipe uses the wildcard
  `optimystic:db-p2p:cluster*`, which matches the renamed `cluster-service` too. The two exact-match
  `optimystic:db-p2p:cluster` recipes in `docs/debugging.md` (lines 514, 535) still resolve to
  `ClusterCoordinator`; step 3's ticket already owns revisiting them.

### Minor — fixed in this pass

- **`libp2p-node-base.ts:1116` interpolated a caller-supplied message into the format string.**
  The arachnode logger was `(msg, ...args) => wiringLog(\`arachnode: ${msg}\`, ...args)`, which is
  correct only while every call site passes a `%`-free literal — an invariant nothing enforced, and
  which the implementer's own handoff listed as an unenforced assumption. Replaced with
  `createLogger('node-wiring:arachnode')`, the same nested-channel convention the package already
  uses for `storage:restoration` and `network:get-manager`. This removes the hazard outright,
  keeps the lines under `optimystic:db-p2p:node-wiring*` next to the rest of the wiring story, and
  makes them separately filterable — so the tripwire `NOTE:` the implementer left about
  filterability is retired rather than carried forward. Step 3's docs-completeness guard picks the
  new namespace up automatically, since it scans `createLogger('…')` literals.

### Considered and deliberately not changed

- **The `spread-on-churn init failed` line now logs on `node-wiring`, not on the package's existing
  `spread-on-churn` channel.** An operator narrowing to `DEBUG=optimystic:db-p2p:spread-on-churn`
  will not see the one line saying spread never started. Left as-is: it is a node-wiring failure
  raised in the node-wiring file, it is visible under the documented `optimystic:db-p2p:*` filter
  (which is the regression this ticket exists to close), and step 3 writes a real description for
  the `node-wiring` row. Same reasoning for `owned-block-seed`, which has no channel of its own.
- **`BlockTransferService` logs through a module-level logger, so two instances in one process are
  indistinguishable** — unlike the cluster/repo services, which now have per-instance loggers.
  `createLogger`'s peer-id suffix is the fix if that ever matters, and `src/logger.ts` already
  carries a `NOTE:` saying exactly that for the package's ~30 flat-namespace call sites. Not
  duplicated at this site.
- **`libp2p-node-base.ts` is 1803 lines.** Measured with `wc -l`. Pre-existing and untouched in
  substance by this diff; the site is already claimed by
  `backlog/debt-node-factory-wiring-steps-own-their-teardown`. No new ticket.
