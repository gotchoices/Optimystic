# Complete: block reads say whether a cohort confirmed them

Before this change a reader could not tell three things apart: an answer the whole cohort confirmed, an answer from a node that merely cannot see its cohort, and an answer from a node that really is the only machine. All three arrived as the same unflagged `GetBlockResult`, because the existing markers (`unavailable`, `unconfirmedAheadRev`) are *doubts* — absent means "no reason to doubt", which an answer nobody was asked about also satisfies. This landed the positive fact, plus the one question the reachability gate could not answer, so `feat-unreferenced-blobs-are-reclaimed` can require both.

Nothing branches on the new marker and nothing sets the new request field, so no existing behaviour changed.

## What landed

Implemented in `ticket(implement): feat-blob-reads-say-whether-a-cohort-confirmed-them`; the review pass below fixed one defect in it and tightened two things.

**Two wire fields** (`packages/db-core/src/network/struct.ts`). `GetBlockResult.cohortConfirmed?: true`, set by the answering coordinator when a cohort member other than itself vouched for the answer; and `BlockGets.awaitConsult?: true`, which asks the answering coordinator to run a window-demanded consult *in front of* the answer rather than behind it. Both optional and additive — a `get` reaches `CoordinatorRepo.get` as the object it was sent as, and replies carry whole entries (`fitGetReply`), so there is no protocol change and no version gate. `downstreamGets` forwards `awaitConsult` with one more conditional spread, exactly as it forwards `skipWindowConsult`.

**The freshness stamp records whether it vouches** (`packages/db-p2p/src/repo/coordinator-repo.ts`). `FreshnessStamp.vouched?: true`. `markBlocksSeen` takes one `basis: { vouched: boolean; floor?: number; quiet?: QuietCohort }` object instead of two positional optionals, so each of its nine call sites states what it means rather than inheriting a default. The cluster commit path's three `armFreshness` sites pass `true` (consensus ran, so another member signed); `noteCohortCommitApplied` passes `applied.cohortSize > 1`; `commitSolo` and the solo-self read exit pass `false`; the three consult exits pass their own verdict. The test seam that writes the map directly writes no `vouched`, so it does not.

**One shared predicate, `consultVouches`**: `answered.length > 0 && silent.length === 0 && currency.kind === 'nothing-ahead' && absence !== 'claimed'`. `fetchBlockFromCluster` returns `vouched: boolean` as a required field, so an exit added later has to choose.

**`markCohortConfirmed`**, called last on each `readRepairBlock` path, after the entry has been replaced by the refreshed read and every doubt flag applied; it refuses an entry carrying `unavailable` or `unconfirmedAheadRev`. The `skipWindowConsult` opt-out, a consult started behind the read, and a consult that threw do not call it at all, so those answers read as unconfirmed.

**`KeyNetworkCohortReachability.aloneFor`** (`packages/db-p2p/src/network/cohort-reachability.ts`). True only when every distinct block's cohort is this node alone *and* the self-only view passes the same test `reachable` applies to one. Exposed through a new `CohortAloneness` interface intersected into `NodeCohortReachability`, so `node.cohortReachability.aloneFor` is reachable; deliberately **not** on db-core's `ICohortReachability`, which would force an answer out of `alwaysReachable` for a question only a node with a real key network can answer.

## Review findings

**Checked by reading the implement diff first and then the surrounding code, and by running it:** every exit of `fetchBlockFromCluster` against `consultVouches` (missing block with the cohort answering, held block at the corroborated revision, convergence, failed convergence, `cohort-too-small`, partial silence, empty cohort, solo-self, no callback); all nine `markBlocksSeen` call sites and the one direct map write; every path through `readRepairBlock` that can reach or skip `markCohortConfirmed`, including the `'off'` and `'paranoid'` modes, the quiet span, the `skipWindowConsult` opt-out and the `catch`; whether the two new fields survive the wire (they do — `RepoBlockGets` widens `BlockGets` and `fitGetReply` carries entries whole, so neither is enumerated field by field anywhere); whether the marker can be carried onto content it did not confirm by `NetworkTransactor.get`'s merge (it cannot — whole entries are selected); resource cleanup and listener handling in `aloneFor` (it adds none); and every doc file the change touched.

**Major — one real defect, fixed in this pass.** The inside-window exit read the stamp's `vouched` directly, on the stated reasoning that a `'lazy'` node reaching that exit has a stamp at most one `readRepairWindowMs` old. That is false. `readRepairDemand`'s `'lazy'` arm also returns "no consult" for a block under a **silent-consult hold** (`SilentConsultHolds`), whatever the stamp's age — and that hold is placed by exactly the consult outcome `consultVouches` refuses to vouch for, while that outcome's exit writes no stamp. So a vouching stamp from *before* the silence stood, and a read during the hold reported a silent cohort's answer as `cohortConfirmed`: the one thing the marker exists to prevent, on the one consumer that deletes data. Reachable on default settings on any node that declares a link round trip (`retryBackoffBaseMs`, hence `linkRoundTripMs`), and reachable *faster* there than the sizes suggest, because the hold cap (`reconcilePassTimeoutMs`, 5 s at the default per-peer budget) is shorter than the default 10 s window, so the stamp is already expired when the hold begins. Fixed by checking the stamp's age at the site (`stampVouchesNow`), which is the invariant the comment already claimed; a quiet span still reaches its own exit, whose `quietCohortStillVouches` guarantee is what legitimately extends the cadence there. One consequence changed deliberately: a `readRepairMode: 'off'` node now reports a held block confirmed for up to one window after a cohort commit stamped it, instead of never — the stamp is a real consensus fact and the age bound is the honest test, where the old mode gate was a proxy for it.

Pinned by one new case in `packages/db-p2p/test/coordinator-repo-cohort-confirmed.spec.ts` ("stops vouching from a stamp that outlived the window, which a silent-consult hold lets happen"), which was confirmed to fail against the pre-fix predicate and pass after it.

**Architecture, not a point ticket.** The defect is the class `backlog/debt-freshness-state-scattered-across-coordinator-repo` already names — "it is easy for a future change to read a record without checking everything that is known about how fresh it is". Its root cause is that `readRepairDemand` collapses four distinct reasons for *not* consulting into one `undefined`, so a caller that wants to know what the stamp means has to reconstruct which reason applied. Appended as that ticket's nineteenth measurement (with the line counts and the recommendation that the collaborator hand back the negative reason the way `ReadRepairDemand` already names the positive ones), rather than filed again as an instance.

**Minor, fixed in this pass.** `judgeAlone` duplicated `judgeCohort`'s cohort assembly — the routing key, the `findCluster`, the self-only tests and the FRET grace `NOTE:` — differing only in what it makes of "the cohort names another member". Both gates now read the cohort through `judgeAlone` and `judge` interprets `'other-members'` as open, so a change to how the cohort is assembled (the `NOTE:`'s own suggestion, requiring a live connection) cannot be applied to one and missed by the other. `aloneFor` keeps its one-line-per-false-answer record by catching at the call site.

**Tripwire parked, not filed.** `NetworkTransactor.get`'s merge breaks an equal-rank tie on served revision alone, so a confirmed entry can lose to an unconfirmed entry at a newer revision and the merged answer then carries no marker. That is the fail-safe direction and the marker is deliberately unranked — ranking it would let it change which *content* a read returns. Recorded as a `NOTE:` at `rankOf` in `packages/db-core/src/transactor/network-transactor.ts`, because nothing at the site said so and the omission is load-bearing.

**Tripwire carried forward from implement, re-read and left as it is.** `consultVouches`'s `NOTE:` records that a **held** block needs a corroborated revision to be confirmed, because the no-quorum path reports any claim at all as `absence === 'claimed'` — so an *undeclared* two-machine deployment (`clusterSize` left at the default while only two machines exist) never confirms a held block. Reclaiming there keeps every blob, which is no worse than before the marker existed, and the remedy (declaring `clusterSize`) is named at the site.

**Considered and not acted on.** `tolerateLocalCommitDivergence` stamps `vouched: true` while this node holds nothing of the commit; correct, since the stamp covers blocks a durable majority of other members holds and consensus ran, and in any case unreadable for a block this node does not hold (such a read is `isMissing` and consults). `aloneFor([])` answers true vacuously, as `reachable([])` does; there are no answers to act on, so it changes nothing for the consumer. The entry mutation in `markCohortConfirmed` matches `flagUnconfirmedCurrency` and `flagUnconfirmedAbsence` exactly, so it introduces no new sharing question.

**Tests.** The implementer's four cases were kept — each pins a distinct contract (marked, unmarked on silence, never marked on a self-only view, and `awaitConsult`'s ordering), none restates the implementation and none verifies a mock, and the `aloneFor` describe's first assertion earns its place by proving `reachable` true and `aloneFor` false in the same test. One case added for the defect above; the factory grew a `setMemberAnswer` and a `retryBackoffBaseMs` option to express it. Nothing cut. No test added for the wire fields or `downstreamGets`' forwarding: a type and one conditional spread, exercised end to end by the coordinator specs.

**Empty categories, with reasons.** No performance finding: the change adds one map read per inside-window read and one boolean per consult exit, and `aloneFor` makes the same `findCluster` call per block that `reachable` does. No resource-cleanup finding: nothing new is allocated, subscribed or timed. No type-safety finding: both new verdict fields are required rather than optional, which is what forces a later exit to choose, and `yarn typecheck` covers the widened `NodeCohortReachability` across all 13 packages.
