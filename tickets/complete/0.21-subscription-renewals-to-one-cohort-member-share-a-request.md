# Subscription renewals to one cohort member share a request

Found while planning `the-reactivity-backstop-check-costs-nothing-while-idle` (GitHub [#48](https://github.com/gotchoices/Optimystic/issues/48)). Each watched collection's cohort-topic registration used to be renewed on every tick (TTL / 3: 30 s Core, 20 s Edge) with its own signed `RenewV1` to its primary over `/register`: 18 tables on an Edge phone whose primary is the other machine of a two-member group cost about 54 renew requests a minute. Now that is one request per tick (3 a minute), and none when the primary is this node.

## What landed

- **Wire (db-core).** `RenewBatchV1 { v, renews: RenewV1[] }` / `RenewBatchReplyV1 { v, replies: RenewReplyV1[] }`, `MAX_RENEW_BATCH_ENTRIES = 64`, validators and decoders. The request validator refuses an empty or oversized batch and any entry where `reattach` or `withdraw` is present at all.
- **Port.** Optional `ITopicRouter.dialMemberRenewBatch` and `RenewBatchUnsupportedError` in `ports.ts`.
- **Participant.** `RenewalParticipant.preparePing` / `settlePing`; `pingLoop` is the two around one send.
- **Service.** `CohortTopicService.renewMany(handles)`; `renew(handle)` is `renewMany([handle])`. It runs at most one cycle per registration (`LiveRenewal.cycle`, released by each cycle's own settle with an ownership check), groups prepared pings by primary, chunks at 64 and sends one batch per chunk. A lone ping, a router without the batch method, or a member remembered as not speaking the protocol gets single pings. `RenewBatchUnsupportedError` makes it remember the member for `RENEW_BATCH_UNSUPPORTED_RECHECK_MS` (10 min) and re-send that chunk singly in the same call. Every send finishes before anything is settled, and a handle that was displaced or withdrawn while its ping was out is not settled. Once every cycle has settled, the call rejects with the single error, or an `AggregateError` when several cycles threw.
- **db-p2p.** `/renew-batch` protocol (`PROTOCOL_COHORT_RENEW_BATCH`, both builders, `cohortTopicProtocolList`). `FretTopicRouter.dialMemberRenewBatch` serves a self-addressed batch in process. A remote negotiation refusal (`isUnsupportedProtocolError`, now shared with `identify-on-open.ts`) becomes `RenewBatchUnsupportedError`. The host's `handleRenewBatchFrame` answers each entry through `resolveRenew` and is registered on the protocol.
- **Watch service.** `tick` makes one un-awaited `renewMany` over every ticked subscription's handle; the per-subscription queued renew step is gone.
- **Docs.** `docs/cohort-topic.md` §TTL and renewal, §Protocol IDs and §Renew batch; `docs/internals.md` §Protocol IDs; `docs/reactivity.md` §The node's watch service.

## Review findings

Read the diff of `ticket(implement): subscription-renewals-to-one-cohort-member-share-a-request` before the handoff, then the touched docs and the unchanged neighbours (`ReactivitySubscriptionManager`, `resolveRenew`, `handleRegisterFrame`, `makeFrameHandler`).

**Correctness: checked, no defect found.**
- In-flight guard: a handle named twice in one call is taken once. `endCycle` checks ownership, so the outer `finally` cannot release a later call's mark. The implementer's second service test fails on the earlier whole-call release.
- Primary stability: between `preparePing` and `settlePing`, a registration's primary changes only through its own settle (guarded) or a re-register. A re-register displaces the handle, and `settleCycle` skips a displaced handle. `moveRoot` does not change the primary.
- Failure mapping matches the single path: signer failure, link failure, a malformed reply and a wrong-length reply each count as no answer (a strike). An unsupported member falls back to single pings in the same call. A lone failover's throw is rethrown as itself, so `renew` callers see what they saw before.
- Frame size: 64 pings of a few hundred bytes each stay far under both the 1 MiB codec ceiling (`DEFAULT_MAX_MESSAGE_BYTES`) and the 512 KiB stream ceiling (`DEFAULT_STREAM_MAX_BYTES`).
- Member side: `handleRenewBatchFrame` gives each entry exactly the `/register` answer (`resolveRenew`). A malformed frame throws inside `makeFrameHandler`'s try, so the stream is closed rather than leaked.
- Watch service: the ticked subscriptions' handles come from `ReactivitySubscriptionManager.registration`. A subscription with no registration yet contributes nothing. A withdrawn handle is skipped by `liveRenewal`.
- `ReactivitySubscriptionManager.renew` and `RenewalParticipant.pingLoop` now have no production caller; both are kept on purpose (public manager surface, and the single-cycle form the registration tests drive).

**Minor, fixed in this pass.**
- `handleRenewBatchFrame` in `packages/db-p2p/src/cohort-topic/host.ts` was a synchronous function wrapped in `Promise.resolve` at both call sites (the inbound handler and the router's in-process path). It is now `async`, like `handleRegisterFrame`, so a malformed frame rejects instead of throwing, and both wrappers are gone.

**Tests.**
- Kept all four new tests. Each pins a contract with real branching or an observed defect: the per-reply settle across one batch, the per-registration in-flight release, the unsupported fallback with its recheck window, and the validator's refusal of privileged entries.
- Kept the real-libp2p router test. It is the only test of the third-party contract that the mixed-version fallback rests on: libp2p's `UnsupportedProtocolError` name. It costs about 0.5 s.
- Added no test for the member-side handler. It is wiring around `resolveRenew`, which is already covered, and the rules say not to test wiring.

**Considered and left as recorded.**
- `AggregateError` on Hermes. It appears only when two or more cycles throw in one call. A single-handle `renew` can never construct one. The watch service catches and logs any rejection, so even a missing global would only change the logged error, not behaviour. Left as is; it is already noted in the implementer's handoff and is not worth a ticket.
- The extra connection left by each negotiation refusal: tripwire `NOTE:` already at `FretTopicRouter.dialMemberRenewBatch`, bounded to one refusal per older member per 10 minutes.
- Growth of the `batchUnsupportedUntil` map: tripwire `NOTE:` already at the map in `service.ts`.
- Behaviour change for direct `renew` callers: while a cycle for that registration is still running, `renew` now resolves at once without pinging. That is intended, and documented on `renewMany`.

**Not found / empty.**
- No major findings, so no tickets were filed.
- No pre-existing test failures.
