# Complete: blob protocol wire format, frames and the progress deadline

The parts of the blob protocol (`${prefix}/db-p2p/blob/1.0.0`, docs/blobs.md §Moving pieces between machines) that need no node wiring. Nothing registers or calls them yet; the server, client, node wiring, stall specs and docs are `feat-blob-protocol-frames-stat-and-get` (in `implement/`, prereq on this slug). Landed by `ticket(implement): blob-protocol-wire-and-frames`.

## What was built

- **Limits** in `packages/db-p2p/src/protocol-limits.ts`: `MAX_BLOB_HEADER_BYTES` (16 KiB), `MAX_BLOB_PIECE_FRAME_BYTES` (db-core's `MAX_BLOB_PIECE_BYTES`, 1 MiB), `MAX_BLOB_GET_PIECES` (16), `MAX_BLOB_STAT_REFS` (64), `MAX_BLOB_INBOUND_GETS_PER_PEER` (2), `MAX_BLOB_INBOUND_GETS` (16).
- **Wire** (`blob/blob-protocol.ts`): `buildBlobProtocol`; `BlobRequest`, `BlobAnswer` and the literal unions; `encodeBlobHeader`, `decodeBlobRequest`, `decodeBlobAnswer` (field-by-field, references and piece ids through db-core's `parseBlobRef` / `parsePieceId`); `checkAnswerFits`; `BlobTransferStalledError`, `BlobPeerRefusedError`, `BlobProtocolError` (an `Error`, deliberately not a `RangeError`). The module doc carries the frame sequences.
- **Progress deadline** (`blob/progress-deadline.ts`): one unref'd timer, `touch()` one assignment, re-armed for the remainder when touched, else aborts `signal` with `BlobTransferStalledError`.
- **Frames** (`blob/blob-frames.ts`): `readBlobFrames` (per-chunk touch, per-position length cap in `onLength`, returns an `AsyncIterator`, translates the decoder's own framing faults to `BlobProtocolError` by `code`), `sendBlobFrame` (send, then `onDrain` under the deadline when the transport is full), `closeBlobStream`.
- **`openStreamWithin`** in `protocol-client.ts`: `ProtocolClient`'s former private dial step, moved verbatim and shared.
- **`Libp2pKeyPeerNetwork.peersServing`**: order kept, self and record-less peers dropped, no membership predicate.
- Exports added to both `src/index.ts` and `src/rn.ts`.

## Review findings

Read the implement diff first, then the handoff; checked the code against `it-length-prefixed` 11.0.1's `decode` source and `@libp2p/utils`' `onDrain`, and against what the next ticket (`feat-blob-protocol-frames-stat-and-get`) expects to call.

- **Correctness of the frame reader — checked, sound.** `onLength` is called exactly once per frame, after the prefix is consumed, so `framesStarted` counts frames correctly; the decoder checks `maxDataLength` before `onLength` and treats any `RangeError` from that block as an incomplete prefix, so `BlobProtocolError` extending `Error` is load-bearing. The four codes in `DECODER_FAULTS` match the installed library's error classes exactly. A zero-length frame is yielded (and then refused by the header parser or, for a piece, by the next ticket's CID check). Ending between frames reports `done`, as the handoff says.
- **Drain wait — checked, sound.** `onDrain` rejects on the stream's `close` event as well as on the deadline's signal, so a reset during a drain wait does not hang the sender.
- **Codec — checked.** Every refusal path throws `BlobProtocolError`; the "not a canonical piece CID" message used for references is accurate, since a reference is its root piece's CID. Unknown fields ignored, `announce.scope` only typed, duplicates allowed in `stat`: all as the handoff stated and consistent with the next ticket's plan.
- **Dial helper move — checked.** Body identical, log lines unchanged, no other reference to the removed private method anywhere in the tree.
- **Interfaces against the next ticket — checked.** Every name and signature the next ticket's plan calls (`readBlobFrames`, `sendBlobFrame(..., cap)`, `closeBlobStream`, `ProgressDeadline(peer, ms)`, `openStreamWithin(..., { signal, dialTimeoutMs })`, `peersServing`) exists in that shape.
- **Tests — one added.** The next ticket's plan marks every malformed-header case as "Inspection", and the header is the one input a hostile peer controls, so `packages/db-p2p/test/blob-protocol-codec.spec.ts` pins three behaviours: every refusal arm of `decodeBlobRequest` (plus one accepted header as the positive control); an oversized header refused from its length prefix alone while the source never delivers the body; and a piece over 1 MiB and a mid-frame end both reported as `BlobProtocolError`. Mutation-checked: changing `BlobProtocolError` to extend `RangeError` makes the oversized-header case hang to mocha's timeout. No test added for `ProgressDeadline`, `sendBlobFrame` or the happy path; the next ticket's real-node stall specs reach those.
- **Resource cleanup — checked.** `ProgressDeadline.stop()` idempotent and clears the only timer; the reader's `return()` propagates down to the stream, as its doc warns.
- **Clock jumps — noticed, no action.** `ProgressDeadline` measures idle time with `Date.now()`, so a wall-clock jump forward can trip a deadline early; every other deadline in db-p2p does the same, and a tripped deadline only costs one retry. Not parked anywhere.
- **Dial timer not unref'd — pre-existing**, carried over unchanged by the move (the handoff's known gap); not this ticket's scope.
- **Docs — deferred by design.** docs/blobs.md is updated by the next ticket's Docs section, which already lists the citations; no doc in the tree names anything this ticket removed.
- **Major findings — none**, so no tickets filed. **Tripwires — none new**; the two `NOTE:`s the implementer placed (`readBlobFrames` buffering, `peersServing` stream-merged protocols) are accurate.
