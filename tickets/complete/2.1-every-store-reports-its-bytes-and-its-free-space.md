# Every store reports its bytes and its free space

## What landed

Three things, all groundwork for `a-node-measures-its-use-against-one-allotment` (in `tickets/implement/`), which is where the figures get a consumer.

### 1. A free-space capability, optional by presence

`approximateBytesFree?(): Promise<number>` on `RawStoreDriver` and `BatchBackend`, surfacing as `getApproximateBytesFree?(): Promise<number>` on `IRawStorage`. The contract, stated once on `IRawStorage.getApproximateBytesFree` and pointed at from the other two: it answers the bytes the store's **location** will still accept (not this store's share of it, so two stores over one location answer the same figure); it is advisory and may be stale, like `getApproximateBytesUsed`; **a failed read rejects and never answers 0**, because 0 means "full" and a transient failure read as full would make a node shed responsibility it did not need to shed; and presence is fixed for the store's life, so a backend that cannot ask its platform omits the method entirely rather than installing a stub.

The whole passthrough chain is wired, each conditional on the thing below having one: `KvRawStorage`, `WriteGroupDriver`, `JournalBatchBackend`, `CachedStoreDriver`, `RawStorageDriverAdapter` (and so `CachedRawStorage`, and so the result of `withReadCache`), and the test-only `TextReadsJournalStore`.

Which backends have one:

| Backend | Free space | How |
|---|---|---|
| `db-p2p-storage-fs` | yes | `fs.promises.statfs(basePath)`, `bavail * bsize`, in `FileBatchBackend`. Opens first, so `statfs` never names a directory the store has not created. `FileRawStorage` re-declares it as always-present. |
| `db-p2p-storage-web` | yes, in a browser | `navigator.storage.estimate()`, `max(0, quota - usage)`, in `IndexedDBJournalStore`. An optional instance field wired in the constructor, so the method is **absent** where there is no `navigator.storage.estimate`; rejects when the estimate carries no `quota`. |
| `db-p2p-storage-ns` | no | handed an open `SqliteDb`, not a path; no free-space call reachable from a handle. `NOTE:` at the site, plus the README. |
| `db-p2p-storage-rn` | no | handed a `LevelDBLike` handle, same gap. `NOTE:` at the site, plus the README. |
| `MemoryStoreDriver` | no | no disk; the free space of a `Map` is the heap, which is not an allotment. `NOTE:` at the site. |

### 2. `IKVStore.storeIdentity?()`

The same one-directional contract `IPieceStore.storeIdentity` carries. Implemented by `FileKVStore` (`fileStoreIdentity(basePath)`), `SqliteKVStore`, `IndexedDBKVStore` and `LevelDBKVStore` (`identityForHandle` under each package's existing scheme constant, on the same handle object the block store tags). `MemoryKVStore` reports none, and its class doc says why.

No `bytesUsed` was added, deliberately; the reason and the condition that would change it are a `NOTE:` on the interface.

### 3. One coverage assertion for all three of a node's stores

New module `packages/db-p2p/src/storage/store-coverage.ts`:

- `blockStoreCountsPieces(storage, pieces)` — moved from `storage-monitor.ts` unchanged. `storage-monitor.ts` imports it.
- `assertOneMeasuredLocation(storage: NodeStorage, location: string)` — replaces `assertBlockStoreCountsPieces`. Throws unless the block store has a `getApproximateBytesUsed`, reports a `getStoreIdentity()`, and **both** the key-value store's and the piece store's `storeIdentity?.()` equal it. The message names the location and which part disagreed.

The four `*NodeStorage` factories call it in place of the old helper, passing their location unchanged. `memoryNodeStorage()` still asserts nothing, correctly: nothing in memory reports an identity.

### Docs

`packages/db-p2p/docs/storage.md` §3 (*Raw Storage Interface*) carries the "How much room is left" paragraph and the backend table; §8's factory paragraph says the assertion covers all three stores and names what each half would otherwise cost silently (pieces counted twice; key-value bytes counted not at all). The four package READMEs say whether their package reports free space, and for `ns` and `rn` why it cannot. `docs/blobs.md` and `docs/repository.md` cite the new module.

## Review findings

Read the implement diff (`ticket(implement): every-store-reports-its-bytes-and-its-free-space`) before its handoff summary, then every passthrough site for `approximateBytesUsed` in the repository (to find a wrapper the free figure had been left out of), the four `*NodeStorage` factories and the identity each of their three stores reports, the object-identity contract of `identityForHandle`, `FileBatchBackend`'s `directoryByteSize` (to confirm it really does measure the key-value store's files the assertion now claims for it), both new tests, and every document the change touches.

**Fixed in this pass (five, all minor).**

- **The free-space contract was stated twice, in full.** `IRawStorage.getApproximateBytesFree` and `RawStoreDriver.approximateBytesFree` carried near-identical fifteen-line statements of the same four rules, so a change to the contract needed both edited and could drift. That also inverted the local convention in `raw-store-driver.ts`, where `listBlockIds`, `approximateBytesUsed` and `close` each get a one-line doc and the contract lives on `IRawStorage`. Shortened the driver's to the house style with a pointer to the one home, and repointed `BatchBackend.approximateBytesFree` (which pointed at the driver) at the same place, so each file is one hop from the contract.
- **The free-space documentation was filed under blob pieces.** The paragraph and backend table landed in §7 of `storage.md`, *Blob pieces and records*, whose subject is blobs; a reader looking for the block store's capacity surface would not find it there. Moved verbatim to the end of §3, *Raw Storage Interface*, where the interface is described.
- **A `NOTE:` wedged between a doc comment and the member it documents.** The "there is deliberately no `bytesUsed`" note sat between the JSDoc of `IKVStore.storeIdentity` and the declaration, so it reads as part of that member's documentation when it is about the interface as a whole. Moved below the member; wording otherwise unchanged.
- **An orphaned sentence in the `rn` README.** The new free-space paragraph was inserted between the factory paragraph and its closing sentence ("The three classes stay exported for a caller that needs one on its own"), which then read as part of the free-space claim. Reattached.
- **Mid-paragraph wrapping the edits left ragged** in the `ns` and `web` READMEs and in the class doc of `FileRawStorage` — one line past 120 columns in the middle of a hard-wrapped block. Rewrapped to the surrounding width. Cosmetic.

**Checked and correct, no action.**

- **The capability is not silently lost anywhere.** Every site in the repository that forwards `approximateBytesUsed` now forwards `approximateBytesFree` beside it, under the same presence guard; the only omissions are the three memory and test backends that have no figure to forward. The hazard that this forwarding is a written contract rather than an enforced one already has its `NOTE:` at the bottom of `RawStoreDriver` and needed nothing new.
- **The three handle-based packages' identity equality holds by construction.** Each new key-value store calls `identityForHandle` with its package's own scheme constant on the same handle object the block store tagged, and `identityForHandle` is a `WeakMap` keyed on that object — so `assertOneMeasuredLocation` cannot throw for `ns`, `web` or `rn`. The previous review of `each-storage-package-opens-a-whole-nodes-storage` already decided this is not owed a test (it would assert a shared constant and a `WeakMap`); nothing has changed that. The one derived case is `fs`, where all three stores compute `fileStoreIdentity(basePath)` independently, and that is the case the new fs test covers.
- **The assertion's claim about the key-value store is true of the fs backend.** `FileBatchBackend`'s used-bytes figure is a recursive walk of the whole base path, so the nested key files of `FileKVStore` are inside the measured figure, as the docs now say. The identity of `FileKVStore` is computed from the constructor argument rather than its own resolved copy, which is harmless: `fileStoreIdentity` resolves (and case-folds on win32) internally.
- **`JournalBatchBackend.approximateBytesFree` passing through without an `open()` first** — the asymmetry with `approximateBytesUsed` the implementer asked for a second opinion on — is right, and better than symmetry would be. Free space is the location's and does not depend on whether the journal has been recovered, so asking for a capacity figure should not trigger recovery as a side effect. The fs backend opens itself anyway, because `statfs` needs the directory to exist. The comment at the site already states the why.
- **`bavail` over `bfree`** is the correct choice: `bfree` includes the reserve only root may write into, and the figure a node wants is what an ordinary process can still write.
- **The fs free-space failure path has nothing to test.** `FileBatchBackend.approximateBytesFree` has no error handling at all — a failing `statfs` rejects because nothing catches it — so the handoff's "reject-don't-guess is untested on fs" is the absence of a branch rather than an untested branch. The rule itself is now pinned on the web implementation, which does branch (see below).
- **The capability has no consumer yet.** Deliberate: `a-node-measures-its-use-against-one-allotment` is already in `tickets/implement/` and is what reads it. Nothing else in the tree should have been converted — `packages/upgrade-check/test/current-build.ts` still hand-builds its stores over a two-directory `fs` layout on purpose and calls neither factory nor assertion, and its typecheck is clean.
- **The first two arms of `assertOneMeasuredLocation`** (no used-bytes figure; no store identity) remain unreachable from any shipping factory and untested, as the handoff says. They are defensive messages for a fifth backend, not behaviour a current caller can produce; a test would have to build a stub store to reach them.
- **Source hygiene.** `store-coverage.ts` is 61 lines, `storage-monitor.ts` is down to 133, and the files that grew are 41 to 493 lines. Every comment added carries a why, a constraint or a consequence; none narrates a statement.

**Tests.**

- Kept both of the implementer's. The `assertOneMeasuredLocation` case pins the arm that would otherwise fail silently (an uncounted key-value store has no figure anywhere), and it can fail — unlike a positive case over a factory-built storage, which the factory's own assertion makes unreachable. The `statfs` case is the only execution of the free-space chain end to end, and it pins something the compiler cannot see: `FileRawStorage` re-declares `getApproximateBytesFree` as always-present, which is a claim about runtime wiring that `declare` makes the type checker accept unchecked.
- **Added one pair of cases, for the contract left unverified:** the free-space path of `IndexedDBJournalStore` had never run anywhere, because the package's specs run on `fake-indexeddb` under Node, where there is no `navigator.storage` and the constructor leaves the method off. Two cases in `packages/db-p2p-storage-web/test/indexeddb-storage.spec.ts` install one own `storage` property on Node's existing `navigator` (the platform global, nothing this repository owns, removed after each case) and pin both halves of the rule the next ticket's consumer depends on: `quota - usage` is the figure, and an estimate with no `quota` **rejects** rather than answering 0. Nothing else was added.

**Major findings: none.** Nothing reached the filing bar — no ticket and no `backlog/` entry, because no latent defect was found. The design question that could have been one (does the three-way assertion hold for the handle-based packages, which no test exercises?) resolves to "yes, structurally", above.

**Conditional or speculative: none new.** The implementer's tripwires are correctly placed as `NOTE:`s at their sites — the three free-space omissions, the whole-filesystem scope of `statfs`, and the pre-existing note about two spellings of one directory that travelled with `blockStoreCountsPieces` — and none was re-filed. No accepted-tradeoff `NOTE:` at any site touched had its revisit condition trip.

**Remaining gaps, unchanged and accepted.** `statfs` has been executed on win32 only (a POSIX CI run covers the rest; the test runs wherever the suite does). A backend author who stubbed `approximateBytesFree` to return 0 would break the contract with nothing failing — true, and true of every optional member here; unlike `readCached`, whose `?: true` type makes "present and false" unrepresentable, a byte count cannot have 0 typed away, since 0 is also a legal "full".
