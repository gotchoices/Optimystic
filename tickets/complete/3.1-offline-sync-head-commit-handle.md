First of four tickets for stage 3 of [docs/offline-sync.md §Implementation stages](../../docs/offline-sync.md#implementation-stages). Implemented in `ticket(implement): offline-sync-head-commit-handle`; reviewed here.

## What landed

- `HeadCommitHandle` and `driveHeadCommit` in `packages/db-core/src/collection/head-commit.ts`: the head commit's steps (`refresh`, `nextRev`, `heldRev`, `stage`, `send`, `release`, `retake`, `fold`, `replay`, `refused`, `close`) exposed one at a time, and the one-collection loop over them. `Collection.commitHead` is now `openHeadCommit` followed by `driveHeadCommit`, with the handle closed on every exit. The handle is a closure over the collection's private state (`Collection.headCommitHandle`); every step that touches instance state asserts the latch is in the state it needs.
- `HeadCommitOptions.recordAttempt` (awaited under the latch, after the attempt is built and before the latch is released; a throw aborts with nothing sent) and `HeadCommitOptions.resume` (an earlier cycle's recorded attempt, seeded as the retained attempt so the opening refresh finishes a torn attempt from it).
- `InFlightAttempt` gained `actionId`, so a resumed attempt can be checked against the cycle's action id before the latch is taken. `retainInFlightAttempt(attempt)` gates on it; `retainedAttempt(staged, actionId)` sets it.
- Docs: `docs/internals.md` §Staged actions are segments names the handle, the driver and both hooks; `docs/offline-sync.md` §Identity across attempts names `recordAttempt` and `resume`, and §The drain does not hold the collection latch across the network names the handle's `release` and `retake` steps.

## Review findings

**Read first:** the implement commit's diff, with the handoff summary read afterwards. Then `Collection.beginInFlightAction`, `logAppendBlockIds`, `foldOwnCommit`, `headTrackerFor`, `buildHeadTracker`, the preconditions, `retainedAttempt`, `stageAttempt`, the `TailLandsButReportsStale` double, the three new tests, and the two follow-on implement tickets (`offline-sync-coordinator-entry-commit`, `offline-sync-queue-core`) for how they consume the seam.

**Checked and found sound (no change):**

- Latch discipline. `release` sets `headInFlight` before releasing; `retake` acquires, then clears it; `fold`, `replay`, `refused`, `stage` and `refresh` assert the latch is held and `send` asserts it is released; `openHeadCommit` releases the latch when a precondition throws and asserts the `resume` action id before taking it. `close` is idempotent and clears the marks latch-free when the latch was left released, as the handoff describes; the hazard that leaves (a refresh mid-flight treating the entry as a stranger's) is a driver defect the interface doc names, and `driveHeadCommit` retakes in a `finally`.
- Fold before replay is preserved (`fold` then `replay`, documented on the interface), and the refusal re-check sits in `stage` and `refused`, so a reader's refresh that refused the head while the latch was released ends the cycle with the recorded refusal rather than another attempt. The changed order between the abort/deadline check and the refusal re-check changes only which error wins when both apply; accepted as documented.
- The `resume` seeding: `beginInFlightAction` runs before `retainInFlightAttempt(resume)`, and the id was asserted equal, so the retain is never a no-op. A `resume` at the wrong revision is refused by `completeOwnEntry` as `transforms-not-held`, as before.
- The `InFlightAttempt.actionId` deviation is right: the journal needs the id anyway, and it is a string, so the type stays plain data.
- Tests. All three kept. The hook-throws case pins the "nothing sent, latch released" contract and the resume case pins the torn-head completion end to end, reading the landed row through the unwrapped transactor. The wrong-action-id case is one guard, but it is the only check that the refusal happens before the latch is taken (the `withinMs` stage after it), which nothing else verifies; cheap, kept. No test restates the implementation or verifies a mock.
- Pre-existing hazards not re-filed: `beginInFlightAction` replacing a coordinator's in-flight mark between its attempts carries its own `NOTE:`; the quadratic replay `NOTE:` moved to the handle's `replay` and is unchanged.

**Minor, fixed in this pass:**

- `retake` racing `close`: a `close()` while `retake()` was awaiting the latch cleared the marks, and the acquire then resolved into a latch nobody would release. `retake` now releases the latch it just took and throws a defect when the handle was closed meanwhile.
- `InFlightAttempt` lived in `collection.ts` and `struct.ts` imported it from there, a type dependency pointing the wrong way (the types module importing from the class module). Moved to `struct.ts`, where `HeadCommitOptions` names it; `collection.ts` and `write-attempts.ts` import it from there, the barrel export is unchanged, and the `docs/offline-sync.md` citation follows it. `collection.ts` is 2821 lines, recorded on the debt ticket.
- The remark in `retainedAttempt` that the transforms reach the hook uncopied is now a greppable `NOTE:` tripwire (copy at `retainedAttempt` if a hook ever needs to mutate its argument), since it is a sharp edge the queue and journal authors will meet.
- The drain-latch section of `docs/offline-sync.md` described the release without naming the mechanism; it now cites the handle's `release` and `retake`.

**Major, filed:** `tickets/fix/offline-sync-resumed-head-commit-rebuilds-the-attempt.md`. A cycle opened with `resume` whose opening refresh finds nothing new (the earlier attempt's tail on a hidden minority) builds a fresh head tracker and a fresh log append and sends different content under the same `(action id, revision)`, which the invariant "A write's log append is a fixed function of the write and the revision it is requesting" forbids. Within one cycle the reused head tracker and `mintedLogBlockIds` prevent it; both die with the cycle, and `resume` restores neither. The remedy is one rule in `stage()` (answer the recorded attempt verbatim while the next revision equals `resume.rev`), which also serves the coordinator's lock-step driver. Filed as a fix ticket with `repro: static` and the reproduction to build, rather than fixed inline: it changes what a resumed cycle sends and needs a roll-over test. The in-line loop had the same gap for a re-drive under an old id; the seam this ticket added is what makes it closable, so it belongs ahead of the queue tickets that rely on the rule. The two follow-on implement tickets were not edited; the fix lands in `stage()`, which both drive.

**Tripwires recorded:** the uncopied-transforms `NOTE:` at `retainedAttempt` (above). No others: the quadratic replay and the base-moved rebuild already carry theirs.
