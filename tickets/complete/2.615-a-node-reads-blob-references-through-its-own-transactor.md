# A node reads blob references through its own transactor

First of three parts of `feat-blob-announcements-are-answered` (docs/blobs.md §Who may fetch and who may store). Landed in `ticket(implement): a-node-reads-blob-references-through-its-own-transactor`.

## What was built

- **`createNodeNetworkTransactor`** (`packages/db-p2p/src/node-network-transactor.ts`): the Quereus plugin's `NetworkTransactor` construction moved into db-p2p unchanged — the `getRepo` closure (self → coordinated repo, or the "a client is in no cohort" throw; others → `RepoClient`, wrapped by `stateHoldingsOnReads` when a store exists), the deadline derivation, the `localPeerId` rule, the clock, and both `NOTE:`s. Exported from `src/index.ts` and `src/rn.ts`. `CollectionFactory.createNetworkTransactor` now calls it.
- **The node's own reader**: `createLibp2pNodeBase` builds one on both roles, after the serving role and the blob service, with no change notifier, not attached to the node; and a `BlobReferenceCheck` over it, left as an unused local for the announce receiver (third part).
- **`BlobReferenceCheck`** (`packages/db-p2p/src/blob/reference-check.ts`): `inScope` reads the registry first and answers `not-listed` for an unregistered scope without reading its tree; `anywhere` walks registered scopes in order, remembering uncertainty. A listing containing the ref is `listed` even when not certain; a throw from either read is `uncertain`, logged `reference:read-failed`.

## Review findings

Read the implement diff first, then the handoff; checked against the implement-stage ticket's specification.

- **Correctness / spec conformance** — checked: the move is byte-for-byte the plugin's former body (diff inspected side by side); plugin passes exactly the values it used before; the node's reader is built after `served` exists so `coordinatedRepo` is the real one on a serving node and absent on a client; `NetworkTransactor`'s constructor starts no timer (`OwedCancels` arms only on a failed cancel), and the reader never pends or cancels, so declining a stop wrapper is correct. The verdict rules match the specification, including its internal contradiction on the first bullet (resolved toward "a listing is evidence", which the `BlobListing` doc supports). No defects found.
- **Judgement calls the implementer flagged** — all accepted as is: `anywhere` continuing past a scope whose read threw (a later scope can still answer `listed`, and the doubt is kept); no stop wrapper (above); `storageRepo` typed `StorageRepo` as the specification named; the unused `blobReferences` local (consumed by the third part, lint clean); two thin `NetworkTransactor`s per node when the plugin builds one too (no connection state of their own — nothing to act on).
- **Test vacuity** — checked that the "never reads the unregistered tree" assertion is not vacuous: a reference tree's collection id is the scope string, and that is its header block id, which every open reads first.
- **Tests** — tightened the possibly-stale case to assert the exact verdict `{ kind: 'uncertain', reason: 'tree-uncertain' }`, which pins that `readCommittedTree` absorbed the error rather than the throw path answering. No tests cut: the three each pin a named rule with real branching. No new tests added; `anywhere`'s uncertainty memory is covered only by inspection, a deliberate choice per the specification's test list.
- **Docs** — `docs/internals.md` (§Client nodes table row and "The node's type", §Reactive Watch Bridge transactor wiring) and `docs/blobs.md` (§Registering references) read and accurate. Missing: the new `reference:read-failed` line was not in `docs/debugging.md`'s `blob:protocol` row — added.
- **Resource cleanup, error handling, type safety, hygiene** — no exceptions swallowed (each throw becomes a logged uncertain verdict); no `any`; files small and single-purpose; comments say why, not what. Nothing to change.
- **Tripwires** — none new; the implementer's `NOTE:` on `inScope` (whole-registry enumeration to test one scope) stands.
