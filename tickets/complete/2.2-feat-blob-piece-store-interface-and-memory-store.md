# The piece store interface, the memory store and the conformance suite

A blob is kept on a node as immutable pieces of at most 1 MiB, each named by its `PieceId`. This work added the storage interface for those pieces and what a backend needs to be tested against it. Nothing uses a piece store yet: the filesystem store is `feat-blob-file-piece-store`, and the blob service that writes pieces, and passes the piece store to `StorageMonitor`, is `feat-a-node-stores-blob-pieces` (its plan ticket already lists that wiring).

## What was built

- **`IPieceStore`** (`packages/db-p2p/src/blob/piece-store.ts`): `has`, `get`, `put`, `delete`, `list`, `bytesUsed`, `flush`, `durability`, optional `storeIdentity` and `close`, with the contract in its doc comments (the store never hashes; a second put of a present id writes nothing; the caller's buffers are never the store's; flush keeps rules 1, 2 and 4 of `RawStoreDriver.flush` but not the prefix rule; `storeIdentity` equal to a block store's means the block store already measures the pieces).
- **`MemoryPieceStore`**: a `Map`, copying on `put` and `get`; `durability: 'none'`.
- **`PowerLossPieceStore`** (`@optimystic/db-p2p/testing`): unflushed writes in an overlay, `flush` applies them, `powerLoss()` / `reopen()` model the crash, reusing `StoreLostPowerError`.
- **`runPieceStoreConformance`** and **`conformancePieceId`**, published with `runRawStorageConformance` through the new `src/testing/conformance/index.ts` barrel, which `./testing/conformance` now points at.
- **`StorageMonitor`** takes an optional piece store as its third argument and adds its `bytesUsed` inside the one memoized scan unless `blockStoreCountsPieces` (equal store identities, and a block store that measures its bytes at all) says the block store already counted it.
- Docs: `docs/blobs.md` §The local store and status line, `docs/repository.md` §Capacity estimation and staleness, `packages/db-p2p/docs/storage.md` §1.

## Review findings

Read the implement diff (`ticket(implement): feat-blob-piece-store-interface-and-memory-store`) before the handoff.

**Checked, no defect found:**
- Contract against implementation: `MemoryPieceStore` and `PowerLossPieceStore` copy on both sides, ignore a second put, treat a zero-length piece as present, and snapshot `list` at the first `next()`. In the double, a delete followed by a put, a put over a durable piece, and a delete of a durable piece each read back correctly through `held` and `view`.
- `blockStoreCountsPieces`: the comparison is one-directional as the store-identity contract requires. A block store without `getApproximateBytesUsed` always adds the piece figure. The decision is made once, which is sound since both identities are fixed at construction. A rejected `bytesUsed` rejects the scan, which the existing "does not cache or wedge on a scan error" path then handles uncached. The `NOTE:` about two spellings of one directory is a correct tripwire.
- Published entries: `test/testing-entry-runtime-deps.spec.ts` and `test/entry-parity.spec.ts` pass. `multiformats` is a declared runtime dependency of db-p2p, and the conformance barrel imports `chai` only under the dev-only subpath.
- Interactions: the barrel repoint is consumed by all four storage packages. The handoff had run only the fs one, so I ran the other three: `db-p2p-storage-ns` 72 passing, `-rn` 68, `-web` 64.
- React Native: the handoff had not run `yarn check:rn`; it passed (Metro bundle plus `hermesc` compile).
- Tests: the conformance cases each pin one clause of the contract. The extra "two concurrent puts" case is kept: it is cheap and it is the clause a file store's rename race or an IndexedDB `add` could break. The power-loss spec pins what the double exists for, and the two `StorageMonitor` cases pin the add/omit branch. No test restates the implementation, so none was cut, and none was added.
- Source hygiene: the files are small, and the comments give reasons rather than narrating statements.

**Fixed inline (minor):**
- `docs/repository.md` said used bytes "include the node's blob piece store's own figure". No node passes one yet, so the sentence now says the figure is added when the monitor is given a piece store (its optional third argument), and that the node does not pass one yet.
- `docs/blobs.md` status line now lists "passing a piece store to the node" among the things still to be built. The section body already describes it as design.

**Tripwires / considered and left:**
- A `PowerLossPieceStore.delete` of an absent id records a `null` in the overlay. Its flush deletes nothing, so this is harmless in a test double and was left as is.
- Two spellings of one directory are counted twice: the existing `NOTE:` at `blockStoreCountsPieces` covers it.

**Major findings / tickets filed:** none. Every gap I found was either the node wiring, which `feat-a-node-stores-blob-pieces` already claims, or a minor doc fix made above.
