# Storage drivers can carry values as text

GitHub #51, first of two tickets. The follow-on, `react-native-reads-decode-utf8-in-native-code` (now in `implement/`), puts the React Native LevelDB backend on this.

## What landed

How a driver holds a stored value in memory is a type parameter, bytes by default at every seam (`ticket(implement): storage-drivers-can-carry-values-as-text`):

- `raw-store-codec.ts`: `StoredValue` (`Uint8Array | string`), `ValueCodec<V>` (JSON and action-id encode/decode, `storedBytes`, `residentBytes`, `toBytes`), `bytesValueCodec`, `textValueCodec` (never builds a `TextDecoder`), `ValueCodecArgument<V>` (codec optional only for bytes) and `resolveValueCodec`. Exported from `src/index.ts` and `src/rn.ts`.
- `RawStoreDriver<V>`, `KvRawStorage<V>(driver, ...codec)`, `CachedStoreDriver<V>(inner, pool?, label?, ...codec)` (charges `residentBytes`; `promote` carries any present cached value, not only a `Uint8Array`), `WriteGroup<K, V>` (`storedBytes` required for non-bytes via `WriteGroupOptionsArgument<V>`), `WriteGroupDriver<V>(backend, options?, ...codec)` (values become bytes in one place, `toBytesSink`, on the way to `commit`), and `BatchBackend<R>` / `JournalStore<R>` / `JournalBatchBackend<R>` (reads return `R`; writes and journal records stay bytes).
- Every existing backend and composition is unchanged; a text composition without its codec does not compile.
- Docs: `packages/db-p2p/docs/storage.md` §5 and §6 and the memory-management bullet; docs/internals.md *Storage Returns References*.
- Test: one persistent `runRawStorageConformance` registration over a whole text composition (`KvRawStorage<string>` → `CachedStoreDriver<string>` → `WriteGroupDriver<string>` → `JournalBatchBackend<string>` → `TextReadsJournalStore` → `MemoryJournalStore`).

## Review findings

**Diff read first**, then the handoff. Read every changed source file in full or by hunk (`raw-store-codec.ts`, `raw-store-driver.ts`, `kv-raw-storage.ts`, `cached-store-driver.ts`, `write-group.ts`, `write-group-driver.ts`, `batch-backend.ts`, `journal-batch-backend.ts`, the test double, the spec) and both doc diffs.

**Correctness — one defect found, fixed.**
- `textValueCodec.encodeActionId` returned the id as given. An action id is client-chosen and never format-checked, so it can hold a lone surrogate. `TextEncoder` replaces that with U+FFFD on the way to disk, so in a text composition a cache or overlay hit served the id as written while a cold read (and every read in a bytes composition) served it replaced: the same key read back two ways depending on cache state. Fixed: `encodeActionId` now returns the text the value reads back as once stored (`asStored` in `raw-store-codec.ts`, a regex with no lookbehind and no `u` flag, so Hermes compiles it). Pinned by `test/raw-store-codec.spec.ts` (one case, compares the text round trip with the bytes round trip). JSON values need no such step: `JSON.stringify` escapes lone surrogates.
- Checked and fine: every `.length` / `byteLength` charge in the cache and write group goes through the codec (remaining `.length` uses are keys, ids and coverage intervals); no `instanceof Uint8Array` remains in the storage layers; `WriteGroup`'s measure handles `null`/`undefined`; `promote` in both the cache and the write-group driver; `ValueCodecArgument` refuses the `StoredValue` union itself (requires a codec); `textValueCodec.storedBytes`'s "at most 3× undercount" claim (a BMP character is one UTF-16 unit and up to 3 UTF-8 bytes; an astral one is 2 units and 4 bytes).
- Noted, not acted on: `TextDecoder` (the bytes path) strips a leading U+FEFF from what it decodes, and a native decoder may not, so an action id starting with U+FEFF could read back differently on the React Native backend than on a bytes backend. This code adds no such difference — the text path here never decodes — so it belongs to the follow-on, and it needs a hostile client-chosen id to arise.

**Handoff deviations, each checked.**
- One conformance registration rather than two durabilities: agreed. The suite's flushes are strict, so a second registration would rerun the same path; the relaxed journaled path over text is untested, and that a journal record holds bytes is enforced by `BatchEntry`'s type.
- `promote` fix not pinned by a test: accepted. The existing bytes test (`promote with the pending transform cached serves the committed read from cache` in `test/cached-raw-storage.spec.ts`) pins the cache-hit behaviour; a text twin would only guard against reintroducing a type test, which nothing suggests.
- Compile-time refusal of a codec-less text composition verified by the implementer, not kept as a type test: accepted; the types are small and a regression fails the follow-on's build immediately.
- Per-commit allocation in `toBytesSink` for bytes compositions: parked as a `NOTE:` tripwire at `toBytesSink` in `write-group-driver.ts` (revisit if commit cost shows in profiles).
- Cache constructor shape: the follow-on ticket's composition sketch left the codec off the cache and the write-group driver, which would not compile. Corrected in place in `tickets/implement/0.81-react-native-reads-decode-utf8-in-native-code.md`.
- Duplicate `UTF16_UNIT_BYTES` / `CHAR_BYTES` (both `2`): left. Sharing one would make an internal constant public through the exported codec module; two one-line constants with stated purposes are cheaper.
- Public surface widened (existing `encodeJson`, `decodeJson`, `encodeActionId`, `decodeActionId`, `cloneDecoded` now exported): acceptable; the follow-on backend package needs the codec names, and the project does not guard backwards compatibility yet.

**Tests.** The conformance registration pays for itself (runs the whole storage contract over a text composition). The test double lives in `src/testing/` beside `MemoryJournalStore`, not exported from the testing entry: consistent with precedent. No tests cut.

**Docs.** `storage.md` §5/§6 and internals.md *Storage Returns References* match the code. The lone-surrogate rationale in §5 still reads correctly with the fix (it explains why strings are not handed to the engine directly). No other doc names the changed signatures.

**Hygiene.** `cached-store-driver.ts` is 954 lines, as before (the change was renames and generics, no growth); not split here. Comments say why, not what.

**Resource cleanup / error handling / performance.** No new resources. Error paths are unchanged (the cache's throw-on-inner-error reaping and the write group's latch are untouched). Text cache hits skip one `TextDecoder` call per read, the point of the change.

**Validation.** `yarn build`, `yarn typecheck`, `yarn lint`, `yarn lint:docs`: clean. `packages/db-p2p` `yarn test`: 3607 passing, 75 pending, 0 failing. `yarn check:rn`: passed.

**I made one mistake and fixed it.** A first attempt at the codec edit through a Python heredoc truncated `raw-store-codec.ts`; the file was restored byte-for-byte from the implement commit (`git show HEAD:…`, `git diff` empty afterwards) before the edit was redone.
