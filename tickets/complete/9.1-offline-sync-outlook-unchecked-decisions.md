Second of three tickets for stage 9 of [docs/offline-sync.md §Implementation stages](../../docs/offline-sync.md#implementation-stages). Implemented in `ticket(implement): offline-sync-outlook-unchecked-decisions`; the design of record is [§Unchecked decisions](../../docs/offline-sync.md#unchecked-decisions) and [§Dependencies between entries](../../docs/offline-sync.md#dependencies-between-entries). The third ticket, `offline-sync-outlook-facts-survive-a-restart`, journals the facts this one records.

## What was built

- **`write-description.ts`** — `uncheckedOf(write)`, the pure derivation of one described statement's decisions against other rows from its target selection, constraints and read watches (the table in [§Unchecked decisions](../../docs/offline-sync.md#unchecked-decisions)); two new `WriteFact` kinds, `statement` and `undescribed`; `foldWriteFacts` answering `EntryFacts.unchecked` (deduped by table, kind and scope with the pinned rows merged) and `EntryFacts.complete`.
- **`txn-bridge.ts`** — `noteWriteDescription(write)`: records a statement's decisions once per `TableWrite` object (the engine binds a fresh object per execution, shared by every row of it), or that a write went undescribed; kept, truncated on savepoint rollback and folded as the fresh-element facts are.
- **`optimystic-module.ts`** — the vtab records the description at the top of `update()`, ahead of every arm's staging; `TableOutlookSource.mainTree()` answers the main collection id and a `rowKey` that encodes a pinned row exactly as a point lookup builds its seek key.
- **`commit-outlook.ts`** — `OutlookSchema` (the controller's view of the schema, replacing the bare `describe` callback), `OwnJudgement.unchecked` with each decision rendered and its span fixed when judged, `WriteIndex` writers per table, the `via: 'unchecked'` dependencies in `outlookFrom` with `'guard'` winning and `kind` ignoring them.
- **`offline-mode.ts`** — implements `OutlookSchema` over the published tables through a lowercased name index.
- **Docs** — docs/offline-sync.md §The outlook, §Unchecked decisions, §Dependencies between entries, the stage 9 status and the test plan; the plugin README's `dependsOn` and `unchecked` bullets and paragraph; one clause in docs/internals.md.

## Review findings

Reviewed from the implement diff first, then the handoff. Read every file the change touched plus the Quereus write-scope contract (`../quereus/docs/write-scope.md` and `bindTableWrite` in `@quereus/quereus/src/planner/analysis/write-scope.ts`) to check the assumptions the plugin trusts.

**Checked and found sound.**

- The once-per-object dedup in `noteWriteDescription` rests on Quereus handing one `TableWrite` per execution. Confirmed: `bindTableWrite` spreads the memo into a fresh object on every execution, so a prepared statement run twice — or re-run after a savepoint rollback truncated its record — is recorded again, and the upsert `DO UPDATE` arm sharing the INSERT's object is deduped as intended. The `WeakSet` is never truncated on rollback, and does not need to be.
- `uncheckedOf`'s rules against the contract: `row-selection` only for a non-INSERT `global` selection; the foreign-key parent probe consumed as a whole-table watch; the target rule (`withinSelection` compares the key positionally and every tuple by rendered value); placeholder and empty-tuple widening; dedupe key over the lowercased name. A self-referencing foreign key resolves the same way (the parent watch on the target is consumed by the constraint before the target rule sees it).
- `rowKeyOf` matches `executePointLookup`'s encoding and refuses a non-primary key; a NULL pinned value encodes to a key no lookup would seek, which is harmless.
- The `'guard'`-wins rule, queue ordering, and `kind` ignoring unchecked dependencies in `outlookFrom`; `withoutCollections` keeping the decisions on a partial commit; `followOutlooks` reusing the frozen own judgement.
- The two SQL-level cases and the unit cases pin one rule each and verify contract, not implementation; kept.

**Fixed inline (minor).**

- **Key-matched reads skipped deferred records entirely.** `outlookFrom` matched a `row` read with encodable keys against staged segments only and `continue`d past the deferred loop, so a journaled transaction still deferred after a restart that wrote the read's table was never listed — one dependency too few, against the stated direction of the design and against how guards treat deferred records. The span now carries its table beside its optional keys (`ReadSpan` in commit-outlook.ts), staged segments are matched by key where keys exist and by table otherwise (`readersOf`), and deferred records are matched by table either way. The doc's sentence on deferred records says so.
- **A published but uninitialized table lost its rendering.** `OfflineMode.publishedTable` answered `undefined` when `mainTree()` did, so the decision fell back to Quereus's lowercased name (`main.conversations`) and matched neither earlier entries' `tables` nor deferred records, which carry `main.Conversations`. Unreachable in this ticket, since the statement that made the decision initialized the table it read, but it is exactly the restore case the next ticket builds: a restored entry judged from journaled facts before the table it read is first touched. `OutlookSchema.table` now answers `{ name, tree? }`, with the tree optional, and `judgedReads` matches by table alone when the tree is absent. Pinned by the new `test/commit-outlook.spec.ts` alongside the deferred case above.
- **One `undescribed` record per cascade row.** A cascade deleting many child rows pushed one record per row for a fact the fold reads as a flag. `noteWriteDescription` now pushes it only when the last record is not already `undescribed`; the savepoint truncation is unaffected.

**Major findings.** None. The one latent defect found (the rendering) was small enough to fix in place and is covered by the next ticket's anchor.

**Tripwires.** None recorded: the per-table writer index is bounded by the queue as the per-collection one is, and `openWriteFacts` folds the open transaction's records on each `CommitOutlook()` call, which is one pass over records the transaction already holds.

**Noted, not filed.** `optimystic-module.ts` measures 5993 lines (`wc -l`), of which this ticket added 46; a split of the vtab has no anchor in this release and no ticket, and is left as observed.

**Known gaps carried from the handoff**, unchanged: no test for `assertion` decisions, `foreign-key-parent` on an UPDATE of a referenced column, the unpublished-table rendering, or the cascade → `'not-computed'` path (each follows the same lines as a pinned sibling); a `row` read pinned by a UNIQUE column rather than the primary key matches by table; a statement that stages nothing still records its decisions; `StampId()` in an autocommit INSERT (backlog `bug-stampid-is-null-inside-an-autocommit-insert`). Not run: `yarn check:rn`, `yarn test:integration`, the db-core suite (no db-core change).
