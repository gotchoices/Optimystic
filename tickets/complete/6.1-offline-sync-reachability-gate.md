## What was built

- `ICohortReachability.onChange?(listener) => unsubscribe` on the db-core port (`packages/db-core/src/offline/reachability.ts`): a hint that reachability may have improved; the listener re-asks `reachable`.
- `IdentifyProgress` (`packages/db-p2p/src/network/identify-progress.ts`): counts identify exchanges in flight on the node, with any peer. `combineIdentifyObservers` in `identify-on-open.ts` fans one exchange out to the bootstrap-contact tracker and the counter, each call isolated.
- `KeyNetworkCohortReachability` (`packages/db-p2p/src/network/cohort-reachability.ts`), exposed as `node.cohortReachability`: per distinct block, open when `findCluster` names another machine; on a self-only view open only when no remembered serving member is absent, no bootstrap peer is awaited and no identify is in flight; closed on an empty cohort or a throwing lookup. One log line per change of answer. `onChange` wakes listeners on `connection:open` / `peer:identify`, trailing-debounced (`NodeOptions.cohortReachability.wakeDebounceMs`, default 500 ms); event listeners exist only while someone is subscribed; `stop()` is wired into node teardown and startup rollback.
- Mesh harness: the per-node key network now answers `absentCohortMembers` with the members its partition filter removed.
- Tripwire `NOTE:`s at `membershipOf` (a failed same-network identify reads as alone), at `reachable` (restored partner reads reachable after a restart), at the "member other than self" arm (FRET's dead-peer grace) and at `onChange` (a steady event stream postpones the wake).

## Review findings

Read the implement diff first, then the architecture section, `identify-on-open.ts`, `absentCohortMembers` in the key network, the queue's re-check backoff and the partition specs.

**Checked and correct**
- Rule matches docs/offline-sync.md §When to submit; the extra `identifying`, `no-cohort` and `lookup-failed` arms are stricter than the doc (closed, never open), so they can only delay a submission, not admit a lone commit. Updating that doc section is assigned to `offline-sync-cohort-reachability`, as the ticket says.
- `IdentifyProgress` can only leak a count if `settled` is skipped; `identifyConnection` calls it in a `finally`, and libp2p identify times out, so the `identifying` arm cannot stick closed.
- The reviewer question on `identifying` counting foreign peers: agreed harmless. A wake that lands while a foreign identify is still in flight reads closed, but a wake resets the queue's re-check backoff to its 1 s base, so the next check (after the refusal) reads open. No tripwire needed.
- Reason precedence (absent → awaiting → identifying) affects only the logged reason; most specific evidence first reads well for an operator. Kept.
- Resource cleanup: last unsubscribe releases events and cancels the timer; unsubscribe is idempotent; `stop()` drops everything and later `onChange` is a no-op; stop wrapper registered right after construction, so startup rollback releases it.
- Harness change: the three partition specs (`mesh-partition-admission`, `mesh-harness-cohort-parity`, `coordinator-repo-absence-write-bypass`) assert admission-gate refusals or cohort views, none the emptiness of `unconfirmed`; none passes for a different reason now.
- Concurrent `reachable` calls can race on `lastAnswer`; this affects only log de-duplication. Not worth a fix.

**Fixed inline (minor)**
- `releaseEvents` used a non-null assertion on `deps.events`, guarded by a separate boolean. Replaced the boolean with `subscribedTo: NetworkChangeEvents | undefined`, holding the source actually subscribed, so there is no assertion and no state that can disagree with itself.
- docs/internals.md called the node gate's `onChange` "optional"; it is optional on the port and always present on `node.cohortReachability`. Reworded.

**Tests**
- The eight `reachable` cases each pin one arm of the branching rule; kept. The debounce test is timing-based (20 ms debounce, 80 ms settle on real timers); both events are dispatched synchronously, so the only risk is a very loaded box stretching 80 ms. Kept as is; no injectable timer seam was worth adding for it. No tests added: no defect found that needed a reproduction.

**Not found / empty categories**
- No major findings, so no tickets filed. No new tripwires beyond the four the implementer placed, which I reviewed and agree with (each names a revisit condition).
- Performance: a self-only view costs one extra cohort assembly (`absentCohortMembers`) per block per ask; the identify observer costs one map update per exchange. Fine at current call rates (the queue asks on re-checks; live reads start asking once `offline-sync-cohort-reachability` lands, and the peer-record cache keeps the lookup cheap).
