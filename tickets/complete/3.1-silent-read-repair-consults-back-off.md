# Silent read-repair consults back off

Third of the three retries in Sereus `../sereus/tickets/blocked/optimystic-retries-do-not-back-off.md` (gotchoices/sereus#48): one block re-asked about every 8.2 s, 224 times in 180 s, each time finding the other member silent, because a read-repair consult that a silent cohort peer leaves without arming the lazy window was re-sent by the next read as soon as the previous one ended.

## What landed (`ticket(implement): silent-read-repair-consults-back-off`)

- `SilentConsultHolds` (`packages/db-p2p/src/repo/silent-consult-holds.ts`): per block a hold of `min(cap, base × 2^(consecutive − 1))`, placed after a consult that ends with nothing corroborated and some cohort peer silent; released (and its count reset) as soon as any peer silent in that consult answers this node at or after the consult ended; forgotten after a consult that ends any other way. Base 0 disables it. Both maps `LruMap(1000)`.
- Base is `LinkDeadlines.retryBackoffBaseMs` (the declared link round trip, 0 when undeclared), passed as `CoordinatorRepoConfig.retryBackoffBaseMs` by `createLibp2pNodeBase`; cap is the repo's `reconcilePassTimeoutMs`. Only `'lazy'` mode places holds.
- `fetchBlockFromCluster` reports `heldBySilence` at the one unarmed-because-silent exit; both consult paths feed it to `noteConsultOutcome`. Answers come from every consult's `answered` list and from the voters on the record returned by pend and commit (`noteVotersAnswered`).
- `shouldReadRepair`'s `'lazy'` arm checks the hold first (sample-rate arm included). Missing blocks, floor-demanded consults and `'paranoid'` are not gated. A held read is served from the local copy with the same `unconfirmedAheadRev` it would carry otherwise.
- Logged once per hold as `cluster-fetch:consult-held`. Docs updated in transactions.md, internals.md, debugging.md, the db-p2p readme, `rpc-deadline.ts`, `cluster-policy.ts`, and the release notes.

## Review findings

**Checked, by reading and running:**

- Where holds are placed: only at the `!corroborated` exit, with a non-empty silent set, after the `cohort-too-small` arming return (a silent pass never produces that deadlock verdict, so no pass is both armed and held). Total silence (the measured two-member shape, declared or undeclared) reaches that exit and is held. Armed exits, the solo-self exit and the empty-cohort exit return no `heldBySilence`, so they clear any hold.
- Background consults: `runHeldBlockConsult` places the hold inside the pass, before the `finally` clears the in-flight marker, so no read can start a consult in the gap between the two.
- What is not gated: a missing block (`isMissing` skips both the window test and the outcome note), a floor above the local copy (`floorDemandsConsult` is evaluated independently), and `'paranoid'` (base forced to 0). A floor-demanded consult's outcome still places or clears the hold, as documented.
- Release rule: `noteAnswered` runs before the hold is placed, and `since` is read after it, so answers from the same consult cannot release the hold that consult places. Answers counted at or after `since`, matching the ticket.
- `noteVotersAnswered`: `ClusterRecord.promises` and `.commits` are required fields on a coordinator-built record and are read directly elsewhere in the same file, so there is no undefined-field risk. Self is excluded.
- The clock goes through the repo's reassignable `now` seam (closure over `this.now()`), so the spec's clock control reaches it.
- Docs: read every touched file. The cadence paragraph, the new hold paragraph, the staleness-bound sentence, the debugging entry and the readme row all match the code. `yarn lint:docs` is clean.
- Deviations from the plan's literal TODO (no hold from a missing block's consult, holds disabled outside `'lazy'`, the repo logs rather than the collaborator): agreed. Each avoids `consult-held` lines for holds that gate nothing.

The result is bounded by the cap and only means the next consult waits longer, so this is not a defect. No tripwire, because no condition makes it worse.
