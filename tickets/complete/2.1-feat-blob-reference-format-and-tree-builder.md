# Blob references and the piece-tree builder

docs/blobs.md is the design of record for native large-value ("blob") support (GitHub #63). This ticket built the pure-logic foundation in `packages/db-core/src/blob/`, with no network or disk access. The reader that checks pieces received from elsewhere is the next ticket, `feat-blob-references-and-verified-piece-trees`.

## What exists

- **References and piece ids** (`blob-ref.ts`): `BlobRef` and `PieceId` are branded strings, a CIDv1 with a 32-byte SHA-256 digest, codec raw (0x55) or dag-pb (0x70), in lowercase base32 with exactly one accepted spelling. `parseBlobRef`, `parsePieceId` and `isBlobRef` share one verdict function; `pieceIdOfCid` re-spells a CIDv0 link as v1; `cidOfPiece` decodes a branded id; `rootPieceId` is the identity cast.
- **Errors** (`errors.ts`): `BlobRefError`, `BlobUnavailableError`, `BlobCorruptError` (its reasons are for the next ticket's reader) and `BlobDigestError`.
- **Limits** (`limits.ts`): the 256 KiB leaf and 174 children the builder writes, and the reader's bounds (1 MiB piece, 1024 links, 8 levels).
- **Hashing port** (`digest.ts`): `defaultBlobDigest` (memoized; `crypto.subtle` when present, else `@noble/hashes` with one `blob:digest-fallback` log line), and `checkBlobDigest`, which runs three FIPS 180-2 known answers against a host-supplied digest.
- **Piece ports** (`pieces.ts`): `PieceSink` and `PieceSource`.
- **List-piece encoder** (`list-piece.ts`): `encodeListPiece`, byte-identical to kubo.
- **Builder** (`builder.ts`): `buildBlob` cuts 256 KiB leaves into fresh buffers and feeds `BlobTreeAssembler`, which holds the level logic so a later builder can supply leaf links it did not cut. Every piece is put after the pieces it names, one put at a time.
- **Service types** (`service.ts`): `BlobService` and its option, result, durability and progress types, matching docs/blobs.md.
- **Routing key**: `routingKeyForBlob(ref)` in `network/routing-key.ts`, the 32 raw digest bytes inside the reference.
- **Dependencies**: `@ipld/dag-pb@^4.2.0` and `ipfs-unixfs@^13.1.2`. `yarn lint:deps` and `yarn check:rn` passed in the implement stage with no alias or shim.

Departures from the plan, all accepted in review: the plan's 56-byte known-answer string was missing characters, and `digest.ts` uses the real FIPS 180-2 message, whose digest is the hex the plan gave; `SubtleDigest` is exported, because declaration emit needs it; `BlobDigestError` takes `ErrorOptions` so it carries the cause; `BlobTreeAssembler`'s constructor takes `(sink, options)` and so shares `BuildBlobOptions` with `buildBlob`.

## Review findings

Read the diff of `ticket(implement): feat-blob-reference-format-and-tree-builder` before the handoff. Checked each module against the plan ticket's spec, the multiformats 14.0.5 source the parse rule relies on, the tests, and every doc the change touches or should have touched.

- **Defect, fixed: a padded reference was accepted.** The final step of the parse rule, "re-encodes to the same string", was a no-op. `CID.parse` caches the string it parsed and `CID.toString` returns that cached string, so `cid.toString(base32) === text` always held. The base32 decoder strips trailing `=`, so `bafk…nu=` and `bafk…nu======` both passed `parseBlobRef` and `isBlobRef`, which breaks "one spelling per blob, so references compare as strings". I confirmed this against the built package. The fix: `canonicalSpelling` in `blob-ref.ts` encodes from `cid.bytes`, with a comment saying why, and both the canonical check and `pieceIdOfCid` use it, since `pieceIdOfCid` had the same hole for any CID that came from `CID.parse`. I added a "base32 padding" row to the rejection table in `blob-ref.spec.ts`. No other alternative spelling gets past the decoder: uppercase fails the prefix rule, non-zero trailing bits and extra characters throw "Unexpected end of data", and trailing bytes throw "Incorrect length".
- **Unverified contract, closed: fresh buffer per leaf.** Each vector test now also asserts that every piece the sink kept still hashes to its id (`RecordingSink.changedSincePut`). I checked that it bites: with the builder changed to reuse its leaf buffer, 3 of the vector tests fail. That change was reverted.
- **Test tightened: `routingKeyForBlob`.** The test compared the key with `cidOfPiece(rootPieceId(ref)).multihash.digest`, which is the implementation's own expression. It now compares against the reference's raw CID bytes after the 4 header bytes, which does not go through the code under test.
- **Builder level logic**, by inspection: I traced `finish` for 1, 174 and 176 leaves. The loop always ends, because the highest level is non-empty and either returns its lone link or flushes into a level above. The vectors pin the encoding. The plan already accepted that three-level trees have no vector, and the code is the same at every level.
- **Failure paths** (a source that throws, a put that rejects, an aborted signal): read, not tested. `throwIfAborted` sits before each chunk is consumed and before each put. A throw inside `for await` calls the source's `return`, so the source is cleaned up. Adding tests here would only exercise wiring.
- **Digest port**: the memoization means the fallback line is logged once. The known-answer check copies its input before each call, so a digest that writes to its input cannot spoil the next check. The `NOTE:` at `defaultBlobDigest` about JavaScript `crypto.subtle` polyfills is a tripwire already in place, and it is in docs/blobs.md, debugging.md and the db-p2p readme.
- **Type safety and import cycles**: the brands come only from the parsers and `pieceIdOfCid`. `errors.ts` imports `blob-ref.ts` as types only, so there is no runtime cycle, and `barrel-import-cycle.spec.ts` and `no-fret-import.spec.ts` pass in the full suite.
- **Docs**: docs/blobs.md, internals.md, debugging.md and the db-p2p readme all match the code. The service-types block is identical to `service.ts`. `packages/db-core/README.md` was not touched and should have been. It now has a Blobs entry under Core Components and in its Documentation list.
- **Tests left as they were**: the six vectors, chunking independence, the assembler fed leaf links it did not cut, and the digest check each cover a named part of the spec with real branching, so none was cut.
- **Tripwires**: none new. The conditional concern, the polyfill note, was already recorded at its site.
- **Major findings and tickets**: none. The one defect was minor and fixed here.

Validation: `yarn workspace @optimystic/db-core build`, which typechecks `src` and `test`, passed. `yarn workspace @optimystic/db-core test` passed with 2079 passing and none failing. `yarn lint:docs` passed, and eslint on the changed files is clean. `lint:deps` and `check:rn` were not re-run, because review changed no dependencies or bundled entry points.
