# A member hashes a committed block once

Part of GitHub #63 (measurements and the split are in the completed `a-consensus-record-is-serialized-once-per-delivery`). Last sibling: `a-large-write-is-measured-once-and-its-cost-is-documented`, which re-measures and writes the cost docs.

## What changed

**1. No copy in the preview.** `StorageRepo.previewCommitDigest` no longer runs `cloneDecoded` over the base block and the pending transform. Its work moved into a private `materializePreview` (which also returns the base the digest was computed over); `previewCommitDigest` wraps it with the memo below. The comment there now states the rule it relies on: the values were decoded for the preview alone.

Premise checked for every input path:
- `BlockStorage.getPendingTransaction` → `IRawStorage.getPendingTransaction`: a fresh JSON decode per read in `KvRawStorage`.
- `BlockStorage.getBlock` → `materializeBlock`: a fresh decode of the materialization, with transforms (each a fresh decode) replayed over it; the re-cache `saveMaterializedBlock` encodes before `materializeBlock` returns, so nothing keeps the returned object.
- Every `IRawStorage` in the repo is the `KvRawStorage` kernel (`MemoryRawStorage`, `FileRawStorage`, `SqliteRawStorage`, `LevelDBRawStorage`, `IndexedDBRawStorage`, `CachedRawStorage`), and every `createBlockStorage` factory builds a `BlockStorage` (or a test subclass). The one test-only `implements IRawStorage` (`CrashingRawStorage` in `mid-ddl-crash.spec.ts`) delegates to a kernel.
- **`CachedRawStorage`**: it IS the kernel, over `CachedStoreDriver` over `RawStorageDriverAdapter`. The adapter re-encodes whatever its inner `IRawStorage` returns to bytes, the cache holds bytes, and the kernel above decodes a fresh object per read — so the rule holds at the kernel above it even if an inner store handed out live objects.

Since the clone had no other caller, `cloneDecoded` was removed from `raw-store-codec.ts` (it was a public export of `@optimystic/db-p2p` and its `rn` entry) along with its three tests in `module-load-globals.spec.ts`.

**2. The commit reuses the preview's digest.** New `PreviewedDigests` (`previewed-digests.ts`), one per `StorageRepo`: a 1024-entry db-core `LruMap` keyed `JSON.stringify([blockId, actionId])`, each entry a reservation (identity-compared object) and optionally a result `{ rev, base, digest }`, `base` being `latest`'s `{ rev, actionId }` or `'insert'` (`digestBaseOf`, shared by preview and commit so both compute it one way).
- `previewCommitDigest` reserves synchronously before its first storage read, and `settle`s at the end: keeps the result only if the key still holds its own reservation; removes its reservation when it computed no digest.
- `pendUnderLatches` pass 2 calls `forget` right AFTER each `savePendingTransaction` resolves (after, not before: a preview that reserved before the save's completion and read the old record is then voided; one that reserves later reads the new record).
- `internalCommit` calls `take` after `setLatest` (so after `promotePendingTransaction`: a preview reserving after the take finds no record), for every commit including the read-driven promotion, and passes the digest to `persistProofIfContentMatches` only when rev and base match. `persistProofIfContentMatches` takes a new optional `blockDigest`; the back-fill path (`backFillProof`) passes none and hashes as before. The comparison with the declared digest and the `commit:proof-digest-mismatch` log are unchanged.
- In-flight ordering (re-pend while a preview is between reserve and settle): by inspection — the pend's `forget` removes the reservation, so `settle` keeps nothing.

**3. No copy before the pending record is encoded.** New `sharedTransformForBlockId` in `packages/db-core/src/transform/helpers.ts`, beside `transformForBlockId` (unchanged), returning the per-block view over the request's own inserted block and update list. `StorageRepo.pend` uses it in pass 1 (only reads `.insert`) and pass 2 (`declaredBaseFor` reads it; `BlockStorage.savePendingTransaction` only logs ids, writes metadata, and passes it to `IRawStorage.savePendingTransaction`, which encodes it to JSON in `KvRawStorage` — nothing keeps or changes it). Added to internals *Functions That Share* and the *Transform Ownership* exception. `transformForBlockId`'s NOTE now names the read-only callers that still clone (`ClusterMember.reservationRequestOf`, `CoordinatorRepo.corroborateHeldBlocks`, cohorts of four and up).

Docs: internals §Commit content-digest check gains a paragraph on the reuse; *Storage Returns References* notes the preview relies on decode-per-read; the two table/ownership entries above. `yarn lint:docs` clean.

## Known gaps / for the reviewer

- **Base immutability is argued, not enforced.** A hit requires the preview's `latest` `{ rev, actionId }` to equal the commit's; that is sound only because the content at a given `(rev, actionId)` never changes (restores are first-writer-wins via `noDivergentRewrite`, invalidations write new revisions, replicas advance monotonically). The preview reads `latest` and `getBlock(latest.rev)` unlatched; `getBlock` at a fixed revision materializes that revision's content even if `latest` moves meanwhile.
- **A preview that throws** leaves its reservation in the memo. A reservation without a result can never produce a hit; the next pend or commit of the key, or the LRU, removes it. Not wrapped in `try/finally` to keep the path simple.
- **`cloneDecoded` was a public export** of `@optimystic/db-p2p` (both entries); removed as dead code (project rule: no backwards compatibility yet).
- **Other cloning callers left alone**: `Tracker.peekMaterialized` and `NetworkTransactor`'s per-block projection (writer side, 0.04 s in the profile) and the two reservation reads named in the NOTE. Out of this ticket's scope.
- The memory bound's tripwire is the `NOTE:` at `PREVIEWED_DIGESTS_CAPACITY`.

## Review findings

Read `ticket(implement): a-member-hashes-a-committed-block-once` before the handoff, then checked the claims against the code.

- **Correctness of the memo (checked, holds).** Walked every interleaving of an unlatched preview against a latched pend and commit: a commit's `take` deletes a still-unsettled reservation, so the preview's `settle` keeps nothing; a pend's `forget` after the save voids a preview that read the old record, and a preview that reserves between the save and the `forget` loses its reservation too (a miss, never a wrong hit). The digest does not depend on `rev`, so the `rev` match is an extra guard, not a requirement. `take` sits after `setLatest`, and `latest` passed to `digestBaseOf` is the pre-commit latest the commit applies over — the same base the preview read. Only `BlockStorage.savePendingTransaction` writes a pending record (it is called only from `pendUnderLatches`), so no other path can replace a record behind the memo. Paths that skip `internalCommit` (idempotent re-commit, refusals) leave an entry for the LRU; harmless.
- **No-copy preview (checked, holds).** `BlockStorage.getPendingTransaction` and `getBlock` have no object cache; `CachedRawStorage`'s adapter re-encodes (`getPending` → `encodeJson`); the only test `IRawStorage` delegates to a kernel. `sharedTransformForBlockId` callers (pend pass 1, `declaredBaseFor`, `savePendingTransaction`) only read or encode.
- **Fixed (minor):** `pendUnderLatches` pass 2 called `forget` only after a successful save. A save that throws partway (the raw write is its last step, but a storage failure there can still have replaced the record) would have left an earlier preview's digest in place for the next commit of that record. Moved `forget` into a `finally` around the save in `packages/db-p2p/src/storage/storage-repo.ts`.
- **Tests:** the two new "after the action is re-pended with other content" cases pin the `forget` contract on real storage, one each way — kept. The removed `cloneDecoded` tests went with the function. No test added for the `finally` fix: reproducing it needs a store that fails mid-write, and the change is one line of ordering.
- **Docs:** read the internals.md additions (*Commit content-digest check*, *Functions That Share*, *Transform Ownership*, *Storage Returns References*); they match the code. `docs/correctness.md` still describes the preview correctly. No other doc or export referenced `cloneDecoded` (`git grep`).
- **Tripwires:** the memory-bound `NOTE:` at `PREVIEWED_DIGESTS_CAPACITY` and the held-object `NOTE:` in `materializePreview` are where the implementer put them; nothing new to park.
- **Known gaps accepted as stated:** base immutability at a fixed `(rev, actionId)` is argued, not enforced (first-writer-wins restores, invalidations write new revisions); a throwing preview leaves an inert reservation; other cloning callers named in the `transformForBlockId` NOTE are out of scope.
- **Validation:** `yarn workspace @optimystic/db-p2p build`; `yarn test` in `db-p2p` 3712 passing, 78 pending; ESLint on the three changed source files clean; `yarn lint:docs` clean. `db-core` was not re-run (no change in this pass; implement ran it at 2068 passing).
