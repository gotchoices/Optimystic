# Blob fetch building blocks

The first half of `feat-blob-fetcher-verifies-and-resumes` (implement/2.42), which wires and exports everything here. Nothing in this ticket dials a peer.

## What was built

- **Constants** in `packages/db-p2p/src/protocol-limits.ts`: `MAX_BLOB_BACKGROUND_GET_STREAMS` (4), `MAX_BLOB_FOREGROUND_GET_STREAMS` (8), `BLOB_WAIT_RETRY_INITIAL_MS` (500), `BLOB_WAIT_RETRY_MAX_MS` (8000).
- **`blobHolderCandidates`** in `packages/db-p2p/src/blob/blob-holders.ts`: hints first (deduplicated), then the blob's cohort (`findCluster(routingKeyForBlob(ref))`), connected before not; drops malformed ids (logged once per call), self, peers the membership predicate refuses, banned peers, and peers whose record does not list the blob protocol; deprioritized peers last. A throwing cohort lookup is logged and read as an empty cohort.
- **`unavailableOutcome`** (same file): the pure classification of one unavailable piece's attempts into `cohort-unreachable`, `peers-unreachable`, `corrupt` or `not-held`, matching docs/blobs.md's failure definitions.
- **`BlobGetSlots`** in `packages/db-p2p/src/blob/blob-get-slots.ts`: two independent pools (foreground, background); per pool at most one stream per peer and at most the limit in all; FIFO with busy-peer waiters skipped rather than blocking; idempotent release; an aborted waiter leaves the queue and rejects with `signal.reason`.
- **`LocalBlobService.fetchStore()`** returning one `BlobFetchStore`: `source`, `holdCached` (adds a `cached` hold, creating a `whole: false` record when none), `storePiece` (inside one shared sweep-gate hold: note the ref for a running sweep, then `put`), `markWhole` (`correctRecord(ref, true, size)`). Nothing flushes.
- `PieceSweeper`'s class comment now names the fourth race it is closed against (a fetch storing a list piece over a child already present as an orphan) and why noting the ref with every fetched piece closes it.
- `docs/debugging.md`: `blob:fetch` row (`holders:bad-peer-id`, `holders:cohort-lookup-failed`), count 66 — required by `packages/db-p2p/test/logger.spec.ts`.

## Review findings

Read the implement commit (`ticket(implement): blob-fetch-building-blocks`) first, then the handoff, the fetcher ticket (implement/2.42), `PieceSweeper`, `LocalBlobService`, `peersServing` and `admittedBy`.

**Checked, no defect found:**
- *Sweep-race argument (review focus 1).* Traced against `PieceSweeper.sweep`: `changed` is set inside an exclusive hold before the records pass, so a fetched piece stored before that is seen by the records pass, one stored after is in `changed` and re-walked by the decide step (which runs under the exclusive gate, after every shared holder), and one whose shared hold waits behind the decide step finds the orphan child already deleted. The fetcher ticket's step "after the batch, if any stored piece is a list piece, walk again" (2.42 §Batches) then sees the child absent and asks for it; once a parent is stored the child can no longer be deleted. Children cannot ride in the same batch as their parent, since only frontier pieces are batched. The argument holds.
- *Abort after grant (review focus 2).* `grant` removes the abort listener before resolving, so a later abort cannot reject; the release is then the caller's. Made that explicit in `BlobGetSlots.acquire`'s doc comment (minor, fixed). The fetcher ticket already releases in a `finally`.
- `SlotPool.grantWaiting` re-entrancy: granting only resolves a promise and abort events cannot fire inside the loop, so splicing while iterating is safe. Listener-add precedes the synchronous grant, so an immediately granted waiter leaves no listener behind.
- `unavailableOutcome`: the code checks `peers-unreachable` before `corrupt` while the table lists them the other way, but the rows are disjoint (the `corrupt` row has no `no-answer`), so the result is the same; consistent with docs/blobs.md's definition of `BlobCorruptError` ("no other holder could supply them").
- `blobHolderCandidates`: a hint for a peer this node has no peer record for is dropped by `peersServing`. That is correct — such a peer cannot be dialed by id (no peer routing in this stack) — and is not logged; noted here rather than as a tripwire because nothing would change if it were.
- Record shape: a `cached` hold and an absent `size` are valid under `blob-record.ts`'s validator; `holdCached` on a record already holding `cached` writes nothing.
- `markWhole` logs `record:corrected` under `blob:store` when a fetch completes; accurate (the record goes from `whole: false` to `true`), so left as is.
- Resource cleanup: no timers or listeners outlive a waiter; the store door is one object built in the constructor.
- Type safety: no `any`; `UnavailableOutcome.reason` excludes `not-here` by type.
- Docs: docs/blobs.md is deliberately unchanged here — its "to be built with the fetcher" paragraphs and §Holds sentence are 2.42's explicit TODO, which cites these modules. docs/debugging.md row matches the two log lines emitted. No other doc names these symbols yet.
- Source hygiene: new files are 128–134 lines; comments state reasons and constraints, none narrate statements.
