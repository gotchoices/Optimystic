# Commit content digest — part 2 of 3: threading to the wire (complete)

Part 1 (`commit-cert-digest-core-primitives`) supplied `computeBlockContentDigests`,
`Tracker.peekMaterialized`, and the optional `blockDigests` field on `CommitRequest` /
`RepoCommitRequest` with no producer and no consumer. This slice added the producers and the
per-peer narrowing on the wire. Part 3 (`commit-cert-digest-member-check`, in `implement/`) adds the
member-side check that consumes the field.

Nothing here changes what a member does with a commit. The observable change is that commit requests
now carry an extra field, and that the field is narrowed per peer.

## What shipped

**Producers.** `TransactorSource.transact` takes a trailing `blockDigests?` and spreads it onto the
`CommitRequest`. `Collection.syncInternal` computes it from the per-attempt snapshot tracker after
the log append (so the log tail, and the header on collection creation, are digested too), recomputed
each retry. `TransactionCoordinator.commitCollection` computes it from `collection.tracker` over the
`blockIds` it was handed, once, before the transient-retry loop.

**Per-peer narrowing.** `NetworkTransactor.commit` threads the action-wide map through both
`commitBlock` calls (header, tail) and `commitBlocks` for the remainder. `digestsFor(all, batchIds)`
narrows it inside the `processBatches` send callback — at send time, not up front, because
`processBatches` re-splits a failed batch across different coordinators on retry. Each cohort
therefore only ever signs declarations for the blocks it is driving.

**Omit-when-empty is now one invariant, not three copies.** A single exported
`blockDigestsField(digests)` in `transform/digest.ts` wraps the map so it spreads to nothing when
absent or empty; all three producers go through it. The key must be absent rather than `{}` because
the request is hashed verbatim into every cohort signature preimage — a commit that declares nothing
has to serialize exactly as it did before the field existed.

**Never break the commit.** Materializing replays staged ops against the *locally cached* base and
can throw on its own (an op naming an entity the cached base no longer has — reachable when another
action's commit folds a different shape into the cache between staging and digesting). The per-id
loop catches, logs, and skips, degrading to "undeclared" exactly like an uncached base.

**Docs.** `docs/repository.md` §`commit(request)` gained the input line and a *Declared block
content* subsection covering the three load-bearing properties (optional per block, rides inside the
request so mixed-version peers hash identically, each cohort sees only its own blocks) and the
never-break-the-commit rule. `docs/transactions.md`'s Phase 3 COMMIT box points at it.

### Minor — fixed in this pass

- **Orphaned doc comment** (`network-transactor.ts`). `digestsFor` was inserted between
  `collectionIdForRef`'s doc comment and its declaration, so the comment described the wrong
  function. Moved `digestsFor` above the comment.
- **Bare `catch { continue }` with no logging** (`digest.ts`). AGENTS.md is explicit: don't eat
  exceptions without at least logging. The swallow is correct in kind — the declaration path is
  advisory and must never fail a commit that would otherwise succeed — but as written it could hide a
  genuine `applyTransform` bug behind a silently-undeclared block, with nothing to grep for. Extracted
  to a `peekOrSkip` helper that logs the block id and the error through `createLogger('digest')`
  before degrading. Behavior unchanged; the swallow is now observable via
  `DEBUG=optimystic:db-core:digest`.
- **Three open-coded copies of "omit when absent or empty"** (`transactor-source.ts`,
  `coordinator.ts`, `digestsFor`). Two spelled it `Object.keys(x).length > 0` inline; the third used
  the existing `isRecordEmpty` utility. Consolidated into the single exported `blockDigestsField`
  described above. This is the rung that retires the class rather than the instance: a future fourth
  producer cannot reintroduce a `{}` that splits cohort signatures, because there is one place the
  field is built.
- **`RepoCommitRequest.blockDigests` doc was factually wrong** (`i-repo.ts`). It said the field is
  "threaded verbatim from the transactor's `CommitRequest`" — it is narrowed per batch, which is the
  whole security property of the slice. Corrected, and added the same narrowing note to
  `CommitRequest.blockDigests` in `struct.ts` so a reader who only sees the action-wide type knows it
  does not reach a peer whole.
- **`docs/transactions.md` was stale.** Its Phase 3 COMMIT box enumerates what the commit phase does
  and did not mention the declaration the coordinator now computes. Added one line pointing at
  `repository.md` rather than restating it. `docs/repository.md`'s new section was read in full and
  is accurate.

### Test gaps — closed in this pass

- **The "mixed-version hash guarantee" test did not test what it claimed.**
  `JSON.parse(JSON.stringify(message))` yields an identical object, so the assertion "an unaware peer
  hashes the same" is near-tautological — and it stays green under exactly the regression it says it
  pins: if someone rewrote the cluster hash helpers to hash an allowlist of known fields, *both* sides
  would drop `blockDigests` alike and the hashes would still match. Added a companion test asserting
  the hash **changes** when `blockDigests` is present versus absent, and changes again when the digest
  value differs. That is the assertion an allowlist rewrite actually fails.
- **`TransactionCoordinator.commitCollection`'s digest computation had no content coverage** (the
  handoff flagged this). The existing phase tests only exercised the empty-tracker case. Added two
  `commitPhase` tests: one stages an insert in each fake collection's tracker and asserts every
  per-collection commit request carries exactly its own block — never a sibling collection's, even
  though both staged one — with no `baseRev` (inserts are base-independent); one asserts the key is
  absent, not `{}`, when nothing is staged. `InstrumentedTransactor` now snapshots each commit
  request; `fakeCollections` takes an optional stage callback.

### Tripwires — recorded at the code site, not filed as tickets

- **Digest recompute on every `Collection.sync` retry.** The snapshot tracker is rebuilt each
  iteration, so a sync that loses N races pays N full hashing passes it did not pay before.
  Unmeasured, and cheap relative to the round trips it is retrying. `NOTE:` at the computation site in
  `collection.ts`, naming the fix (memoize per id + staged ops) and the condition (digest hashing
  showing up in a profile).
- Part 1's cache-capacity coverage bound (a commit touching more update-carrying blocks than the
  `CacheSource` capacity digests only the resident ones) is already a `NOTE:` at the top of
  `digest.ts`. Unchanged, not re-recorded.

### Checked, nothing found

- **Per-batch narrowing, the security-relevant behavior.** Re-read `commit` → `commitBlock` →
  `commitBlocks` → `digestsFor` end to end. Header and tail each leave as their own single-block
  batch, each narrowed to itself; the remainder narrows per coordinator batch at send time. The
  existing spec's retry-split case (peer-B fails, its two blocks re-resolve to two *different* peers)
  genuinely fails if anyone hoists the subsetting up front. No defect.
- **Wire survival.** `RepoClient.commit` wraps the whole request into a `RepoMessage` that
  `protocol-client.ts` serializes with `JSON.stringify`, and `repo/service.ts` hands
  `operation.commit` straight to the repo. Nothing on that path filters unknown fields, so the claim
  that the declarations reach the member intact holds.
- **Signature preimage docs.** `docs/correctness.md` §Promise/commit signatures spells out the
  preimage formulas; they hash `message` as a whole, so a new field inside the commit op needs no
  change there. Deliberately left alone.
- **Type safety, imports, cleanup.** No `any`, no unused imports, `isRecordEmpty` still used by its
  original call site, nothing allocated that needs releasing anywhere in the diff.
- **File size.** `network-transactor.ts` is 978 lines and `coordinator.ts` 1119 (`wc -l`). Both were
  already that large; this slice added roughly 20 lines to each. Splitting either is a separate
  refactor with its own risk and is not this ticket's business, so no size-debt ticket was filed —
  recording the measurement here so a future reviewer has it.
