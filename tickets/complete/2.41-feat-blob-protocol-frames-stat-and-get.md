# Blob protocol server and client (`stat` and `get`)

The blob protocol (`${prefix}/db-p2p/blob/1.0.0`) has a server on every node, serving and client alike, and a client a caller constructs. The fetcher (`feat-blob-fetcher-verifies-and-resumes`) is the first consumer of the client and constructs it; the node does not.

## What was built

- `BlobProtocolService` (`blob/blob-protocol-service.ts`): per inbound stream, the authorization gate before anything is read; one request frame read under a `ProgressDeadline`, then the reader released so a second frame is never read; `stat` answered from local holdings one ref at a time (`here`/`partial`/other → `whole`/`partial`/`none`, a throwing local stat answered `none` and logged); `get` takes a slot from `InboundGetAllowance` (2 per peer, 16 per node, released in the handler's `finally`), sends the `held` header, then reads and sends each held piece in turn; a piece swept between header and frame aborts the stream. `announce` → `onAnnounce` or `declined`; `held` → `onHeld`, acknowledged. A failure aborts the stream (`serve:stalled` when the deadline fired, else `serve:aborted`).
- `BlobProtocolClient` (`blob/blob-protocol-client.ts`): `stat`, `get`, `wireBytes`. Refuses locally an empty list, an over-cap list, and a `get` naming a piece twice. `get` resolves on the header; `pieces` reads exactly the held count then requires end of stream (`truncated` / `extra frame`); leaving the loop early aborts the stream; the caller's abort reason wins over a stall.
- `blob-frames.ts` gained `abortStreamOnStall` and `releaseBlobFrames`, and `closeBlobStream` now rethrows libp2p's `close` event as an `Error`.
- Node wiring: `inboundAuthorizationOf(options)` builds the authorization slice once and spreads it into the four storage services and the new `blob` service, registered on both roles; the blob protocol is deliberately not in the prepared-stream pool. Exports in `index.ts` and `rn.ts`. Docs: `docs/blobs.md` (status and §Moving pieces between machines), `docs/internals.md` (§Inbound Stream Authorization, §Client nodes), `docs/debugging.md` (`blob:protocol` row).

## Tests

- `test/blob-protocol-stalls.spec.ts`: a header that promises a piece it never sends fails the client's read with `BlobTransferStalledError` within one deadline; a requester that stops reading is reset by the responder within one deadline.
- The authorization wiring spec covers the blob protocol; the service-set spec lists `blob` on every node shape.

## Review findings

Read the implement diff (`ticket(implement): feat-blob-protocol-frames-stat-and-get`) before the handoff, then the touched docs and the modules they cite.

- **Correctness — server.** Checked the gate-before-read order, the single `next()` and the release of the reader on both the decoded and the refused paths, slot release on every path (the `finally` in `handleStream` covers stalled, aborted, refused-busy, malformed and success; the slot is only taken after a well-formed `get`), the stall path (the deadline aborts the stream, the pending read throws, `abandon` reports `serve:stalled`), an oversized piece from the store (fails `sendBlobFrame` after the header, aborting the stream — correct), and that the header cap applies to frame 0 only. No defect found.
- **Correctness — client.** Checked every exit of `stat`, `get` and `receivePieces`: each path stops the deadline, removes the caller's listener and releases the reader (`finish`, idempotent); a failure aborts once with the caller's reason ahead of the stall ahead of the error; an early `break` aborts; a `get` with nothing held settles inside `get`. The documented gaps (a `pieces` never iterated leaves the caller's abort listener attached until the stream ends, and a second iteration of `pieces` yields nothing) are documented on `BlobGetReply.pieces`. No defect found.
- **Minor, fixed:** the server called `blobs.stat(ref)` relying on `probe` being off by default; it now passes `{ probe: false }` explicitly, so a remote peer's `stat` can never make this node query the blob's cohort on its behalf once the probe is built (`holdingOf` in `blob-protocol-service.ts`).
- **Node wiring and docs.** `inboundAuthorizationOf` is spread into all five gated services; `logIgnoredServingOptions` no longer names the authorization options; the `servesBlocks` and `authorizeInboundStream` doc comments, `docs/internals.md` §Inbound Stream Authorization and §Client nodes, `docs/blobs.md` and the `docs/debugging.md` row all match the code. `yarn lint:docs` clean.
- **Source hygiene.** Both new modules are under 300 lines with small methods. A one-line `describe(err)` helper is now repeated in five blob modules (two from this ticket); left as is — consolidating it means touching three earlier modules for no behavioural gain.
- **Tests.** The two stall specs pin a named contract on real nodes (each end gives up within one deadline) and were mutation-checked by the implementer; kept. The handoff asked whether the throwaway checks (busy refusal and slot release, early exit, caller abort) should become permanent here: declined. Slot release is structural (one `finally`), and early exit and caller abort are contracts the fetcher's specs exercise end to end as their first consumer; adding them here would be a second copy of the same coverage.
- **Tripwires:** none new. The receive-side buffering bound and the `stream.pause()` rejection are already recorded as a `NOTE:` at `readBlobFrames`.
- **Tickets filed:** none; nothing found past the filing bar.
