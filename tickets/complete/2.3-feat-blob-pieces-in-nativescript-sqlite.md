# Complete: blob pieces in the NativeScript SQLite database

## What was built

- `SqlitePieceStore` (`packages/db-p2p-storage-ns/src/sqlite-piece-store.ts`), exported from the package index: one `pieces (id TEXT PRIMARY KEY, bytes BLOB NOT NULL)` table appended to `SCHEMA_SQL` (`CREATE TABLE IF NOT EXISTS`, so an older database gains it on its next open, no version bump). Prepared statements for `has`, `get`, `put` (`INSERT … ON CONFLICT(id) DO NOTHING`), a separate zero-length put writing `zeroblob(0)`, `delete`, keyset-paged `list` (1000 ids a page, each drained before yielding) and `bytesUsed` (`sum(length(bytes))`, logs and answers 0 on failure, as the block store's byte count does). `durability = 'power-loss'`, no `close` (shared handle), `storeIdentity()` = `identityForHandle(SQLITE_HANDLE_SCHEME, db)`, equal to the block store's over the same handle.
- `SQLITE_HANDLE_SCHEME` in `sqlite-storage.ts`, used by both `SqliteBatchBackend` and the piece store.
- `PendingSqliteSync` in `sqlite-sync.ts` (internal): dirty flag, failure latch and `flush` through `syncSqliteDb`; `SqliteKVStore` now runs over it, unchanged in behaviour.
- Implement-stage deviation from the plan, kept: `node:sqlite` binds a zero-length typed array whose `.buffer` has been read as NULL (re-verified in review with a plain `node -e`), and `INSERT OR IGNORE` would swallow the resulting NOT NULL failure, so an empty piece is written by its own `zeroblob(0)` statement and both puts use `ON CONFLICT(id) DO NOTHING`.

## Review findings

Read the `ticket(implement): feat-blob-pieces-in-nativescript-sqlite` diff first, then the handoff; ran `yarn build` and `yarn test` in the package (86 passing), `eslint` on the package and `tsc --noEmit` over `src` and `test` (clean), and `yarn lint:docs` from root (clean). Full `yarn check` and any device run were not done.

- **Correctness / error handling — fixed.** `get` threw a `TypeError` when the driver returned NULL for a row. The column is NOT NULL, so a NULL can only be a driver's spelling of an empty BLOB (SQLite's C API answers a zero-length BLOB with a null pointer); since the node's own piece source is read as `verified: true` and is not re-hashed, there was no later check to fall back on either way, and throwing would make every zero-length piece unreadable on a device whose binding does this. `get` now reads NULL as the zero-length piece; any other non-bytes value still throws. The `NOTE:` it replaced is gone and the README device section was updated to match.
- **Test coverage — added one.** `list`'s page loop (keyset continuation, stop on a short page) had real branching and no test, since the conformance listings hold under 1000 pieces. Added "lists every id once across several pages": 2,500 rows inserted with one recursive-CTE statement, then listed; asserts count and uniqueness. Kept the conformance run and the upgrade test (the only coverage that an older database gains the table). No test for `PendingSqliteSync` itself: the existing kv-store flush test and the conformance flush cases cover it.
- **API surface — trimmed.** `PIECE_LIST_PAGE` was exported from the package index for no consumer; it is now module-level only (the spec imports it from the module).
- **Docs — one stale note fixed.** The read-concurrency `NOTE:` on `NSPluginStatement.get` in `ns-opener.ts` listed the autocommit writers of non-block tables; added the piece store. `docs/blobs.md` §The local store and §Platforms and limits, `packages/db-p2p/docs/storage.md` §7 and the package README (usage, shutdown, table list, durability, device section) were read and reflect the new store.
- **Concurrency — checked, nothing found.** Piece writes go through the connection mutex, so they never land inside the block store's write-group transaction; piece reads are unserialized but no transaction writes `pieces`; keyset paging tolerates the sweep deleting ids while it lists, within the interface's listing promise.
- **Durability — checked, nothing found.** A flush is one synced transaction over the shared WAL, covering every earlier autocommit write; a failed sync latches the store (`StoreFailedError` on writes and flush, reads keep working), matching the `IPieceStore.flush` contract.
- **Byte accounting — checked, nothing found.** Identity equality means `blockStoreCountsPieces` leaves the piece store's figure out, so `bytesUsed`'s full-table sum is rarely called.
- **Tripwires — none new.** The JNI 512 KiB `NOTE:` in `ns-opener.ts` already covers pieces larger than this design writes.
- **Known gaps, unchanged:** nothing has run on a device (1 MiB piece over the JNI bridge, empty-BLOB read-back, sub-view binding); whether the plugin returns BLOBs as `Uint8Array` on every platform is unverified (`get` throws a named `TypeError` otherwise). The README example still does not pass the raw storage to `createLibp2pNode` (pre-existing, left alone).
- **No tickets filed.**
