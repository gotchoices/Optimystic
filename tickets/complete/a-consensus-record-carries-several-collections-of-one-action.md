# A consensus record carries several collections of one action

First of three tickets for GitHub #42 (siblings: `a-coordinator-runs-an-actions-collections-as-one-record`, `a-transaction-pends-and-commits-its-collections-together`). This one is the cohort-member side: what a member does when a consensus record's message carries more than one operation.

## What landed

- `RepoMessage.operations` is `[RepoOperation, ...RepoOperation[]]`. A message of more than one operation must be a **batch**: all `pend` or all `commit`, one action id, no block id in two operations. `batchShapeFault` in `packages/db-p2p/src/cluster/record-operations.ts` is the one implementation; `ClusterMember.validateRecord` throws `Malformed batch: …` on any other multi-operation record, as a fault of the record (an empty list is left to the membership admission gate's signed vote).
- A member applies a batch's operations one at a time and retains ONE verdict for the record (`batch-verdicts.ts`): a pend record succeeds only when every operation's pend did, otherwise the first conflict-shaped refusal (else the first refusal); a commit record succeeds only when every operation's post-reconcile durable verdict does. Per-block pend refusals are still retained per operation, so the action's commit record is refused at the promise vote when any collection's pend was refused.
- The commit cert and commit proof are built once per record and shared by every operation. A later reconcile (`reconcileRefusedCommit`) repeats only the operations whose own verdict is a behind refusal.
- Other readers fixed to see every operation: coordinator hints in `ClusterClient`, `LatePendRefusals.pendsOf` (which previously kept only the last collection's blocks). Every doc and comment naming the removed `applyConsensusOperation` now names the function that does the thing described.
- `RepoService` ingress still serves `operations[0]` only; the next sibling ticket adds the shape check there. No sender builds a batch yet.

Validation: `yarn workspace @optimystic/db-p2p test` 3488 passing / 73 pending; `yarn lint`, `yarn lint:docs`, db-p2p `typecheck` clean. `yarn test:integration` not run (single-operation behaviour is unchanged and no sender builds a batch).
