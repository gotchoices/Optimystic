# What landed

**The drain.** `UnderReplicationDrain` is a `Startable` constructed in `createLibp2pNodeBase` right after the spread-on-churn block and before the arachnode/FRET gate, on every node unless `underReplicationDrain: { enabled: false }`. A pass runs on start, on `connection:open` and `peer:identify` (debounced 5 s, throttled to one pass per 15 s with a trigger inside the window deferred rather than dropped), and on a 30 s re-check timer armed while the ledger has entries. A pass skips under a partition; computes the pushable peers (connected and identified as serving this network's block-transfer protocol) and skips when there are none; lists the ledger; rotates through at most 64 entries oldest-first; and per entry works out who is owed (a named set as recorded, never re-resolved; an empty set re-resolved via `findCluster`, a self-only cohort counted as `solo` with no attempt), pushes to the reachable non-abandoned owed peers through the shared helper, takes confirmed peers off the entry, counts a round via `noteAttempt` when a reachable peer did not confirm, abandons a peer per block after 5 consecutive unconfirmed rounds until it reconnects, deletes the entry for a block gone from local storage, and fires the full-replication event after the entry is deleted.

**Revision guard.** `IUnderReplicationLedger.satisfy` gained an optional `heldRev`: an entry recording a higher revision than the copy the peer confirmed is left alone. A copy of a newer revision satisfies an older entry.

**The event.** `BlockDurabilityReachedEvent` / `IBlockDurabilityNotifier` in db-core, implemented by `StorageRepo` beside `IBlockChangeNotifier`, block-keyed with the rationale in the type's doc comment. The drain receives a one-method sink. Emitted per block.

**The push loop.** `pushBlockToPeers` in `block-transfer-service.ts` is the read-certify-push-interpret core, with `stopAfterConfirmed`, the two per-peer deadlines, reason and prefix as parameters, returning `no-local-data` / `unavailable` / `pushed` with confirmed, refusals (`rejected` vs `unreachable`) and skipped. All three existing copies (`executePush`, `executeConfirm`, the spread loop) were converted. The helper logs nothing per peer; each caller keeps its own log namespace.

**Ledger warm-up.** `KvUnderReplicationLedger.list` seeds the eviction index when it is the first scan; `size()` reads the index.

# Deviations from the ticket

- Reachable means identified, not merely connected: a peer counts as pushable only once identify reports it serving this network's block-transfer protocol, which makes the "nobody to push to" short-circuit precise. `peer:identify` is therefore a trigger.
- `executePush` / `executeConfirm` now pass `transferTimeoutMs` as the client's dial and reply deadlines (which abort the dial and tear down a silent stream) instead of a `withTimeout` race that left the dial running. Worst-case per-peer wait is two deadlines rather than one; documented on `BlockTransferConfig.transferTimeoutMs`.
- Naming an unnamed entry happens only when at least one peer confirmed, and (after review) through a dedicated `name` operation rather than a re-`record`.
- `node.underReplicationLedger` and `node.underReplicationDrain` are exposed untyped, matching the other monitors.

## Review findings

**What was checked.** The implement-stage diff was read in full before the handoff summary: the drain, the push-loop helper and all three conversions, the ledger changes, the node wiring, the event on `StorageRepo`, every spec and the integration util, and every doc the change touched. libp2p 3.1.3's connection manager was read to confirm the ordering the reconnect logic depends on. The coordinator's `unconfirmed` derivation was read to confirm a recorded missing set never names this node. Lint, typecheck, docs lint, the db-p2p build, the full db-p2p unit suite (2895 passing, 63 pending, 0 failing after the review's additions) and the lifecycle integration spec (7/7, both phase 5 and phase 7 on the acknowledged branch, so the drain assertions ran through the reviewed naming path) all pass.

**Minor, fixed in this pass.**

- **Entry resurrection on a concurrent settle.** The drain named an unnamed entry by calling `record` again at the same revision. `record` creates an entry that does not exist, so a `full` commit that settled the entry while the push was in flight was undone: the drain wrote a stale entry back into the durable ledger, which then owed named peers until they connected and confirmed, and eventually fired a second event. Fixed by adding `IUnderReplicationLedger.name(blockId, rev, missingPeerIds)`, which names only an entry still standing at that revision and still unnamed, and creates nothing. The drain uses it; the kv implementation, the fake ledger in the coordinator durability spec, the interface docs, `docs/debugging.md` and `packages/db-p2p/docs/repo.md` are updated. Pinned by three ledger cases and the drain case "an unnamed entry settled by a full commit mid-push is not resurrected under the resolved names".
- **A pass that threw was not throttled.** `lastPassAt` was stamped only on a pass that ran to completion, so a ledger fault mid-pass made the next trigger an unthrottled retry. The stamp now happens in the pass's `finally` for any pass that scanned; a skipped pass still does not count, so an identify arriving after a "nobody pushable" skip is not delayed.
- **The backlog ticket on the solo-node index load was wrong about what the drain changed.** It said a node that starts alone still pays the load on its first commit. It does not: the start pass's `size()` call (which decides whether to arm the re-check timer) loads the index on every node with the drain enabled. Corrected in the ticket and in the `NOTE:` on `KvUnderReplicationLedger.index()`, and pinned by the drain case "the start pass loads the ledger index even when nobody is connected".

**Major.** None. The one behavioural change to existing paths (the `transferTimeoutMs` semantics in `executePush` / `executeConfirm`) is an improvement, documented, and covered by the existing block-transfer and rebalance-reaction specs.

**Tripwires parked in code.**

- `NOTE:` on `UnderReplicationDrain.recordConfirmed`: an entry settled mid-push by a newer `full` commit is reported "gone" by `satisfy`, so the event fires under the older revision. True in substance (the block is fully replicated), but if a host ever needs "cleared by the drain" told apart from "settled by a later commit", `satisfy` would need to distinguish "deleted now" from "absent".
- `NOTE:` on `UnderReplicationDrain.handleConnectionOpen`: "fresh connection" is read as "the peer's only connection", which relies on libp2p's connection manager storing the connection synchronously before user listeners run (true on 3.x). If an upgrade defers that store, parallel connections look fresh and an abandoned peer is retried on each one, which is cheap; the check would then want `peer:connect`.
- Pre-existing `NOTE:` on the class about the whole-ledger scan per pass, and on `KvUnderReplicationLedger.index()` about the load cost, both still accurate after the corrections above.

**Considered and declined, with reasons.**

- The `unref` timer helper now exists three times (`rebalance-monitor.ts`, `cohort-topic/host.ts`, the drain). Three one-line private helpers are cheaper than a shared module and a ticket; not filed.
- `checkNow()` can return the result of a pass another trigger started while it was waiting, rather than a manual one. Only tests call it, and every spec asserts on ledger state as well as counts; not changed.
- An in-flight pass is not awaited by `stop()`, so a push already on the wire may write the ledger after the node stopped. The key-value store is not closed by node stop and the write is a correct fact; not changed.
- Entries recorded while the owed member is already connected wait for the 30 s re-check rather than a hook from `record`. The commit retry usually lands the copy first; the timer is bounded and cheap; not changed.

**Docs.** Every touched doc was read against the code. `docs/debugging.md` gained the new ledger tag. No other drift found.
